## 연구 관계 지도

Cognitive Flow는 전체 연구를 연결하는 상위 가설이고, 나머지 네 연구는 판단·실행·실전 영역·마지막 Hand를
각각 깊게 다루는 전문 연구다. 서로 경쟁하는 기능 목록이 아니다.

```text
상위 순환
T5 Cognitive Flow
사용자·모델·Runtime·현실의 판단과 행동이 어떻게 끊김 없이 이어지는가
        ↓
판단층
T5 실천지능
무엇이 중요하고 어느 깊이·방법·중단이 적절한가
        ↓
실행 조합층
T5 Method Runtime
현재 Work의 Terminal·Hand를 한 임시 방법으로 결속할 필요가 있는가
        ↓
첫 고가치 실전 영역
Document Reality & Reconciliation
현재 문서 감각·관계·근거·결과가 실제 사용자 목적에서 충분한가

별도 마지막 감각·행동 확장
Computer Use
File·Terminal·Browser·Connector로 닿지 못하는 desktop app 현실이 반복되는가

별도 기본 감각기관
T5 Auditory Intelligence
사용자가 맡긴 local audio·video를 exact source·coverage와 함께 듣고 실제 결과로 전달하는가
```

역할 경계:

- Cognitive Flow는 새 Engine·Store·Planner가 아니라 기존 T5 순환의 actual 실패를 측정하고 필요한 경계만
  강화하는 상위 연구다.
- 실천지능은 목적·깊이·방법을 판단하는 모델 측 후보이며 Runtime 의미 Router가 아니다.
- Method Runtime은 모델이 정한 임시 방법의 exact input·authority·execution·effect·settlement만 담당한다.
- Document Reality는 Method Runtime의 자동 개통 사유가 아니라, 현재 T5 능력과 실패 원인을 분리하는 실전 영역이다.
- Computer Use는 Method Runtime이나 안드로이드 비유만으로 열지 않고 대체 불가능한 실제 GUI 목적에서 별도 자격한다.
- Auditory Intelligence는 Computer Use·상시 microphone이 아니라 File Reality·Attachment·Channel media에 결속된
  bounded 청각기관이며, Whisper 전사와 후속 목적 판단을 같은 Runtime 의미로 합치지 않는다.

## 6차 이후 개통 판정

6차 UX·WA delta·총괄 HQ·해당 물리 범위를 먼저 닫는다. HQ 결과에서 다음 중 실제로 재현된 한 결함 가족에 따라
연구선 하나만 연다.

| 실제 관측 | 첫 연구선 | 아직 열지 않을 것 |
|---|---|---|
| 일반 사용자식 지시와 전문가식 지시의 목적 결과 격차 | 실천지능 baseline | 전역 Prompt·Method Runtime |
| 복합 문서 인식·source 선택·관계·근거 실패 | Document `DR-0` | 새 문서 플랫폼·Method Runtime |
| 정확한 복합 여정의 단계별 model/tool 왕복이 주 병목 | Method `MR-0` | GUI·external effect·거대 Planner |
| 안정된 대안으로 해결되지 않는 desktop app 현실 | Computer `CU-R0` | action·좌표·상시 screenshot |
| local audio·video를 실제로 듣지 못하거나 hosted STT 없이 긴 녹음을 끝내지 못함 | Auditory `AU-0` | TTS·voice clone·music·상시 microphone |

원인 분리:

```text
사용자 목적 실패
→ 지시 이해 문제인가
→ 현실 관측·문서 인식 문제인가
→ Hand 선택·연결 문제인가
→ 단계별 모델 왕복 비용 문제인가
→ GUI에만 존재하는 현실인가
```

같은 Mission에서 여러 원인이 보이면 제품 변경 0의 baseline으로 각각 측정하고, 사용자 목적 실패의 최초 경계 하나만
후보화한다. 연구 문서 수·아이디어의 중요도·미래 잠재력은 동시 개발 근거가 아니다.

## 공통 우선순위

연구를 제품화하는 고정 순서는 없다. 다만 product delta 0의 조사 비용과 위험을 고려한 기본 연구 순서는 다음이다.

```text
총괄 HQ Evidence 분석
→ 실천지능: 표현 격차 baseline
→ Document: 현재 능력 actual baseline
→ Method: 실제 왕복 병목이 증명된 경우만
→ Computer Use: 대체 불가능 GUI 목적이 증명된 경우만
```

이는 구현 우선순위가 아니다. 각 baseline이 이미 충분한 현재 T5를 확인하면 해당 연구는 제품 변경 0으로 닫는다.
