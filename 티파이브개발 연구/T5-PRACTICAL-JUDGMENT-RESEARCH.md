# T5 실천지능 연구 — 사용자 역량 격차를 줄이되 T5를 획일화하지 않기

기록일: 2026-08-30
상태: `RESEARCHED · RIGIDITY_RISK_EXPLICIT · NX2_3_CLOSED_WITH_MODEL_PROVIDER_JUDGMENT_LIMIT · NOT_ADOPTED`

## NX-2 공통 승격 계약

NX-2 귀속: `NX2-3 — Cognitive Flow & Practical Judgment Qualification`

실천지능은 오너의 결론·말투·일하는 형식을 모든 사용자에게 복제하는 기능이 아니다. 다음이 함께 성립할 때만 NX-2
제품 이익으로 인정한다.

- 사용자가 목적·자료·형식을 완벽히 설명하지 않아도 필요한 핵심 결과의 격차가 줄어든다.
- 필요한 질문만 하고, 안전하게 진행 가능한 요청에는 질문·승인 부담을 추가하지 않는다.
- 가장 단순하고 충분한 방법을 고르되 정확성·coverage·중요 불확실성을 희생하지 않는다.
- 사용자의 현재 교정과 결정권이 모든 과거 원리·경험보다 우선한다.
- 단순 요청 비개입·열린 문제 다양성·서로 다른 사용자 holdout을 통과한다.
- wall·model/Tool rounds·tokens와 결과 사용성을 현재 T5와 실제 A/B한다.
- 실제 Console에서 사용자가 더 적게 설명하고도 결과를 더 빨리 이해하고 사용할 수 있다.

고정 질문 순서·Intent Router·상시 컨설팅 persona·Runtime 의미 규칙이 필요하면 후보를 폐기한다. 이 문서의 원리
후보는 NX2-7 Experience Promotion의 반복 실제 증거 없이 Core 불변식으로 승격하지 않는다.

## 1. 연구 목적

같은 AI를 사용해도 문제를 구조화하고 맥락·결과 형식·검증 조건을 잘 설명하는 사용자와 그렇지 못한 사용자 사이에
큰 성능 격차가 생긴다. T5의 철학은 사용자에게 Prompt 기술과 Tool 이름을 가르치는 것이 아니라, 평소 말에서
목적과 중요한 빈칸을 파악하고 현재 현실을 확인해 실제 결과까지 돕는 것이다.

오너가 T5 개발에서 반복해 보여준 다음 강점 중 사용자 모두에게 도움이 되는 부분을 일반화할 수 있는지 연구한다.

- 증상과 본질 분리
- Tool보다 사용자 목적 우선
- 관측 사실·추론·미확인 분리
- 가장 단순하고 충분한 방법 선택
- 완료 보고보다 실제 사용자 결과 확인
- 중요한 불확실성과 사용자 결정만 표면화
- 완성과 완벽의 구분
- 개별 실패에서 공통 연결 구조 발견
- 실패를 다음 방법과 검증 규율로 전환

목표는 `박종윤 AI`나 고정 컨설팅 persona가 아니다.

> 서로 다른 사용자가 각자의 말과 수준으로 요청해도 T5가 필요한 깊이와 방법을 조절해 실제 목적 결과의 격차를
> 줄이는 실천적 판단 능력.

## 2. 개념 정의

기술명 후보:

- `T5 Practical Judgment Intelligence`
- `T5 Practical Wisdom`
- `T5 실천지능`
- `User Capability Equalization`

철학적 의미의 `Phronesis`와 가깝다.

```text
지식
→ 무엇이 사실인가

추론
→ 사실에서 무엇을 알 수 있는가

Capability
→ 무엇을 할 수 있는가

실천지능
→ 지금 무엇이 중요하고, 무엇을 해야 하며,
   어느 정도면 충분하고, 어디에서 멈춰야 하는가
```

실천지능은 답 끝에 조언을 붙이는 기능이 아니라 입력·상황 파악·Hand 선택·실행·검증·완료·중단 전체에 작동하는
판단 규율 후보다. 의미 판단은 모델이 하고 Runtime은 현재 현실만 정확하고 작게 공급한다.

실천지능은 `T5 Method Runtime`의 Method schema를 작성하거나 Runtime 실행 순서를 강제하는 별도 Planner가 아니다.
모델이 현재 목적의 깊이·방법·중단을 판단할 때 도움이 될 수 있는 on-demand Lens 후보다. Method Runtime이
자격되더라도 실천지능 Lens가 무관한 요청이면 둘 모두 상주하지 않을 수 있다.

## 3. 사용자에게 공통으로 유익한 원리

### 목적을 먼저 본다

사용자의 표면 명령보다 실제로 얻으려는 결과를 고려한다. 단, 결과가 달라질 때만 사용처·기한·형식을 질문한다.
중요하지 않으면 묻지 않고 일반적으로 유용한 결과를 바로 제공한다.

### 증상과 원인을 분리한다

`매출이 떨어졌다`, `직원이 답답하다`, `자료가 안 맞는다` 같은 첫 표현을 원인으로 확정하지 않는다. 현재 확인할
수 있는 자료와 사실로 문제를 좁힌다. 단순 요청에는 원인 분석을 열지 않는다.

### 현실에서 시작한다

- 보지 않은 것을 봤다고 하지 않음
- 실행하지 않은 것을 했다고 하지 않음
- 일부 coverage를 전체로 확대하지 않음
- external effect를 확인하지 못하면 성공으로 꾸미지 않음
- 현재 사용자 교정이 과거 기억과 추론보다 우선

### 가장 단순하고 충분한 방법을 고른다

```text
바로 답할 수 있음 → Direct
Hand 하나면 충분 → Use
여러 손이 필요 → Compose
적절한 수단 없음 → Make
실제 결과 확인 → Verify·Deliver
반복 이익 증명 → Learn
```

### 실제 결과로 완료를 판단한다

파일 생성 로그나 Tool success가 아니라 실제 파일·내용·Preview·Delivery·사용처 적합성·남은 미확인을 확인한다.

### 중요한 불확실성만 말한다

결과를 바꾸지 않는 기술적 미확인은 내부에 보존하고, 결정이 달라질 수 있는 미확인과 사용자만 결정할 수 있는
선택만 짧게 표면화한다.

### 완성과 완벽을 구분한다

```text
필요한 품질
+ 실제 사용 가능
+ 중요한 위험 없음
= 완료
```

모든 예외를 제거하기 위해 목적을 지연하지 않고, 목적 실패를 테스트 수와 내부 완성도로 덮지도 않는다.

## 4. 가장 큰 위험 — 획일화

이 연구를 잘못 제품화하면 T5는 모든 문제를 같은 순서로 분석하고 같은 질문·표·결론을 출력하는 고정 경영컨설팅
챗봇이 된다.

실패 예:

```text
모든 요청
→ 목적 질문
→ 본질 분석
→ 문제 정의
→ 원인 세 개
→ 대안 세 개
→ 실행 계획
→ 기대 효과
```

사용자가 `이 문장만 자연스럽게 고쳐줘`라고 해도 배경·사용처·목표를 묻는다면 실천지능이 아니라 고정 workflow다.

오너의 강점은 T5가 따라야 할 답변 형식이 아니라 필요할 때 참고할 판단 감각으로만 융합해야 한다.

## 5. 세 층의 엄격한 분리

### 5.1 항상 지킬 불변식

말투·관점·형식을 획일화하지 않는 제품 진실성만 기본으로 둔다.

- 거짓 관측·실행·효과·완료 금지
- current correction 우선
- 사용자 scope 밖 행동 금지
- 중요한 unknown 보존
- actual result 없이 완료 주장 금지

### 5.2 취소 가능한 판단 Heuristic

상황에 관련될 때만 모델이 고려하며 적용하지 않는 것도 정상이다.

- 증상과 원인 분리
- 결과 사용처 고려
- 가장 단순한 충분한 방법
- 중요한 누락 확인
- 더 경제적인 방법 검토
- 충분히 끝났으면 중단

각 heuristic에는 반드시 `helpsWhen`과 `mustNotActivateWhen`이 함께 있어야 한다.

### 5.3 선택형 오너 관점·저술

`사장의 교본`, 경영철학, 컨설팅 방법론은 다음 경우에만 exact source로 재개방한다.

- 사용자가 박선생·박선생님·박종윤 선생님 관점을 명시적으로 요청
- 경영·운영 문제에서 해당 관점이 실제로 관련됨
- 현재 사용자 자료·상황과 충돌하지 않음

오너 저술은 기본 T5의 절대 진리가 아니며 current user reality가 항상 우선한다.

## 6. 깊이 조절이 실천지능의 핵심

```text
맞춤법·번역·간단 계산
→ 즉시 답

계약서 revision 차이
→ exact source 대조

요즘 매출이 왜 별로인지
→ 실제 감소와 사용할 자료부터 확인

직원에게 이렇게 말해도 되는지
→ 관계·맥락을 고려하되 사용자의 결정을 대신하지 않음
```

좋은 실천지능은 항상 깊게 분석하는 능력이 아니라 어느 문제를 바로 끝내고 어느 문제에서 한 번 더 확인할지를
구분하는 능력이다.

## 7. 필수 금지선

- `박종윤은 이렇게 답한다` 식의 말투·문체·결론 복제
- 모든 요청의 목적·사용처·기한·형식 질문
- 결론→원인→대안→계획 고정 템플릿
- 업무명·감정 표현·사용자 직함 정규식 Router
- Runtime의 본질·중요도·최적 방법 의미 선택
- 한 번 추론한 목적·역량·성격의 영구 persona화
- 요청하지 않은 경영 코칭·확장 제안
- `더 도와드릴까요` 자동 부착
- 단순 요청의 Work·Tool·Memory·Skill 증가
- 오너 원리로 current user correction 덮기
- 사용자에게 무능·비전문·프롬프트 부족 label 부여
- 한 번의 좋은 답을 전역 Instruction으로 승격

## 8. 원리 후보 기록 계약

오너의 실제 판단 사례를 다음 형태로만 연구한다.

```yaml
principle:
sourceIncident:
helpsWhen:
mustNotActivateWhen:
requiredReality:
goodBehavior:
counterexample:
userBenefit:
probe:
rollback:
```

예:

```yaml
principle: 완료 보고보다 실제 사용자 결과를 확인한다
helpsWhen: 파일·설치·전달·외부효과가 있는 작업
mustNotActivateWhen: 단순 의견·설명·창작 요청
requiredReality: Artifact·Effect·Delivery
goodBehavior: 실제 결과를 재개방하고 사용자 표면에 전달
counterexample: 생성 로그만 보고 완료
userBenefit: 결과를 즉시 열고 사용
```

원칙 문장만 Prompt에 추가하지 않는다. 실제 사고·활성 조건·비개입 반례·probe·rollback과 결속되지 않은 원리는
제품 후보가 아니다.

## 9. User Capability Equalization 자격

같은 실제 목적을 표현 수준만 달리해 비교한다.

```text
전문가의 상세 지시
평범하고 짧은 지시
감정적·모호한 지시
진행 중 교정된 지시
```

목표는 일반 사용자의 문장을 전문가 Prompt로 기계적으로 다시 쓰는 것이 아니다. 현재 현실에서 중요한 빈칸을
관측하고 결과를 실질적으로 바꾸는 결정만 묻는 것이다.

측정:

- 목적 정확성·완전성 차이
- 필요한 사용자 질문 수
- first useful·final wall
- model/tool calls·tokens
- 불필요한 Work·Tool·Memory
- 결과 사용성
- 답변 길이·문체·구조 다양성
- 통제감·신뢰·다시 맡길 의향

합격:

```text
일반 사용자와 전문가 지시의 목적 결과 격차 감소
AND 불필요한 질문·Tool·비용 증가 없음
AND 중요한 사용자 결정은 빼앗지 않음
AND 단순 요청 비개입
AND 답변 구조·문체 획일화 없음
AND current correction 우선
```

## 10. Rigidity Holdout

### 단순 요청 비개입

- 번역
- 맞춤법
- 한 줄 설명
- 간단 계산
- 인사
- 창작

본질 분석·고정 질문·Work·Tool·계획이 추가되면 실패다.

### 열린 문제의 다양성

- 브레인스토밍
- 전략 대안
- 사람 관계
- 창작
- 개인적 고민

하나의 정답 구조·오너 관점·행동 지시를 강제하지 않는다.

### 사용자 차이

- 빠른 답 선호
- 자세한 근거 선호
- 전문가·비전문가
- 직접 결정 선호·추천 선호

같은 문체·길이·질문 수를 강제하지 않는다.

### 비활성 양성 대조

후보 Lens가 현재 요청에 무관하면 model Context·Tool·calls·final 형식 증가 0이어야 한다.

## 11. 연구·제품화 순서

6차 UX·총괄 HQ 전에는 현재 제품 Instruction을 바꾸지 않는다.

```text
오너의 실제 판단 사례 수집
→ 공통 원리와 개인 관점 분리
→ helpsWhen/mustNotActivateWhen/counterexample 작성
→ product change 0 baseline
→ 격리된 on-demand Lens A/B
→ User Capability Equalization + Rigidity Holdout
→ 실제 인간 UX 판정
→ 이익 있는 최소 원리만 instruction family 후보
→ 회귀 시 제거
```

첫 후보는 전역 Prompt 재작성이나 새 Store가 아니다. 격리 runner에서 현재 모델에 작은 관련 판단 Lens를 공급한
경우와 공급하지 않은 경우를 같은 목적에서 비교한다.

다른 연구와의 관계:

- 문서 목적의 일반 사용자 지시가 실패하면 먼저 이해·perception·source selection 중 원인을 분리한다.
- 실천지능 후보가 목적 이해를 개선해도 Document Reality·Method Runtime·Computer Use를 자동 개통하지 않는다.
- Method Runtime은 실행 비용 후보이며 실천지능의 판단 내용을 Runtime truth로 저장하지 않는다.
- Computer Use 화면 내용은 실천지능 원리나 사용자 instruction source가 아니다.

## 12. 최종 판정 기준

이 연구의 성공은 T5가 박종윤처럼 말하는 것이 아니다.

> 서로 다른 사용자가 각자의 말과 수준으로 요청했을 때 T5가 필요한 깊이·방법·설명을 유연하게 조절하고,
> 프롬프트 기술 격차 때문에 실제 목적 결과가 과도하게 벌어지지 않는 것.

잘 구현된 실천지능은 T5를 획일화하지 않는다. 오히려 단순 요청은 더 단순하게, 복잡한 문제는 필요한 만큼
깊게, 사용자별 설명과 질문은 더 적합하게 만든다.

현재 결정:
