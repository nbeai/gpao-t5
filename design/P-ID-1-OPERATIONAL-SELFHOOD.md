# P-ID-1 · 자가 정체성 / 지속 자기인지 (Operational Selfhood 완성)

날짜: 2026-07-26 · 브랜치: `p-id-1-operational-selfhood`
오너 지시(2026-07-26): "T5는 **어떤 모델이 연결되더라도** 기본적으로 자기가 어떤 AI 운영체제와
함께 하고 있고, 그 운영체제를 통해 **무엇을 어디까지 할 수 있는지를 계속 인지**할 수 있어야 한다."

## 근거 (실측)

**오너 실사용 2026-07-26에서 자기인지가 실제로 무너졌다:**

| 물음 | T5 가 한 답 | 문제 |
|---|---|---|
| "넌 이름이 뭐야?" | "저는 ChatGPT예요." | 하부 모델을 자기 정체로 말함(디브랜딩 계약 위반) |
| "어떤 운영체제 기반이야?" | "Linux/Windows/macOS 중 확정 불가" | **자기가 OS 인 줄 몰랐다** |
| "지파오티파이브 말할 수 있어?" | GPT-5 설명 시작 | 자기 이름을 못 알아들음 |
| "니 이름은 아이기스야" | "알겠어요" | 받아들였지만 **어디에도 안 남아** 다음 대화에서 소실 |

**원인**: 모델에게 준 자기 소개가 `"너는 사용자의 작업 비서다"` 한 줄뿐이었다. 헌법 §5(자기파악
헌법)가 요구하는 다섯 가지 중 절반이 모델에 도달하지 않았고, 빈칸을 모델이 자기 출신으로 채웠다.

**헌법 §5 요구 대비 현재:**

| 헌법 §5 | 지금 모델에게 가는가 |
|---|---|
| 어떤 모델을 쓰는가, 강점·한계 | 모델명만(강점·한계 없음) |
| 연결된 도구, 각각 실행 가능한가 | 실행 가능한 것 위주(불가 사유 일부) |
| 무엇이 승인됐고 무엇이 승인 필요인가 | 승인 필요만 |
| 어떤 실행이 위험한가 | **안 감** |
| 실패 시 안전한 것·다음 안전 행동 | **안 감** |

## 설계상의 긴장과 해법 (오너 제안 채택)

계획서 v3.0 **Phase 2** 는 "모델 입력 다이어트"·"OS 계약 설명으로 가득 차면 실패"를 요구한다.
자기인지는 반대로 더 많은 사실을 요구한다. 그대로 두면 서로를 깬다.

**해법(오너 제안)**: 능력을 **문서로 한쪽에 정리**하고, 상시로는 요약만 싣고 **필요할 때만 찾아
반영**한다. 그러면 상시 입력은 가볍고(Phase 2), 깊이 물으면 정확하다(자기인지). 확장도 문서가 받는다.

## 범위

### 1) 문서 두 개 — 사용자 경로(`GPAO_T5_DATA_DIR`)

- **`SOUL.md`** — 이름·정체·말투. **초기 내용은 계획서 v3.0 §0·§0.1 문장 그대로**(오너 지시).
  요약해 다시 쓰지 않는다 — 원문의 뜻이 바뀐다. 사용자가 직접 열어 고칠 수 있다.
- **`CAPABILITIES.md`** — 능력과 경계. 두 부분으로 가른다:
  - **자동 파생 구역**(`<!-- derived:begin -->…<!-- derived:end -->`): 등록된 도구·실행 가능 여부·
    승인 필요·위험 종류. **레지스트리에서 생성**한다. 사용자가 도구를 늘리면 자동으로 늘어난다.
  - **사람이 쓰는 구역**: 왜 있는지·어디까지가 한계인지·예시. 사용자가 편집한다.

> **어긋남은 사고다.** 문서에만 있고 레지스트리에 없는 능력(또는 반대)이 생기면 T5 가 자기
> 자신에 대해 거짓말하게 된다(T3 "보이는 것≠되는 것"의 최악 형태). → 파생 구역은 **매번 재생성**
> 하고, 사람 구역이 없는 능력을 주장하지 못하도록 **불변식 테스트**로 고정한다.

### 2) 상시 자기인지 (매 턴, 가볍게)

`buildIdentityFacts()` 가 프롬프트 맨 앞에 싣는다:
- 너는 GPAO-T5 라는 AI 운영체제다(모델이 아니다). 지금 쓰는 모델은 **두뇌이지 정체가 아니다**.
- 모델이 잘하는 것 / T5 가 맡는 것 구분(계획서 §0 그대로, 짧게).
- 지금 상태 한 줄 요약: 쓸 수 있는 것 N개 · 승인 필요 M개 · 지금 막힌 것 K개.
- 이름이 지어져 있으면 그 이름.

### 3) 필요할 때 상세 반영 — (a) 방식(오너 결정)

서버가 발화를 보고 관련 섹션만 골라 넣는다(모델에게 검색 도구를 주는 (b) 는 부족하면 뒤에 얹는다).
- "뭘 할 수 있어" / "어디까지" / 특정 도구 이름이 나오면 → 해당 섹션 주입.
- 매칭은 결정적이고 싸게(라벨·별칭 문자열). 놓치면 상시 요약으로 답하고 **지어내지 않는다**.

### 4) 다섯 항목 전부 채우기 (헌법 §5 — "필요한 건 제대로")

파생 구역과 상시 요약이 다섯 가지를 모두 담는다: 모델(+강점·한계) · 도구와 실행 가능성 ·
승인된 것과 승인 필요 · **위험한 실행 종류** · **실패 시 다음 안전 행동**.

### 5) 이름 (OpenClaw SOUL 계열 참고)

- 사용자가 대화에서 이름을 지어 주면 `SOUL.md` 에 반영하고 다음 세션에도 유지한다.
- 조사 근거: OpenClaw 는 `SOUL.md`/`IDENTITY.md` 파일 + 저장소에 **이중 영속화**하고, 부팅 시
  Project Context 로 주입한다. T5 는 파일 하나(SOUL.md)로 하되 같은 원리를 쓴다.
- **명시적 지시만** 잡는다(추정으로 이름을 바꾸지 않는다 — §6.18 추정≠반영).

## 경계

- 모델을 바꿔도 같은 정체를 유지한다. 이건 프롬프트만으로 보장되지 않으므로 **모델 무관 회귀
  테스트**로 고정한다(같은 질문 세트를 stub·OpenAI계열·gemini 셰이프에 던져 계약 확인).
- 문서는 사용자 경로에 둔다(재설치로 덮이지 않고, 사용자가 편집·백업할 수 있다).
- 상시 입력은 짧게 유지한다(Phase 2 다이어트). 길어지면 요약을 줄이지 능력을 숨기지 않는다.
- 내부 id·스키마·진단은 문서·프롬프트 어디에도 새지 않는다(사용자면 언어만).

  다섯 항목이 모두 담김 · 관련 섹션 선택(맞으면 주입, 없으면 상시 요약으로) · 이름 지정·지속 ·
  모델 무관 정체 유지.
