## 0. 판정 — 문제는 여덟이 아니라 **셋**이다

조사가 불편 스물몇을 냈는데, 뿌리를 세면 셋이다.

### 뿌리 ① 그리는 방식 하나가 세 증상을 만든다

```
index.html:2066  renderMarkdownInto(preview, previewText)   ← 조각마다 innerHTML 통째 교체
index.html:2068  scrollToBottom()                           ← 바로 뒤에서 scrollHeight 를 읽는다
```
조각당 **3.82ms**. 그중 마크다운 파싱은 **0.024ms(0.6%)** — 나머지 99.4%가 **강제 동기 레이아웃**이다.
4,500자 답 하나에 메인스레드 **2.6초**. 그동안 휠·드래그가 밀린다.

여기서 오너가 겪은 것 셋이 **동시에** 나온다:
```
"너무 빠르다"        → 조각마다 글자가 다시 그려지고 자리를 바꾼다(미완성 마크다운 · 완료 시 −33%)
"스크롤이 안 먹는다"  → 메인스레드가 막혀 입력이 밀린다 + 문턱 120px 되끌림
"복사가 안 된다"      → innerHTML 교체가 선택 앵커를 없앤다(실측: 10자 선택 → 다음 조각에 0자)
```
**속도를 늦추는 것은 답이 아니다.** 원인이 속도가 아니다.

### 뿌리 ② 「새 화면을 만들지 않는다」가 원칙으로 박혀 있다

`index.html:2097`·`737-738` 주석이 명문으로 적어 뒀다. 그 결과:
- 서버 라우트 80개 중 **24개가 화면 없음.** 자동화 목록·일시정지·재개·재시도, 기억 목록,
  스킬 수명주기 6단계 중 5단계, 사용자 모델 넷이 **백엔드만 있고 문이 없다**
- **켠 자동화를 볼 화면도 멈출 화면도 없다**

원칙 자체는 옳다(*"죽은 버튼 대신 텍스트"*). 그런데 **서버가 이미 답하는 것**까지 안 만들었다.

### 뿌리 ③ 같은 원칙이 **기본 동작**까지 삼켰다

복사 0 · 수정 0 · 재생성 0 · 코드블록 복사 0 · 「맨 아래로」 0 · Esc 0 · ⌘K 0.
**이 넷은 서버 상태를 안 만든다** — 「죽은 버튼」이 될 수 없는 것들이다.
그리고 응답 중지는 **있는데 안 보인다**(투명 배경·회색 글자).

## 1. 동시 작업이 가능한가 — **가능하다. 조건 하나만 있다**

`index.html` 은 2,147줄 한 파일이지만 자바스크립트 덩어리들이 **서로 다른 줄 구간**에 있어
3-way merge 가 대개 붙는다. **충돌이 확실한 공유 영역은 `<style>` 8-384 하나**다.

> **조건: 새 스타일은 `<style>` 맨 끝에 「조각 이름」 주석과 함께 덧붙인다. 기존 줄을 고치지 않는다.**
> 고쳐야 하면 그 조각이 **먼저** 들어가고 나머지가 리베이스한다(§5 순서).

**그래서 「파일 쪼개기」를 선행 조각으로 두지 않는다.** 쪼개기는 그 자체로 위험하고
(검사 9개가 `index.html` **원문**을 읽는다 — 특히 `audit-mutation.mjs` 는 **정확한 리터럴 문자열**
5개를 찾는다), 지금 불편을 하나도 안 줄인다. **필요해지면 그때 한다.**

## 2. 조각 — 여섯. 파일이 안 겹친다

각 조각은 **닫는 문장 · 소유 · 반대시험**을 갖는다. 다른 팀이 이 절만 보고 시작할 수 있다.

### 조각 A. 스트리밍이 사람 속도로 흐른다 ★ 최우선
> **닫는 문장**: 답이 흐르는 동안 위로 올려 읽을 수 있고, 드래그 복사가 되고, 글자가 자리를 안 바꾼다.

```
소유    index.html: 1022-1048(스크롤) · 2052-2084(streamTurn) · markdown.js:170-173
        style 은 맨 끝에 덧붙인다(§1)
```
**할 일**
1. **강제 레이아웃 제거** — `scrollToBottom()` 을 조각마다 부르지 않는다. `requestAnimationFrame`
   한 번에 묶고, `scrollHeight` 읽기를 쓰기와 분리한다(읽기 → 쓰기 순서 고정)
2. **증분 렌더** — 조각마다 `innerHTML` 을 통째로 갈지 않는다. 마지막 블록만 갱신하고
   완성된 앞부분은 그대로 둔다. **선택이 살아남는 것이 판정 기준**이다
3. **따라가기 규칙** — 문턱 120px 를 **「사용자가 스크롤했는가」로 바꾼다**.
   한 번 올리면 그 답이 끝날 때까지 안 끌어내린다. 새 발화에서만 초기화
4. **「맨 아래로」 버튼** — 따라가기가 꺼져 있을 때만 보인다
5. **완료 시 −33% 점프 제거** — 미리보기와 최종의 `class` 를 맞춘다(`.msg` → `.msg.bot`)

**반대시험**
```
① 위로 100px 올린 뒤 조각 50개 → 이동 0px          (지금은 169.5px 되끌림)
② 큰 조각(12줄) 뒤에도 따라가기가 살아 있다          (지금은 영영 끊긴다)
③ 스트리밍 중 드래그 선택이 유지된다                (지금은 다음 조각에 풀린다)
④ 완료 순간 높이가 안 바뀐다                       (지금은 249px → 168px)
⑤ 조각당 메인스레드 점유가 1ms 미만                (지금 3.82ms)
⑥ 답 내용은 한 글자도 안 바뀐다                    (렌더만 바꾼다)
```
⚠️ `test/scroll-keeps-place.test.js` 가 **호출 순서**를 검사한다. 정면으로 부딪히는 자리이므로
그 계약을 읽고, 바꿔야 하면 **이유를 검사에 적어라**(C5 — 무르게 하지 말고 새 사실을 물게).

### 조각 B. 기본 동작을 준다
> **닫는 문장**: 답을 복사하고, 발화를 고쳐 다시 보내고, 답변을 다시 받을 수 있다. 손이 반사적으로 가는 곳에 있다.

```
소유    index.html: 1460-1577(renderResult) · 2085-2095(입력창) · 마크업 386-468
        server.js: 없음(복사·중지는 서버 무관) / 수정·재생성은 §4 참조
```
**할 일**
1. **복사** — 사용자 발화·T5 답·코드블록 각각. 호버 시 나타난다
2. **중지를 보이게** — 이미 있다(`.stopbtn` 292-296). 스타일만 눈에 띄게 + `Esc` 배선
3. **사용자 발화 수정 → 다시 보내기**
4. **답변 재생성**
5. **키보드** — `Esc`(중지·오버레이 닫기) · `⌘K`(대화 찾기) · `⌘Enter`(전송)

**반대시험**
```
① 복사가 스트리밍 중에도 된다(조각 A 선행)
② 중지 버튼이 답이 흐르는 동안 늘 보인다
③ 수정 후 다시 보내면 그 아래 답이 어떻게 되는지 사용자가 안다
④ 「죽은 버튼」이 안 생긴다 — 못 하는 상황에서는 버튼이 없다(원칙 유지)
```

### 조각 C. 세션 제목이 구별된다
> **닫는 문장**: 목록에서 같은 제목이 나란히 뜨지 않는다.

```
소유    server.js:2097(한 줄) · session-store.js:35-40 · index.html:1215
겹침    없음 — 가장 깨끗한 조각. 아무 때나 넣을 수 있다
```
지금은 첫 발화 **앞 30자 그대로**. 요약도 모델도 안 쓴다.
**반대시험**: 사용자가 직접 붙인 이름(`manualTitle`)은 안 덮는다 · 같은 말로 시작한 대화 넷이 구별된다.

### 조각 D. 손이 한 일이 남는다
> **닫는 문장**: 답이 끝난 뒤에도 「무엇을 읽고 무엇을 바꿨는지」를 접었다 펼 수 있다.

```
소유    index.html: 2001-2005(trace) · 2030-2045(steps) · 1442-1458(기록 라벨)
        kernel/turn-surface.js:69-86 · kernel/turn.js:2420
```
지금은 `tool_progress` 가 trace **한 줄을 덮어쓰고**, `partial_result` 는 답이 시작되면
**통째 삭제**되며(2060), 끝나면 접힌 줄 하나만 남는다.

**★ 여기가 클로드코드에서 가장 많이 가져올 자리다** — 나는 도구 호출을 **한 줄로 접고
필요하면 펼친다.** 규칙은 「지금 필요한 것만 보이고 나머지는 한 번 더 눌러야 보인다」이고,
그 규칙은 웹에도 그대로 간다.

**반대시험**: 잔소리를 늘리지 않는다(기본은 접힌 한 줄) · 실패한 손이 성공한 것과 구별된다.

### 조각 E. 백엔드가 이미 답하는 것에 문을 낸다
> **닫는 문장**: 켠 자동화를 목록으로 보고, 멈추고, 다시 켤 수 있다.

```
소유    index.html: 742-745(SET_SECTIONS) · 761-865(SET_RENDER) · 새 렌더 함수
서버    수정 0 — GET /automation · pause · resume · retry 가 이미 있다
```
**설정 허브에 섹션으로 넣는다**(등록표가 이미 있어 **2곳만** 고치면 된다).
새 오버레이 화면을 만들면 5곳을 고쳐야 한다 — §3 참조.

**반대시험**: 「죽은 버튼」 금지 — 서버가 못 하는 동작은 버튼을 안 만든다 ·
자동화가 0개일 때 무엇을 보이나(빈 목록이 아니라 「아직 없어요 + 어떻게 만드나」).

### 조각 F. 확장 통로를 하나로
> **닫는 문장**: 새 화면 하나를 더하는 데 **두 곳**만 고친다(지금은 다섯 곳).

```
소유    index.html: 335-338(오버레이 CSS) · 715-760(open/close) · 386-468(마크업 틀)
```
지금 화면 전환이 **3종**으로 섞여 있다(오버레이 `classList` · `style.display` · 상태 변수).
라우팅은 **없다**(`hash`·`pushState` 0건) — 세션조차 주소가 없어 **깊은 링크가 불가능**하다.

**할 일**: 오버레이 등록표 하나 + 열기/닫기 한 벌. **주소(해시 라우팅)는 이번에 안 한다** — §4.

**반대시험**: 기존 화면 둘(도구함·설정)이 그 통로로 옮겨도 동작이 같다 · 새 화면 추가가 2곳.

## 5. 확장성 — 이번에 세우는 것

**지금 새 화면 하나 = 5곳 수정**(마크업 · CSS 선택자 3줄 · open/close · 진입 · 닫기 배선 3개).
**설정 섹션과 인라인 카드만 등록표가 있어 2곳**이다.

조각 F 가 그것을 **오버레이도 2곳**으로 만든다. 그러면 나중에 붙을 것들 —
기억 화면 · 스킬 수명주기 · 배송 기록 · 채널(디스코드·왓츠앱) · 커넥터/MCP 편입 — 이
**등록표 한 줄씩**으로 들어온다.

그리고 **화면이 서버 사실을 받는 이름이 통일돼 있지 않다**(`userSafe`·`userSafeSummary`·
`userStatus`·`userSafeReason`·`nextSafeAction` — 공통 타입 없음). 조각 E 가 첫 소비자이므로
**거기서 한 벌로 모으고, F 가 그것을 껍데기에 넣는다.**

## 6. 비교군에서 가져오는 것 — 조각별로 흡수

### 6-1. 관통 원칙 하나 — **판단에 꼭 필요한 최소치만 1차 화면에**

클로드코드는 승인 창에서조차 *"왜 실행하는가·무엇이 잘못될 수 있나"* 를 **기본으로 안 띄운다**
(`Ctrl+E` 로만). 사고 과정은 접힘이 기본이고 펼쳐도 **요약**이다. 비용·컨텍스트는 상태줄이
**기본 꺼짐**이라 물어야 나온다. 긴 출력은 화면에 붓지 않고 크기만 알린다.

오픈클로는 한 발 더 간다 — **같은 정보를 시점에 따라 다르게 감춘다.**
승인 시점엔 명령 전문을 다 보여주고(`tools/exec-approvals-advanced.md:354`),
사후 로그에는 **인자 값을 저장조차 안 하고 「인자 N개」만** 적는다(`web/control-ui.md:177`).

### 6-3. T5 가 이미 더 나은 자리 (베끼지 말 것)

  (`session-search.js:32`)과 전용 패널이 있다. **말로 시키는 쪽으로 바꾸지 않는다** —
  T5 는 「기억이 어디서 왔는지」를 되짚는 원장이 있고, 그 축이 더 강하다.
- **승인**: T5 는 헌장 넷에만 묻는다. 비교군 셋(도구별 승인 · `ask: always` · 4지선다)이
  전부 이 문장과 부딪힌다(§4).
