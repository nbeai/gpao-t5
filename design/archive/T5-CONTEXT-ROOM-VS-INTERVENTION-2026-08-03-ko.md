# 방을 짓는가, 입에 손을 넣는가 — 맥락 주입 구조 정면 분석

**작성** 2026-08-03 · **계기** 오너 라이브(실모델 gpt-5.1) 다운로드 정리 5턴 교착
**오너 판단** "기억과 맥락, 자가학습은 모델을 **제어**하는 영역이 아니라 모델이 들어가 있는
**방을 구성**하는 것과 같다. 거기서 양질의 콘텍스트가 모델에게 제공되는 것이고 그게 우리
말귀의 힘이 되어야 한다."

---

## 0. 한 줄

> T5 는 현실을 **모델이 보기 전에** 고정 크기로 미리 씹어서 준다. 그리고 **더 달라고 말할
> 문이 없다.** 헤르메스는 크게 주고, 넘치면 **어디에 두었는지와 다음에 무엇을 부르면 되는지**를
> 함께 준다.

---

## 1. 실측 — 무엇이 벌어졌나

오너가 "내 다운로드 폴더 정리하자"고 했다. T5 는 다섯 턴 내내 같은 계획만 되풀이했다.

```
폴더에 있던 것              437개
compactResult 가 고른 것     40개   (slice(0, 40))
1200자에서 다시 잘려         23개   ← 모델이 받은 전부 (5%)
요약은                      "437개를 찾았어요"
나머지를 가져올 방법          없음
```

같은 프롬프트의 다른 블록은 이렇게 요구한다: "확인이나 예고만으로 한 턴을 소비하지 않는다."

**불가능한 자리에 세워 놓고 재촉했다.** 모델은 정직했다 — 5%로 437개를 분류할 수 없으니
계획을 쓰고 다음 턴을 기약했고, 다음 턴에 또 23개를 받았다.

---

## 2. 헤르메스와 정면 대조

| | T5 | 헤르메스 |
|---|---|---|
| 도구 출력 상한 | **1,200자** | **50,000자** (`config.yaml` 로 조절) |
| 파일 읽기 상한 | 1,200자 | **2,000줄** (조절 가능) |
| 자르는 방식 | 앞만 (`slice(0,n)`) | **앞 40% + 뒤 60%** |
| 얼마나 뺐는지 | 폴더 목록은 침묵(`…`) | 항상 — `[OUTPUT TRUNCATED - N bytes omitted out of M total]` |
| 넘친 것은 | **버린다** | **디스크에 저장하고 경로를 준다** |
| 나머지를 볼 방법 | **없다** | `read_file(offset=N)` |
| 다음 수를 알려주나 | 안 알려줌 | **`Use offset=746 to continue (showing 1-745 of 3200)`** |
| 압축 시점 | **항상, 생산 즉시** | **창이 실제로 찰 때만** |
| 압축할 때 표식 | — | `[Old tool output cleared to save context space]` |
| 지운 뒤 착각 방지 | — | ghost-skill defense(`[SKILL_PRUNED]`) — 지웠는데 모델이 아직 있다고 믿는 사고를 막는 전용 장치 |

**40배 작은 상한을, 항상, 문 없이.**

---

## 3. 진단 — 병의 이름

처음엔 "T5 가 모델에게 지시를 너무 많이 한다"고 의심했다. **틀렸다.** 실측하니 모델에게 가는
39개 블록 중 명령형은 4개뿐이고, 코드 주석은 도처에서 "지시가 아니라 사실로 준다"를 지키고 있다.

병은 다른 데 있다.

> **선(先)소화.** 런타임이 모델을 대신해 "이만큼이면 충분하다"고 판단하고, 그 판단을 숨기고,
> 되물을 문도 두지 않는다.

이건 지시보다 더 깊은 간섭이다. 지시는 모델이 무시할 수라도 있지만, **못 본 것은 무시할 수도
없다.** 오너 기준으로 정확히 이 위반이다 — 「모델 앞 현실을 정확히 주는가, 아니면 Runtime이
판단을 대신하는가」.

그리고 이건 한 함수의 버그가 아니라 **자세**다. 같은 자세가 T5 곳곳에 있을 것이므로,
아래 원칙을 계약으로 세우고 전수로 훑어야 한다.

---

## 4. 세울 원칙 넷

### P1. 방은 넉넉해야 한다 — 상한은 마지막 수단이지 기본값이 아니다
1,200자는 "요약"이 아니라 **차단**이다. 상한은 크게 잡고, 사용자가 조절할 수 있게 한다.

### P2. 자를 땐 앞뒤를 남긴다
앞만 남기면 결론이 통째로 사라진다. T5 의 파일 본문·웹 본문 갈래는 이미 지키고 있고,
폴더 목록만 안 지켰다. 갈래마다 달랐다는 것 자체가 계약이 없었다는 증거다.

### P3. 뺀 것은 반드시 **양과 전체**를 말한다
"…" 하나는 말이 아니다. `나머지 165개 / 전체 178개`처럼 센 값을 준다.
(2026-08-03 `58bea46` 로 폴더 목록·링크·비교 후보에 적용 완료)

### P4. **문을 둔다** — 나머지를 가져올 길과, 다음에 부를 것을 함께 준다
이게 핵심이다. 헤르메스의 `Use offset=746 to continue` 한 줄이 막다른 길을 방으로 바꾼다.
T5 의 `local.file` 에는 `offset`·`limit` 이 아예 없다. **문이 없으면 아무리 정직하게
"165개를 뺐다"고 말해도 모델이 할 수 있는 일은 여전히 계획뿐이다.**

## 5. 무엇을 배우고 / 버리고 / 개선하고 / 만들 것인가

### 배울 것 (헤르메스에서 그대로)
- 상한을 설정으로 뺀다(`tool_output.max_bytes`) — 하드코딩된 숫자는 언젠가 틀린다
- 잘린 사실을 **텍스트 표식과 구조화 메타데이터 둘 다로** 준다
  (헤르메스 주석: "textual marker can be missed or later re-truncated by a client layer")
- 넘친 것을 파일로 흘리고 경로를 준다
- 압축은 **창이 찰 때**, 그리고 압축했다는 표식을 남긴다
- 지운 뒤 "아직 있다고 믿는" 사고를 막는 전용 표식(ghost-skill defense)

### 버릴 것 (T5 에서)
- `maxChars = 1200` 고정값과 생산 시점 선압축이라는 **전제 자체**
- `slice(0, 40)` 같은 개수 상한
- 앞부분만 남기는 절단

### 개선할 것
- `compactResult` 상한 대폭 상향 + 설정 가능화
- 모든 갈래 앞뒤 보존으로 통일
- (완료) 모든 갈래가 뺀 양을 말하게 — `58bea46`

### 만들 것
1. **문** — `local.file` 의 `list`·`read` 에 `offset`·`limit`, 그리고 결과에
   "다음엔 `offset=N`" 한 줄. **1순위.**
2. **넘침 보관소** — 큰 결과를 파일로 두고 경로를 주는 공통 자리
3. **창이 찰 때의 압축** — 지금 T5 에는 없다. 대신 항상 선압축하고 있었다.
   문과 보관소가 서면 그때 필요해진다.

---

## 6. 버리지 말아야 할 것 — 헤르메스를 그대로 베끼지 않는다

헤르메스는 맥락 압축에만 5,454줄을 쓴다. 그 규모를 목표로 삼지 않는다.
T5 가 가져올 것은 **자세**이지 분량이 아니다 — 넉넉한 방, 정직한 표식, 그리고 문.

그리고 T5 가 이미 더 잘하는 것은 지킨다:
- 상대시각을 사람 말로(`179일 전 고침`) — 헤르메스는 ISO 를 그대로 준다
- 실행 결과를 사용자 언어 영수증으로 남기는 계약
