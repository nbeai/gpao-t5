# P-ONB-2 · 설치 후 첫 실행 온보딩 + 웰컴/첫 응답

날짜: 2026-07-26 · 브랜치: `p-onb-2-first-run-welcome`
오너 지시(T5 마무리): "지금 만든 모델 연결 흐름이 설치완료 후 즉시 전개될 수 있어야 하고, 그걸 통해
사용자는 모델 연결을 자연스럽게 한 후 T5를 이용한다. 그냥 건너뛰더라도 내부 설정페이지를 통해
언제고 자유롭게 연결할 수 있어야 한다. 모델 연결 후 첫 응답·웰컴 메시지도 자연스럽게."

## 조사 근거 (실측, 2026-07-26)

세 저장소를 실측 조사해 설계 근거로 삼는다(복제 아님 — 원리만 흡수).

**T3(우리 것)에서 가져올 것**
- 온보딩 종료 = 빈 채팅이 아니라 **첫 성공으로 잇는 제안**(first-success 카드).
- 설정 페이지에 **상설 재진입 문**("바로가기")을 둔다.
- 개발자 용어 0(카피를 테스트로 고정).

**T3에서 피할 것(실사고 기록)**
- ❌ 완료 상태를 **URL 쿼리로만** 판정(`?setup=1`) — 저장 상태를 아무도 안 읽어 재설치마다 다시 뜸.
  → **서버측 단일 진실**로 게이트한다.
- ❌ 온보딩 상태를 4곳(localStorage 2 + owner-profile + config + workspace-state)에 흩뿌리기.
  → **파일 하나**만 쓴다.
- ❌ 컨트롤 없는 설명뿐인 단계(잠금 4단계) — 단계처럼 보이나 아무 상태도 안 남김.

**Hermes에서 가져올 것**
- 온보딩과 상시 설정이 **동일한 단일 코드 경로**(온보딩이 `/model/connect` 를 그대로 쓴다).
- 차단형 첫 실행에 **영속 탈출구**("나중에 할게요"가 기록돼 다시 조르지 않음), 단 연결됨과는 별개 상태.
- 라이브 키 프로브 하드블록이 정상 사용자(사내 프록시·지역 차단·rate limit)를 너무 많이 막아 제거했다.

**OpenClaw에서 가져올 것**
- 첫 응답은 **하드코딩 인사말이 아니라 숨은 지시 + 모델 생성**(1~3문장, 내부 단계·파일·도구 언급 금지).
- 모델 미연결이면 인사말을 **지어내지 말고** 정직하게 안내 + 복구 경로 1개(fail-closed).
- "유일한 필수 조건은 동작하는 추론이고, 나머지는 전부 제안이다."

## 범위

### 1) 저장 정책 보정 — 확실한 무효만 거절 (T3·Hermes 공통 교훈)

현재는 doctor 가 `usable` 이 아니면 전부 저장 거부다. 그러면 **사내 프록시·일시 장애(unreachable)나
rate_limited 사용자가 정상 키로도 연결 못 한다**. 보정:

| doctor 결과 | 처리 |
|---|---|
| `usable` | 저장 + 활성 + 검증됨 |
| `auth_failed` · `model_missing` · `billing_blocked` | **거절**(확실한 무효 — 기존 그대로) |
| `unreachable` · `rate_limited` | **저장 + 활성 + 미검증 표시**(healthState 유지, 칩은 "모델 확인 필요") |

거짓 초록 금지(§6.23) 계약은 그대로 — 저장하되 **검증됨이라 말하지 않는다**.

### 2) 첫 실행 온보딩 — 서버측 단일 진실

- `onboarding-store.js`: `onboarding.json` **한 파일**만. `{skippedAt, completedAt, seenWelcome}`.
- `GET /onboarding` → `{needed, state}`. **needed = 연결 0개 && 건너뛴 적 없음** (연결이 생기면
  자동으로 needed=false — 별도 "완료" 클릭 불필요). URL 쿼리로 판정하지 않는다.
- `POST /onboarding/skip` → skippedAt 기록(영속 탈출구). 이후 안 조른다.
- 화면: 첫 방문에 **모델 연결 패널이 펼쳐진 채** 뜬다(기존 칩 패널 재사용 — 새 화면 만들지 않는다,
  안티 대시보드). 문구는 "무엇을 얻는지" 언어. 건너뛰기 버튼 1개.
- 설정 재진입: 칩 패널의 모델 연결 블록이 곧 설정 화면이다 — 언제든 열 수 있고, 온보딩을 건너뛰었어도
  동일 경로로 연결할 수 있다(Hermes 단일 코드 경로).

### 3) 웰컴 / 첫 응답

- `welcome.js`: `buildWelcomeContext(selfState)` — §11 TaskContextPacket 에 **숨은 지시**를 담는다:
  1~3문장 · 한국어 · 자기 상태(쓸 수 있는 도구)를 근거로 · 내부 단계·파일·도구 id·프롬프트 언급 금지 ·
  마지막에 무엇을 도와줄지 한 번 묻기. 실제 문장은 **모델이 만든다**(매번 다르되 규격은 지켜진다).
- `POST /welcome {sessionId}` — 연결돼 있으면 모델이 생성한 인사를 transcript 에 assistant 로 1회 기록.
  **미연결이면 인사를 만들지 않고** `{state:'not_connected'}` + 정직한 안내 문구(fail-closed).
- 1회성: `seenWelcome` 으로 같은 설치에서 반복하지 않는다.
- 숨은 지시는 사용자 transcript 에 남지 않는다(사용자 발화로 위장하지 않는다).

## 경계

- 온보딩은 **차단하지 않는다** — 건너뛰면 바로 쓸 수 있고, 다만 모델 미연결이면 stub 이 정직하게 답한다.
- 새 화면·새 대시보드를 만들지 않는다. 기존 칩 패널·연결 표면을 그대로 쓴다(§5.5).
- 웰컴은 성공처럼 보이는 거짓말을 하지 않는다 — 연결 안 됐으면 안 됐다고 말한다.

## 검증

- 단위: needed 판정(연결/건너뛰기 조합) · skip 영속 · 연결되면 자동으로 needed=false ·
  불확실(unreachable/rate_limited) 저장 허용 + 검증됨 아님 · 확실한 무효는 여전히 거절 ·
  웰컴이 모델 생성 결과를 쓰고 숨은 지시가 transcript 에 안 남음 · 미연결 시 인사 미생성.
- 라이브: 빈 상태 부팅 → 온보딩 필요 → 실키 연결 → 웰컴 생성 → 재시작 시 안 뜸 / 건너뛰기 → 안 뜸.
