# P-STR-1 · 답변 토큰 스트리밍 (체감 속도)

날짜: 2026-07-26 · 브랜치: `p-str-1-answer-streaming`

## 배경 (실측, 2026-07-26 오너 실사용)

| 구간 | 시간 |
|---|---|
| T5 자체 처리(모델 호출 제외) | **0.001s** |
| gpt-5.5 · "안녕" | 1.4s |
| gpt-5.5 · "구체적으로 설명해봐"(긴 답) | **23.4s** |

느린 것은 T5가 아니라 **모델이 긴 답을 쓰는 시간**이다. 그런데 체감은 그보다 더 나쁘다:
백엔드는 이미 토큰을 흘려보내는데(`stream:true`) 어댑터가 **다 모은 뒤에** 한 번에 넘겨서,
23초 동안 화면에 글자가 하나도 안 나온다. 사용자는 "멈춘 것"으로 느낀다.

## 범위

1. **ModelClient 계약 확장(일반형)**: `respond(tc, { onDelta })` — 두 번째 인자는 선택.
   스트리밍 가능한 어댑터는 조각이 올 때마다 `onDelta(text)` 를 부르고, 못 하는 어댑터는 그냥
   무시한다(기존 구현 그대로 동작 — 계약 파괴 없음).
2. **어댑터**: chatgpt(Codex SSE)·OpenAI 계열(`chat.completion.chunk`, beai·호환 서버 포함)에
   증분 파싱을 넣는다. 응답 본문을 `await r.text()` 로 통째로 기다리지 않고 reader 로 읽는다.
   gemini/anthropic 은 이번 슬라이스 밖(지금처럼 단발 — 계약상 아무 문제 없다).
3. **턴 관통**: `ctx.onAnswerDelta` 를 turn 이 model 에 넘긴다. 커널은 조각을 저장하지 않는다.
4. **표면**: `/turn/stream` 이 `answer_delta` 이벤트로 흘린다.
   **durable 에 남기지 않는다** — EventLog 에 토큰마다 append 하면 §6.21 후속의 "EventLog 무한
   성장" 을 우리가 직접 만든다. 진실은 완성된 assistant 결과 하나뿐이고, 델타는 **화면용 미리보기**다
   (OpenClaw 도 delta preview 를 never persisted 로 둔다 — 조사 근거).
   재접속 시 델타는 재생되지 않는다(완성 결과가 재생된다) — 손실이 아니다.
5. **UI**: 조각이 오면 그 자리에 이어 그리고, `complete` 에 지속된 결과로 **교체**한다
   (미리보기 ≠ 진실. 최종 렌더는 항상 durable 결과다).

## 경계

- 델타는 사용자면 텍스트만이다. 모델 사고 원문·도구 인자·진단은 절대 흘리지 않는다(§6.12 계약).
- 델타가 안 와도 동작은 같아야 한다(스트림 미지원 provider·중간 실패). 최종 결과가 진실이다.
- 승인 게이트·원장·타임아웃 계약은 그대로 — 스트리밍은 표시 계층이지 실행 계층이 아니다.
- 토큰 단위로 EventLog·transcript 를 건드리지 않는다(쓰기 폭증 금지).

## 검증

- 단위: onDelta 없이도 기존과 동일 반환 · SSE 조각을 순서대로 onDelta 로 흘림 · 델타 합계 = 최종
  텍스트 · EventLog 에 델타가 안 쌓임 · 델타 미지원 어댑터에서 무해.
- 라이브: 긴 답 질문에서 **첫 글자까지 시간**이 1~2초대로 떨어지는지 실측(23초 대기 → 즉시 흐름).
