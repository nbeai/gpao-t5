# Phase 0-1 · 로컬 파일 손발 (스텁 → 실제)

날짜: 2026-07-26 · 브랜치: `p0-1-local-file`
근거: v3.1 보강안 §21 Phase 0-1(즉시), §22 로컬 지배력 순서(범위 축 먼저), §16-D 능력 완결 단위.

## 왜 지금

`local.file` 핸들러가 `{ scanned: true }` 를 반환하는 **스텁**인데, 레지스트리에 등록돼 있어
CAPABILITIES.md 는 "이 컴퓨터의 파일을 읽고 정리한다"고 적고 T5 는 사용자에게 그렇게 말한다.
**지금 이 순간 T5 가 사용자에게 거짓말하고 있다.** §6.30 의 문서 파생만으로는 이걸 못 잡았다.

## 완결 정의 (§16-D — 쪼개서 반쪽을 내보내지 않는다)

이 슬라이스가 닫히려면 아래가 **전부** 되어야 한다.

- **읽기**: 파일 내용 읽기, 폴더 목록 보기
- **쓰기**: 새 파일 만들기, 기존 파일 덮어쓰기
- **정리**: 이동/이름 변경, 삭제
- **범위 권한**: 허용된 작업 폴더 안에서만. 밖은 차단하고 사용자에게 요청
- **되돌리기**: 덮어쓰기·삭제는 되돌릴 수 있다
- **실패 처리**: 없는 파일·권한 없음·범위 밖·너무 큰 파일을 각각 사용자 언어로
- **정직한 능력 표기**: CAPABILITIES.md 가 실제와 일치

## 권한 — 등급이 아니라 범위를 더한다 (§22-0)

등급은 이미 맞다. `write`·`delete` 는 `SAFETY_FLOOR_KINDS` 라 모드와 무관하게 항상 승인(A2+)이다.
**빠진 것은 "어디까지"** 다.

- `file-scope.js`: 허용 루트 목록(기본 `~/GPAO-T5`) + 경로 판정.
  - `resolveInScope(path)` → 절대경로 정규화 후 루트 안인지 판정. **심볼릭 링크 탈출도 막는다**
    (realpath 기준 재판정 — `../` 만 막으면 링크로 뚫린다).
  - 범위 밖은 **거부**하고 `nextSafeAction` 으로 "이 폴더를 열어줄까요?"를 준다(막다른 답 금지).
- 읽기도 범위를 지킨다(범위 밖 읽기 = 정보 유출).
- 범위는 env(`GPAO_T5_FILE_ROOTS`)로 넓힐 수 있다. 기본은 좁게.

## 되돌리기

- 덮어쓰기·삭제 전에 **원본을 휴지통 디렉터리로 복사**하고 되돌리기 표를 남긴다.
- `file.undo` 로 마지막 작업을 되돌린다. 되돌린 뒤 실제 파일 상태가 복구되는지 테스트로 고정(§18).
- 휴지통은 사용자 데이터 경로 아래(`trash/`). 자동 삭제하지 않는다.

## P0-1b 안전 hotfix 체크

P0-1은 main에 병합됐지만, P0-2를 계속하기 전에 아래 실사용 데이터 손실 경로를 닫는다.

- **기존 대상 파일이 있는 이동(move) 금지 또는 양쪽 복구**:
  `a.txt`를 이미 존재하는 `b.txt`로 옮길 때 `b.txt`의 원래 내용이 조용히 사라지면 안 된다.
  기본 정책은 **대상 파일이 있으면 막고 확인/다른 이름을 요청**하는 쪽을 우선한다.
- 회귀 테스트:
  `a.txt=A`, `b.txt=B` 상태에서 `move a.txt -> b.txt`가 `B`를 잃지 않음을 증명한다.
  허용 정책을 "덮어쓰기+되돌리기"로 선택한다면 undo 뒤 `a.txt=A`, `b.txt=B`가 모두 복구되어야 한다.
- 실사용 검수 문장:
  "파일을 옮겼어요"라고 말하기 전에, 사용자가 기존 파일을 잃지 않았는지까지 확인한다.

## 스텁 금지 게이트 (§16-C)

등록된 도구가 실제로 동작하지 않으면 **테스트가 실패**해야 한다. `local.file` 같은 사고 재발 방지.

- 게이트: 라이브 도구 레지스트리의 모든 핸들러가 "스텁 표식"을 갖지 않아야 한다.
- demo/fixture 는 예외(테스트 전용임을 명시적으로 표시).

## 경계

- **임의 명령 실행 없음**(§20). 파일 I/O 만.
- 실행 가능 판정은 기존 SelfState 게이트를 그대로 탄다.
- 결과는 항상 ToolReceipt. 못 한 것을 한 척하지 않는다.

## 검증

- 단위: 범위 안/밖 · 링크 탈출 · 읽기/쓰기/이동/삭제 · 되돌리기 후 실제 복구 · 실패 4종 사용자 언어 ·
  스텁 금지 게이트가 실제로 실패하는지(반대 검증).
- 라이브(오너 실사용 경로, §19): 대화로 "이 폴더에 메모 파일 하나 만들어줘" → 승인 → 파일 생성 확인 →
  "지워줘" → 승인 → 삭제 → "되돌려줘" → 복구.
