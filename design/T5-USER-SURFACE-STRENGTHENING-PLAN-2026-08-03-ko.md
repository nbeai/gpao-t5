## 1. 리서치 결과

착수 전에 네 자리를 확인했다. 문서가 아니라 **실물 코드와 선행 실측**이다.

### 1.1 「안티 대시보드」의 실제 범위 — 확대 해석이었다

원문(`UX-ARCHITECTURE` §1.2)은 화면을 금지하지 않는다.

> "T5는 복잡한 **개발자 대시보드**가 아니다."
> "Today / Project / Connection / Ledger 는 사용자를 관리자로 만드는 화면이 아니라,
> **대화 흐름에서 필요한 상태와 다음 행동을 조용히 보여 주는 작업 표면이다.**"

금지 대상은 둘뿐이다 — ① 개발자 대시보드 ② 사용자를 관리자로 만드는 화면.
그리고 **바로 다음 절이 §2 표면 카탈로그 14개 화면**이다. 화면은 처음부터 설계돼 있었다.

T5 자신의 선행 연구도 같은 정정을 이미 적었다(`10-SURFACE-ARCHITECTURE-RESEARCH` §2).

> "현재의 anti-dashboard 원칙은 보존한다. **내부 상태를 늘 펼쳐 놓지 않는다는 뜻이지,
> 사용자가 자신의 작업을 다시 찾을 장소까지 만들지 않는다는 뜻은 아니다.**"

### 1.2 현재 실측 — 화면 1개에 11개가 눌러 담겨 있다

| 봉인된 14 표면 | 현재 실체 |
|---|---|
| 2.1 Work Chat | **독립 화면 있음** |
| 2.5 Tool/Connection · 2.4 Memory | 패널 2개(`setpanel`·`tbpanel`) |
| 나머지 11개 | **Work Chat 안 인라인 카드 조각** — `renderOverview`·`renderRecovery`·`renderRecord`·`renderPatternCandidate`·`renderToolbox` 등 렌더러 22종 |

화면을 안 만든 것이 아니라 **전부 대화 안에 밀어 넣었다.**

### 1.3 선행 연구가 이미 낸 결론 — 다시 만들지 않는다

`rf-005`가 T5·Codex·Claude Code·OpenClaw·Hermes를 **세 과제**로 비교했다.

| 과제 | 판정 |
|---|---|
| 작업 | 독립 페이지 근거 부족 → **보류** |
| **자동화** | **유일 후보** |
| 결과물 | 독립 페이지 근거 부족 → **보류** |

그리고 **결정적 공백**을 찾았다. T5는 자동화 취소 실패 시 이렇게 말한다.

> "취소하지 못했어요. **자동화 목록에서** 상태를 확인해 주세요."

**그 목록으로 가는 길이 제품에 없다.** 새 기능 욕구가 아니라 **제품이 이미 약속한 복구 경로가 끊긴 것**이다.

### 1.4 아무도 연구하지 않은 축 — 그리고 비교군에도 없다

선행 연구 둘 다 **"돌아갈 자리"만** 봤다. 표면 지도 6행이 전부 *다시 찾기*이고, rf-005 세 과제도
전부 *지난 것 되짚기*다. **"처음 켰을 때 무엇을 보여주는가"는 정의역 밖이었다.**

비교군 실물을 확인했다.

| 제품 | 진입 시 | 화면 수 |
|---|---|---|
| OpenClaw | 채팅으로 직행. 32개 페이지는 네비게이션 뒤 | `ui/src/pages` **32개** |
| Hermes | TUI 프롬프트로 직행 | TUI·web |
| T5 | 채팅으로 직행 | 1 + 패널 2 |

**셋 다 "당신 상황을 보니 이런 걸 해드릴 수 있어요"를 먼저 말하지 않는다.**
사용자가 무엇을 시킬지 이미 알고 있다고 전제한다. 이것이 **개발자 사용자에게는 맞고,
한국 사장님에게는 틀린 전제**다. 우리 타깃은 "AI에게 뭘 시킬 수 있는지" 자체를 모른다.

흡수할 원리는 다르다.
- **OpenClaw에서**: 페이지 32개가 아니라 **현재 상태 → 실패 실행 → 실행 대화로 이어지는 연결**
- **Hermes에서**: 명령 개수가 아니라 **다음 실행·마지막 오류·전달 실패를 한 신분으로 조회**
- **둘 다에서 배우지 않을 것**: 관리 페이지를 늘려 능력을 전시하는 방식

## 2. 그래서 빈자리는 둘이다

```
① 돌아갈 자리   — 선행 연구가 확인함. 자동화 하나가 유일 후보. 복구 경로가 끊겨 있음
② 시작하는 자리 — 아무도 연구 안 함. 비교군에도 없음. 우리 타깃에게 가장 큰 벽
```

둘은 다른 문제이므로 **다른 단계로 만든다.** 한 화면에 섞으면 그게 대시보드가 된다.

---

## 3. 무엇을 만들고 무엇을 안 만드는가

판정 기준은 페이지 수가 아니라 이것 하나다(선행 연구 §1 그대로).

> **한 턴보다 오래 살거나, 여러 개를 비교해야 하거나, 실패 뒤 원 대화를 기억하지 않고도
> 복구해야 하는 것만 자기 자리를 갖는다.**

| 만든다 | 안 만든다 (근거) |
|---|---|
| **자동화 현재 상태** — 대화가 끝나도 혼자 상태가 변한다 | 승인 센터 — 승인은 그 순간의 일. 인라인이 맞다 |
| **Today(오늘)** — 켤 때마다 필요한 진입점 | 복구 센터 — 실패는 그 턴에서 다뤄야 한다 |
| (이미 있음: 도구함·설정) | 기억 센터 — 설정 안 확인·철회로 충분(선행 연구 §5) |
| | 작업·결과물 페이지 — **증거 부족으로 보류**(rf-005) |
| | 전역 활동 로그 — 작업·결과물의 근거 보기로 제공 |

**14개 중 넷이면 충분하다**: Work Chat + Today + 자동화 + 연결/도구함.

## 4. 단계

### S1. 끊긴 복구 경로를 잇는다 (자동화 목록)

**사용자 문장**: "목요일 자동화 왜 안 됐지?"

- 제품이 이미 약속한 경로다. **새 기능이 아니라 지킬 일.**
- 재사용: `/automation` 조회 · `/overview` projection · 승인·취소·일시정지·재개·재시도 계약
- 새로 만드는 것: **웹 렌더러 한 자리**(현재 값이 있는데 표시하지 않는다)
- 다섯 줄만 만족한다(rf-005 최소 후보 계약 그대로)
  - 활성·일시정지·검토 필요
  - 다음 실행 시각과 마지막 실행 결과
  - 실패 이유와 안전한 다음 행동
  - 일시정지·재개·취소·허용된 재시도
  - **승인 범위·실행 근거와 원 대화 연결** ← OpenClaw 흡수 지점
- 형태(전체 화면 / 설정 하위 / 서랍)는 **실제 재방문 과제로 고른다**(선행 연구 §6-2·3)

### S2. Today — 최소형 세 줄

**사용자 문장**: (아무 말도 안 함. 켜기만 함)

UX §2.2가 이미 정의했다 — *"오늘 해야 할 일, 이어갈 일, 막힌 일. 로그인 후 첫 화면.
**진입점일 뿐 대화를 대체하지 않는다. 한 항목 클릭 시 Work Chat으로 이어짐.**"*

세 줄로 시작한다. **위젯을 만들지 않는다.**

| 줄 | 내용 | 파생 계약(이미 있음) |
|---|---|---|
| **이어갈 일** | "지난주 정산 정리하다 멈췄어요" | `WorkRef`·`carryableWork`·`workingState.recentOutcome` |
| **돌고 있는 일** | "목요일 자동화 1개 · 마지막 실패" | S1의 `/automation` projection |
| **해드릴 수 있는 일** | "다운로드에 거래명세서 12개가 쌓였어요. 합쳐 볼까요?" | `selfState`(가능한 손) + `local.locate`(실제 자리) |

**셋 다 없으면 Today를 띄우지 않고 바로 대화로 간다.** 빈 화면을 만들지 않는다.

세 번째 줄이 **오너가 말한 "마법사"의 실체**다. 단계별로 사용자를 끌고 가는 흐름이 아니라,
**T5가 자기 현실을 보고 먼저 한마디 하는 것**이다. 통합 초안 §15.3이 기록한 관찰과 같다 —
*"선제 행동의 본체도 복잡한 자율성 엔진이라기보다 현재 세션, 사용자 이해, heartbeat와
적절한 프롬프트의 조합이다."*

### S3. 손이 늘 때마다 한 줄을 얹는다

집사계획 4~10단계에서 손이 늘 때, **그 손이 Today에 자기 줄을 얹는다.** 화면을 두 번 짓지 않는다.
- 브라우저 손(4단계) → "로그인 유지된 사이트 3곳"
- 문서 손(6단계) → "정산 파일 새로 들어옴"
- 채널(8·9단계) → "네이버 메일 12통 · 답장 필요 2통"

## 5. 금지선

- **위젯·그래프·통계 카드 0.** 숫자를 보여주는 화면이 아니다.
- **Today에서 일을 처리하지 않는다.** 누르면 대화로 들어간다. 여기서 끝내면 관리 화면이 된다.
- **정상일 때 조용하다.** 이어갈 일도 자동화도 제안도 없으면 화면 자체가 안 뜬다.
- **내부 용어 0** — id·경로·스키마·상태 코드는 사용자면에 나오지 않는다(§1.1).
- **대화와 화면이 다른 진실을 만들지 않는다.** 같은 계약에서 파생하고 한쪽만 갱신하지 않는다.
- **OpenClaw 관리 페이지를 묶어 복제하지 않는다.** Hermes cron 문법을 노출하지 않는다.
- **제안을 광고로 만들지 않는다.** 실제 사용자 자료·연결·미완료에서만 나온다. 없으면 안 만든다.

## 6. 완료 증거 (결과 전 동결)

집사계획 §7-2의 HS-01~04를 그대로 공통 게이트로 쓴다. **새 시험 축을 만들지 않는다.**

| 신분 | 이 계획에서 재는 것 |
|---|---|
| HS-01 `back_whole_surface_control_inventory` | **기능명을 모르는 사장님이** Today에서 시작해 원래 대화로 돌아온다 |
| HS-02 `back_whole_surface_scroll_navigation` | 목록이 길어져도 읽던 자리·목적을 잃지 않는다 |
| HS-03 `back_whole_surface_failure_state_recovery` | **자동화 실패를 화면만 보고** 재시도 또는 안전 중단 |
| HS-04 `journey_task_running_navigation_return` | 작업 도는 중 Today로 갔다가 결과·대화로 복귀 |

절대 게이트(rf-005 봉인 조건 §7):

- 페이지와 원장·영수증·실제 파일의 불일치 **0**
- 승인 전 효과·권한 우회 **0**
- 현재 요청과 철회가 즉시 반영
- 빈 상태·오류·모바일 경로 완결
- **화면을 안 쓰는 사용자에게 기존 대화 경험의 부담이 늘지 않음**

상대 성능:

- 사장님이 **이전 대화 제목을 기억하지 않고** 목적 상태를 찾는다
- 현재 T5보다 탐색 질문·불필요한 이동이 줄어든다
- 비교군 대비 필요한 정보는 부족하지 않고 **운영 용어는 더 적다**

## 7. 순서와 의존

```
S1 자동화 목록   ← 지금 열 수 있다. 끊긴 약속이고 값이 이미 있다
      ↓
S2 Today 최소형  ← S1 의 한 줄을 재사용한다
      ↓
S3 손이 늘 때마다 한 줄  ← 집사계획 4~10 단계와 함께 자란다
```

**S1 은 본선 M3·M4 와 독립이다**(자동화 계약은 이미 봉인). S2 는 `index.html`·`server.js` 를
건드리므로 **본선 통합 창이 필요하다.**

## 8. 오너 확정이 필요한 것

| # | 결정 | 막는 단계 |
|---|---|---|
| D1 | S1 자동화 목록의 **형태** — 전체 화면 / 설정 하위 / 서랍 | S1. 선행 연구는 "실제 재방문 과제로 고른다"까지만 정했다 |
| D2 | S2 Today 를 **지금** 열 것인가, 집사계획 9단계에서 세 표면과 함께 열 것인가 | S2 착수 시점 |
| D3 | Today 를 **첫 화면으로 할 것인가**, 대화가 첫 화면이고 Today 는 들어가는 곳인가 | S2 설계. UX §2.2 는 "로그인 후 첫 화면"이라 적었으나 그 뒤 제품은 대화 우선으로 갔다 |

D2 에 대한 내 추천: **지금 최소형으로 열고 손이 늘 때마다 한 줄을 얹는다.** 나중에 몰아 만들면
손 하나당 화면 한 번씩 다시 짓게 된다.

D3 에 대한 내 추천: **대화가 첫 화면을 유지한다.** Today 는 상단 한 줄로 접혀 있다가
이어갈 일·돌고 있는 일·제안이 있을 때만 펼쳐진다. 통합 초안 §12 의
*"기본 화면은 Work Chat"* 과 §2.2 의 *"로그인 후 첫 화면"* 이 충돌하는데, 지금 제품과
오너의 여섯 원칙(*카드와 클릭으로 괴롭히지 마라*)은 전자를 가리킨다.

## 9. 이 계획이 하지 않는 것

- 14 표면을 다 만들지 않는다. 넷만이다.
- 새 계약·새 저장소·새 권한 축을 만들지 않는다. **전부 기존 계약의 투영이다.**
- 자동화 생성기·고급 편집기로 확대하지 않는다(rf-005 금지선).
- 본선 M2~M5 를 막지 않는다. S1 은 독립이고 S2 는 통합 창을 기다린다.
