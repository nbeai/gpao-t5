# P6-18 · 사용자 표면 통합 — Slice-2: Overview Actions (조용한 조치)

작성: 2026-07-26 · 상태: 구현·라이브 검증 완료, 깊은 감사 대기.
근거: §6.19 Status Overview 후속(액션 붙여도 구분 유지), 헌법 §5.5(안티 대시보드)·§3(승인 경계).
관련: [[gpao-t5-hermes-absorption-roadmap]], §6.13~6.19.

## 왜

Slice-1은 상태를 조용히 "보여주기"까지였다. Slice-2는 그 요약에서 **바로 조치**로 잇는다 — 전달 실패→재전달,
추천 스킬→승인, 대기 선호→확인. 감사 봉인 조건: **액션을 붙여도 구분이 무너지면 안 된다** — `추천됨`·`추정됨`·
`전달 실패`는 조치 전까지 계속 "아직 완료/반영/활성 아님"으로 보여야 한다.

## 절대 원칙

- **액션은 이미 만든(게이트 있는) 엔드포인트를 그대로 부른다 — 우회 없음.** 재전달=`/deliveries/:id/retry`
  (세션 소유 §6.13), 승인=`/skills/:id/approve`(replay+확인 §6.17), 확인=`/user-model/preferences/:id/confirm`
  (§6.18). 요약이 새 권한 경로를 만들지 않는다.
- **구분 유지**: 액션은 항목을 "아직 아님"(추천/대기/실패)에서 "완료"(활성/반영/보냄)로 **옮길 뿐**. 누르기
  전엔 계속 아직 아님. 액션 후 재조회로 이동을 보여준다.
- **추정(inferred)은 액션 없이 읽기 전용** — 추정→승인 자동 승격 금지(§6.18) 경계를 표면에서도 지킨다.
  추정에는 버튼(id)이 붙지 않는다. 확인 액션은 **대기 선호(pending operating_preference)**에만.
- **안티 대시보드**: 여전히 칩 열 때만. 액션 후 그 자리서 1회 재조회(폴링 없음).

## 계약 (`surface/overview.js`)

- actionable 항목만 **id**를 싣는다: `skills.recommended[].id`(승인) · `preferences.pending[].id`(확인) ·
  `deliveries.failed[].id`(재전달). 읽기 전용(활성·반영·추정·ready)은 id 없음.
- preferences에 **`pending`(확인 대기)** 범주 추가: 추정(inferred, 읽기 전용) ↔ 대기(pending, 확인 액션) ↔
  반영(reflected, 읽기 전용) 3분.
- `GET /overview`는 각 store에서 id를 함께 실어 준다(신규 상태 없음).

## 배선 (UI)

- `renderOverview`: actionable 항목은 `<button.ov-act data-act data-id>`. 위임 핸들러 `onOverviewAction`이
  해당 엔드포인트 호출 → `refreshOverview`로 재렌더(이동 반영). 읽기 전용 항목엔 버튼 없음.

## 테스트 (6, 총 279)

두 범주 분리(+대기 선호 3분) · **actionable은 id·읽기전용(추정·활성·반영)은 id 없음(추정 경계)** · 빈 입력 안전 ·
/overview 스토어 조합+세션 스코프 · **액션이 항목을 아직 아님→완료로 이동(승인→활성·확인→반영·재전달→완료),
액션 전엔 계속 아직 아님** · sessionId 없으면 전달 미노출.

반대 테스트: `buildOverview`가 inferred에 id를 실으면(추정에 액션이 붙으면) "읽기전용 id 없음" 테스트 실패 실측
→ 추정 경계가 load-bearing. 라이브(브라우저): 칩 열기 → 확인 대기 "글로 요약해서 주세요 [확인(반영)]", 추정됨
"저녁형일 수도"(버튼 없음). 확인 클릭 → "반영 중"으로 이동, 추정은 그대로. 구분 유지.

## 완료/미완료 (사용자 언어)

- **된 것**: 요약에서 바로 "다시 보내기 / 승인 / 확인(반영)"으로 이어간다. 조치 전엔 계속 "아직 아님"으로 보이고,
  누르면 "완료/반영/활성"으로 옮겨간다. **짐작(추정)은 버튼 없이 그대로** — 사용자가 원하지 않으면 반영되지 않는다.
- **아직 아닌 것**: 검색 결과 "찾은 기억↔반영된 기억" 카드(검색 표면 슬라이스), 모바일 375px 정밀화, 액션 실패
  시 사용자 언어 안내(지금은 조용히 롤백·재조회).

## 남은 후속

- 검색 표면에서 "찾은 기억(반영 안 됨)" 명시(§6.16 admittedIntoContext).
- 모바일 375px 레이아웃 회귀(요약 4구역+버튼이 안 겹치게).
- 액션 실패(재전달 여전히 실패 등) 사용자 언어 표면.
