# P5-B-1 Authenticated Surface Access — 설계 비교 (구현 전 결정 기록)

**문제 정의(오너 교정 원문):**
> T5가 로그인된 외부 서비스에 닿을 수 있는 안전한 경로가 아직 없다.

특정 구현("사용자 브라우저 프로필 접근")으로 바로 확정하지 않고, 8개 후보를 비교해 결정한다.

## 기각 — 후보 1·2 (기록 의무: 오너 지시)

**성능이 아니라 정합성 때문에 기각한다.**

1. **세션·쿠키·계정 전체 접근 위험.** 프로필 디렉터리(또는 열린 브라우저의 CDP)는 특정
   서비스가 아니라 **사용자의 모든 로그인**을 한꺼번에 연다. 쿠키·세션·저장된 비밀번호·
   자동완성까지. 한 서비스를 읽으려고 전부를 여는 구조다.
2. **사용자가 판단 가능한 승인 카드로 만들 수 없다.** 카드에 정직하게 쓰면 "당신의 모든
   로그인된 서비스에 접근합니다"가 된다. P5 채널에서 이미 기각한 패턴 — 판단할 수 없는
   승인은 승인이 아니다. 쪼개서 쓰면 그건 거짓 카드다.
3. **T5 자신의 보호 계약과 충돌한다.** Chrome/Safari 프로필은 T5가 `secret` 영역으로
   선언했다(F2·F3): "승인으로도 열지 않는다." 능력을 넓히려고 자기 경계를 허물면,
   "위험은 기능 제거가 아니라 경계로 다룬다"의 **경계 쪽을 우리 손으로 깨는 선례**가 된다.

후보 2는 추가로 F7 때문에 실질이 1과 같다 — 사용자의 크롬을 껐다 켜야 하고(작업 중단),
그 순간부터 프로필 접근과 동일한 위험이 된다.

## 결정 (오너 확정)

- **본선: 후보 4 — OAuth 커넥터, 첫 대상 Google.** 진실층의 `connectable → 동의 → 연결
  테스트 → executable 승격 → schema·도구함·능력 문장 동시 갱신 → 원장 → 승계`가 이
  순환을 위해 지어졌다. `mail.send` 유령이 실제 손으로 닫히고 Gmail·Drive·Calendar 가
  커넥터 하나로 열린다.
- **단, 바로 구현하지 않는다. 먼저 P5-B-1A Local Connector Probe Layer 를 닫는다**(오너 지시):
  사용자가 연결 의도를 말하면 T5가 **터미널·파일 손으로 직접 확인 가능한 것**(동기화 폴더 ·
  MCP 설정 · CLI 설치 · 로컬 인증 흔적)을 확인하고, 그 결과를 connector status / selfState /
  model reality 에 반영한다. "이미 설치된 것은 사용자가 아니라 T5가 확인한다"의 첫 실물이며,
  P5-B-0 잔여(`lastCheckedAt`·`lastError` 공백, 정적 상태)가 여기서 닫힌다.
- **보류(후보 유지): 3(확장) · 5(MCP 능동 설치).** 3은 "로그인된 화면 보기"의 중기 정답이나
  배포 부담(스토어 등록 전 개발자 모드)이 있어 P10 전 재평가. 5는 4의 전달 경로 변형으로
  취급하되, **기존 설정의 확인·활용**은 P5-B-1A 범위다.
- 6·7·8은 이미 있는 손이며 `externalReality`(P5-B-0.5)가 모델 앞에 공급 중이다.
