## 0. 계약을 다시 본다 — 원래 동기의 절반은 이미 해결됐다

정본 §S4 의 동기는 이랬다: *"437개가 한 턴에 돈다."*

**그건 이미 된다.** S1 재실행 실측(2026-08-04, gpt-5.1):

| 회차 | 이동 | 수단 |
|---|---|---|
| r6 | 426 | `bulk_move` 조건 6번 |
| r2 | 410 | 확장자별 6번 |
| r3 | 274 | 날짜+확장자 4번 |
| r6′ | 274 | 문(`limit:200`) + 조건 4번 |

한 턴에 돈 것은 캡슐이 아니라 **다중 호출 실행 + 조건 인자 + 문**이었다. 그러므로
**"437개"를 S4 의 성공 조건으로 쓰면 안 된다** — 이미 참인 것을 다시 증명하는 일이 된다.

### 그러면 캡슐이 아직 사는 이유는

| 남는 값 | 왜 지금 도구로 안 되나 |
|---|---|
| **손을 가로지르는 조합** | `bulk_move` 의 `match` 는 파일 손 안의 조건이다. "각 CSV 를 읽어 합계가 100만 넘는 것만 옮겨"는 읽기 결과가 다음 조건이 되는 일이라 한 호출로 표현되지 않는다 |
| **중간 결과가 프롬프트에 안 들어간다** | 파일 100개를 읽어 요약하려면 지금은 100개 본문이 전부 모델 입력을 지난다. 문(`offset`)이 있어도 **양 자체**는 줄지 않는다 |
| **왕복 없는 반복** | 조건으로 표현 안 되는 반복은 호출 하나당 왕복 하나다. 예산의 비용 축이 그걸 정직하게 세지만, 줄여 주지는 않는다 |

**그래서 성공 조건을 바꾼다**: "437개"가 아니라 **"읽기 결과가 다음 조건이 되는 일을
왕복 하나에 끝낸다"**.

## 1. 비교군 실측 (문구가 아니라 코드)

### Hermes `execute_code` (`tools/code_execution_tool.py`)

- 자식 프로세스 + **UDS/파일 RPC**. 도구 표면은 `SANDBOX_ALLOWED_TOOLS` 7종:
  `web_search · web_extract · read_file · write_file · search_files · patch · **terminal**`
- 상한: `DEFAULT_TIMEOUT=300s` · `DEFAULT_MAX_TOOL_CALLS=50` · `MAX_STDOUT_BYTES=50_000` ·
  `MAX_STDERR_BYTES=10_000`
- **OS 커널 격리는 없다.** `sandbox-exec`·`bwrap`·`nsjail`·`setrlimit` 어느 것도 안 쓴다
  (전수 grep 확인). 격리는 프로세스 경계뿐이다.
- **`terminal` 이 허용 목록에 있다** — 스크립트가 셸을 부를 수 있으므로, 스크립트 안에서
  하는 일은 T5 의 헌장 같은 경계를 지나지 않는다. 정본이 지목한 "Hermes 실사고 #33057 계열
  (헌장 우회)"이 구조적으로 여기서 나온다.

### T5 가 이미 가진 것 (`src/runtime/sandbox.js` · `terminal-run.js`)

**Hermes 보다 강하다.** macOS `sandbox-exec`(SBPL) 커널 격리:

```
(deny file-write*)            쓰기 전면 차단 (probe)
(deny network*)               네트워크 차단
(deny signal)                 다른 프로세스 죽이기 차단  ← killall 실사고로 들어온 줄
(deny appleevent-send)        다른 앱 원격 조종 차단     ← osascript 우회 차단
(deny file-read* …)           비밀 자리·이름 규칙·홈 Library 읽기 차단
```

여기에 `redactEnv`(비밀 환경변수 제거) · `stdio.stdin = ignore` · 타임아웃+SIGKILL ·
실행마다 새 scratch 자리와 삭제까지 이미 있다.

**결론: S4 는 새 격리 수단을 도입하지 않는다.** 정본이 "수단을 동결하지 않는다"고 한 것은
`worker_threads` 처럼 격리가 아닌 것을 격리라 부르지 말라는 뜻이었고, T5 에는 이미
**진짜 커널 경계**가 있다. 새 의존성 0 으로 간다(§17 유지).

## 2. 설계 — "손만 있는 캡슐"

캡슐은 **파일시스템을 아예 못 만진다.** 모든 효과는 RPC 로 T5 의 손을 지난다.
그래서 Hermes 보다 좁고, 그 좁음이 증명을 가능하게 한다.

```
모델 ──(스크립트)──▶ 캡슐(sandbox-exec, 쓰기 0·네트워크 0·비밀 0)
                        │  파일 RPC (scratch 안에서만)
                        ▼
                     T5 커널 ── 기존 Authority · ToolReceipt · 원장 · 되돌리기
                        │
                        ▼  결과만 (중간 결과는 프롬프트에 안 들어간다)
                     모델
```

- **언어**: `node`(T5 가 이미 도는 런타임). 새 의존성 0.
- **RPC 채널**: scratch 안 **파일**. 네트워크가 막혀 UDS 를 못 쓰기 때문이고,
  Hermes 의 원격 백엔드도 같은 이유로 파일 RPC 를 쓴다(원리 흡수).
- **표면**: `t5.call(tool, args)` 하나. 셸도, `require('fs')` 도 주지 않는다.

### 상한 (Hermes·OpenClaw 대조 후 T5 값)

| 축 | Hermes | T5 (동결) | 왜 |
|---|---|---|---|
| 시간 | 300s | **60s** | 턴 벽시계 예산이 180s 다(S3). 캡슐 하나가 그 3분의 1을 넘으면 사용자가 기다린다 |
| 호출 수 | 50 | **200** | 파일 이동은 호출당 수 ms. 되돌릴 수 있는 것 뒷단(200)과 같은 값으로 맞춘다 |
| stdout | 50KB | **16KB** | 모델 입력 상한 1,200자 실측(§S3)과 같은 사고 — 결과는 요약이지 덤프가 아니다 |

값은 **잠정**이다. 실측 회차 뒤에 다시 정한다.

## 3. 증명해야 하는 여섯 (정본 §S4 표 그대로)

전부 **반대시험**으로. 통과가 아니라 **탈출 시도가 막히는 것**을 본다.

| 성질 | 반대시험 |
|---|---|
| 파일시스템 기본 차단 | scratch 밖 쓰기·읽기 시도 → 막힘 |
| 네트워크 기본 차단 | 외부 요청 시도 → 막힘 |
| 환경변수·비밀 제거 | `process.env` 에서 비밀 이름 읽기 → 없음 |
| RPC 표면만 | `require('fs')`·`child_process` 시도 → 막힘 |
| 헌장 넷 유효 | 캡슐 안에서 되돌릴 수 없는 일 시도 → **승인 카드**(자동 실행 0) |
| self-grant 불가 | 권한·승인 상태를 바꾸는 RPC 시도 → 거부 |

## 4. 안 하는 것

- **raw shell 캡슐**: 정본이 "위험 미상 raw shell(그때만 승인)"을 말하지만, 그건 이미
  `local.terminal` 이 하는 일이다. 캡슐에 셸을 넣으면 Hermes 의 구멍을 그대로 들여온다.
- **비 macOS 지원**: `sandboxAvailable()` 이 false 면 **캡슐을 열지 않는다**(모르면 막는다).
  없는 능력을 있는 척하지 않는다.
- **437개 재증명**: 이미 참이다(§0).

## 5. 중단 조건

여섯 반대시험 중 **하나라도 못 막으면** 캡슐을 켜지 않는다. 부분 격리는 격리가 아니다.
