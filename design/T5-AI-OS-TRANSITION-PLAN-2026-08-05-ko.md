## 1. 왜 이 계획이 필요한가

검사 2,373건이 전부 초록인 상태에서, 오너가 새 대화창을 열고 16턴을 나누자 네 가지가 한꺼번에 무너졌다.
런타임이 모델을 제한적으로 답하게 하고, 기능이 단편적으로 전달되고, 웹은 엉망이었다.

> **정정(v2.1)** — v1·v2 는 여기에 *"파일은 한 폴더만 보고"* 를 적었다. **사실이 아니다.**
> 제품 기본 뿌리는 넷이고(`src/runtime/file-scope.js` — 작업 폴더·Downloads·Documents·Desktop),
> `local.locate` 는 `from` 이 비면 **홈 전체**를 훑는다. 한 폴더는 사람 사용시험 **격리 하네스**의
> 설정(`GPAO_T5_FILE_ROOTS: fixtureDir`)이지 제품이 아니다.
> 오너가 본 "Documents 만 본다"는 **모델이 스스로 `from: "Documents"` 를 고른 결과**였다.
> 나는 오너의 인상을 검증 없이 계획서의 사실로 옮겼다 — 오늘 세 번째다. **S0 이 필요한 이유가 이것이다.**

원인은 기능 부족이 아니었다. **AI 운영체제의 기본 원리를 모른 채 칸 안쪽 기능만 정교하게 만들어 왔다.**
그래서 구조와 프로세스가 이상해졌고, 그 위에 쌓은 정교함이 첫 대화에서 무너졌다.

OpenClaw·Hermes·Claude Code·Codex 는 이 지점에서 서로 같다. 그 공통 골격이 AI 운영체제의 기본이다.

## 2. 원리 여섯 — 우리가 배우는 것

**파일 이름이나 구현을 복제하지 않는다.** 아래는 원리이고, T5 는 T5 의 방식으로 구현한다.

**① 등록** 기능은 커널이 정의한 계약 슬롯에 드라이버로 등록된다.
OpenClaw 확장은 매니페스트에 `contracts` 슬롯을 채운다고 선언한다. `webSearchProviders` 한 슬롯에
드라이버가 13개다. 수집 도구는 드라이버를 모른 채 슬롯에 요청한다. → T5 **매듭(§2-C)** 의 레지스트리 형태.

**② 해석** 이번 런에 붙는 도구는 상황에서 계산된다.
`resolveConversationCapabilityProfile` 이 40여 개 런타임 사실에서 정책층을 병합한다.
위조된 권한은 떨어뜨리고, 오너 세션이 손님 정책으로 흘러내리지 않게 막는다.

**③ 제시** 도구 목록이 곧 능력 선언이다.
모델이 받는 것은 `name · label · description · parameters` 뿐이다.
**못 쓰는 도구의 목록은 주지 않는다.** 프로세스는 부를 수 없는 시스템콜의 목록을 받지 않는다.
시스템 프롬프트는 *무엇이 있는지*가 아니라 *어떻게 행동할지*만 말한다.

**④ 집행** 정책은 실행 경계의 훅에 있다.
`prepare → before_tool_call(거부 가능) → execute → normalize → after_tool_call → persist`.
OpenClaw 문서가 못 박는다 — *"프롬프트의 안전 문구는 권고이지 강제가 아니다."*

**⑤ 귀결** 차단도 실패도 모델에게 결과로 돌아간다.
`buildBlockedToolResult` · `buildToolExecutionErrorResult`.
**커널은 사용자에게 직접 말하지 않는다.** 무슨 말을 할지는 모델이 정한다.

**⑥ 집** 에이전트의 집은 역할과 수명이 선언된 파일들이다.
*"The workspace is the agent's home… treat it as memory."*
집과 설정·상태를 나눈다. 파일마다 수명이 다르다 — 매 세션 / 조건부 / **안 싣고 필요할 때 꺼내 보는 것**.
기억과 스킬은 마지막에 속한다. 그래서 **기억이 그냥 파일**이고 자가학습에 특수 통로가 필요 없다.

## 3. 불변식 넷 — 모든 단계가 지킨다 (v2 신규)

단계가 아니다. **단계마다 위반 여부를 확인하는 것**이다. v1 에 이게 없어서 S7 이 잘못 서 있었다.

**불변식 A · 프롬프트 캐시는 신성하다**
Hermes `AGENTS.md` 19행 — *"Anything that mutates past context, swaps toolsets, or rebuilds the system
prompt mid-conversation invalidates that cache and multiplies the user's cost. We do not do it
(the one exception is context compression)."*
→ **대화 중에 도구 집합과 시스템 프롬프트를 흔들지 않는다.** 안정 구역과 휘발 구역을 가른다.

**예외 ① 압축**(S9). 긴 대화를 잇는 유일한 길이다.

**예외 ② 능력 획득**(v2.2 신규). T5 는 대화 중에 손이 실제로 늘어난다 — 사용자가 "노션 붙여줘"
하면 `admitHttpTools` 가 그 자리에서 새 손을 들인다([connector-connect.js:182](../src/runtime/connector-connect.js:182)·`:310`).
이걸 금지하면 "붙이고 새 대화를 여세요"가 되어 **자동성 헌장에 정면으로 어긋난다**(마찰을 늘려 절약을 사는 꼴).
그래서 예외로 두되 **규칙을 함께 단다**:

> **새로 얻은 손은 도구 목록 뒤에만 붙인다(append-only).
> 중간 삽입·재정렬·제거는 대화 경계에서만 한다.**

근거 — T5 는 이미 `systemStable`/`systemVolatile` 을 가르고 도구 목록 **마지막 하나**에
`cache_control` 을 건다([model-provider.js:326](../src/runtime/model-provider.js:326)·`:508`).
뒤에만 붙으면 앞 직렬화가 그대로라 접두가 산다.
**캐시 적중 자체는 공급자 거동이라 우리가 통제하지 못한다** — 그래서 우리가 통제하는 것,
곧 **접두가 안 바뀌는가**를 S0 계측이 잰다(`toolPrefixSha`·`systemStableSha`).

**불변식 B · 좁은 허리, 넓은 가장자리**
같은 문서 24행 — *"Every model tool we add is sent on every API call, so the bar for a new core tool is high."*
→ 코어 도구 하나는 **매 API 콜 비용**이다. 능력은 가장자리에서 넓힌다.
→ **T5 는 지금 쓸 수도 없는 도구 목록(`blocked`)을 매 콜마다 돈 내고 싣는다.** S1 이 이걸 없앤다.

**불변식 C · 모든 도구 실행은 보이고 멈출 수 있다**
Hermes 아키텍처 원칙. T5 는 이미 `/turn/cancel` 과 `취소됐나` 를 가지고 있다.
→ **지키고 넓힌다.** 새로 붙는 손(특히 컴퓨터 유즈)은 예외 없이 이 계약 안에 들어온다.

**불변식 D · 격리는 승인 카드가 아니라 구조로 한다**
OpenClaw 보안 문서의 공식 입장이며 **T5 자동성 헌장과 정확히 같은 방향**이다.
마찰(카드)을 늘려 안전을 사지 않는다. 경계·샌드박스·권한으로 푼다.
→ 이 계획으로 승인 카드가 늘어나면 그 단계는 실패다.
**재는 법**(v2.2) — "늘었다/안 늘었다"로 다투지 않게 미리 박는다:

> ① **기존 사용자 흐름에서 카드 수가 변하지 않는다**(회귀로 고정한다).
> ② **새 능력에서 나는 카드는 자동성 헌장 넷 안에서만** 난다.
>
> CU E 는 승인 경계를 화면에 세우는 단계라 새 카드가 0 일 수 없다 — ②가 그 자리의 판정 기준이다.

## 3-A. 이 전환의 **중심 계약** — 답의 저작권 (v2.3 · v2.4 정정)

오너 지적 2026-08-05: *"오픈클로를 만든 사람이 모델의 응답을 제어하려고 했겠어? LLM 을 활용해
자기 일을 하게 만드는 **연결과 작동 환경, 흐름**을 만드는 데 집중했을 거고 그게 지금의 기본이야."*

맞다. 그리고 T5 는 거기서 가장 크게 벌어져 있다.

> **v2.4 정정** — v2.3 은 이것을 *"모델의 답에 손대는 자리 22곳 → 0"* 이라는 **숫자**로 세웠다.
> **대리지표였다**(검토 지적). 22 → 0 을 목표로 삼으면 렌더 12곳을 뜯어 내부 표식이 화면으로 새고,
> 빈 답 안전망을 뜯어 *"빈 답이 네 번 연속 나갔다"*(turn.js 주석 · 오너 실사용) 가 재현된다.
> 그리고 22 → 8 이 큰 진전처럼 보이는데 **진짜 것은 하나도 안 바뀔 수 있다.**
> 명제는 그대로 두고 **지표를 칸으로 바꾼다.**

### 세 칸 — 숫자가 아니라 계약이다

| 칸 | 무엇 | 목표 | 지금 |
|---|---|---|---|
| **갈아치움**(replace) | 모델의 답을 **런타임이 쓴 다른 문장**으로 바꾼다 | **0** | `읽은척차단` → `정직한답` (turn.js 2자리) |
| **반환**(return) | 원장과 대조해 **모델에게 되돌린다.** 고쳐 쓰는 것도 모델 | 있어도 된다 | `출구검증` — OpenClaw 훅과 같은 자리 |
| **렌더**(render) | 내부 표식 제거·미리보기 순서 | **있어야 한다** | `userFacingModelText` · `미리보기정렬` |

**빈 답 안전망**(`fallbackReplyFrom`)은 네 번째 성질이다 — 제어가 아니라 **공백 처리**다.
모델이 두 번 침묵했을 때만 원장 사실로 채운다. OpenClaw 도 0 이 아니다:
`heartbeat-runner.ts` 가 빈 답을 다룬다 — 다만 **없으면 없는 것으로 두고**(빈 하트비트),
T5 는 원장 사실로 채운다. 안 만지는 게 아니라 **다르게 다룬다.**

`test/answer-authorship-lanes.test.js` 가 이 칸들을 못 박는다. **새 갈아치움이 생기면 거기서 걸린다.**

### 왜 갈아치움을 0 으로 갈 수 있다고 보는가 — S1·S2 가 이미 보여줬다

게이트들은 **모델에게 사실을 안 주던 시절의 보상책**이었다.
- 2026-08-03: 모델이 국세청 안내를 지어냈다 → 원인은 **차단 사실이 모델에게 안 갔던 것**.
  그때의 처방이 `출처못댐` 단독 차단이었다.
- 2026-08-05 S2: 차단을 교환으로 돌려주자 **모델이 스스로 정직하게 답했다**(라이브 453자).
- 그러자 그 게이트는 **정직한 답만 죽였다**(F-15).

**연결을 제대로 하면 제어가 필요 없어진다.** 이게 이 전환의 핵심 발견이고, 한 칸 안에서 인과가 증명됐다.

### 목표 상태

> **최종 답은 모델의 것이다.** 강제는 **도구 경계**(S6)에 있고, 절대 게이트는 거기서 선다.
> 원장·영수증·실물 대조는 그대로 — 오히려 그 자리가 제자리다.
> 갈아치움 2자리는 **S6 에서 반환으로 바뀐다**(원장 불일치를 모델에게 주고 모델이 다시 쓴다).

> **같은 범주의 요청이 셋 이상 쌓이면** 하나씩 병합하지 말고 인터페이스를 먼저 만들고

**지금 이 문을 통과해야 하는 것: 컴퓨터 유즈.** §7 에서 판정한다.

## 6. T5 가 이미 가진 것 — 지켜서 더 강해질 자산

점검에서 확인한 것 — T5 는 **쓰기 락**(`src/surface/writer-lock.js`), **중단**(`/turn/cancel`),

새면서 원장에도 남는다. 바꾸면 사유는 모델에게 결과로 가고 원장에는 그대로 남는다. 새는 자리만 없어진다.

## 7. 컴퓨터 유즈 — 사다리 판정과 엇물리기 (v2 신규)

**판정**: 컴퓨터 유즈는 사다리 **6칸(코어 도구)** 에 해당한다.

`CU0-DEPENDENCY-AUDIT`(감사 정본) · `CU0-PLAN-CORRECTIONS`(정정 6건) ·
`CU0-SLICING-PROPOSAL`(A~J 재단) · peekaboo v3.9.10 소스 고정(저장소 밖).

**엇물리기** — 직렬이 아니다. CU 는 새 뼈대의 **첫 검증 대상**이다.

```
S0 계측 · S1~S3 빼기
   커널이 거짓말하고 모델 대신 말하는 상태에서 CU 를 붙이면 같은 병이 복제된다
        ↓
CU A·B (눈, 관찰 전용)   ∥   S4 집 · S5 기억
   CU 눈은 손이 없어 위험이 낮고 셀프후드를 한 칸 올린다
        ↓
S6 집행 경계  ★ 관문 — CU C 이전에 반드시
   CU 의 A14(효과 없으면 성공 영수증 0)는 원장 매듭 그 자체다.
   CU 안에 따로 만들지 않고 이 경계에 건다
        ↓
CU C~E (첫 손 → 클릭·입력 → 승인)   ∥   S7 해석 · S8 등록
   CU 가 슬롯 레지스트리의 첫 드라이버가 되어 S8 을 실증한다
        ↓
CU F~J (스크린샷 → 브라우저 통합 → 화면·복구 → 서명 PKG → 사람 사용시험)   ∥   S9 지속
```

**CU C 를 S6 뒤에 두는 것이 이 배치의 핵심이다.** 지금처럼 정책이 `turn.js` 인라인인 상태로
CU 를 붙이면 CU 정책도 인라인으로 쌓인다 — 지난 두 달에 벌어진 일이 정확히 그것이다.

**A 착수 전 오너 결정 4건**(`CU0-PLAN-CORRECTIONS` 참조)
① shell 경로 — 계획서의 "shell 제외"는 사실이 아니다(여섯 자리 전수됨)
② 비공개 API(CGS/SCK) 사용 여부 — 기본이 켜짐이라 나중에 하면 켜진 채 굳는다
③ 최소 OS 14 vs 15 — 14 를 지원하면 창 캡처 보정이 CU F 에 들어간다
④ peekaboo 벤더링 여부
→ ③④ 는 내가 권고안을 만들어 올린다. ①② 는 오너 판단이 필요하다.

## 8. 단계 — 열 칸

각 단계는 **사용자 문장 하나가 다르게 끝나야** 닫힌다. 계약 관통은 닫힘이 아니다.
단계마다 **불변식 넷 위반 여부를 함께 판정**한다(v2).

**S0 · 계측 — 모델이 실제로 무엇을 받는지 본다**
턴마다 모델에 들어간 것을 그대로 덤프한다(비밀 마스킹). 조립된 프롬프트를 볼 수 있게 한다.
*닫힘*: "안녕" 한 턴의 입력 전문을 열어 **능력 목록이 어디에 실리는지 눈으로 확인한다.**
*이유*: 오늘 재는 자리를 몰라 세 번 잘못 짚었다 — `CAPABILITIES.md` 두 번, **파일 뿌리 한 번**.

> **결과(2026-08-05, 닫힘)** — `blocked` 가 아니었다. **네 번째 추측도 틀릴 뻔했다.**
> 능력 목록은 시스템 프롬프트가 아니라 **사용자 메시지 안에** 실린다([model-provider.js:274](../src/runtime/model-provider.js:274)).
> 같은 자리에 커널이 쓰는 블록이 **15개**이고 진짜 사용자 발화는 맨 마지막에 붙는다.
> **커널이 사용자 입으로 말하고 있다.** 전문: `docs/03-verification/evidence/s0-prompt-2026-08-05/RESULT-ko.md`
>
> → **S1 의 표적이 바뀐다**(아래).
*불변식*: A — 덤프가 프롬프트 자체를 바꾸면 안 된다(관측이 대상을 바꾸지 않는다).
*S0 이 답해야 할 열린 질문*(v2.1): 홈 전체를 훑을 수 있는데도 **모델은 왜 `from: "Documents"` 를
골랐나.** 도구 설명이 그렇게 몰고 있는지, 모델의 선택인지 — 프롬프트를 보면 알 수 있다.
추측으로 고치지 않는다.
*계측 항목*(v2.2): **커넥터를 대화 중에 붙였을 때 캐시 접두가 살아 있는가.**
적중은 공급자 거동이라 통제 밖이므로, 우리가 통제하는 **접두 불변**을 잰다 —
붙이기 전 / 붙인 턴 / 다음 턴의 `systemStableSha` 와 `toolPrefixSha` 를 대조한다.
불변식 A 예외 ②(append-only)가 실제로 지켜지는지가 여기서 판명된다.

**S1 · 제시(③) — 커널이 사용자 입으로 말하는 것을 멈춘다**

> **표적 정정(S0 결과)** — 원래 "`blocked` 를 뺀다"였다. 재 보니 `blocked` 는 인사 턴에 실리지도
> 않았다(`fast_chat` 은 `limits` 를 비운다). 진짜 병은 **커널이 쓴 블록 15개가 사용자 발화 앞에
> 붙는 구조**다. 사실은 시스템 프롬프트(안정) 또는 **도구 결과**(모델에게 돌아가는 데이터)로
> 가야 한다 — 사용자 목소리가 아니라. 이건 원리 ③ 위반의 가장 나쁜 형태이고, 불변식 B 도
> 함께 깬다(사용자 턴은 캐시에 안 얹혀 매 콜 새로 지불한다).

능력 선언은 도구 스펙 목록 하나로 만든다. 사용자 메시지에는 **사용자가 말한 것만** 남긴다.
*닫힘*: 새 대화창에 **"안녕"** → 능력 목록을 읊지 않는다.
*동시 보호*: 셀프후드 질문("너 뭐 할 수 있어?")에는 여전히 정확히 답한다 — **물어봤을 때** 싣는다.
*불변식*: B — 매 콜 비용이 실제로 준다. 토큰으로 대조한다.

**S2 · 귀결(⑤) — 차단과 실패를 모델에게 돌린다**
`못한호출남기기` 의 `사람말` 인자를 없앤다. 차단 사유는 **도구 결과**로 모델에게 간다.
원장 기록은 그대로 둔다(매듭 유지). 범위는 `되풀이`·`되묻기중단`·`승인대기중단`·`예산소진` 등 6곳 전부.
*닫힘*: 같은 URL 재요청에서 **"방금 한 것과 같은 일이라…"** 가 답에 안 나온다.

**S3 · 정직한 시스템콜 — 커널이 확신을 지어내지 않는다**
`local.locate` 의 이름 대조를 구조로 바꾼다(확장자는 낱말이 아니다). 확신도는 실제 일치에서만 나온다.
*닫힘*: `YOON.md` 를 찾으면 후보를 지어내지 않고, 있으면 정확히 찾는다.

**S4 · 집(⑥-1) — 집과 설정을 나눈다**
에이전트의 집을 설정·상태와 분리한다. **운영 지침**과 **사용자가 누구인가**를 세운다(이름은 T5 방식).
파일마다 **수명**을 선언한다: 매 세션 / 조건부 / 안 싣고 꺼내 보는 것. 예산을 건다.
*닫힘*: 사용자가 집의 운영 지침을 고치면 다음 턴 답이 그대로 달라진다.
*불변식*: A — 수명 선언이 곧 캐시 경계다. 안정 구역이 대화 중에 흔들리면 안 된다.
*함께 푼다(v2.1)*: **기대 범위와 기본 범위가 다르다.** 기본 뿌리는 넷인데 모델은 라이브에서
`Pictures` 를 포함해 답했다(선언에는 없다). 이건 슬롯 문제가 아니라 **온보딩·설정 문제**다 —
"첫 실행에서 어떤 방을 열고, 사용자가 어떻게 넓히는가". 집이 그 답을 가진다.

**S5 · 기억을 집으로(⑥-2) — 전용 채널을 없앤다**
기억을 파일로 내리고 모델이 자기 파일 도구로 읽고 쓰게 한다.
`memory.propose`/`memory.cite` 통제 채널과 **그 누출을 막던 방어 정규식이 함께 사라진다.**
*닫힘*: 지난 대화를 인용해 답할 때 화면에 채널 이름이 원천적으로 나올 수 없다.
*지킨다*: T5 의 **성장 승인 계약**(제안→검토→적용). 파일이 되어도 자동 반영되지 않는다.
*미결(오너)*: `memory-ledger.key` 암호화를 유지한 채 파일 의미론을 줄지, 평문으로 갈지. **착수 전에 묻는다.**

**S6 · 집행(④) — 정책을 실행 경계로 옮긴다 ★ 관문**
`turn.js` 에 인라인으로 흩어진 판정을 도구 실행 앞뒤 경계로 모은다.
**여기가 T5 의 매듭 자리다** — 원장·영수증·절대 게이트·승인 생애주기·중단(불변식 C)을 한 곳에 건다.
*닫힘*: 게이트 판정 한 건이 경계에서만 일어나고 `turn.js` 본문에서 사라진다. 절대 게이트 0 유지.
*이 단계 없이 CU C 로 갈 수 없다.*

**S7 · 해석(②) — 이번 런의 도구를 상황에서 계산한다**
정적 손 목록을 버리고 맥락에서 계산한다. 층수는 T5 축으로 정한다.
*불변식 A 가 여기를 지배한다* — **대화 안에서는 도구 집합이 안정적이어야 한다.**
계산은 대화 시작·상황 전환 같은 경계에서 하고, 매 턴 흔들지 않는다. v1 은 이걸 놓쳤다.
*닫힘*: 상황이 다르면 다른 도구 집합이 가고, **같은 대화 안에서는 안 바뀐다** — 원장으로 대조된다.

**S8 · 등록(①) — 계약 슬롯과 드라이버**
커널이 슬롯을 정의하고 기능이 드라이버로 등록된다. **웹이 여기서 층을 얻는다**
(정적 수집 → 읽기 추출 → 브라우저 승격). 이 단계의 근거는 **웹 하나로 충분히 선다.**
*닫힘*: 네이버 플레이스 **후기 본문을 실제로 읽고** 분석한다. 못 읽으면 못 읽었다고 말한다.
*여기서 파일을 다루지 않는다*(v2.1) — 풀 제한이 제품에 없다. 없는 병을 고치는 칸을 두면
나중에 "풀렸다"고 닫으면서 **아무것도 안 바뀐 것을 성과로 적게 된다.**
*CU 가 이 단계의 첫 드라이버다.*

**S9 · 지속 — 긴 대화가 끊기지 않는다 (v2 신규)**
지금 T5 는 도구 결과는 압축하지만(`compactResult`) **대화 자체는 압축하지 않는다.**
예산이 차면 멈춘다 — 그건 압축이 아니다. 불변식 A 가 허용하는 유일한 예외가 여기다.
*닫힘*: 하루 종일 이어 쓴 대화가 앞을 잃지 않고 계속된다.
*배치 이유*: **가장 안 막는 것**이지 덜 중요한 것이 아니다. 오너가 실제로 길게 쓰면 바로 만난다.

## 9. 순서의 근거

- **S0 이 먼저다.** 계측 없이 고치면 오늘처럼 엉뚱한 것을 원인으로 확신한다.
- **S1~S3 은 빼기다.** 커널이 모델 자리에서 말하던 것을 걷어내는 일이라 위험이 낮고 효과가 즉시 화면에 난다.
- **S4~S5 는 자리 옮기기다.** 새 능력이 아니라 있던 것을 제자리로 보낸다.
- **S6 이 매듭이자 관문이다.** T5 자산을 한 곳에 건다. S7·S8·CU C 는 이 경계 위에서만 안전하다.
- **S8 이 늦은 이유**: 가장 크고, 경계 없이 붙이면 지금 같은 인라인 누적이 반복된다.
- **CU 는 직렬이 아니라 엇물린다**(§7). 새 뼈대의 첫 검증 대상이기 때문이다.

## 10. 단계 공통 규율

1. 착수 전 **실패를 먼저 본다** — 고치기 전에 재현되는 검사를 세운다.
2. **라이브로 밟는다.** 실모델 실행 전 `scripts/human-use/prove-isolation.mjs` 통과. 예외 없다.
3. 단계 끝마다 `npm test` · `npm run gate` · `npm run audit:mutation` 초록.
4. **못 고친 것은 검사로 박지 않는다.** 장부(`design/T5-FOLLOWUP-LEDGER-ko.md`)에 적는다.
5. 각 단계는 **독립적으로 되돌릴 수 있어야** 한다. 한 흐름이되 한 덩어리가 아니다.
6. 닫힘 판정은 **사용자 문장**으로 한다.
7. **단계마다 불변식 넷을 판정한다**(v2). 특히 A(캐시)와 D(카드 증가 금지)는 수치로 본다.
7-A. **단계마다 §3-A 세 칸을 판정한다**(v2.4) — 갈아치움은 늘면 안 되고 줄어야 한다.
   반환·렌더는 숫자가 아니다. **숫자를 목표로 세우지 않는다**(대리지표 금지).
8. **S9 착수 때 앞에서 정한 안정 구역 정의를 다시 확인한다**(v2.2). S9 는 불변식 A 의 예외 ①이다 —
   앞의 아홉 칸이 캐시를 신성시하며 설계된 뒤 마지막에 그걸 깨는 기능이 들어온다.
   깨도 되는 자리가 정확히 어디까지인지 그때 다시 못 박는다.
