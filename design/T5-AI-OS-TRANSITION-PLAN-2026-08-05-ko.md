# T5 를 AI 운영체제로 — 전환 개발계획

작성 2026-08-05 · 기준 커밋 `82ebd5e` · 상태 **수립됨(착수 전)**

> 이 계획은 기능을 더하지 않는다. **T5 의 뼈대를 AI 운영체제의 기본 골격으로 바꾼다.**
> 근거는 OpenClaw·Hermes 실제 소스와 2026-08-05 오너 라이브 대화다.

---

## 1. 왜 이 계획이 필요한가

검사 2,373건이 전부 초록인 상태에서, 오너가 새 대화창을 열고 16턴을 나누자 네 가지가 한꺼번에 무너졌다.
런타임이 모델을 제한적으로 답하게 하고, 기능이 단편적으로 전달되고, 파일은 한 폴더만 보고, 웹은 엉망이었다.

원인은 기능 부족이 아니었다. **AI 운영체제의 기본 원리를 모른 채 칸 안쪽 기능만 정교하게 만들어 왔다.**
그래서 구조와 프로세스가 이상해졌고, 그 위에 쌓은 모든 정교함이 첫 대화에서 무너졌다.

OpenClaw·Hermes·Claude Code·Codex 는 이 지점에서 서로 같다. 그 공통 골격이 AI 운영체제의 기본이다.

---

## 2. 우리가 배우는 것 — 원리 여섯

**파일 이름이나 구현을 복제하지 않는다.** 아래 여섯 개는 원리이고, T5 는 T5 의 방식으로 구현한다.

**원리 ① 등록 — 기능은 커널이 정의한 계약 슬롯에 드라이버로 등록된다**
OpenClaw 확장은 도구를 "추가"하지 않고 매니페스트에 `contracts` 슬롯을 채운다고 선언한다.
`webSearchProviders` 슬롯 하나에 드라이버가 13개다. 수집 도구는 드라이버를 모른 채 슬롯에 요청한다.
→ T5 의 **매듭(§2-C)** 을 레지스트리로 세운 형태다.

**원리 ② 해석 — 이번 런에 붙는 도구는 상황에서 계산된다**
`resolveConversationCapabilityProfile` 이 40여 개 런타임 사실에서 12층 정책을 병합한다.
위조된 권한은 떨어뜨리고(`resolveTrustedGroupId`), 오너 세션이 손님 정책으로 흘러내리지 않게 막는다.

**원리 ③ 제시 — 도구 목록이 곧 능력 선언이다**
모델이 받는 것은 `name · label · description · parameters` 뿐이다.
**못 쓰는 도구의 목록은 주지 않는다.** 프로세스는 부를 수 없는 시스템콜의 목록을 받지 않는다.
시스템 프롬프트는 *무엇이 있는지*가 아니라 *어떻게 행동할지*만 말한다.

**원리 ④ 집행 — 정책은 실행 경계의 훅에 있다**
`prepareArguments → before_tool_call(거부 가능) → execute → normalize → after_tool_call → tool_result_persist`.
OpenClaw 문서가 못 박는다 — *"프롬프트의 안전 문구는 권고이지 강제가 아니다."*

**원리 ⑤ 귀결 — 차단도 실패도 모델에게 결과로 돌아간다**
`buildBlockedToolResult` · `buildToolExecutionErrorResult`.
**커널은 사용자에게 직접 말하지 않는다.** 무슨 말을 할지는 모델이 정한다.

**원리 ⑥ 집 — 에이전트의 집은 역할과 수명이 선언된 파일들이다**
*"The workspace is the agent's home… treat it as memory."*
집(워크스페이스)과 설정·상태(`~/.openclaw/`)를 나눈다. 집은 사용자가 고치고 백업한다.
파일마다 수명이 다르다 — 매 세션 싣는 것, 조건부로 싣는 것, **안 싣고 필요할 때 꺼내 보는 것**.
기억과 스킬은 마지막에 속한다. 그래서 **기억이 그냥 파일**이고, 자가학습에 특수 통로가 필요 없다.

## 3. 우리가 배우지 않는 것 (비목표)

- **파일 복제 금지.** `AGENTS.md`·`SOUL.md` 같은 이름을 그대로 쓸 이유가 없다. 필요한 건 **역할과 수명**이다.
- **도구 개수 늘리기 금지.** 이 계획에 새 손을 추가하는 단계는 없다.
- **정책 12층 복제 금지.** OpenClaw 의 층수는 그들의 채널·그룹·서브에이전트 사정이다. T5 는 T5 의 축으로 만든다.
- **절대 게이트 완화 금지.** 일곱은 그대로 0 이다.
- **자동성 헌장 위반 금지.** 이 계획으로 승인 카드가 늘어나면 안 된다. T5 가 묻는 것은 넷뿐이다.
- **회귀 빨간 채로 본선 금지.** 단계마다 2,373 이 초록이어야 다음으로 간다.

## 4. T5 가 이미 가진 것 — 지켜서 더 강해질 자산

OpenClaw 에 **없는** 것들이다. 골격을 바꾸되 이것들은 매듭으로 다시 건다.

원장 · 영수증 · 실물 대조 · 절대 게이트 일곱 · 승인 생애주기 · 되돌리기 · 자동성 헌장 ·
말귀(한국어) · 셀프후드 · T-cell · 기억/맥락/자가학습.

특히 **원리 ⑤ 를 적용하면 원장이 약해지는 게 아니라 강해진다.**
지금은 차단 사유가 사용자 문장으로 새면서 원장에도 남는다.
바꾸면 사유는 모델에게 결과로 가고, 원장에는 그대로 남는다. 새는 자리만 없어진다.

## 6. 단계 — 한 흐름, 여덟 칸

각 단계는 **사용자 문장 하나가 다르게 끝나야** 닫힌다. 계약 관통은 닫힘이 아니다.

**S0 · 계측 — 모델이 실제로 무엇을 받는지 본다**
지금은 조립된 프롬프트를 볼 수 없다. 그래서 오늘 `CAPABILITIES.md` 를 원인으로 잘못 짚었다.
턴마다 모델에 들어간 것을 그대로 덤프한다(비밀은 마스킹).
*닫힘*: "안녕" 한 턴의 입력 전문을 파일로 열어 `blocked` 목록을 눈으로 확인한다.
*이유*: **재는 자리를 검증하지 않으면 틀린 결론을 확신한다.** 오늘 두 번 당했다.

**S1 · 제시(③) — 못 쓰는 손을 모델에게 알리지 않는다**
`blocked` 를 프롬프트에서 뺀다. 능력 선언은 도구 스펙 목록 하나로 만든다.
프롬프트에는 *어떻게 행동할지*만 남긴다.
*닫힘*: 새 대화창에 **"안녕"** → 능력 목록을 읊지 않는다.
*주의*: 셀프후드 질문("너 뭐 할 수 있어?")에는 여전히 정확히 답해야 한다. 그건 **물어봤을 때** 싣는다.

**S2 · 귀결(⑤) — 차단과 실패를 모델에게 돌린다**
`못한호출남기기` 의 `사람말` 인자를 없앤다. 차단 사유는 **도구 결과**로 모델에게 간다.
원장 기록은 그대로 둔다(매듭 유지).
*닫힘*: 오너가 준 것과 같은 URL 재요청에서 **"방금 한 것과 같은 일이라…"** 가 답에 안 나온다.
*범위*: `되풀이`·`되묻기중단`·`승인대기중단`·`예산소진` 등 6곳 전부.

**S3 · 정직한 시스템콜 — 커널이 확신을 지어내지 않는다**
`local.locate` 의 이름 대조를 구조로 바꾼다(확장자는 낱말이 아니다). 확신도는 **실제 일치**에서만 나온다.
못 찾았으면 못 찾았다고 반환한다.
*닫힘*: `YOON.md` 를 찾으면 후보를 지어내지 않고, 있으면 정확히 찾는다.
*이유*: 원리 ⑤ 와 같은 병이고 가장 작다. S2 직후에 붙인다.

**S4 · 집(⑥-1) — 집과 설정을 나눈다**
에이전트의 집을 설정·상태와 분리한다. 집에는 **운영 지침**과 **사용자가 누구인가**를 세운다
(이름은 T5 방식으로 정한다 — 복제하지 않는다). 파일마다 **수명**을 선언한다:
매 세션 / 조건부 / **안 싣고 꺼내 보는 것**. 예산을 건다.
*닫힘*: 사용자가 집의 운영 지침을 고치면 다음 턴 답이 그대로 달라진다.

**S5 · 기억을 집으로(⑥-2) — 전용 채널을 없앤다**
기억을 파일로 내리고, 모델이 자기 파일 도구로 읽고 쓰게 한다.
`memory.propose`/`memory.cite` 통제 채널과 **그 누출을 막던 방어 정규식이 함께 사라진다.**
*닫힘*: 지난 대화를 인용해 답할 때 화면에 채널 이름이 원천적으로 나올 수 없다.
*미결 판단(오너)*: T5 는 `memory-ledger.key` 로 기억을 암호화한다. 파일로 내리면 그 보호가 약해진다.
**암호화를 유지한 채 파일 의미론을 줄지, 평문 파일로 갈지는 오너 결정이다.** S5 착수 전에 묻는다.

**S6 · 집행(④) — 정책을 실행 경계로 옮긴다**
`turn.js` 에 인라인으로 흩어진 판정을 도구 실행 앞뒤의 경계로 모은다.
**여기가 T5 의 매듭 자리다** — 원장·영수증·절대 게이트·승인 생애주기를 이 경계 한 곳에 건다.
*닫힘*: 게이트 판정 한 건이 경계에서만 일어나고 `turn.js` 본문에서 사라진다. 절대 게이트 0 유지.

**S7 · 해석(②) — 이번 런의 도구를 상황에서 계산한다**
정적 손 목록을 버리고 대화 맥락에서 계산한다. **층수는 T5 축으로 정한다**(12층 복제 금지).
*닫힘*: 같은 T5 가 상황에 따라 서로 다른 도구 집합을 모델에게 준다 — 원장으로 대조된다.

**S8 · 등록(①) — 계약 슬롯과 드라이버**
커널이 슬롯을 정의하고 기능이 드라이버로 등록된다. 웹이 여기서 **층**을 얻는다
(정적 수집 → 읽기 추출 → 브라우저 승격). 파일 뿌리도 슬롯으로 열려 한 폴더 제한이 풀린다.
*닫힘*: 네이버 플레이스 **후기 본문을 실제로 읽고** 분석한다. 못 읽으면 못 읽었다고 말한다.
*가장 크다. 마지막이다.* S6 의 경계가 있어야 안전하게 붙는다.

## 7. 순서의 근거

- **S0 이 먼저다.** 계측 없이 고치면 오늘처럼 엉뚱한 것을 원인으로 확신한다.
- **S1→S3 은 빼기다.** 커널이 모델 자리에서 말하던 것을 걷어내는 일이라 위험이 낮고 효과가 즉시 화면에 난다.
- **S4→S5 는 자리 옮기기다.** 새 능력이 아니라 있던 것을 제자리로 보낸다.
- **S6 이 매듭이다.** 여기서 T5 자산을 한 곳에 건다. S7·S8 은 이 경계 위에서만 안전하다.
- **S8 이 마지막인 이유**: 가장 크고, 오너가 본 웹·파일 증상을 최종적으로 없애는 칸이며,
  경계(S6) 없이 붙이면 지금과 같은 인라인 누적이 반복된다.

## 8. 단계 공통 규율

1. 착수 전 **실패를 먼저 본다** — 고치기 전에 재현되는 검사를 세운다.
2. **라이브로 밟는다.** 실모델 실행 전 `scripts/human-use/prove-isolation.mjs` 를 통과한다. 예외 없다.
3. 단계 끝마다 `npm test` · `npm run gate` · `npm run audit:mutation` 초록.
4. **못 고친 것은 검사로 박지 않는다.** 장부(`design/T5-FOLLOWUP-LEDGER-ko.md`)에 적는다.
5. 각 단계는 **독립적으로 되돌릴 수 있어야** 한다. 한 흐름이되 한 덩어리가 아니다.
6. 닫힘 판정은 **사용자 문장**으로 한다. 계약 통과는 닫힘이 아니다.
