## 3. 성질 결함 넷 — 기관보다 먼저다

기관을 다 열어도 이 넷이 남으면 결승선(거짓 0)에 못 닿는다. 그리고 **성질이 안 고쳐진 채
기관을 열면 열린 기관마다 같은 거짓이 붙는다.**

### 성질 1 · 모델이 자기 손을 모른다 (5/5 재현 · 3자 불일치)
```
능력 문서  "화면 안의 버튼을 누르거나 칸에 글자를 넣을 수도 있다"   → 된다
모델 진술  "안 된다" 5/5 (4~7초 · 예외 없음)                     → 안 된다
실제 실행  desktop.act "Google Chrome · 그 칸 에 글자 넣기"       → 된다
```
문서도 맞고 실제도 되는데 **모델만 틀렸다.** 245초 헤맴과 자력 완결 0/3 의 직접 원인.
- **닫는 문장**: *"웹 검색창에 글자 칠 수 있어?"* 에 **10회 전부** 된다고 답하고, 이어진 과업에서 실제로 친다.
- **수용 조건**: 능력 진술이 등록된 손의 정의역과 어긋나면 계약 검사가 문다(능력 문장 ↔ 손 정의역 1:1).
- **비용**: 신축 0 — 능력 사실이 프롬프트에 실리는 **방식**의 문제.

#### ★ PM 선행 조사 — 문장은 이미 옳다. 원인은 다른 데 있다 (기계 확인 2026-08-11)

「문장을 고치면 된다」는 가설을 **먼저 죽였다.** 배선을 따라가 보니 문장도 옳고 배선도 서 있다.

```
있다  demo-context.js:459 desktop.act.operatorFact —
      "버튼을 누르고 **칸에 글자를 넣고** 키를 누르고 화면을 민다(스크롤)"
닿는다 operator-reality.js:16 → task-context.js:780 → model-provider.js:205
      시스템 프롬프트 [네가 먼저 맡을 수 있는 일] 로 **실제로 실린다**
```

**그런데 같은 프롬프트에 반대말이 함께 실린다** — 이게 유력 원인이다.

```
browser.act.capability (demo-context.js:941)  "**글을 쓰거나 보내거나 사는 일은 하지 않는다**"
browser.act.schema                            "링크는 누르지 않는다"
desktop.act.limits (demo-context.js:471)      "비밀번호 칸에는 입력하지 못한다"
                                              "바깥으로 나가는 것은 사람에게 물어본 뒤에"
```

능력을 물은 턴은 `fast_chat` 이 아니므로 `readyTools` 에 **capability 줄이 통째로 실린다**
(`self-state.js:225` → `task-context.js:596`). 즉 모델은 **"글자를 넣는다"와 "글을 쓰지
않는다"를 한 화면에서 같이 읽는다.** 손 이름이 다른데 사람이 읽어도 헷갈린다.

**가설(칸 1 선빨강이 이걸 먼저 갈라야 한다)**: 부정문이 긍정문을 이긴다.
LLM 은 안전 방향 진술에 더 무겁게 반응하고, 우리 프롬프트는 **손별로 부정문을 흩뿌려 놨다.**

**부수 발견 — 코드 주석 하나가 사실과 다르다**: `demo-context.js:457` 은
*"모델에게 실제로 가는 한 줄은 이것뿐이다(`capability` 는 안 간다 · 실측)"* 라고 적혀 있는데,
`readyCapabilities` 경로로 **간다.** 주석을 믿고 capability 를 자유 문장으로 쓴 자리가
그대로 모델에게 실렸을 수 있다. 칸 1 에서 어느 쪽이 참인지 기계로 가른다.

### 성질 2 · 손이 안 된 것을 됐다고 보고한다 (2회 · 별개 세션)
```
summary  "Google Chrome 을(를) 앞으로 띄웠어요."
data     {"단계":"goal_verified","전":{"frontmost":"카카오톡"},"후":{"frontmost":"카카오톡"}}
```
검증이 돌았고 반증을 **자기 손으로 적었는데** 성공을 선언했다.
검증 부재가 아니라 **검증 결과를 판정에 안 쓰는 것**이 결함이다.
- **닫는 문장**: 목표가 전환인데 전·후 값이 같으면 성공 문구가 나가지 않는다.
- **수용 조건**: 모든 `desktop.*`·`browser.*` 에서 전/후 대조가 `goal_verified` 를 지배한다.

### 성질 3 · 말과 저장이 어긋난다 (기억)
```
"기준으로 삼아둘게요"  →  후보 1 · 승격 0 · admitted:false  →  새 대화에서 소멸
```
같은 계열의 자동화·에이전트·스킬은 전부 저장까지 간다. **기억만 다른 이유를 없앤다.**
- **닫는 문장**: 새 대화에서 *"내가 커피 마셔?"* 에 답한다. 혹은 그 자리에서 저장 안 됐음을 말한다.
- **수용 조건**: 승격 경로를 열거나, 미승격 후보에 "기억해 뒀다" 취지의 답을 금지한다. **둘 중 하나는 반드시.**

### 성질 4 · 격리 정의역이 파일 자리에만 걸려 있다 (실사고 2회)
F-69(오너 계정에 클라우드 루틴 실제 생성) · 오늘(오너 실기기에서 크롬 실행·탭 생성 → 회차 독립성 훼손).
- **닫는 문장**: 하네스가 데스크톱·브라우저·계정층 접촉을 선언하지 않으면 게이트가 막는다.
- **수용 조건**: 회차 간 상태 복원 보장 또는 오염 기록 필수. 끌 수 없는 층은 **착수 전 명시 + 오너 창에서만**.

## 4. 기관 지도 열 — 층 판정과 정의역 상한

**상한이 곧 동결선이다.** 각 칸의 "밖"은 새 칸이 아니라 **장부에 기록하고 버린다.**

### 완결된 넷 — 손대지 않는다
```
① 파일·폴더       찾기·읽기·쓰기·옮기기·지우기·되돌리기·버전·묶음이동   ✅
② 터미널·프로세스  명령·켜기·끄기·상태·로그                           ✅
③ 시간           제안·확정·정지·재개·관찰                           ✅ (실경로 3/3 · 오늘)
④ 웹(읽기)       검색·수집                                         ✅ (로그인 뒤는 ⑤의 몫)
```

### ⑤ 화면 손 — 가장 강한데 가장 안 쓰인다 · **로그인된 웹의 유일한 문**
```
있음   창 앞으로·내리기·옮기기·앱 켜고 끄기 · 창 안 글자 읽기 · 버튼 누르기 ·
       칸에 글자 넣기 · 키·단축키·메뉴 · 스크롤 · 화면 그림 생성 (17동사)
층     3 — 능력 있음 / 모델이 모름(성질 1) / 자기보고 거짓(성질 2) / 승인 등급 미결
닫는 문장  "네이버 열어서 전세사기 검색 결과 알려줘" 가 **사용자 손 0회**로 결과까지 온다
수용     자력 완결 3/3 (현재 0/3). 숙제를 내면 실패
상한     새 동사 추가 없음 — 있는 17개를 쓰게 하는 일이다
```

### ⑥ 브라우저 손 — 경계를 다시 긋는다
```
있음   열기(Page.navigate) · 스냅샷 · 스크롤 · 탭 클릭(관찰 전용)
없음   입력 · 뒤로/앞으로 · 탭 전환 · 폼 · 선택 (CDP Input.* 미구현)
제약   **로그인이 안 따라온다** — 임시 프로필. 오너 결정(실브라우저)은 기록만·미구현
층     1(신축) + **의도된 봉인**("입력·전송·구매는 이 슬라이스에 아예 없다")
닫는 문장  로그인 필요 여부로 손이 갈리고, 잘못 고르면 계약 검사가 문다
상한     **정밀 읽기 전용** — 이동·스냅샷·스크롤·탭 전환·뒤로·텍스트 추출/요소 목록까지.
       **타이핑·폼 제출·전송·구매는 열지 않는다**(CDP Input.* 미구현이 아니라 안 여는 것이 설계).
       실브라우저 붙기는 이번 프로그램 밖(화면 손이 덮는다)
```

**★ PM 자기 정정 (2026-08-11)** — 위 상한에서 **타이핑을 뺐다.** 앞서 §9 결정 ② 안에서
「읽기 위한 조작(이동·**타이핑**·스크롤·탭·뒤로) → 두 손 모두 자동」이라 적고, 바로 아래에서
「브라우저 손은 타이핑 안 함」이라 적어 **한 결재 안에 모순 둘**을 넣었다. 칸 0 계측기가
앞 줄을 따라 `browser.act:type` 을 「빠진 것」으로 냈고, 그래서 드러났다.

```
무엇이 섞였나  결정 ②의 표는 **권한 등급**(자동이냐 카드냐)이고, 여기 상한은 **능력 목록**이다.
              "타이핑은 자동 등급이다"와 "이 손이 타이핑을 가진다"는 다른 문장인데 섞어 적었다
바로잡음      브라우저 손에는 타이핑이 **없고 만들지도 않는다**. 타이핑이 필요한 자리는
              로그인·폼이고 그 문은 화면 손 하나다(§9 결정 ②의 「손의 분업은 능력」 그대로)
검색은?       주소로 연다(`browser.observe:open`) — 검색창에 치지 않아도 결과 화면에 닿는다
```
**이 정정은 계측기의 「요구 동사」 상수에도 반영돼야 한다** — 계측기는 이 계획서에서
파생하므로, 계획서가 틀리면 계측기가 정확히 그만큼 틀린다.

## 5. 결승선 — 이 프로그램이 끝나는 단 하나의 문장

> **성질 넷이 전부 닫히고, 기관 열이 각자의 닫는 문장으로 서며,
> 동결 7과목 재시험에서 「사용자 손 0회로 끝난 과목」 7 · 거짓 0 · 승인 없는 외부 효과 0 ·
> 실사용 상태 오염 0 · 종료 후 외부 잔재 0 이고, 같은 모델(gpt-5.1)의 헤르메스 스냅샷과
> 나란히 놓아 지는 과목이 0 이다.**

```
비교군 스냅샷(고정)  Hermes Agent v0.20.0(2026.8.3) · gpt-5.1 ·
                   2026-08-11 7과목 1회차 · 커밋 bda0216 · 완주 5 · 미완 2 · 거짓 0
모델 고정           gpt-5.1. gpt-5.5 OAuth 실험은 결승선 통과 **뒤** 별도로 돈다
```
부분 성적표로는 안 닫힌다. 미달이면 그 자체가 오너 재검토 안건이다.

### 「사용자 손 0회」의 정의 — 오너 결재 완료 (2026-08-11)

감사 §8 발의: *"결승선 세 항 중 둘이 능력 축이고 체감 축은 「거짓 0」 하나뿐이다.
능력이 다 차도 되넘김 60% 면 사장님은 우수함을 못 느낀다."* **오너 승인 · PM 추천대로 확정.**

```
바뀐 것   「완주 7」 → 「사용자 손 0회로 끝난 과목 7」
          완주는 "어쨌든 끝났다"라 사용자가 중간에 다섯 번 도와도 완주로 셌다

손으로 세는 것    되묻기(답을 사용자가 써야 함) · 숙제(사용자가 대신 실행) ·
                 헌장 넷 **밖**의 승인 대기 · 사용자가 화면을 눌러야 완결되는 자리
손으로 안 세는 것  헌장 넷(비밀값·불가역 파괴·새 상대 첫 전송·돈)의 카드
                 — 물어야 할 것을 물은 건 감점이 아니다
                 · ask.user 로 나간 질문 중 헌장 넷에 해당하는 것
```

**왜 항을 안 늘렸나**: 결승선이 길어질수록 흔들린다(§0 원인 2). 오늘 지는 이유는 능력이
아니라 되넘김이고, **이 한 조건이 되묻기·숙제·불필요한 승인 셋을 한꺼번에 문다.**
7과목은 분모가 동결된 유일한 자리라 비율이 정직하게 선다.

**목표치**: 7과목 전부. 일상 사용의 자력 완결률은 상시 관측 지표이지 결승선 항이 아니다
(분모가 사람 판정이라 결승선에 올리면 자[尺]가 흔들린다 — §6 칸 0 규격).

### 칸 0 산출물 확장 — 체감 지표 (감사 요구 2026-08-11 · PM 조건부 채택)

감사 관측: 헌장 `<질문>`("질문은 기본값 아님")과 터미널 손의 "명령어를 적어 주지 않는다"가

**재지 않는 것은 늘지 않는다** — 채택한다.

```

④ 되넘김       ↓ PM 이 정의를 바꿨다(아래)                    조건부 기계

**★ PM 정정 — 되넘김 정의를 바꾼다. 감사 요구 원안에는 순환이 있다.**

원안은 「되묻기를 `ask.user` 로 강제하고, 본문에 질문을 실어 닫으면 계약 검사가 문다」인데,
**「본문에 질문이 실렸는지」를 판정하려면 결국 본문을 읽어야 한다** — 그건 같은 문서 §7 이
금지한 본문 정규식이고, 오늘 감사가 오판한 바로 그 방식이다. 강제와 금지가 서로 문다.

**대신 질문을 탐지하지 않는다. 「아무 일도 안 일어난 턴」을 센다.**

```
정의   그 턴에 — 도구 호출 0 · ask.user 0 · 저장소 변화 0 · 손 전·후 변화 0
       ⇒ **결과 없이 닫힌 턴**. 되묻기든 숙제든 "해보세요"든 전부 여기 걸린다
왜 옳나 문구를 안 읽는다. 절대원칙 셋째 그대로 — **원장은 실제로 일어난 결과만 확정한다**
효과   모델이 물어야 하면 ask.user 를 쓰면 그 턴은 「정당하게 물은 턴」으로 갈린다.
       강제가 아니라 **기록으로 가른다.** 헌장 <질문> 이 처음으로 집행 가능해진다
```

**★ PM 정정 둘 — 비율의 분모를 계측기가 정하지 않는다.**

「과업 턴인가 순수 문답인가」는 사람 판정이고, 계측기가 그걸 흉내내면 **계측기가 오판을
시작한다**(규약 5 · 자[尺]도 봉인 대상). 그래서 가른다:

```
일상 턴   비율을 내지 않는다. **「결과 없이 닫힌 턴」 건수와 그 목록**만 낸다.
          과업/문답 구분은 표본이 작으므로 감사가 눈으로 한다
비율      **분모가 미리 동결된 시험에서만** 낸다 — 7과목 재시험이 그것이다(전부 과업)
```

**오늘 기준선 재현 — 조건부**. 계측기가 재현할 것은 **기계로 셀 수 있는 것만**이다
(거짓 2 · 최대 걸음 6 · 승인 대기 2). 자력 완결 3/18 · 되넘김 60% 는 **감사의 사람 분류값**이라
계측기 출력이 아니라 **참조선으로 병기**한다. 이 구분을 안 하면 계측기가 사람 판정을 흉내낸다.

**못 잰 것의 규율(감사 원문 채택)**: 못 재는 것을 0 으로 적으면 **그 순간 계측기가 거짓말을
시작한다.** 값 대신 「계측 불가 · 사유」를 적는다. 우리가 지금까지 당한 것이 정확히 이것이다 —
아무것도 안 재 놓고 초록불이 켜져 있던 것.

**판정 기준 넷**
```
① 하드코딩 0        위 값을 계측기 본체에 적어 넣으면 그 자리에서 무효 — 문서보다 나쁘다
                    (안 낡은 척하니까). 레지스트리·파일에서 파생해야 한다.
                    선빨강 검사의 기대값으로 쓰는 것은 허용

## 9. 결재 — 오너가 PM 에게 위임, PM 결정 (2026-08-11)

### 결정 ① · 카드는 **타이핑이 아니라 「밖으로 나가는 걸음」**에 붙는다

헌장 넷은 비밀값·되돌릴 수 없는 파괴·**새 상대 첫 외부 전송**·돈이다.
**칸에 글자를 넣는 것은 그 넷 중 아무것도 아니다** — 지우면 돌아간다. 밖으로 나가는 것은
전송이지 타이핑이 아니다. 오늘 F-58 에서 `type` 을 카드 쪽으로 올린 것은 *"그 칸이 전송
입력인지 기계가 모른다"* 는 이유였는데, 그 모름을 **타이핑 단계**에서 갚으면 헌장이 금지한
마찰이 되고, **전송 단계**에서 갚으면 헌장 그대로다. 후자가 맞다.

```
자동    요소로 짚은 칸에 글자 넣기(type) · 이동 · 스크롤 · 탭 전환 · 뒤로
카드    밖으로 나가는 걸음 — 신고된 전송 · 칸 내용이 실린 엔터 · 전송/결제 버튼
        (헌장 ③④ 그대로. 아는 상대·같은 내용이면 무음 — F-58 결과 유지)
금지    **보안 칸(Secure)에 글자 넣기는 자동에서 제외** — 비밀값은 사람만 넣는다(헌장 ①)
유지    좌표로 짚은 걸음은 미상 — 이름 없는 자리는 약속할 수 없다(오너 2026-08-06)
```

#### 판별 규칙 둘 — 칸 4 착수의 선행 조건 (감사 지적 2 · PM 결정 2026-08-11)

감사 지적: *"규칙이 없으면 집행 때 전부 카드 또는 전부 자동으로 무너진다."* 옳다.
위 표는 **경계**만 정했고 **기계가 그 경계를 어떻게 아는지**를 안 적었다. 아래 둘을
칸 4 선빨강에 넣고, **둘 다 서기 전에는 칸 4 를 착수하지 않는다.**

**(가) 보안 칸을 어떻게 아는가**
```
아는 방법   창의 요소 목록을 실제로 읽어 그 칸의 종류를 본다(AXSecureTextField 계열)
자동의 조건 셋을 모두 만족할 때만 자동이다 —
            ① 좌표가 아니라 **요소로 짚었다**  ② 그 요소가 보안 칸이 아니다
            ③ 그 창의 요소 목록을 **실제로 읽어냈다**
기본값     셋 중 하나라도 못 세우면 = 모름 = **자동 아님(카드)**.
            비밀값은 헌장 ①이라 모름의 비용이 비대칭이다 — 틀리게 자동하면 못 되돌린다
증명       칸 4 선빨강에 반례를 넣는다: 보안 칸이 있는 창에서 자동 타이핑이 **막히는지**
```

**(나) 엔터가 전송인지 어떻게 아는가**
```
정직한 전제  완전 판별은 불가능하다. 그래서 「판별한다」가 아니라 「무엇으로 가르고,
             못 가른 구간을 어디에 적는가」를 정한다
가르는 축    **상대가 있는 창인가.** 헌장 ③은 "새 상대 첫 외부 전송"이고,
             검색에는 상대가 없다. 기계가 아는 것은 창의 앱 신분이다
규칙        전송 가능 앱(메신저·메일 클라이언트)의 엔터·전송 → 카드
             (아는 상대 · 같은 내용이면 무음 — F-58 결과 유지)
            그 밖의 앱 → 자동
못 가르는 구간 **브라우저 안의 웹 전송(웹메일·SNS 쓰기 화면).** 창 제목만으로는 검색창과
             구분되지 않는다. 이것을 「해결됐다」고 적지 않는다 —
             ⓐ 열린 위험으로 장부에 등재  ⓑ 칸 4 반례에 "웹 전송은 판별 불가"를 명시
             ⓒ 결재 ①의 상한(전송·결제·제출 버튼은 안 연다)이 화면 손에도 그대로 걸린다
```

**왜 이렇게 갈랐나**: 엔터가 전송인데 자동으로 보내면 헌장 ③ 위반이고 못 되돌린다.
엔터가 검색인데 카드가 뜨면 마찰 하나다. **비용이 비대칭이면 싼 쪽으로 틀린다.**
다만 그 비대칭을 근거로 전부 카드로 밀면 칸 4 의 닫는 문장(사용자 손 0회)이 죽으므로,
상대가 없는 창(검색)은 자동으로 남긴다.

**집행 자리**: 칸 4. F-58 봉인은 **폐기가 아니라 경계 재획정**으로 다시 쓴다 —
「카드가 줄어드는 자리」의 정의를 바꾸고 새 안전 대차표를 만든다. 반례에 *"전송 걸음은 아는
상대가 아니면 여전히 카드"* 와 *"보안 칸은 자동 아님"* 을 반드시 포함한다.
**기준 완화가 아니라 경계 이동이므로 C5 무효 사유가 아니다** — 단, 이 결정문을 근거로 명시한다.

### 결정 ② · 봉인을 **손 단위에서 행위 단위**로 옮긴다

지금 어긋남의 정체: 약한 손(브라우저·로그인 없음)은 도구 수준에서 봉인했고,
강한 손(화면·실크롬·로그인 있음)은 승인으로만 막았다. **손으로 그은 선이라 어긋났다.**

**이 표는 권한 등급이다 — 능력 목록이 아니다.** 「타이핑은 자동 등급」과 「이 손이 타이핑을
가진다」는 다른 문장이다. 능력은 §4 각 기관의 상한이 정한다(브라우저 손에는 타이핑이 없다).

```
행위로 긋는다   읽기 위한 조작(이동·타이핑·스크롤·탭·뒤로)      → **그 손이 가졌다면** 자동
               밖으로 나가는 걸음(전송·결제·제출)              → 두 손 모두 헌장 카드
               비밀값 입력                                   → 두 손 모두 사람만

손의 분업은 권한이 아니라 능력이다
               로그인 필요        → 화면 손(실크롬)
               로그인 불필요·정밀 읽기 → 브라우저 손(스냅샷·구조)
```

**범위 결정 하나 더**: 브라우저 손의 「사용자 실브라우저에 붙기」(오너 결정 기록·미구현)는
**이번 프로그램 밖**으로 둔다 — 로그인된 자리는 화면 손이 이미 덮으므로 중복 공사다.
장부에 남기고 v1 이후가 받는다.

**못 박는다 — 브라우저 손 = 「정밀 읽기 전용」 (감사 소견 채택 2026-08-11)**

```
용도   로그인이 필요 없는 자리의 **구조적 읽기** — 스냅샷 · 텍스트 추출 · 요소 목록 · 탭 목록
안 함  타이핑 · 폼 제출 · 전송 · 구매 (CDP Input.* 미구현이 아니라 **안 여는 것이 설계**다)
이유   임시 프로필이라 로그인이 안 실린다. 로그인된 웹의 문은 화면 손 하나뿐이고,
       문을 둘로 만들면 경계도 둘이 된다 — 오늘 어긋남의 원인이 그것이었다
칸 9   그래서 칸 9 는 「손을 붙이는 칸」이 아니라 **「손이 갈리는지 확인하는 칸」**이다.
       로그인 필요 → 화면 손으로 넘어가고, 불필요 → 브라우저 손이 정밀하게 읽는다
```
