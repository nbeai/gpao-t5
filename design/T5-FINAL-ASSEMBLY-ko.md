3판의 사유 (오너 2026-08-12):
```
① 완료 기준 교체    채점기·러너·문서가 아니라 **콘솔 라이브만** 완료다 (§3)

③ 목표 확정        오픈클로·헤르메스·클로드코드·코덱스와 **동급 이상.** 원장이 그

```

## 0-핵. ★ T5 는 넷이다 — 나머지는 수단이고, 수단은 훔쳐오면 된다 (오너 2026-08-12)

> *"티파이브는 이게 다야. 나머지는 그냥 수단과 도구고 — 그 수단과 도구는
> 남이 하는 방식 훔쳐오면 되는 거였고."*

```
1등  원장          답이 실제 기록과 맞는지 대조하고, 안 맞으면 답을 도로 거둬들인다.
                  비교군은 전부 「확인은 사용자가 하세요」 — 개발자면 되고 사장님이면 안 된다.
                  **비개발자용 AI 가 성립하는 유일한 조건.** 남들은 만들 이유가 없어서
                  안 만들었고, 그래서 따라오기도 어렵다
2등  네 가지만 묻는다  비밀번호 · 못 되돌리는 파괴 · 처음 보는 상대에게 보내기 · 돈.
                  넷 말고는 알아서 한다. 물을 것을 넷으로 줄였기에 나머지를 알아서
                  할 **자격**이 생겼다 — 그 자격의 담보가 1등(원장)이다. **둘이 한 쌍이다**
3등  현실을 차려주는 층  지금 어느 폴더가 대상인지 · 뭐가 열려 있는지 · 얼마나 잘렸는지를
                  정리해 모델 앞에 놓는다. "모델 앞의 환경"이 실제로 있다
4등  기억          어디서 나온 말인지 · 아직 유효한지 · 취소할 수 있는지가 붙어 있다.
                  사장님은 잘못된 기억을 눈으로 못 찾으니까 이게 필요하다
```

**완성된 T5 의 한 사이클** — 이 그림 그대로 돌면 완성이다:

```
사용자가 말한다
→ T5 가 현재 현실을 모델 앞에 놓는다                 (3등)
→ 모델이 길과 손을 고른다
→ 네 경계가 아니면 자동으로 실행한다                  (2등)
→ 결과가 원장에 기록된다
→ 모델의 답과 실제 결과를 대조한다
→ 불일치하면 답을 거두고 **다시 수행한다**             (1등)
→ 출처·유효성·철회 가능성이 붙은 기억으로 다음 대화를 잇는다 (4등)
```

**원장의 완료 조건은 "거짓말을 잡는다"에서 끝나지 않는다.** 거짓 완료를 막기만 하고 올바른
결과를 생산하지 못하면 정직한 미완성일 뿐이다. **T5 의 목표는 거짓말하지 않는 AI 가 아니라,
정직하게 끝까지 해내는 AI 다.**

```
실제 목적을 달성했는가
→ 어떤 증거가 그 목적을 받치는가
→ 모델의 완료 주장이 그 증거와 일치하는가
→ 불일치하면 **어떤 다음 손으로 이어갈 것인가**
```

## 0-B. ★ 컴퓨터유즈의 결승선 — **동작 열 개**. 카톡·크롬이 아니다

> 오너 2026-08-11: *"카톡, 크롬 신기하게 움직이는 거 구경하려고 이거 시켰냐.
> **컴퓨터유즈의 원활한 작동을 위해서 이걸 하나의 종합 사례로 말한 것**이다."*

**결승선은 이 열 개가 아무 앱에서나 도는 것이다.**

```
①  앱을 찾는다        이름으로. 안 떠 있으면 켠다
②  연다
③  그 안에서 대상을 찾는다   목록의 특정 항목 · 탭 · 방 · 파일
④  띄운다 / 이동한다
⑤  읽는다            화면에 보이는 글자
⑥  스크롤한다         화면 밖의 것을 본다
⑦  입력한다           칸에 글자
⑧  확정한다           엔터 · 버튼
⑨  결과를 읽는다       내가 한 것이 어떻게 됐나
⑩  그걸로 일한다       요약 · 판단 · 다음 걸음
```

**표본 두 줄** — 이것을 **재는 자**로만 쓴다. 목표가 아니다.

```
카톡   열고 → 대화목록에서 「사일런트서비스」 방 찾고 → 띄우고 → 스크롤해서 읽고
       → 입력하고 → 엔터                                    (① ② ③ ④ ⑤ ⑥ ⑦ ⑧)
크롬   열고 → 탭 추가 → 네이버 이동 → 검색어 입력 → 결과 보고 → 요약
                                                          (① ② ④ ⑦ ⑧ ⑨ ⑩)
```

**★ 카톡·크롬만 파면 그 두 앱 전용 도구가 된다.** 그러니 **셋째 앱(메모·파인더·넘버스
등)으로도 같은 열 개를 재라.** 두 사슬만 초록이면 아직 아무것도 아니다.
**한 칸을 결승선으로 올리지 마라** — 「연다」 하나 재고 초록 보고한 사고(2026-08-11)가 있다.

프롬프트는 그 리터럴만 가리킨다(`agent/prompt_builder.py:572-596`) —
*"do not conclude 'cua-driver can't drive this app' — **climb the ladder**"* ·

**포기의 결론을 금지하되 행동은 지정하지 않는다.** 트리거는 모델의 감이 아니라 손이 낸 값이다.

그 밖: *"retry with a different query **or strategy** before giving up"*(`:413`) ·
*"Ask a clarifying question **only when** the information cannot be retrieved by tools"*(`:463`) ·
빈 성공을 **실패로 재분류**해서 실패 배관을 타게 한다(`tools/browser_tool.py:2682`) ·
Lightpanda 빈 스냅샷(20자 미만)이면 **Chrome 으로 조용히 재시도**(`:1010-1057` — 모델 아래에서).

**되돌린 기록**: `verify_on_stop`(답 가로채고 검증 요구)을 배포했다가 두 마이그레이션에 걸쳐
껐다(`hermes_cli/config_migrations.py:540`·`:574`). 문서 편집에도 터졌다.

#### 오픈클로 — **무주어 「상황 : 처방」** 문형, 그리고 축만 준다

```
Execution Bias (dist/system-prompt-config-CSXINJ_0.js:314-327) — 7줄, 이 문제에 1줄
  "Weak/empty tool result: vary query, path, command, or source before concluding."
  "Continue until done or genuinely blocked; do not finish with a plan/promise
   when tools can move it forward."

GPT-5 오버레이 (dist/gpt5-prompt-overlay-CWFmv6lQ.js:60-70)
  "If a lookup is **empty, partial, or suspiciously narrow**, retry with a
   different strategy before concluding."
  ← 「에러는 아닌데 얇다」를 빈 결과와 **같은 등급**으로 묶은 유일한 언어화

completion_contract (:78-83)
  "Treat the task as incomplete until every requested item is handled or

  ← 포기를 금지하지 않고 **서식을 요구한다**. 이 코드베이스에서 본 가장 영리한 수
```

**루프 가드를 「횟수」가 아니라 「무변화」에 건다**(`dist/tool-loop-detection-C0f6cDzo.js:229-243`):
streak 은 `toolName + argsHash + resultHash` **셋이 다 같을 때만** 쌓인다. 그래서
*"질의·경로·명령·출처를 바꿔라"* 를 따르면 **카운터가 저절로 초기화된다** — 유도 프롬프트와
강제 가드가 서로를 안 갉아먹는다. 횟수 상한으로 짰으면 정면충돌한다.
덤: `hashToolOutcome`(`:166-207`)이 PID·duration·messageId 같은 휘발성 칸을 해시에서 뺀다 —
안 그러면 「달라졌다」가 의미를 잃고 가드가 영영 안 터진다.

#### 클로드코드(나 자신) — **빈 결과는 봉투가 다르다**

직접 돌려 본 실측:
```
빈 파일     <system-reminder>Warning: the file exists but the contents are empty.</system-reminder>
출력 없음    (Bash completed with no output)
```
**명령 0개 · 사실만 · 그런데 정상 결과와 다른 자리로 온다.** "파일은 있다"와 "내용이 없다"를
나눠 말한다. T5 는 같은 사실을 결과 문자열 **한 줄로** 넣는다(`task-context.js:196`) —
링크·본문과 나란히 묻힌다. **명령을 더할 게 아니라 봉투를 나누는 것**이 유도의 모양이다.

**훔칠 것 다섯**(전부 유도): ① 판정을 데이터로 항상 싣기 ② `empty, partial, suspiciously
narrow` 를 한 등급으로 ③ 포기에 서식 요구 ④ 질문에 예산 ⑤ 루프 가드를 무변화에 걸어 축 정렬.
**훔치지 말 것**: 발동 조건이 부정확한 강제. 반드시 되돌아온다.

## 1. 완성의 정의 — 문장 열둘 + 두 층 결승선

### 1-0. ★ **완성의 단위는 「손」이다** (오너 정의 2026-08-13)

> *"내가 말하는 손은 기능이 아니라 **기능과 성능의 조합**이야. 더하기가 아니라 **곱하기**이고
> **함수**이지. … 터미널 손은 터미널을 만지는 기능과 **터미널을 만져서 할 수 있는 일들의
> 성능과 수준**을 가리키는 거다. **특정 영역의 일만 잘 할 수 있다면 그건 손이 아니라
> 로봇팔인거다.** AI의 절대 목표는 **사용자의 요구를 실현시키는 것**이다."*

```
손 = 기능 × 성능
     ↑          ↑
  그 영역에서   그 작동의 수준을
  모든 작동을   T5 가 높여준다
```

**그래서 도구 수를 세지 않는다.** `web.search`·`web.collect`·`browser.observe`·`desktop.screen`
은 각각 손이 아니다 — **웹 손이라는 하나의 함수가 쓰는 눈과 관절**이다. 터미널·MCP·CUA·스킬도
같다. 이것들은 목적 함수가 부르는 수단이지 완성 개수의 단위가 아니다.

**각 영역의 손은 이 한 함수로 닫힌다:**

```
사용자 목적 → 현재 현실 관측 → 가장 적절한 수단 선택 → 권한 판정 → 실행
→ 사후 상태 관측 → 목적과 결과 대조 → 미달이면 다른 수단으로 전환
→ 원장이 목적 달성을 확인 → 답
```

사용자는 이 전환을 **알 필요가 없어야 한다.**

#### 검증 단위가 다섯이다 — 앞의 셋이 초록이어도 넷째가 빨강이면 손은 빨강

```
배선 검사   도구가 호출됐다
원장 검사   영수증이 생겼다
관절 검사   동작이 실행됐다
손  검사   **사용자 목적이 정확한 결과로 끝났다**       ← 완성의 기준
성능 검사   비교군보다 품질·시간·사용자 개입이 낫다        ← 우위의 기준
```

**밟은 증거**(2026-08-12 오너 라이브 · 세션 `6a412df3`): *"청담 팔식당 네이버 플레이스 리뷰
분석해줘"* 에 `web.collect` 5회 + `browser.observe` 3회가 **전부 `failureState: none`**.
`desktop.screen` 0회. **코드 기준 여덟 번 성공, 사용자 기준 0번 성공.** 영수증은 *"관절이
움직였다"* 를 증명했고 *"손이 원하는 것을 집었다"* 는 증명하지 못했다.

오너 진단: *"손이 손답게 안 움직이고 **로봇팔**처럼 움직이는거지."*

#### 성능을 올리는 법 — **강제가 아니라 유도** (오너 2026-08-13)

> *"강제가 아니라 유도야. 모델 다루는 법을 절대 잊지마. **엘엘엠을 깡통으로 만드는건
> 한순간**이니까."*

수리를 적기 전 리트머스: *"이걸 넣으면 모델이 **더 잘 판단하게** 되나, **판단을 안 하게**
되나?"* 후자면 강제다. 커널이 대신 고른 만큼 모델은 그만큼 멍청해진다.

**선행자가 값을 치른 기록**(오픈북 2026-08-13): 헤르메스는 「검증 안 됐으면 답을 가로채기」를
배포했다가 **두 마이그레이션에 걸쳐 껐다** — 검증할 것이 없는 문서 편집에도 터졌기 때문이다
(`hermes_cli/config_migrations.py:540`). **발동 조건이 부정확한 강제는 반드시 되돌려진다.**
오픈클로도 진짜 강제(`MUST`)는 **되돌릴 수 없는 것**(메시지 발송)에만 쓴다.

**어법 넷** — 전부 도구 이름을 안 지정한다:

```
상황 라벨 : 처방      "얇거나 빈 결과: 결론 내리기 전에 질의·경로·명령·출처를 바꿔 본다"
                     ← 무주어. 도구가 아니라 **바꿀 수 있는 축**을 준다
포기에 서식 요구      "[막힘] + 무엇이 없어서" 를 채우게 한다 — 금지가 아니라 **비용 부과**.
                     막연한 포기는 서식을 못 채워 자연 도태되고 진짜 막힘은 통과한다
질문에 예산           "도구로 알아낼 수 없는 결정 하나가 막으면 **간결한 질문 하나**"
                     ← 금지 대신 조건과 개수
순서만 정한다         "…before concluding" — 결론을 막지 않고 **앞에 한 칸을 끼워 넣는다**
```

**경계선** — 무엇을 코드가 밟고 무엇을 모델이 정하나:

> **결과가 같고 방법만 다르면 코드가 밟아도 된다. 결과가 달라지면 모델이 정해야 한다.**

HTML 추출기 교체(Readability→기본 정리)는 어느 쪽이든 **같은 결과**라 코드가 밟는다.
「웹으로 읽을까 화면으로 볼까」는 **결과가 달라지므로** 모델 자리다. CUA 드라이버 교대도
전자다 — 같은 화면을 다른 통로로 볼 뿐이다.

#### 지금 손 판정 (2026-08-13 조사 · 근거는 지도 §12·§14)

```
목적을 끝내는 손      local.file · local.locate        (제한된 범위 안에서)
사거리는 넓고 성능 미완  터미널 · Desktop/CUA
눈은 섰고 손이 안 이어짐  웹·브라우저
로봇팔               브라우저 동작 · 캡슐 · 자동화 · 제한 위임
```

**T5 는 부품이 없는 제품이 아니라 강한 기관과 많은 관절을 가진 미조립 몸이다.**
완성의 핵심은 도구를 더 붙이는 것이 아니라, 이미 있는 것들이 **어떤 목적에서도 서로 교대하며
사후확인과 원장까지 한 호흡으로** 움직이게 만드는 것이다.

### 5-1. 원장을 제품 전체의 종결자로 만든다 — **가장 먼저. 나머지 자동화의 자격이 여기서 나온다**

모든 효과성 손(파일·화면·브라우저·프로세스·자동화·채널·커넥터·에이전트)이 **같은 완료
고리**를 지난다. 손마다 공통으로 내야 하는 것:

```
의도한 결과 · 실제로 호출한 손과 인자 · 실제 실행 결과 · 사후 상태 ·
사용자 목적과 결합된 완료 증거 · 확인되지 않은 범위 · 복구 또는 다음 손
```

**반드시 닫는 반대시험 일곱** — 하나라도 통과 못 하면 원장은 아직 기능이지 원리가 아니다:

```
①  파일 이름만 .xlsx 이고 내용이 잘못이면 → 실패
②  창 전환 요청인데 앞창이 그대로면 → 성공 금지
③  자동화 후보만 생기고 실제 job 이 없으면 → 등록 성공 금지
④  전송 호출이 실패했으면 → 보냈다고 말하지 않음
⑤  도구 호출 일부가 큐에서 사라지면 → 완료 금지 (F-68)
⑥  실제 결과가 있는데 모델이 실패라고 말하면 → **거짓 실패도 회수**
⑦  답을 회수한 뒤 → 실제 다음 실행으로 이어짐 (회수가 끝이 아니다)
```

장부의 해당 결함: F-64(목적 결과↔완료 상태 갈림) · F-66(사용자 확정·자료 관측·모델 제안의
신분 섞임) · F-68(큐 잔여 호출 무흔적 소실) · F-47(답이 기계 사실에서 안 나옴).

### 5-2. 네 경계를 모든 행동의 단일 권한 계약으로 만든다

도구별 승인 목록을 버리고 **실행 순간의 실제 효과**를 분류한다. 화면·브라우저·채널·자동화
전체가 **같은 분류 함수**(`l2-plan/authority.js`)를 소비한다 — 타이핑만 예외 처리하면 또
앱별 패치다.

```
비밀번호 입력          보호된 입력면
복구 불가능한 파괴      승인
새 상대 첫 외부 전송    승인
돈이 나가는 행동        승인
그 밖                 **전부 자동**
```

결재 ① 의 실제 분류 (타이핑 한 덩어리가 아니다):

```
검색창·일반 칸 타이핑            자동 (초안 — 세상에 아직 영향 0)
엔터 = 단순 확정(검색·이동)      자동
엔터 = 외부 전송, 새 상대        승인 (헌장 ③)
엔터 = 외부 전송, 아는 상대      자동
구매·결제 버튼                  승인 (헌장 ④)
비밀 칸                        보호된 입력면 (헌장 ①)
입력 뒤                        실제 효과를 재관찰 (쿠아 SKILL.md:339 축)
```

자동 실행 뒤에는 **원장 기록 · 사후 확인 · 가역 작업의 되돌리기**가 붙는다 — 이것이 원장과
네 경계를 한 쌍으로 만드는 실제 배선이다.

### 5-3. 모델 입력과 사용자 출력을 분리한다

지금 T5 는 사용자에게 친절하게 만든 문장을 모델에게도 먹인다. 이 절단을 없앤다.

```
모델에게 주는 것 (날것)
  구조화된 원시 결과 · 실제 호출 인자 · 실패 원문과 상태 ·
  잘린 전체 크기와 다음 위치 · 후보와 신뢰 근거 ·
  확인됨/확인 안 됨 구분 · 지금 사용할 수 있는 다른 손
사용자에게 주는 것
  원장에서 만든 자연스러운 설명 (출력 층에서만 친절)
```

자리: `task-context.js:880`(사용자용 문장을 모델에 먹임) · `:887`(1,200자 산문 접기) ·
`:891`(실패 시 진단 통째 누락). 흡수: 헤르메스 실패 원문 2,000자 · 큰 결과는 파일로 흘리고
미리보기+경로. 유지하는 계약: 실패 내용을 사실로 승격하지 않는다 — 「확인 안 됨」 표식을
달아 **주기는 준다**. 동시에 F-73(프롬프트 접두 흔들림 → 캐시 깨짐)을 닫는다 —
기능이 같아도 원가·지연이 비교군보다 나쁘면 동급이 아니다.

### 5-4. 결과가 다음 손을 고르게 한다

병합된 손 갈아타기 루프(turn.js P6-L·5a5a08a)를 **전체 손**으로 확장한다:

```
파일을 못 찾으면        검색 범위를 바꿈
웹 수집이 막히면        브라우저로 전환
브라우저 정밀이 막히면   화면 손으로 전환
화면 접근성이 비면      이미지 관찰로 전환
결과가 잘렸으면         다음 페이지
같은 호출 반복이면      무진전 감지 (있음 · turn-budget.js)
A→B→A→B 이면          ping-pong 감지 (오픈클로 detectors.pingPong 축 흡수)
사용자가 방향을 바꾸면   현재 목표를 갱신 (오픈클로 steer 축)
```

종료 조건은 "도구를 몇 번 썼나"가 아니라 셋이다:

```
① 목적 달성   ② 네 경계에서 사람 입력 대기   ③ 가능한 수단을 실제로 소진했고
                                           그 사실이 원장에 있음
```

### 5-5. 기억을 새 대화까지 완결한다

`kind==='preference'` 를 무작정 제거하지 않고 기존 기억 계약에 연결한다.

```
승격 자격    사용자 원문에서 나옴 · 지속 의도 · 현재 요청에 실제 관련 · 민감정보 아님 ·
            일회성 예외 아님 · replay 통과 · 표면 즉시 가시 + 한 번에 철회
검증할 것    저장됐다가 아니라 —
            새 대화에 적용 · 서버 재시작 뒤 적용 · "이번만"은 다음 대화에 안 남음 ·
            새 지시가 과거 기억을 이김 · 철회한 기억이 다시 안 개입 ·
            모델 제안이 사용자 확정으로 승격 안 됨
```

잘못 올리면 T5 의 장점(4등)이 바로 결함으로 바뀐다 — 자격 일곱이 그 문이다.

### 9-1. ★ HOME 격리 — **판마다 갈린다. 여기가 한 자리다** (2026-08-14 통합)

이 자리에서 **되돌릴 수 없는 사고가 두 번** 났다(개인 문서 이름이 모델 공급자로 나감 ·
파일 443개 이동). 그런데 규율이 두 문서에 **반대로** 적혀 있었다. 둘 다 밟은 사실이고
어느 쪽도 틀리지 않았다 — **재는 대상이 다르다**:

```
화면(desktop.*) 을 재는 판   HOME 을 바꾸면 화면 드라이버가 죽어 `blocked` 가 난다.
                           그건 제품 실패가 아니라 하네스가 만든 거짓 실패다 —
                           상태 자리·파일 뿌리(GPAO_T5_HOME)만 격리한다
터미널·파일을 재는 판        GPAO_T5_HOME 만 바꾸면 터미널 손의 `~` 가 오너의 진짜 홈으로
                           풀린다. **그게 두 사고의 공통 원인이었다** —
                           HOME 자체를 격리 루트로 바꾼다
```

**판마다 정하고, 정한 이유를 회차 기록에 남긴다.** 그리고 무엇을 하든:

```bash
node scripts/human-use/prove-isolation.mjs    # 통과해야 실모델을 돌린다
```

**증명을 먼저 부르고 그 뒤에 HOME 을 바꾼다** — 먼저 바꾸면 증명의 기준 자체가 무너진다.
터미널 손을 안 쓰는 판(자동화 라이브 등)은 `GPAO_T5_HOME` 만 바꿔도 됐다. 터미널이 끼는
판에서 같은 방식을 쓰면 **사고가 재현된다.**

## 11. 일하는 방식

```
· 문서로 상태를 단정하지 않는다. **라이브로 정한다** (§3)
· 고치면 그 자리에서 라이브를 돌린다. 좋아졌는지 말로 하지 않는다
· 새 계획서를 만들지 않는다. 이 문서에 줄을 고친다
· 안 잰 것을 「완료」로 넘기지 않는다. 못 잰 것은 「계측 불가 · 사유」로 적는다
· 막히면 책을 연다(§0-A). 그래도 막히면 오너에게 올린다. 조용히 넘어가지 않는다
· "증명 안 됐네 · 어렵네"로 멈추지 않는다. 기준을 적고 밟는다. **해낸다**
```
