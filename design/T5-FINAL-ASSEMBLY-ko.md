## 0-핵. ★ T5 는 넷이다 — 나머지는 수단이고, 수단은 훔쳐오면 된다 (오너 2026-08-12)

> *"티파이브는 이게 다야. 나머지는 그냥 수단과 도구고 — 그 수단과 도구는
> 남이 하는 방식 훔쳐오면 되는 거였고."*

```
1등  원장          답이 실제 기록과 맞는지 대조하고, 안 맞으면 답을 도로 거둬들인다.
                  비교군은 전부 「확인은 사용자가 하세요」 — 개발자면 되고 사장님이면 안 된다.
                  **비개발자용 AI 가 성립하는 유일한 조건.** 남들은 만들 이유가 없어서
                  안 만들었고, 그래서 따라오기도 어렵다
2등  네 가지만 묻는다  비밀번호 · 못 되돌리는 파괴 · 처음 보는 상대에게 보내기 · 돈.
                  넷 말고는 알아서 한다. 물을 것을 넷으로 줄였기에 나머지를 알아서
                  할 **자격**이 생겼다 — 그 자격의 담보가 1등(원장)이다. **둘이 한 쌍이다**
3등  현실을 차려주는 층  지금 어느 폴더가 대상인지 · 뭐가 열려 있는지 · 얼마나 잘렸는지를
                  정리해 모델 앞에 놓는다. "모델 앞의 환경"이 실제로 있다
4등  기억          어디서 나온 말인지 · 아직 유효한지 · 취소할 수 있는지가 붙어 있다.
                  사장님은 잘못된 기억을 눈으로 못 찾으니까 이게 필요하다
```

**완성된 T5 의 한 사이클** — 이 그림 그대로 돌면 완성이다:

```
사용자가 말한다
→ T5 가 현재 현실을 모델 앞에 놓는다                 (3등)
→ 모델이 길과 손을 고른다
→ 네 경계가 아니면 자동으로 실행한다                  (2등)
→ 결과가 원장에 기록된다
→ 모델의 답과 실제 결과를 대조한다
→ 불일치하면 답을 거두고 **다시 수행한다**             (1등)
→ 출처·유효성·철회 가능성이 붙은 기억으로 다음 대화를 잇는다 (4등)
```

**원장의 완료 조건은 "거짓말을 잡는다"에서 끝나지 않는다.** 거짓 완료를 막기만 하고 올바른
결과를 생산하지 못하면 정직한 미완성일 뿐이다. **T5 의 목표는 거짓말하지 않는 AI 가 아니라,
정직하게 끝까지 해내는 AI 다.**

```
실제 목적을 달성했는가
→ 어떤 증거가 그 목적을 받치는가
→ 모델의 완료 주장이 그 증거와 일치하는가
→ 불일치하면 **어떤 다음 손으로 이어갈 것인가**
```

## 0-B. ★ 컴퓨터유즈의 결승선 — **동작 열 개**. 카톡·크롬이 아니다

> 오너 2026-08-11: *"카톡, 크롬 신기하게 움직이는 거 구경하려고 이거 시켰냐.
> **컴퓨터유즈의 원활한 작동을 위해서 이걸 하나의 종합 사례로 말한 것**이다."*

**결승선은 이 열 개가 아무 앱에서나 도는 것이다.**

```
①  앱을 찾는다        이름으로. 안 떠 있으면 켠다
②  연다
③  그 안에서 대상을 찾는다   목록의 특정 항목 · 탭 · 방 · 파일
④  띄운다 / 이동한다
⑤  읽는다            화면에 보이는 글자
⑥  스크롤한다         화면 밖의 것을 본다
⑦  입력한다           칸에 글자
⑧  확정한다           엔터 · 버튼
⑨  결과를 읽는다       내가 한 것이 어떻게 됐나
⑩  그걸로 일한다       요약 · 판단 · 다음 걸음
```

**표본 두 줄** — 이것을 **재는 자**로만 쓴다. 목표가 아니다.

```
카톡   열고 → 대화목록에서 「사일런트서비스」 방 찾고 → 띄우고 → 스크롤해서 읽고
       → 입력하고 → 엔터                                    (① ② ③ ④ ⑤ ⑥ ⑦ ⑧)
크롬   열고 → 탭 추가 → 네이버 이동 → 검색어 입력 → 결과 보고 → 요약
                                                          (① ② ④ ⑦ ⑧ ⑨ ⑩)
```

**★ 카톡·크롬만 파면 그 두 앱 전용 도구가 된다.** 그러니 **셋째 앱(메모·파인더·넘버스
등)으로도 같은 열 개를 재라.** 두 사슬만 초록이면 아직 아무것도 아니다.
**한 칸을 결승선으로 올리지 마라** — 「연다」 하나 재고 초록 보고한 사고(2026-08-11)가 있다.

| # | 사용자 문장 | 통과 조건 | 층 |

**뚫어도 안 되는 것은 셋뿐이다**: npm 의존성 0 · 헌장 넷 · 안전 바닥.
그리고 **판정 자를 고쳐 초록을 만드는 것** — 그건 완성이 아니라 조작이다(C5).

### 5-1. 원장을 제품 전체의 종결자로 만든다 — **가장 먼저. 나머지 자동화의 자격이 여기서 나온다**

모든 효과성 손(파일·화면·브라우저·프로세스·자동화·채널·커넥터·에이전트)이 **같은 완료
고리**를 지난다. 손마다 공통으로 내야 하는 것:

```
의도한 결과 · 실제로 호출한 손과 인자 · 실제 실행 결과 · 사후 상태 ·
사용자 목적과 결합된 완료 증거 · 확인되지 않은 범위 · 복구 또는 다음 손
```

**반드시 닫는 반대시험 일곱** — 하나라도 통과 못 하면 원장은 아직 기능이지 원리가 아니다:

```
①  파일 이름만 .xlsx 이고 내용이 잘못이면 → 실패
②  창 전환 요청인데 앞창이 그대로면 → 성공 금지
③  자동화 후보만 생기고 실제 job 이 없으면 → 등록 성공 금지
④  전송 호출이 실패했으면 → 보냈다고 말하지 않음
⑤  도구 호출 일부가 큐에서 사라지면 → 완료 금지 (F-68)
⑥  실제 결과가 있는데 모델이 실패라고 말하면 → **거짓 실패도 회수**
⑦  답을 회수한 뒤 → 실제 다음 실행으로 이어짐 (회수가 끝이 아니다)
```

장부의 해당 결함: F-64(목적 결과↔완료 상태 갈림) · F-66(사용자 확정·자료 관측·모델 제안의
신분 섞임) · F-68(큐 잔여 호출 무흔적 소실) · F-47(답이 기계 사실에서 안 나옴).

### 5-2. 네 경계를 모든 행동의 단일 권한 계약으로 만든다

도구별 승인 목록을 버리고 **실행 순간의 실제 효과**를 분류한다. 화면·브라우저·채널·자동화
전체가 **같은 분류 함수**(`l2-plan/authority.js`)를 소비한다 — 타이핑만 예외 처리하면 또
앱별 패치다.

```
비밀번호 입력          보호된 입력면
복구 불가능한 파괴      승인
새 상대 첫 외부 전송    승인
돈이 나가는 행동        승인
그 밖                 **전부 자동**
```

결재 ① 의 실제 분류 (타이핑 한 덩어리가 아니다):

```
검색창·일반 칸 타이핑            자동 (초안 — 세상에 아직 영향 0)
엔터 = 단순 확정(검색·이동)      자동
엔터 = 외부 전송, 새 상대        승인 (헌장 ③)
엔터 = 외부 전송, 아는 상대      자동
구매·결제 버튼                  승인 (헌장 ④)
비밀 칸                        보호된 입력면 (헌장 ①)
```

자동 실행 뒤에는 **원장 기록 · 사후 확인 · 가역 작업의 되돌리기**가 붙는다 — 이것이 원장과
네 경계를 한 쌍으로 만드는 실제 배선이다.

기능이 같아도 원가·지연이 비교군보다 나쁘면 동급이 아니다.

### 5-4. 결과가 다음 손을 고르게 한다

병합된 손 갈아타기 루프(turn.js P6-L·5a5a08a)를 **전체 손**으로 확장한다:

```
파일을 못 찾으면        검색 범위를 바꿈
웹 수집이 막히면        브라우저로 전환
브라우저 정밀이 막히면   화면 손으로 전환
화면 접근성이 비면      이미지 관찰로 전환
결과가 잘렸으면         다음 페이지
같은 호출 반복이면      무진전 감지 (있음 · turn-budget.js)
A→B→A→B 이면          ping-pong 감지 (오픈클로 detectors.pingPong 축 흡수)
사용자가 방향을 바꾸면   현재 목표를 갱신 (오픈클로 steer 축)
```

종료 조건은 "도구를 몇 번 썼나"가 아니라 셋이다:

```
① 목적 달성   ② 네 경계에서 사람 입력 대기   ③ 가능한 수단을 실제로 소진했고
                                           그 사실이 원장에 있음
```

### 5-5. 기억을 새 대화까지 완결한다

`kind==='preference'` 를 무작정 제거하지 않고 기존 기억 계약에 연결한다.

```
승격 자격    사용자 원문에서 나옴 · 지속 의도 · 현재 요청에 실제 관련 · 민감정보 아님 ·
            일회성 예외 아님 · replay 통과 · 표면 즉시 가시 + 한 번에 철회
검증할 것    저장됐다가 아니라 —
            새 대화에 적용 · 서버 재시작 뒤 적용 · "이번만"은 다음 대화에 안 남음 ·
            새 지시가 과거 기억을 이김 · 철회한 기억이 다시 안 개입 ·
            모델 제안이 사용자 확정으로 승격 안 됨
```

잘못 올리면 T5 의 장점(4등)이 바로 결함으로 바뀐다 — 자격 일곱이 그 문이다.

### 5-6. 채널 보관함 — 유일하게 새로 만드는 것

배열 하나가 아니다. 최소 요건:

```
수신 신분과 대화 귀속 · 중복 제거 · 읽은 위치와 다음 위치 · 재시작 뒤 복원 ·
민감정보 경계 · "왔다"와 "사용자에게 전달됐다"의 분리 ·
조회 뒤 원래 대화로 돌아가는 왕복 (문장 7)
```

## 7. 배끼면 안 되는 것 — 하나뿐

**비개발자용 안전 경계.** 비교군의 승인 모델은 **diff 를 읽을 줄 아는 사람** 전제다.
사장님은 못 읽는다. 여기를 배끼면 정직한 무능이 아니라 조용한 사고가 된다.

```
묻는 것 넷(헌장)   비밀값 입력 · 되돌릴 수 없는 파괴 · 새 상대 첫 외부 전송 · 돈
그 밖             전부 자동. **코드와 헌장이 어긋나면 코드가 결함이다**
원장              실제로 일어난 결과만 확정한다. 말이 아니라 값으로
승인 등급(결정)    저장·활성은 안 묻는다(정의는 세상에 영향 0). **행동에서 묻는다**
                 단 넷을 함께: 출처가 오너 대화일 것 · replay 통과 · 즉시 가시성 · 되돌리기 한 번
```

## 11. 일하는 방식

```
· 문서로 상태를 단정하지 않는다. **라이브로 정한다** (§3)
· 고치면 그 자리에서 라이브를 돌린다. 좋아졌는지 말로 하지 않는다
· 새 계획서를 만들지 않는다. 이 문서에 줄을 고친다
· 안 잰 것을 「완료」로 넘기지 않는다. 못 잰 것은 「계측 불가 · 사유」로 적는다
· 막히면 책을 연다(§0-A). 그래도 막히면 오너에게 올린다. 조용히 넘어가지 않는다
· "증명 안 됐네 · 어렵네"로 멈추지 않는다. 기준을 적고 밟는다. **해낸다**
```

**하루를 태우는 셋**: 새 계획서 만들기 · 문서로 상태 단정하기 · 안 돌려보고 원인 적기.
