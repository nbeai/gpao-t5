# P5-B-1B Google OAuth 커넥터 — 설계 (구현 전)

작성: 2026-07-27 · 상위: `design/P5-B-1-AUTHENTICATED-SURFACE-ACCESS-2026-07-27-ko.md`(본선 결정)
감사 기준: `GPAO-T5-MODEL-OS-OPERATING-LOOP-2026-07-27-ko.md`
**지위: 설계다. 구현은 오너 승인 후 별도 슬라이스로 한다.**

## 목표 (사용자 말로)

> "구글 연결하고 싶어" → 동의 화면에서 허용 → **그 순간부터 T5 의 능력이 된다.**
> "드라이브에서 6월 정산 찾아줘"가 실제로 된다.

이 커넥터가 닫는 것: §15 #7(외부 도구 연결)의 첫 실물 · `mail.send` 유령의 실제 손(후속 범위) ·
"내 자료 기준"(#8)의 원천 자료 접근.

## 사용자 흐름 (7단계 — 오너 프로세스 그대로)

```
1. "구글 연결하고 싶어"
2. T5: 로컬 흔적 확인(P5-B-1A 이미 있음 — 동기화 폴더·CLI·MCP) + 현재 상태 정직하게
3. 연결 카드: 무엇을 연결하고(구글 드라이브 읽기), 무엇이 가능해지고, 어떻게 끊는지
4. 승인 → T5 가 브라우저로 구글 동의 화면을 연다
   · 로그인·동의는 **사용자가** 그 화면에서 한다 — T5 는 비밀번호를 보지도 받지도 않는다
5. 루프백(localhost)으로 코드 수신 → 토큰 교환 → **연결 테스트**(파일 목록 1건 읽기)
6. 성공 → 진실층 승격: connected=true → 도구 executable → model schema·도구함·능력 문장
   동시 갱신(P5-B-0 이 정확히 이 순환을 위해 지어졌다 — 커널 무변경 예상)
7. 원장 기록 + "연결됐어요. 이제 드라이브에서 찾아올 수 있어요" + 다음 턴 승계
```

실패 경로: 사용자가 거부 → `needs_permission` + 사용자 언어("허용하지 않으셨어요. 언제든
다시 연결할 수 있어요") · 타임아웃/만료 → `error` + `lastError` · **실패를 성공으로 기록하면 게이트 차단.**

## 기술 결정

| 결정 | 근거 |
|---|---|
| **설치형 앱 흐름(루프백 + PKCE)** | T5 는 사용자 로컬에서 돈다 — 공개 리다이렉트 URL 불필요, **client secret 자체가 없다**(설치형 앱은 PKCE 로 대체) |
| 토큰 저장: `channel-credential-store` 패턴 재사용 | 0600 · 소스 트리 밖 · 마스킹 — 텔레그램 토큰이 이미 이 길로 산다. 새 저장소를 만들지 않는다 |
| **scope 는 `drive.readonly` 하나로 시작** | 읽기는 자연 진행이라는 기존 권한 경계와 포개진다. 쓰기·전송(Gmail 발송·캘린더 등록)은 **별도 슬라이스** + needsApproval + previewOf(게이트가 이미 강제) |
| 도구: `google.drive` (search·read) · `connector:'google'` 선언 | 진실층 파생 그대로 — 커넥터에 도구 목록을 손으로 들지 않는다 |
| 토큰 갱신(refresh)은 T5 가 조용히 | 사용자에게 재로그인을 시키지 않는다(§18 지속성). 갱신 실패 시에만 `needs_permission` 으로 내려간다 |
| HTTP 는 전역 fetch, 의존성 0 유지 | google SDK 를 들이지 않는다 — 필요한 건 REST 세 개(토큰 교환·갱신·drive files) |

## 순서 (오너 확정 요청)

추천: **Drive 읽기 → Calendar 읽기 → Gmail 읽기 → 쓰기·전송(각각 별도 승인 경계)**.
Drive 가 먼저인 이유: "내 자료 기준으로 봐줘"(#8)와 직결되고, 소상공인 실사용 문장
("정산 자료", "견적서")의 자료가 대부분 여기 있다. Gmail 은 민감도가 가장 높아 뒤로.

## 승인·위험 경계

- **연결 자체의 승인은 이중이다**: T5 연결 카드(무엇을·범위·되돌리기) + 구글 동의 화면(사용자 본인).
- 읽기 도구는 자연 진행(A0) — 단 원장에는 남는다.
- 연결 해제: 토큰 파기 + revoke 호출 + 진실층 강등(schema·도구함·능력 문장에서 즉시 소멸 —
  P5-B-0 반대 검증이 이미 이 전이를 검사한다).
- 비밀 경계: access/refresh 토큰은 transcript·receipt·로그·UI 에 절대 노출 금지(기존 게이트).

## 배포 전제 (P10 잔여로 기록)

client_id 는 개발 단계엔 **오너의 GCP 프로젝트**에서 발급(설치형 앱이라 client_id 는 비밀이
아니다). 배포 단계엔 제품 소유 등록 + 구글 검증 심사가 필요하다 — **P10 릴리스 잔여**로 넘긴다.
