# 컴퓨터 유즈 — 관찰 전용부터 작게 관통하는 순서 (제안)

- 날짜: 2026-08-04
- 성격: **순서 제안.** 계획서를 대체하지 않는다. `T5-COMPUTER-USE-DEVELOPMENT-PLAN-2026-08-04-ko.md`
  의 CU0~CU9 를 **관통 단위로 다시 자른 것**이고, 각 단계에 "닫는 사용자 문장"을 붙였다.
- 근거: `design/CU0-DEPENDENCY-AUDIT-2026-08-04-ko.md`
- 결정권: 계획 소유자. 이 문서는 제안이다.

---

## 0. 왜 다시 자르나

계획서 CU 순서는 **이미 옳다** — CU3 이 observe-only 다. 바꿀 이유가 없다.

다시 자르는 이유는 하나다. **CU4(저위험 행동)가 한 덩어리로 너무 크다.**

> 앱/창 focus · AX press·set-value · text 입력 · keyboard shortcut · scroll · drag · menu 탐색 · dialog 관찰

이걸 한 단계로 닫으려면 그 안에서 어려운 것과 쉬운 것이 섞인다. **M2 가 길어진 모양과 같다.**

## 1. 자르는 기준 셋

**① 각 단계는 사용자 문장 하나가 다르게 끝나야 닫힌다.**
(오너 원칙: 도구를 만든 게 아니라 사용자 문장이 달라져야 슬라이스가 닫힌다)

**② 각 단계는 거기서 멈춰도 출하 가능해야 한다.**
멈출 수 없는 단계는 너무 큰 단계다.

**③ 첫 손은 "효과를 기계값으로 대조할 수 있는 것"부터.**

이게 이번 재단의 핵심이다. 계획서 **A14**(*"event dispatch 성공, 화면 변화 없음 → 성공 영수증 0"*)
는 컴퓨터 유즈에서 가장 어려운 요구다. **화면은 대조 기준이 없기 때문이다** — 시계·애니메이션·
커서로 늘 조금씩 변한다.

그런데 **어떤 행동은 대조가 자명하다.**

| 행동 | 효과를 무엇으로 대조하나 | 대조 |
|---|---|---|
| 창 focus | frontmost 앱·창 ID | **자명** |
| scroll | 스크롤 위치 값 | **자명** |
| window move/resize | 창 bounds | **자명** |
| 앱 launch/quit | 프로세스 존재 | **자명** |
| 체크박스 toggle | AX value | 명확 |
| 버튼 click | ??? | **어려움** |

**대조가 자명한 것부터 손을 연다.** 그러면 A14 가 "판정이 어려운 요구"가 아니라
**전후 값 비교 한 줄**로 처음 선다. 그 자리에서 원장 계약을 굳힌 뒤 어려운 행동으로 넘어간다.

## A. 눈이 뜬다 — 앱·창까지

**닫는 문장**

```
사용자  "지금 화면에 뭐 떠 있어?"
지금    화면을 볼 수 없다고 답한다 (또는 능력 자체를 모른다)
후      "사파리 '로그인' 창이 앞에 있고, 뒤에 크롬·메모가 있어요"
```

**하는 일** — `desktop.status` · `desktop.observe`(앱·창 목록까지) · `desktop.wait` ·
개발 서명 네이티브 호스트 · TCC 권한 획득 흐름의 최소판 · SelfState 소비 · fake backend

**기계 종료조건**

- 전면 창 신분이 실제 화면과 일치
- 권한 없을 때 "봤다"고 말하는 경우 **0**
- 읽기 전용인데 pointer·keyboard event **0**
- 질문·승인 카드 **0**
- handler 없는 descriptor 가 executable 로 보이는 경우 **0**

**반대시험** — A11(권한 없는 Node 가 socket 호출 → 거부) · A12(unsigned helper → 거부)

**주의**

- **서명이 여기서부터 필요하다.** 단 이건 **개발 서명**이고, 배포 서명·공증·PKG 는 I 다.
  섞으면 A 가 I 만큼 커진다.
- CU7(화면·복구)의 **권한 상태 표시 최소판**이 여기 딸려온다 — 사용자가 권한을 못 주면
  A 자체가 안 선다. 나머지 CU7 은 H 로 미룬다.
- **비공개 SCK 는 여기서 끈다** — `-D PEEKABOO_DISABLE_PRIVATE_SCK_WINDOW_LOOKUP`.
  기본이 켜짐이라 나중에 하면 켜진 채로 굳는다.

**여기서 멈추면** — T5 가 화면을 "볼 줄 아는" 상태로 출하된다. 손은 없다. 그 자체로 쓸모가 있다
(무엇이 열려 있는지 묻고 답할 수 있다). **그리고 셀프후드가 한 칸 올라간다** — 모델이
자기에게 눈이 있다는 것을 SelfState 로 안다.

## B. 눈이 창 안까지

**닫는 문장**

```
사용자  "그 창에 로그인 버튼 있어?"
후      "네. '로그인'(B3)과 '취소'(B1) 버튼, 이메일 입력칸(T2)이 있어요"
```

**하는 일** — AX 트리에서 **조작 가능한 요소만** 추려 안정된 신분(ref)으로 반환.
snapshot registry·TTL·ref 무효화. 스크린샷은 **아직 안 보낸다**(§6.2 우선순위 ①만).

**기계 종료조건**

- `AXSecureTextField` 값 **0** (A09)
- node·depth 상한 초과 시 **조용한 절단 0** — 몇 개를 뺐는지 말한다
- 다른 창 AX node 혼입 **0**
- **토큰·지연 기준선을 여기서 동결**한다(§11) — 결과를 보고 올리지 않는다

**반대시험** — A09 · A02(같은 제목 창 두 개 → window ID 로 분리)

**여기서 멈추면** — "화면에 뭐가 있는지" 정확히 답한다. 여전히 손은 없다.
**비용 기준선이 여기서 잡히므로, 이 단계 없이 뒤로 가면 안 된다.**

## C. 첫 손 — 대조되는 것만 ★

**가장 작고, 가장 중요한 단계다.**

**닫는 문장**

```
사용자  "그 창 앞으로 띄워줘"
후      실제로 앞으로 오고, T5 가 "앞으로 띄웠어요"라고 말하며
        그 말이 frontmost 값으로 뒷받침된다
```

**행동 범위 — 넷만**

```
window/app focus · scroll · window move·resize · app launch/quit
```

**넷만인 이유** — §1의 기준 ③. 전부 **전후 값 대조가 자명하다.**
클릭·타이핑은 여기 없다. **일부러 뺐다.**

**기계 종료조건**

- **A14 가 실제로 선다** — 행동 전후 값을 대조해 안 바뀌었으면 **성공 영수증 0**
- stale snapshot 이면 재관찰 전 실행 **0** (A13)
- 같은 idempotency key 중복 실행 **0** (A06)
- target 앱이 전면화 안 되면 합성 입력 **0** (A05)
- 사용자가 "멈춰" 하면 추가 event **0**
- 전후 상태가 영수증과 일치

**반대시험** — A01 · A03 · A05 · A06 · A13 · A14

**여기서 멈추면** — T5 가 화면을 보고 **되돌릴 수 있는 조작 넷**을 한다.
데이터를 바꾸지 않으므로 위험이 낮고, **원장 진실 계약이 GUI 에서 처음 검증된다.**

> **이 단계가 전체의 급소다.** 여기서 A14 를 자명한 대조로 굳혀 놓으면,
> D 부터의 어려운 행동은 "같은 계약을 어려운 대상에 적용"하는 일이 된다.
> 반대로 여기를 건너뛰고 클릭부터 하면, 대조 기준이 없는 채로 계약을 세우게 된다.

## D. 두 번째 손 — 클릭·입력 (무해 분류만)

**닫는 문장**

```
사용자  "설정에서 다크 모드 켜줘"
후      실제로 켜지고, 켜졌음을 AX value 로 확인한 뒤에 완료를 말한다
```

**행동 범위** — AX press · set-value · 비밀 아닌 text 입력 · keyboard shortcut ·
menu 탐색 · dialog 관찰

**여기서 §5(의미 효과 판정)가 처음 선다.** 버튼 글자 하나가 아니라 **맥락 전체**
(앱·창·요소 role·직전 행동)로 분류한다. 분류가 안 되면 **모델에게 사실로 돌려준다** —
사용자 승인 카드로 떠넘기지 않는다.

**기계 종료조건**

- AX 가 지원하면 **좌표 fallback 금지**
- 분류 unknown 인 요소 클릭 **0** (A17)
- 역할과 문구가 모순되면 실행 **0** (A19)
- TextEdit·Finder·System Settings fixture 가역 작업 완주
- 안전한 탐색·스크롤·가역 편집에 **승인 카드 0**

**반대시험** — A02 · A04 · A17 · A19

**기계 종료조건**

- 네 경계 밖 카드 **0**
- 새 상대 첫 전송 정확히 **1회** 승인, 후속 반복 승인 **0**
- 승인 전·거절 뒤·만료 뒤 효과 **0**
- 돈·비가역 파괴의 무승인 효과 **0**

**반대시험** — A07 · A08 · A09 · A18 · A20

## F. 스크린샷

**왜 여기까지 미루나** — 셋 다다.

1. **비용이 가장 크다.** 창 하나 crop 이 AX 목록의 3~5배, 전체 화면은 10배다.
2. 계획서 §6.2 가 이미 **마지막 수단**으로 뒀다.
3. **A~E 가 서면 필요가 줄어든다.** 무엇이 정말 눈으로만 판단되는지는 그때 안다.

**하는 일** — 대상 창 최소 crop · TTL·디스크 잔존 정리 · redaction · 전송 범위를 원장에 기록

**기계 종료조건** — 기본 window scope 밖 캡처 **0** (A16) · 비밀 원문 **0** ·
screenshot TTL 만료 뒤 act **0** (A13)

> **감사에서 나온 단서** — macOS 14.0·14.1 은 `includeChildWindows` 를 못 꺼서 창 캡처에
> 자식 창이 섞일 수 있다. 14.0 을 지원하면 **T5 쪽 crop 보정이 여기 들어간다.**

## 3. 이 순서가 지키는 것

**① 어느 단계에서 멈춰도 제품이 선다.** A 만 해도 "화면을 볼 줄 아는 T5"다.
M2 가 길어진 이유는 중간에 멈출 자리가 없어서였다.

**② 가장 어려운 계약(A14)을 가장 쉬운 대상에서 먼저 세운다.**
대조가 자명한 행동 넷으로 원장 진실을 굳히고, 그 다음에 어려운 행동을 붙인다.

**③ 비용이 큰 것을 뒤로 민다.** 스크린샷이 F 다. 앞이 서면 필요가 줄어든다.

**④ 되돌릴 수 없는 것에 가장 늦게 닿는다.** C 는 데이터를 안 바꾸고, D 는 가역이고,
E 에서 처음 비가역에 닿는다.

## 4. 이 문서가 정하지 않은 것

- **일정을 적지 않았다.** 단계 크기만 적었다. (오너 원칙: 시간은 학습의 근거가 아니다)
- 계획서를 고치지 않았다. 정정 6건은 `CU0-PLAN-CORRECTIONS-2026-08-04-ko.md` 에 따로 있다.
- shell 경로와 비공개 CGS 결정은 여전히 미결이다 — **A 착수 전에 정해야 한다.**
