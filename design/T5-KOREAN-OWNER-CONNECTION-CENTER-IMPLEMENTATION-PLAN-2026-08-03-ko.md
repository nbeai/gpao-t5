## 0. 한 문장 제품 정의

> 한국 사장이 "무엇을 연결해야 하는지" 공부하지 않아도, 하고 싶은 일을 기준으로 필요한 서비스를
> 발견한다. 공개 정보는 처음부터 쓰고, 자기 계정이 필요한 서비스만 `연결` 한 번으로 T5의 실제 손에
> 편입한다.

연결 센터는 API·MCP 목록을 전시하는 개발자 페이지가 아니다. T5가 법률 확인, 지원사업 탐색,
상권·시장 분석, 뉴스 감시, 문서 처리, 홍보물 제작, 판매·정산을 실제로 수행하기 위해 쓰는 외부 손을
사용자가 이해하고 관리하는 곳이다.

성공한 사용자는 다음 용어를 몰라도 된다.

- API, MCP, OAuth, PKCE, scope, token, endpoint, schema
- Client Secret의 저장 형식
- 어느 실행기가 어느 전송 방식을 쓰는지
- 연결 뒤 어떤 ToolDescriptor가 편입됐는지

사용자가 알아야 하는 것은 네 가지뿐이다.

1. 이 연결로 무엇을 맡길 수 있는가.
2. 어떤 정보가 밖으로 나가는가.
3. 지금 연결되어 실제로 되는가.
4. 연결을 끊으면 무엇이 멈추는가.

### 0.1 실제 사용자 상황을 먼저 고정한다

연결 센터는 정상 연결 한 번만 설계해서는 안 된다. 다음 사용자가 모두 같은 제품을 쓴다.

| 실제 사용자 상황 | 제품이 해야 할 일 |
|---|---|
| API라는 말을 처음 듣는 사용자 | 기술 이름 없이 계정 로그인 또는 바로 사용으로 끝낸다. 개발자센터 가입을 주 경로로 삼지 않는다. |
| 공공정보를 쓰려는 사용자 | 합법적으로 기본 제공할 수 있으면 연결을 요구하지 않는다. `기본 제공 · 사용 가능`으로 보인다. |
| 같은 서비스를 처음 연결하는 사용자 | 필요한 권한·데이터 이동만 짧게 보고 계정 선택·동의만 한다. |
| 같은 서비스에 계정이 여러 개인 사용자 | `본점몰`, `2호점몰`, `고객사 A`처럼 각각 연결하고 작업·자동화에 어느 계정을 쓸지 구분한다. |
| API 키가 필요한 사용자 | 일반 연결과 분리된 `직접 키 연결`에서 발급부터 검증까지 안내한다. 키를 모르면 이 길을 강요하지 않는다. |
| 연결 중 창을 닫은 사용자 | 연결 대기 상태가 남고, 돌아오면 이어서 한다. |
| 동의를 거절한 사용자 | 오류로 몰지 않고 연결하지 않은 상태로 돌아간다. 원래 대화는 보존한다. |
| 키·토큰이 만료된 사용자 | 필요한 순간 조용히 갱신하고, 실패할 때만 `다시 연결`을 보여준다. |
| 서비스가 장애·점검 중인 사용자 | 자격 오류와 서비스 장애를 구분하고 하던 작업을 보존한다. |
| 호출 한도를 다 쓴 사용자 | 비용·다음 초기화 시각·대체 경로를 알려준다. 거짓 성공을 만들지 않는다. |
| 연결을 해제하려는 사용자 | 영향받는 자동화·작업·계정을 먼저 보여주고 자격·도구·자동 실행을 함께 정리한다. |
| API가 없는 국내 사이트 사용자 | 브라우저 로그인과 데스크톱 손으로 이어가되 API 연결인 척하지 않는다. |
| 다른 컴퓨터로 옮긴 사용자 | 자격을 무단 복사하지 않고 다시 연결하거나 승인된 복원 절차를 따른다. |
| 팀원과 같은 사업 계정을 쓰는 사용자 | 개인 자격과 공유 사업 자격을 구분하고 소유자·사용 범위를 표시한다. |
| 서비스를 잘못 연결한 사용자 | 연결 해제와 계정 변경을 쉽게 하고 과거 결과물은 임의로 삭제하지 않는다. |

이 표의 각 행은 구현 뒤 설명으로 남는 것이 아니라 최소 하나의 제품 시험을 가져야 한다.

## 1. 현재 T5에서 재사용할 기반

이 계획은 새 연결 체계를 만들지 않는다. 현재 제품에는 이미 아래 계약이 있다.

| 현재 기반 | 실제 위치 | 이 계획에서의 사용 |
|---|---|---|
| 선언형 서비스 프로필 | `src/kernel/l2-plan/connector-profile.js` | 서비스별 이름·별칭·사용자 업무·연결 방식 선언 |
| 연결 실행 손 | `src/runtime/connector-connect.js` | MCP·API 키·CLI·OAuth 연결 및 해제 |
| 비밀 입력면 | `POST /connectors/secret` | 키를 대화·모델·원장에 남기지 않고 전달 |
| 연결 자격 저장 | `src/surface/connector-credential-store.js` | 재시작 뒤 연결 유지. 계정 확대 전 Keychain 이관 필요 |
| 동적 도구 편입 | `src/runtime/tool-admission.js` | 실검사를 통과한 도구만 모델의 손으로 편입 |
| 연결 진실 투영 | `GET /connectors/truth` | 연결·실행 가능·승인 필요를 실제 상태에서 계산 |
| 작업 중 연결 복귀 | `connectionNeeded`, `surfaceRequest` | 연결 후 사용자가 원래 부탁한 일을 이어서 수행 |
| 모델 연결 UX | `renderModelConnect()` | 목록·연결·검사·활성·해제의 사용 경험 참고 |
| 도구함 | `src/surface/toolbox-view.js` | 연결 결과로 실제 사용 가능한 도구를 보여주는 후속 표면 |

현재의 부족한 점은 연결 엔진이 없는 것이 아니다.

- 서비스 선언이 `demo-context.js` 안에 섞여 있어 제품 카탈로그로 관리하기 어렵다.
- 설정의 `도구와 연결`은 상태 확인 중심이며, 사용자가 목록에서 바로 연결하는 완성된 센터가 아니다.
- 서비스별 출처·약관·비용·데이터 이동·지원 지역·마지막 검증일을 보여줄 카탈로그 계약이 없다.
- 공개 데이터, OAuth, API 키, MCP, 브라우저 대체 경로를 한 UX로 묶는 페이지 흐름이 없다.
- 사용자 계정 자격을 대규모로 받기 전에 macOS Keychain 저장 경계를 닫아야 한다.
- 현재 자격 저장은 `connector id` 하나당 기록 하나라 같은 서비스의 복수 계정을 보존할 수 없다.
- 페이지가 연결 handler를 직접 부르면 대화 경로의 실행 영수증·생명주기와 갈라질 수 있다.
- 공공 API도 인증키·활용신청을 요구할 수 있는데 `공개`와 `무자격 즉시 사용`을 구분하는 계약이 없다.
- 서비스 약관·API 이전·호출 제한이 바뀌었을 때 해당 연결만 안전하게 내릴 제품 게이트가 없다.

따라서 구현의 본질은 **기존 연결 허리를 그대로 사용하면서 계정 인스턴스·자격 소유·제품 카탈로그·
일반 사용자 표면을 완성하는 것**이다.

### 2.2 연결 제품에서 확인된 UX

- ChatGPT Apps는 검색, 동기화, 심층 조사, 외부 행동과 대화 안 UI를 하나의 앱 디렉터리로 묶고,
  쓰기 행동 전 확인을 요구한다. [공식 안내](https://help.openai.com/en/articles/11487775-connectors-in)
- Claude Connectors는 1차 제공 연결과 MCP 연결을 같은 메뉴에서 다루고, 연결 후 대화에서 자료 조회와
  행동에 사용한다. [공식 안내](https://support.anthropic.com/en/articles/11817150-connect-your-tools-to-unlock-a-smarter-more-capable-ai-companion)
- Microsoft Power Automate는 사전 제작 커넥터와 사용자 정의 커넥터를 함께 제공하고, 연결 상태와
  그 연결을 사용하는 흐름을 추적한다. [커넥터 개요](https://learn.microsoft.com/en-us/Connectors/overview)

T5가 가져올 것은 대형 앱스토어의 규모가 아니다.

1. 목록에서 발견하고 한 번에 연결한다.
2. 읽기와 쓰기 권한을 구분한다.
3. 연결 상태·만료·재연결을 한곳에서 관리한다.
4. 연결된 자료와 행동을 대화에서 바로 쓴다.
5. 외부 행동은 T5의 기존 승인·영수증·원장 계약을 그대로 탄다.

### 2.3 자격 소유 모델을 서비스 목록보다 먼저 정한다

`공개 API`라는 이름은 무료·무자격·공용키 허용을 뜻하지 않는다. KOSIS와 OpenDART처럼 공개된 API도
개별 인증키 신청을 요구한다. 따라서 각 연결은 출시 전에 다음 중 하나로 분류돼야 한다.

| `accessMode` | 자격 소유 | 주 사용자 경험 | 제품 원칙 |
|---|---|---|---|
| `builtin_public` | 자격 없음 또는 공식 무자격 접근 | 처음부터 `사용 가능` | 연결 클릭을 요구하지 않는다. |
| `t5_managed` | T5 운영 주체 | 사용자가 별도 키를 만들지 않음 | 약관상 제3자 서비스 제공 허용, 서버측 비밀, 할당량·남용·비용 통제가 선행돼야 한다. |
| `user_oauth` | 사용자 계정 | `연결` → 로그인·동의 | T5 등록 앱, redirect URI, PKCE/secret 경계, scope 심사를 완료해야 한다. |
| `user_key_advanced` | 사용자 | `직접 키 연결` → 안전한 입력 | 일반 사용자의 주 경로가 아니다. 발급 절차·용도·회수 방법을 함께 제공한다. |
| `browser_session` | 사용자의 브라우저 로그인 | `브라우저로 사용` → 로그인 | API가 없거나 신청 문턱이 큰 서비스의 실제 수행 경로다. |
| `local_capability` | 사용자 PC | `이 컴퓨터에서 사용` | 설치·권한·실행 가능성을 직접 확인한다. |

`t5_managed`는 데스크톱 앱에 공용 API 키를 심는 방식이 아니다. 필요한 경우 별도 연결 중계 서비스,
사용자·기기 신분, 호출량 제한, 자격 회전, 장애·비용 운영이 생긴다. 이 운영 기반을 만들지 않는다면
해당 서비스는 `builtin_public`, `user_oauth`, `user_key_advanced`, `browser_session` 중 실제 가능한 길을
선택해야 한다. 편의를 약속하기 위해 비밀을 설치본에 넣지 않는다.

## 3. 제품 범위와 제외 범위

### 3.1 이번 계획이 만드는 것

- 사이드바 `연결`에서 여는 독립 연결 센터
- 한국 사장 업무 기준의 카테고리와 검색
- 실제로 연결 가능한 서비스 카드
- 기본 제공 정보와 사용자 계정 연결의 명확한 구분
- 한 서비스의 복수 계정·복수 사업장 연결
- 공개 연결, OAuth, API 키, MCP, 로컬 CLI를 같은 `연결` 경험으로 처리
- 연결 직후 실검사와 도구 편입
- 연결 상태, 마지막 확인, 실패 이유, 재연결과 해제
- 연결이 필요한 작업에서 해당 카드로 이동하고 연결 후 원래 작업 재개
- 비용·할당량·데이터 이동·출처·약관의 사용자 언어 표시
- 서비스 수명주기 변화에 대응하는 마지막 검증일과 비활성화 상태

### 3.2 이번 계획이 만들지 않는 것

- 커넥터별 독립 실행 엔진
- 서비스 이름을 `turn.js`, `authority.js`, `server.js`의 판단 조건문에 추가하는 것
- 모든 서비스의 기능을 첫 출시에서 구현하는 것
- 출처 없는 법률 판단, 세무 판단, 투자 판단
- 정부 사이트의 실제 제출·신고를 API가 된다고 가정하는 것
- 뉴스 전문을 복제·재배포하는 것
- 브라우저로 가능한 일을 API가 없다는 이유로 불가능 처리하는 것
- 준비되지 않은 서비스에 작동하지 않는 `연결` 버튼을 보여주는 것
- 연결 자체를 곧 외부 쓰기 승인으로 간주하는 것

## 4. 정보 구조와 화면

### 4.1 진입

- 기존 사이드바 `연결`을 유지한다.
- 설정 안의 작은 도구 목록이 아니라 독립된 전체폭 작업 표면으로 연다.
- 대화는 사라지지 않는다. 닫으면 원래 대화와 스크롤 위치로 돌아간다.
- 대화 중 연결이 필요해 열렸다면 해당 서비스 카드가 선택된 상태로 시작한다.

### 4.2 첫 화면

상단에는 다음만 둔다.

- 제목: `연결`
- 검색: `무엇을 맡기고 싶으세요?`
- 필터: `전체`, `연결됨`, `연결 필요`
- 카테고리 탭 또는 왼쪽 목록

카테고리는 공급자 기술이 아니라 사용자 목적을 따른다.

1. 법률·규정
2. 지원사업·행정
3. 상권·시장
4. 뉴스·동향
5. 문서·증빙
6. 홍보 콘텐츠
7. 판매·정산
8. 메일·일정·업무

### 4.3 서비스 카드

각 카드는 다음 정보만 첫눈에 보인다.

| 요소 | 예시 |
|---|---|
| 이름 | 국가법령정보 |
| 한 줄 가치 | 현재 법령과 개정 이력을 찾아요 |
| 대표 업무 2개 | 관련 조문 찾기 · 개정 전후 비교 |
| 상태 | 연결됨 / 연결 필요 / 다시 연결 필요 / 지금 사용할 수 없음 |
| 비용 | 무료 / 사용량에 따라 비용 / 별도 계약 필요 |
| 행동 | `사용 가능`, `연결`, `다시 연결`, `관리`, `브라우저로 사용` 중 하나 |

기술 방식은 기본 카드에 표시하지 않는다. 상세의 `연결 정보`에서만 API·MCP 등 사실을 확인할 수 있다.

### 4.4 상세 화면

카드를 누르면 같은 페이지의 상세 패널이 열린다. 카드 안에 또 카드를 넣지 않는다.

- 이 연결로 할 수 있는 일
- 지금은 할 수 없는 일
- T5가 요청할 권한: 보기 / 만들기 / 수정 / 보내기
- 외부로 전달되는 정보
- 데이터 제공자와 원문·약관 링크
- 무료 여부와 사용량 한도
- 마지막 연결 확인 시각
- 이 연결을 사용하는 자동화와 진행 중인 작업
- 연결된 계정·사업장과 기본으로 사용할 계정
- `연결` 또는 `연결 해제`

법률·통계·상권처럼 공개 자료를 쓰는 연결도 출처와 데이터 기준일을 반드시 보여준다.

### 4.5 상태 언어

내부 상태를 그대로 노출하지 않는다.

| 내부 사실 | 사용자 표시 |
|---|---|
| 선언 + 실검사 성공 + 도구 1개 이상 | 연결됨 |
| 자격이 필요 없는 기본 제공 정보 | 사용 가능 |
| 자격 없음 | 연결 필요 |
| 자격 만료 또는 폐기 | 다시 연결 필요 |
| 서비스 장애 | 잠시 연결할 수 없음 |
| 약관·API 종료 | 현재 지원하지 않음 |
| 계획만 있고 실행기 없음 | 카탈로그에 노출하지 않음 |

`등록됨`, `로그인됨`, `토큰 있음`은 연결 성공이 아니다.

### 4.6 페이지와 대화의 연계

연결 버튼 뒤의 모든 일을 별도 설정 화면에 가두지 않는다. 연결 난이도에 따라 두 흐름으로 나눈다.

**즉시 연결**

- 공개 기본 제공, 이미 설치된 로컬 기능, 표준 OAuth처럼 다음 행동이 결정적인 경우
- 페이지 안에서 확인→로그인→실검사→완료까지 끝낸다.
- 모델 호출과 대화를 추가하지 않는다.

**대화형 연결**

- 계정·사업장 선택, 발급 절차, 서비스 기능 선택, 브라우저 로그인, 오류 복구처럼 사용자 상황을 알아야 하는 경우
- `연결`을 누르면 현재 대화로 돌아가며 `○○ 연결 중` 작업 띠가 열린다.
- T5는 연결 센터에서 확인한 사실과 원래 사용 목적을 받은 상태로 시작한다. 사용자가 서비스 이름과 목적을
  다시 설명하지 않는다.
- 비밀값은 대화로 받지 않고 기존 비밀 입력면을 연다.
- T5가 브라우저를 열고 확인할 수 있는 단계는 직접 수행하며, 계정 선택·동의·비밀 입력만 사용자에게 맡긴다.
- 완료되면 작업 띠가 `연결됨`으로 바뀌고, 연결 센터에서 시작했다면 결과를 알린다. 대화 작업에서 시작했다면
  원래 부탁을 즉시 이어서 수행한다.

새 대화를 자동 생성하지 않는다. 사용자가 이미 하던 대화가 있으면 그 대화를 사용하고, 연결 센터에서 독립적으로
시작한 경우 현재 작업 대화에 연결 작업을 연다. 연결 안내용 대화가 세션 목록을 불필요하게 늘리지 않게 한다.

대화에 넣는 것은 가공된 사용자 문장이 아니라 구조화된 연결 작업 상태다.

```js
ConnectionTask {
  taskId,
  connectorId,
  instanceId,
  originSessionId,
  originRequestRef,
  purpose,
  state,
  confirmedFacts: [],
  missingHumanActions: [],
  nextAction,
  startedAt,
  updatedAt
}
```

모델은 이 상태를 보고 자연스럽게 돕지만 연결 성공을 판정하지 않는다. 성공은 여전히 orchestrator의 실검사와
도구 편입이 결정한다. 페이지·대화·재시작은 같은 `ConnectionTask`를 본다.

### 4.7 대화에서 준비된 연결을 먼저 발견한다

연결 센터는 사람이 찾아보는 목록인 동시에 T5의 자기 능력 지도다. 사용자가 대화에서 서비스 이름이나
그 서비스로 할 수 있는 일을 말하면, T5는 현재 실제 상태를 다음 네 층으로 구분해 알아야 한다.

| 자기 상태 | 모델 앞의 사실 | 사용자에게 할 일 |
|---|---|---|
| `builtin_available` | 지금 바로 쓸 수 있음 | 설명보다 먼저 사용해 결과를 만든다. |
| `instance_usable` | 연결된 계정·사업장이 있음 | 대상이 분명하면 실행하고, 여러 개면 결과가 생기기 전에 필요한 계정만 묻는다. |
| `published_connectable` | 제품이 검증한 연결 경로가 있으나 아직 미연결 | “준비된 연결이 있어요”라고 알리고 `연결`을 열어 원래 일을 이어 간다. |
| `known_unavailable` | 서비스는 알지만 현재 제품 연결이 없음 | 연결된 척하지 않고 브라우저·데스크톱 대체 경로를 확인한다. |

모델에게 전체 카탈로그를 매 턴 길게 넣지 않는다. 사용자의 원문·현재 목적과 관련된 항목만
`aliases`, `userJobs`, `jobTags`, 현재 연결 상태로 좁혀 Task Context에 올린다. 이 선택은 특정 서비스
문구 정규식이 아니라 기존 capability-resolution과 카탈로그의 선언형 의미를 사용한다.

대화 흐름:

```text
사용자: “우리 지역 경쟁 카페를 좀 보고 싶어.”
→ T5가 관련 능력에서 상권정보를 찾음
→ 기본 제공이면 바로 조사
→ 미연결이지만 published_connectable이면 준비된 연결과 필요한 권한을 짧게 알림
→ 사용자가 연결을 선택하면 해당 카드 또는 대화형 ConnectionTask를 바로 엶
→ 실검사·도구 편입
→ “경쟁 카페를 보고 싶다”는 원래 요청으로 자동 복귀
```

사용자가 서비스 이름을 정확히 몰라도 목적에서 찾을 수 있어야 하고, 반대로 `KOSIS`, `DART`, `카페24`처럼
이름을 말해도 같은 정의에 닿아야 한다. 제품에 `published`되지 않은 연구 후보를 가능한 기능처럼 말해서는
안 된다.

## 5. 한 번의 연결 흐름

### 5.1 공통 순서

```text
사용자가 연결 선택
→ T5가 현재 흔적·기존 자격·서비스 상태 확인
→ 사용자에게 필요한 권한과 데이터 이동을 짧게 표시
→ 연결 방식 실행
→ 실제 서비스와 악수
→ 대표 읽기 동작 1회 실검사
→ 성공한 도구만 편입
→ SelfState·연결 센터 상태 갱신
→ 대화 중 하던 작업이 있으면 그 자리에서 재개
```

### 5.2 연결 방식별 사용자 경험

**공개 데이터**

- 자격이 필요 없고 약관상 제품 기본 제공이 가능하면 설치 시점부터 `사용 가능`이다.
- 사용자가 연결 버튼을 누르지 않아도 T5가 필요한 순간 선택해 쓴다.
- 공개 API라도 인증키·활용신청이 필요하면 `builtin_public`이 아니다. 약관 검토 뒤 `t5_managed` 또는
  `user_key_advanced`로 분류한다.

**OAuth 로그인**

- 사용자는 `연결`을 누른다.
- T5가 공식 로그인·동의 창을 연다.
- 사용자는 계정 선택과 권한 동의만 한다.
- 콜백, 토큰 교환, 갱신, 재연결은 T5가 처리한다.
- 동의를 취소하면 실패가 아니라 `연결하지 않았어요`로 끝낸다.

**API 키**

- 일반 카드의 주 연결 버튼과 분리된 `직접 키 연결`에서 시작한다.
- T5가 발급 페이지를 열고 그 화면에서 해야 할 최소 단계만 안내한다.
- 값은 비밀 입력면에서 받고 대화·모델·전사·원장에 남기지 않는다.
- 키를 저장한 뒤 대표 기능을 실제로 호출한다.
- 키 오류와 기능 미활성화를 가능한 범위에서 구분한다.

**MCP**

- 로컬 설정이나 공식 원격 MCP를 T5가 먼저 탐색한다.
- 원격 인증이 필요하면 공식 동의 화면을 연다.
- `tools/list`와 대표 읽기 동작을 확인하고 도구가 있어야 연결로 인정한다.
- 사용자를 Claude나 Codex 설정 화면으로 보내지 않는다.

**CLI·로컬 앱**

- 설치·로그인 흔적을 T5가 직접 확인한다.
- 현재 실행 경계에서 실제 명령을 호출할 수 있어야 연결로 인정한다.
- 다른 앱의 광범위한 키체인을 열어야 한다면 우회하지 않고 T5 전용 자격 경로를 안내한다.

**공식 연결이 없는 서비스**

- 브라우저 손으로 로그인 상태를 확인하고 해당 사이트에서 수행할 수 있다.
- 반복 업무는 브라우저 절차를 검증된 skill/workflow로 축적한다.
- 마지막으로 데스크톱 손을 사용한다.
- 이 경로도 연결 센터에는 `브라우저로 사용`처럼 사용자 언어로 표시하되, API 연결인 척하지 않는다.

### 5.3 복수 계정과 사업장

- `Cafe24`와 `본점몰`은 같은 신분이 아니다. 서비스 정의와 실제 계정 연결을 분리한다.
- 연결 완료 때 서비스가 허용하는 최소 계정 식별 정보로 표시명을 제안하되 사용자가 바꿀 수 있다.
- 같은 서비스의 계정 추가는 기존 자격을 덮어쓰지 않는다.
- 대화에서 대상이 분명하면 해당 연결을 고르고, 둘 이상 가능하면 사업 결과가 생기기 전에만 짧게 묻는다.
- 자동화·장기 작업은 `connectionInstanceId`를 고정해 나중에 기본 계정이 바뀌어도 대상이 바뀌지 않는다.
- 공유 사업 계정은 개인 계정과 구분하며 소유자·허용 사용자·해제 권한을 기록한다.

### 5.4 연결 해제

연결 해제는 다음을 원자적으로 처리한다.

1. 런타임 도구 편입 해제
2. 모델 schema에서 제거
3. 저장 자격 삭제
4. 자동 갱신·백그라운드 작업 중지
5. 해당 연결을 쓰는 자동화 목록 표시
6. 진행 중인 작업은 `연결이 끊겨 멈춤`으로 보존
7. 사용자 데이터와 과거 영수증은 임의 삭제하지 않음

## 6. 카탈로그 계약

### 6.1 분리 원칙

서비스의 정적 설명과 현재 실행 상태를 분리한다.

- **카탈로그:** 이름, 설명, 사용자 업무, 발급 안내, 출처, 비용 분류, 약관, 지역 관련성
- **런타임 진실:** 연결됨, 자격 유효, 실행 가능, 편입된 도구, 마지막 성공·실패
- **도구 진실:** ToolDescriptor, 권한, 출처 요구, 실행 handler

카탈로그에 `지원한다`고 적혀 있어도 런타임 실검사가 실패하면 `연결됨`이 될 수 없다. 반대로 도구의 승인
정책을 카탈로그에 복제하지 않는다.

### 6.2 서비스 정의와 실제 연결을 분리한다

기존 `ConnectorProfile`은 서비스 정의의 출발점으로 유지하되, 실제 계정 상태를 그 객체의
`connected` 한 값으로 소유하지 않는다.

```js
// 제품에 알려진 서비스
ConnectorDefinition {
  id,
  label,
  aliases,
  categories: [],
  jobTags: [],
  userJobs,
  requiredSetup,
  limits,
  authMethods,
  accessMode,
  localeRelevance: 'kr',

  catalog: {
    summary,
    icon,
    provider,
    officialUrl,
    termsUrl,
    privacyUrl,
    pricing: 'free' | 'metered' | 'paid_contract' | 'unknown',
    dataClasses: ['public_data', 'business_document'],
    dataLeavesDevice: true,
    regions: ['KR'],
    lastReviewedAt,
    lifecycle: 'active' | 'migration' | 'deprecated',
    admissionState: 'researched' | 'terms_checked' | 'adapter_tested'
      | 'live_verified' | 'package_verified' | 'published'
  },

  fallback: [
    { kind: 'official_api' },
    { kind: 'browser' },
    { kind: 'desktop' }
  ]
}

// 사용자가 실제로 연결한 계정·사업장
ConnectionInstance {
  instanceId,
  connectorId,
  ownerPrincipalRef,
  displayName,              // 본점몰 · 2호점몰 · 고객사 A
  accountHint,              // 비밀이 아닌 식별 힌트
  credentialRef,            // 비밀 자체가 아니라 CredentialVault 참조
  grantedScopes: [],
  workspaceRefs: [],
  state: 'connecting' | 'usable' | 'degraded' | 'reauth_required' | 'disconnected',
  lastCheckedAt,
  lastError
}
```

`catalog`은 사용자에게 보여줄 정적 사실만 소유한다. 계정 상태는 `ConnectionInstance`, 실행 가능한
도구와 승인 필요 여부는 기존 SelfState와 ToolDescriptor에서 투영한다. 한 서비스 카드의 상태는 연결
인스턴스들의 요약일 뿐이며 그 자체가 자격을 소유하지 않는다.

### 6.3 CredentialVault 계약

연결 실행기는 파일·Keychain·Credential Manager를 직접 알지 않는다.

```js
CredentialVault {
  put({ instanceId, secretRecord }) -> credentialRef
  get(credentialRef) -> secretRecord
  remove(credentialRef)
  describe(credentialRef) -> { kind, canRefresh, expiresAt, filled }
}
```

- macOS 제품: Keychain adapter
- Windows 제품: Credential Manager adapter
- 결정적 검사: 격리 메모리·임시 파일 adapter
- `t5_managed`: 데스크톱에 공용 비밀을 저장하지 않고 서버측 broker가 소유
- 자격의 내보내기·동기화는 기본 금지. 별도 승인된 이전 계약이 있을 때만 연다.

## 8. 서버와 표면 계약

### 8.1 조회

`GET /connectors/truth`를 단일 진실로 유지하고 카탈로그 메타데이터를 합성한다. 별도 상태 판정기를 만들지 않는다.

응답에 필요한 축:

- `catalog`: 이름, 요약, 카테고리, 사용자 업무, 비용, 출처와 약관
- `runtime`: connected, executable, lastCheckedAt, lastError
- `permissions`: 실제 편입된 ToolDescriptor에서 파생한 보기·쓰기·보내기 범위
- `usage`: 이 연결을 쓰는 활성 자동화와 진행 중 작업 수
- `action`: connect / reconnect / manage / unavailable

같은 진실에서 모델용 `RelevantConnectionCapabilities`를 투영한다. 별도 목록을 손으로 유지하지 않는다.

```js
RelevantConnectionCapabilities {
  builtinAvailable: [],
  connectedInstances: [],
  publishedConnectable: [],
  knownUnavailable: []
}
```

이 투영은 사용자의 현재 목적과 관련된 항목만 Task Context에 싣는다. 전체 카탈로그를 상시 주입해 대화
문맥을 밀어내지 않으며, `published` 전 후보와 만료된 연결을 가능한 손처럼 보여주지 않는다.

### 8.2 행동

페이지 행동과 대화 행동은 같은 `ConnectionOrchestrator`를 호출하는 얇은 표면이어야 한다.

```text
POST /connectors/action
{ connector, action: 'connect' | 'disconnect' | 'recheck' }
```

이 라우트는 서비스별 분기를 갖지 않는다. `ConnectionOrchestrator`가 기존 연결 실행기를 사용해
`needsSecret`, OAuth 진행, 대화형 연결 전환, 성공, 실패를 반환하고 사용자 표면은 이를 투영한다.
라우트가 handler·자격 저장소·도구 편입을 직접 부르지 않는다.

`ConnectionOrchestrator`는 다음을 한 책임으로 묶는다.

- ConnectionTask 생성·재개
- accessMode에 맞는 실행기 선택
- CredentialVault 읽기·쓰기
- 실검사와 도구 편입
- ConnectionInstance 상태 변경
- 연결 생명주기 사건과 ToolReceipt 발행
- 원래 작업 복귀
- 중복 연결·취소·재시작 복구

### 8.3 실시간 상태

- 연결 시작, 로그인 대기, 확인 중, 연결 완료, 실패를 TurnEvent 계열의 사용자 언어 사건으로 보낸다.
- 모델 사고 원문이나 토큰 상태를 스트리밍하지 않는다.
- 페이지를 닫아도 연결 시도 상태는 사라지지 않는다.
- 재접속하면 현재 상태를 다시 읽는다.
- 같은 연결 작업을 페이지와 대화가 동시에 진행해도 orchestrator 하나만 실행한다.

## 9. 권한·비밀·법적 경계

### 9.1 자격 저장

- `builtin_public`은 CredentialVault 없이 먼저 구현할 수 있다.
- OAuth refresh token, API key, Client Secret을 받는 제품 연결은 CredentialVault와 해당 OS adapter가
  구현된 뒤에만 연다. Keychain은 마지막 설치 시험이 아니라 첫 비밀 연결의 선행조건이다.
- 현재 0600 파일 저장은 개발·시험 기준선으로만 사용하고 팀 사용자 대상 대규모 자격 저장의 최종 형태로 삼지 않는다.
- 비밀은 로그, 오류 문장, 전사, 모델 입력, WorkEvent, ToolReceipt에 들어가지 않는다.

### 9.2 읽기와 쓰기

- 연결 시 처음부터 최대 권한을 받지 않는다.
- 첫 연결은 가능한 경우 읽기 scope로 시작한다.
- 만들기·수정·발송이 실제로 필요해질 때 추가 권한을 요청한다.
- 연결 동의는 외부 행동 승인이 아니다. 발송·게시·신청·결제·삭제는 기존 실행 시점 경계를 탄다.

### 9.3 분야별 고지

| 분야 | 반드시 지킬 것 |
|---|---|
| 법률·행정 | 정보 탐색과 문서 준비를 제공한다. 전문 법률 판단이나 제출 완료를 가장하지 않는다. 조문·시행일·원문을 보존한다. |
| 뉴스 | 제목·요약·출처·링크를 제공하고 전문을 재배포하지 않는다. 서비스 약관을 따른다. |
| 상권·시장 | 점포·공공통계와 실제 매출·유동인구 추정을 구분한다. 기준일과 지역 범위를 표시한다. |
| 문서·OCR | 민감 문서가 외부 서비스로 나갈 때 먼저 알린다. 로컬 처리 가능 여부를 우선 확인한다. |
| 이미지·영상 | 상업 이용권, 인물, 상표, 저작권과 생성물 표시 정책을 제공자별로 확인한다. |
| 판매·메일 | 읽기와 쓰기 권한을 나누고, 게시·발송·상품 변경은 실제 결과가 생기는 순간 승인·영수증을 남긴다. |

## 10. 구현 순서

### 단계 0. 계약과 기준선

- 기존 모델 연결과 커넥터 연결의 사용자 흐름을 데스크톱·모바일에서 기록한다.
- `/connectors/truth`, `connector.connect`, 비밀 입력, 작업 복귀의 현재 행동을 고정한다.
- 현재 본선 작업과 공용 파일 소유권을 확인한다.
- 카탈로그의 정적 사실과 런타임 진실의 소유 표를 확정한다.
- accessMode와 자격 소유 주체를 서비스별로 확정한다.
- ConnectorDefinition·ConnectionInstance·ConnectionTask의 저장·복원 계약을 확정한다.

종료 조건: 기존 연결·해제·작업 복귀 행동을 재현하는 결정적 검사가 선다.

### 단계 1. 계정 인스턴스와 자격 금고

- 기존 단일 `state[connector]` 저장을 ConnectionInstance 구조로 이관한다.
- 과거 단일 연결 기록은 기본 인스턴스 하나로 무손실 승격한다.
- CredentialVault 인터페이스와 테스트 adapter를 만든다.
- macOS Keychain adapter를 서명 설치본에서 확인한다.
- 연결·해제·재인증과 자동화의 instance 참조를 고정한다.

종료 조건: 같은 서비스 계정 두 개가 서로 덮어쓰지 않고 재시작 뒤 각각 작동한다.

### 단계 2. 제품 카탈로그 분리

- `demo-context.js`에서 제품 커넥터 선언을 `src/connectors/`로 옮긴다.
- ConnectorDefinition의 정적 메타데이터와 출시 심사 상태를 추가한다.
- 검색, 카테고리, 별칭, 출시 가능 여부를 순수 투영으로 만든다.
- 서비스 선언이 커널·권한 코드로 새지 않는 감사를 추가한다.

종료 조건: 서비스 하나 추가할 때 카탈로그 선언과 adapter만 바뀌고 커널은 바뀌지 않는다.

### 단계 3. 공통 연결 오케스트레이터

- 대화와 페이지의 연결 행동을 ConnectionOrchestrator 하나로 합친다.
- ConnectionTask·Receipt·생명주기 사건·작업 복귀를 연결한다.
- 즉시 연결과 대화형 연결의 결정 기준을 accessMode와 누락된 사람 행동에서 계산한다.
- 연결 중 종료·재시작·취소·중복 클릭을 복구한다.

종료 조건: 같은 연결을 페이지와 대화에서 시작해도 실행·자격·영수증의 진실이 하나다.

### 단계 4. 연결 센터 표면

- 기존 `연결` 진입을 전체폭 센터로 바꾼다.
- 검색·카테고리·상태 필터·서비스 카드·상세 패널을 구현한다.
- `연결`, `다시 연결`, `관리`, `해제`를 실제 상태에서 투영한다.
- 대화형 연결은 현재 대화의 ConnectionTask로 이동하고 페이지로 돌아오는 길을 제공한다.
- 375px 모바일부터 넓은 데스크톱까지 텍스트와 버튼 겹침을 확인한다.

종료 조건: 노출된 모든 `연결` 버튼이 실제 실행 경로를 갖고, 죽은 버튼은 0개다.

### 단계 5. 연결 방식별 대표 관통

- `POST /connectors/action`을 ConnectionOrchestrator의 표면으로 연결한다.
- OAuth·API 키·MCP·CLI 결과를 하나의 진행 상태로 투영한다.
- 실검사 뒤에만 연결 완료로 표시한다.
- 연결 후 원래 작업을 재개한다.
- 해제 시 자격·도구·자동화 의존을 일관되게 처리한다.

종료 조건: `builtin_public`, `user_oauth`, `user_key_advanced`, `browser_session`, `local_capability`를
fixture로 모두 통과하고, 실제 제품 서비스는 출시할 accessMode마다 최소 1개씩 관통한다.

### 단계 6. 한국 공공·시장 1차 묶음

- 국가법령정보, KOSIS, OpenDART, 소상공인 상가업소를 우선 구현한다.
- 각각 출처·기준일·원문 링크를 ToolReceipt와 결과에 보존한다.
- 법률·시장 수치를 합성하는 공통 조사 흐름을 검증한다.

종료 조건: “이 지역에서 카페를 열 때 시장과 규정을 조사해줘” 한 문장에서 여러 연결을 선택해 근거 보고서를 만든다.

### 단계 7. 지원사업·뉴스·문서

- SME24, BIG Kinds, CLOVA OCR을 구현한다.
- 지원사업 적합성은 사용자 사업정보와 공고 원문을 분리해 근거를 남긴다.
- 뉴스는 중복 제거와 출처 링크를 지킨다.
- OCR은 외부 전송 고지와 원본 불변을 지킨다.

종료 조건: 공고 탐색→첨부 분석→준비자료 목록→마감 자동화가 한 흐름으로 이어진다.

### 단계 8. 제작·판매 연결

- Canva/OpenAI 이미지, Adobe PDF, Cafe24를 순서대로 연다.
- 비용·할당량을 연결 상세와 실행 전 상태에 반영한다.
- 생성 결과와 실제 게시·상품 변경을 분리한다.

종료 조건: 조사 결과에서 홍보물·견적서·상품 초안까지 만들고, 외부 반영은 실행 순간에만 승인받는다.

### 단계 9. 설치본 라이브 검증

- 서명·공증 PKG의 Keychain 자격 저장으로 실제 계정을 연결한다.
- 재시작, 로그인 자동시작, 네트워크 단절, 자격 만료, 서비스 장애, 해제를 검증한다.
- 실제 사용자 홈과 시험 홈을 분리한다.
- 설치본에서 브라우저 로그인 창과 콜백이 정상인지 확인한다.

종료 조건: 소스 트리가 아니라 팀 설치본에서 연결→작업→재시작→재사용→해제가 모두 작동한다.

## 11. 시험 계획

### 11.1 절대 기능 시험

1. 연결 전 도구가 모델 schema에 나타나지 않는다.
2. 연결 실검사 실패를 성공으로 표시하지 않는다.
3. 로그인됐지만 도구가 0개면 연결 완료가 아니다.
4. 비밀이 전사·로그·원장·오류·화면 응답에 노출되지 않는다.
5. 연결 해제 뒤 도구·schema·자동화 실행에서 함께 사라진다.
6. 재시작 뒤 연결 자격과 실제 실행 가능 상태가 일치한다.
7. 자격 만료 시 한 번 갱신하고, 실패하면 다시 연결 상태로 간다.
8. 연결이 필요한 대화의 원래 요청이 보존되고 연결 뒤 재개된다.
9. 연결 동의가 게시·발송·삭제 승인을 대신하지 않는다.
10. 서비스 이름이 커널 판단 코드에 추가되지 않는다.
11. 공개 자료 결과에 출처·기준일·원문 링크가 남는다.
12. 준비되지 않은 서비스에 죽은 `연결` 버튼이 없다.
13. 기본 제공 공개 정보는 사용자에게 연결 클릭을 요구하지 않는다.
14. 같은 서비스의 계정 두 개가 자격·도구·자동화에서 섞이지 않는다.
15. 페이지와 대화가 같은 ConnectionInstance·ConnectionTask·Receipt를 본다.
16. 대화형 연결로 이동해도 원래 요청과 페이지 복귀 정보가 보존된다.
17. `직접 키 연결`은 일반 사용자의 기본 연결로 표시되지 않는다.
18. 자격을 받는 연결은 CredentialVault 밖에 비밀을 저장하지 않는다.
19. 대화에서 관련된 published 연결을 발견하고 미연결 상태와 연결 방법을 정확히 알린다.
20. 관련 없는 대화에는 카탈로그 목록이 모델 문맥과 사용자 답에 나타나지 않는다.
21. 연구 후보·미검증 연결을 모델이 `연결하면 된다`고 약속하지 않는다.

### 11.2 실패·복구 시험

- OAuth 거절, 창 닫기, 시간 초과
- API 키 오타, 권한 미활성, 할당량 초과
- MCP 악수 실패, tools/list 0개, 중간 연결 끊김
- 인터넷 단절과 서비스 5xx
- 저장 자격 폐기와 재인증
- 연결 중 T5 재시작
- 같은 연결 버튼 연속 클릭과 중복 도구 편입
- 페이지와 대화에서 같은 연결을 동시에 시작
- 계정 A 연결 중 같은 서비스의 계정 B 추가·해제
- 연결 해제와 자동화 실행의 경합
- 약관 변경·API 종료·이전 공지
- pagination 중간 실패와 일부 결과만 도착
- 호출 한도 초과와 한도 초기화 시각
- 응답 schema·업종코드·행정구역 변경
- 한국어 조합문자·주소·법인명·시간대 처리

### 11.3 HumanRealTest 시나리오

**발견**

- “내 가게 주변에 같은 업종이 얼마나 있어?”라고 말한다.
- T5가 상권 연결을 선택해 해당 카드로 이동시킨다.
- 사용자는 `연결`만 누르고 개발자 용어 없이 완료한다.

**복합 조사**

- “성수동에 디저트 매장을 열까 고민이야. 시장과 규정부터 봐줘.”
- T5가 상권·KOSIS·법령을 골라 출처가 있는 보고서를 만든다.

**지원사업**

- “우리 회사가 이번 달 신청할 만한 지원사업 찾아줘.”
- 공고 원문, 자격 근거, 마감일, 필요한 서류를 보여준다.
- 사용자가 원하면 반복 감시로 이어진다.

**문서 처리**

- 영수증과 사업자등록증 이미지를 준다.
- 외부 OCR 전송을 알리고 동의를 받은 뒤 표로 정리한다.
- 원본을 바꾸지 않고 결과 파일을 만든다.

**홍보 제작**

- “이번 행사 카드뉴스 만들어줘.”
- 조사→문구→이미지→Canva 템플릿 결과를 만든다.
- 게시 전까지는 외부 계정에 아무것도 올리지 않는다.

**복구**

- 연결 중 창을 닫고 T5를 재시작한다.
- 실패 이유와 다음 행동이 남아 있고 처음부터 다시 설명시키지 않는다.

**복수 사업장**

- 같은 판매 서비스를 `본점몰`과 `2호점몰`로 각각 연결한다.
- “2호점 지난주 주문만 정리해줘”가 본점 자료를 섞지 않는다.
- 2호점 연결을 끊을 때 영향받는 자동화를 먼저 보여주고 본점 연결은 유지한다.

**대화형 연결**

- 지원사업을 찾다가 필요한 서비스 연결 버튼을 누른다.
- 현재 대화로 돌아와 T5가 목적과 확인한 상태를 이미 알고 필요한 사람 행동 하나만 요청한다.
- 연결 뒤 사용자가 처음 요청을 반복하지 않아도 지원사업 탐색을 이어서 완료한다.

**자기 능력 발견**

- 사용자가 서비스 이름 없이 “우리 동네 경쟁 가게를 알아봐줘”라고 말한다.
- T5가 카탈로그의 `userJobs`에서 상권정보 능력을 찾아 현재 상태를 정확히 말한다.
- 기본 제공이면 바로 쓰고, 연결이 필요하면 준비된 카드로 안내한 뒤 원래 조사를 이어 간다.
- 다음 턴의 일반 대화에는 상권 연결 목록이 불필요하게 반복되지 않는다.

각 시나리오는 버튼, 스크롤, 상세 열기, 뒤로 가기, 새로고침, 모바일 화면까지 실제 인간 행동으로 수행한다.

### 11.4 비교 검증

같은 사용자 문장과 같은 계정을 가능한 범위에서 다음과 비교한다.

- ChatGPT Apps: 발견성, 연결 단계 수, 대화 복귀
- Claude Connectors/MCP: 연결 범위와 실제 도구 사용
- OpenClaw: 연결 생명주기, doctor, 재연결, 지속 운영
- Hermes: 도구 편입, 실행 루프, 실패 복구
- Codex·Claude Code: 사용자가 직접 설정하지 않아도 일을 끝내는 정도

점수 축:

| 축 | 측정 |
|---|---|
| 연결 성공률 | 처음 보는 사용자가 도움 없이 완료한 비율 |
| 연결 부담 | 클릭 수, 입력 필드 수, 개발자 페이지 체류 시간 |
| 작업 복귀 | 연결 뒤 원래 요청을 다시 말하지 않고 완료한 비율 |
| 진실성 | 거짓 연결·거짓 실행 가능·거짓 완료 0 |
| 복구 | 만료·장애·재시작 뒤 이어서 성공한 비율 |
| 한국 업무 가치 | 법률·지원사업·상권·문서·판매 시나리오 완료율 |

절대 기능은 기계적으로 전부 통과해야 한다. 상대 성능은 동일 조건 비교에서 연결 성공률과 사용자 부담이
비교군보다 열세가 아니어야 한다.

## 12. 돌연변이와 회귀 계약

최소 다음 변이를 등록한다.

- 실검사 없이 `connected=true`
- OAuth 토큰만 있으면 도구 0개여도 성공
- 두 번째 계정 연결이 첫 계정 자격을 덮어씀
- 자동화가 connectorId만 저장해 기본 계정 변경 후 다른 사업장을 실행
- 비밀값을 오류 문장에 포함
- 해제 뒤 모델 schema에 도구 잔류
- 카탈로그 상태가 SelfState 대신 자체 값을 사용
- 페이지 route가 orchestrator를 우회해 handler를 직접 호출
- 대화형 연결 전환 때 originRequestRef를 버림
- 연결 후 pending 작업 삭제
- 서비스명을 `turn.js` 조건문에 추가
- 읽기 연결에 쓰기 scope 선요청
- 법률·뉴스·통계 결과에서 출처 제거
- 준비 중 서비스에 활성 `연결` 버튼 표시
- builtin_public에 불필요한 연결 버튼 표시
- user_key_advanced를 일반 사용자의 기본 연결로 표시
- published 전 후보를 RelevantConnectionCapabilities에 포함
- 모든 턴에 전체 카탈로그를 모델 문맥으로 주입
- 목적과 무관한 연결을 추천해 대화를 방해
- 연결 동의를 외부 쓰기 승인으로 재사용

각 변이는 관련 반대시험이 실제로 물어야 한다. 문법 오류나 도달 불가능한 변이를 성공으로 세지 않는다.

공용 파일은 한 작업선이 직렬 소유한다. 서비스 adapter는 서로 다른 파일로 분리한 뒤 최대 3개 작업선에서
병렬화할 수 있지만, 통합자는 한 명이다.

권장 순서:

```text
현재 M2~M4 본선 완료
→ accessMode·ConnectionInstance·ConnectionTask 계약 동결
→ CredentialVault + macOS Keychain
→ ConnectionOrchestrator
→ 공통 카탈로그 계약
→ 연결 센터 표면
→ 공공 데이터 adapter 병렬 구현
→ 통합·절대 게이트
→ 실계정 adapter와 HumanRealTest
→ Keychain 기반 서명 PKG 재검증
```

## 14. 완료 판정

다음이 모두 참일 때만 `한국 사장 연결 센터 1차 완료`라고 한다.

### 절대 영역

- 노출된 모든 서비스가 실제 연결 경로를 가진다.
- 기본 제공 정보는 연결을 요구하지 않고 바로 작동한다.
- 연결 성공은 실검사와 도구 편입으로 증명된다.
- 같은 서비스의 복수 계정·복수 사업장이 서로 섞이지 않는다.
- 즉시 연결과 대화형 연결이 같은 오케스트레이터·영수증·복구 계약을 탄다.
- 비밀 노출, 승인 우회, 거짓 성공, 해제 뒤 유령 도구가 0이다.
- 연결 뒤 원래 작업이 이어진다.
- 재시작·만료·장애·해제가 복구 계약을 지킨다.
- 데스크톱·모바일·설치본에서 같은 사용자 흐름이 작동한다.
- 전체 회귀·돌연변이·plan·docs·workspace·package 게이트가 통과한다.

### 상대 영역

- 처음 보는 한국 사용자도 개발자 도움 없이 연결한다.
- 같은 업무에서 ChatGPT·Claude의 연결 경험보다 단계와 설명 부담이 더 크지 않다.
- 법률·행정·상권·시장·뉴스·문서라는 한국 사장 핵심 업무의 실제 완료율이 비교군보다 낮지 않다.
- 연결 페이지를 몰라도 대화만으로 필요한 연결을 발견하고 완료할 수 있다.

### 사용자 최종 경험

```text
“우리 가게 근처 경쟁 매장과 최근 시장 흐름을 보고 싶어.”
→ T5가 필요한 연결을 고른다.
→ 사용자는 연결 한 번만 누른다.
→ T5가 확인하고 자료를 모은다.
→ 출처가 있는 분석 결과를 만든다.
→ 필요하면 보고서와 반복 감시까지 이어 간다.
```

연결 센터의 완성은 카드가 많아지는 것이 아니다. **한국 사장이 기술 연결을 배우지 않고도, 대화에서
부탁한 일을 실제 결과까지 맡길 수 있게 되는 것**이다.
