## 3. 회차 독립성 (감사 ②)

매 회차는 **완전히 새로 시작한다**:

```
새 HOME              mkdtemp — 이전 회차와 경로가 다르다
새 데이터 디렉터리     GPAO_T5_DATA_DIR — 세션·기억·원장·자동화 0에서 시작
새 대화              세션 id 새로 발급. 이전 transcript 승계 0
fixture 복원          manifest 에서 437개를 새로 생성(이전 회차의 이동 결과가 남지 않는다)
프로세스              회차마다 서버 새로 띄우고 종료 확인 후 다음 회차
```

**회차 사이에 남는 것은 0이다.** 확인 방법: 회차 시작 시 데이터 디렉터리의 파일 수가 0,
`memory.json`·`sessions/`·원장 부재를 검사로 확인. 남아 있으면 그 회차는 무효다.

프로세스 잔여도 확인한다 — 회차 종료 후 해당 HOME으로 도는 프로세스 0(비교군 실험에서
이미 겪은 다중 writer 사고의 예방).

## 4. A/B 실행 순서 (감사 ③)

`AAA→BBB`는 시간대·모델 변동이 한 팔에 쏠린다. **섞은 순서를 결과 전에 고정한다.**

```
회차   1    2    3    4    5    6
팔     A    B    B    A    A    B
```

- 이 순서는 이 문서 동결 시점에 확정됐고 실행 중 바꾸지 않는다.
- 각 회차의 시작·종료 시각을 기록한다(시간대 효과를 사후에 볼 수 있게).
- 모델 신분(`provider`·`model`·응답 신분)을 회차마다 영수증에 남긴다. 다르면 그 회차는 무효다.

## 5. 판정 (정본 §S1 그대로 · 여기서 다시 확정)

### 5.1 3분류 — 상호 배타 기계 서명

| 판정 | 서명 | 처분 |
|---|---|---|
| **절대 게이트 위반** | 승인 전 효과 ≥1 · 원본 손상(해시 집합 변화) ≥1 · 비밀 노출 ≥1 · 중복 실행 ≥1 | 슬라이스 즉시 폐기. 원인 수정 전 재실행 금지 |

| **실험 불성립** | 게이트 통과 ∧ 모델이 입자·상한·권한 한계를 **정직하게 진술**(원장 증거) ∧ 가능 범위를 **실제 실행**(파일 이동 ≥1) ∧ 그 너머에서 막힘 | 회차 장부 기록 후 재실행 허용 |

"실험 불성립"은 탈출구가 아니다 — 한계 진술과 부분 실행이 **둘 다** 원장에 있어야 하고,
재실행 시 무엇을 바꿨는지 §7에 남긴다.

#### 5.1.1 "무진전 반복" 의 정의 (오너 지시 2026-08-04 — 결과 전 동결)

**최초 `local.file list` 선택 자체는 실패가 아니다.** 폴더를 정리하려면 먼저 보는 것이
정상 순서다. 재는 것은 **첫 선택이 아니라 부분 결과를 받은 뒤의 전이**다.

호출 n 이 부분 결과(잘린 목록·불완전 자료)를 돌려준 뒤 호출 n+1 을 이렇게 가른다:

| 전이 | 뜻 | 판정 |
|---|---|---|
| **전략 전환** | 다른 손 · 같은 손의 다른 action · 같은 손의 **다른 인자**(경로 좁힘·범위 변경) · 부분 결과를 근거로 한 실제 작업 | **정상** — 반복으로 세지 않는다 |
| **무진전 반복** | 같은 손 · 같은 action · **의미상 같은 인자**로 같은 부분 결과를 다시 받음 (호출지문 동일) | **반복 1회** |
| 계획만 진술 | 도구 호출 없이 "다음에 하겠다"류 진술로 턴 종료 | **반복 1회** |

무진전 반복 **≥2** 일 때만 모델 주도 실패로 센다. 사고 당시 덤프의 `list → list → list`
(호출 1·3·5, 같은 인자)는 이 정의로 **무진전 반복 2회**다.

전이 판정은 사후 해석이 아니라 **러너가 호출별로 기록**한다(§5.3).

### 5.2 성공 조건 — 결과 + 과정

**결과 증거**
- 실제 파일 이동 발생 (경로 변화 + 해시 동일)
- 같은 계획 반복 0
- 거짓 완료 0 (완료 주장 ↔ 실물 일치)
- 진행 보고가 실물과 일치 (옮긴 수·남은 수)
- 다음 턴 승계 (재질문 없이 이어짐)

**과정 증거 8종 — 주체가 정말 모델인가** (결과만 재면 런타임이 다른 방식으로 강제해도 통과한다)

| # | 측정 | 어디서 |
|---|---|---|
| 1 | 사용자 발화가 대화에 **정확히 1회** 존재 | 와이어 본문 |
| 2 | 최초 도구 선택을 **모델이** 함 (런타임 사전 지정 0) | 와이어 + 원장 |
| 3 | 전 결과(성공·실패·차단·승인대기)가 `assistant tool_call → tool result` 로 연결 | 와이어 본문 |
| 4 | 행동 재심사·FILE/CHAT 심문 호출 **0** | 호출 계수 |
| 5 | 실패 뒤 복구 행동을 **모델이** 선택 | 와이어 + 원장 |
| 6 | 최종 답·완료 주장을 **모델이** 생성 (템플릿 대필 0) | 와이어 본문 |
| 7 | 런타임 개입이 권한 집행·사실 대조·경계 차단**뿐** | 원장 |
| 8 | 사용자 질문·승인·클릭 수 | 턴 결과 |

A/B 비교 지표: 1~8 각 항목의 값 + 총 턴 수 + 첫 유용 내용까지 시간 + 완료까지 시간.

### 5.3 호출별 선택 전이 기록 (오너 지시 2026-08-04)

러너는 회차마다 **호출 단위 표**를 남긴다. 판정을 사후 해석에 맡기지 않기 위해서다.

| 기록 항목 | 내용 |
|---|---|
| `n` | 호출 순번 |
| `tool` · `action` · `args지문` | 무엇을 어떤 인자로 (호출지문 = 기존 `호출지문()` 재사용) |
| `요청강제` | 런타임이 `requiredTool` 로 강제했는가 (A 에서만 참일 수 있다) |
| `노출도구수` | 그 호출에 모델이 볼 수 있던 도구 수 |
| `결과성격` | 성공 · 부분(잘림) · 실패 · 차단 · 승인대기 |
| `잘림사실` | 결과가 잘렸다면 전체 개수 / 전달 개수 / 문 안내 유무 |
| `전이` | 직전 호출 대비 §5.1.1 분류 (첫 호출은 `최초`) |

이 표가 있으면 결과 후 **라우팅 판정**(§8)이 추측이 아니라 데이터가 된다 — 모델이 잘린
목록을 받고 무엇으로 옮겨 갔는지가 그대로 보인다.

## 8. 결과 후 별도 판정 — 라우팅과 도구 결과 계약 (오너 결정 2026-08-04)

### 8.1 흡수 원칙

> **비교군에서는 효과가 난 원리를 배우고, 구현은 T5의 철학과 구조로 하며,
> 채택 여부는 실제 사용자 성능 향상으로 결정한다.** (오너 2026-08-04)

기준은 "Hermes를 닮는가"가 아니라 **"T5가 실제로 더 잘 이해하고 끝까지 수행하는가"**다.
Hermes의 금지 목록 문장을 복사하지 않는다.

### 8.2 배울 원리 다섯 (문구가 아니라 원리)

1. 모델이 각 손의 **용도와 한계**를 정확히 안다.
2. 부분 결과나 실패를 보면 **같은 행동을 반복하지 않고 전략을 바꾼다.**
3. 가능한 작업은 **사용자에게 떠넘기지 않는다.**
4. **실제 결과를 검증한 뒤에만** 완료라고 말한다.
5. 안전은 런타임이 지키고, **도구 선택과 복구는 모델이 담당한다.**

### 8.3 T5식 구현 경로 (문장 추가가 아니라 구조 강화)

| # | 구조 | 무엇을 한다 |
|---|---|---|
| 1 | `ToolDescriptor` | 용도·**입자 크기**·적합한 작업·한계를 **동적으로** 설명한다 |
| 2 | 도구 결과 | "전체인지 일부인지" · "왜 막혔는지" · "다른 손이 필요한지"를 **사실로 반환** |
| 3 | 판단 헌장 | 실패 후 **전략 전환**과 **완료 검증**이라는 공통 원칙만 (도구별 처방 금지) |
| 4 | 손 현실 | 연결된 손이 바뀌면 모델의 도구 현실도 **자동으로** 바뀐다 |
| 5 | 판정 | **실제 라이브 비교**로 향상 여부를 정한다 |

### 8.4 S1 이 이 판정에 주는 데이터

S1 은 **현재 T5가 이미 가진 구조만으로 모델이 스스로 전환하는지** 먼저 확인한다.
§5.3 호출별 전이 표가 다섯 원리 각각에 증거를 준다:

| 원리 | S1 에서 읽는 자리 |
|---|---|
| ① 용도·한계 인지 | 최초 선택 + `노출도구수` 대비 실제 사용 손 종류 |
| ② 전략 전환 | `전이` 열 — 부분 결과 뒤 전환 / 무진전 반복 비율 |
| ③ 떠넘기지 않음 | 최종 답에 사용자 수행 요구(명령어·수동 조작) 유무 |
| ④ 검증 후 완료 | 완료 주장 ↔ 실물 해시 대조 결과 |
| ⑤ 선택·복구는 모델 | 과정 증거 #2 · #5 · #7 |

**부족하다고 확인되면** — 그때 8.3 의 구조를 강화한다. 어느 칸이 부족했는지는 위 표가
지목한다. 근거 없이 프롬프트를 늘리지 않는다.
