## §4. 공통 계약

### §4-0. TurnRef — 전 표면 공통 불변 turn 신분 (F1)

- 턴 경로(웹 일반 `/turn`·SSE·채널)는 저장 시점에 세션 파일 안에서 단조 증가하는
  `turnSeq`를 발급하고, transcript 항목·ledger 항목·TurnEvent에
  `turnRef = {sessionId, turnSeq}`를 새긴다(수정 허용 구역 ③·④).
- 관찰 파이프라인의 정확히-한-번 계약은 **세션 단위**다: watermark는 단일 값이 아니라
  `{sessionId → lastProcessedSeq}` 지도이며 파생 산출물과 한 원자 쓰기로 갱신된다.
  세션 간 전역 순서는 요구하지 않는다(관찰 파생은 세션 내 순서만 필요하고, 묶음 단계가
  세션 횡단 병합을 멱등 ID로 수행한다 — 이 비요구를 계약에 명시해 "전역 순서 부재"가
  숨은 가정이 되지 않게 한다).
- 늦게 저장된 턴: turnSeq는 세션 파일 쓰기와 같은 원자 단위로 발급되므로 세션 내 역전이
  없다. 새 세션 발견: 워커는 매 pass에 세션 저장소를 열거한다.
- 반대시험: 같은 턴 이중 처리 0(멱등 ID 충돌 검출) · 크래시 후 재개 시 누락 0 ·
  채널·웹 턴이 같은 turnRef 계약을 갖는지 스키마 검사.

### §4-1. 응답 뒤 경계 — v2 유지 + 판정 분리·실패 격리

- 불변식(구조): T-cell은 턴 경로에 코드를 추가하지 않는다(단 §4-0의 turnRef 발급은 턴 경로의
  **허용된 유일한 추가**이며 O(1) 필드 기입이다 — diff로 감사). 관찰은 durable 산출물의
  소비자, 기존 tick의 워커, 세션 큐 미점유, `withMemory`만 사용.
- 성능 판정(실측): H 계측기 재사용, T-cell 활성 전후 **p95 턴 완료시간 +5% 이내**를 S2·S4
  완료 조건으로. "1ms" 문구는 철회한다 — 구조 불변식과 성능 판정은 별개 검사다.
- tick 실패 격리(§3 지적): T-cell 워커는 자동화 tick과 같은 스케줄러를 쓰되 독립 오류
  경계로 감싼다 — 한쪽 예외가 다른 쪽 실행을 막으면 실패. 워커 연속 실패 3회면 자체
  격리(비활성 + 표면 사람말 경고 + 원장 기록). 반대시험: 워커 강제 예외 주입 시 자동화
  tick 정상 동작, 그 역도 성립.

### §4-2. 발화 신분과 내용의 구성적 결합 (F2)

의미 검증기를 만들지 않는다(2축 — 규칙이 의미를 판단하지 않는다). 대신 **결합을 구성으로
보장한다**:

- auto_reversible 승격이 저장하는 statement는 **utteranceQuote 그 자체(원문 그대로)다.**
  모델의 요약·정규화·확장 statement는 auto 경로에서 금지되며, 그런 제안은 기존 확인 통로
  (카드/명시 확인)로 강등된다. 인용과 내용이 다를 수 있는 자유도 자체를 제거한다.
- 검증(기계): quote가 이번 턴 사용자 원문의 부분 문자열 ∧ statement === quote ∧
  kind=preference ∧ 민감값 게이트 통과. speechAct 판단은 모델의 것.
- 표면·입장: "기억했어요: '<사용자 원문 그대로>' · 되돌리기". `[반영된 기억]`에도 원문이
  들어간다 — 모델은 사용자의 말 그대로를 근거로 받는다(요약 왜곡 원천 제거).
- 반대시험: v2의 4형(질문·인용·부정·회상) auto 0 유지 + **statement≠quote 제출 시 auto 강등**
  + quote 부분 문자열 위조(과거 턴 문장) 시 거부.

### §4-3. 실질 replay — 실행 증거가 있는 수명주기 (F3)

- **ReplayCase 스키마**(후보마다 저장):
  `{caseId, principleId, kind(positive|negative|boundary), sourceRefs[turnRef…] — 실제 과거
  턴 계보, input(당시 사용자 원문·당시 admitted 목록), baselineFacts(당시 실제 응답·결과
  발췌 digest — 저장소에서 조회 가능해야 함), run{modelCallReceipt(원장 ref — §4-6 신분 검증
  포함), outputDigest}, verdict{pass|fail, rationale, citedCaseRefs}}`.
- **`replay_passed` 전이의 OS 가드**(기계 — 이것 없이 전이 불가):
  ① 모든 case의 sourceRefs가 실제 저장소에서 해석된다(계보 실존)
  ② 모든 case에 run.modelCallReceipt가 있고 §4-6 신분 검증을 통과했다(실제 실행됨)
  ③ 표본 기준 충족: positive ≥2 · negative 0(존재하는 반례 케이스에서 후보가 모순을
    만들지 않음) · boundary ≥2에서 침범 0
  ④ verdict.citedCaseRefs ⊆ 실제 caseId 집합(허공 인용 금지)
  ⑤ 케이스가 부족하면 승격 불가(표본 없음 = 통과 아님).
- 의미 판정(pass/fail 자체)은 모델의 것이며 rationale과 함께 기록된다 — OS는 실행·계보·
  신분·표본을 증명하고, 의미 오판의 안전망은 제한 입장(influenceScope)+S5 효과 감사다.
  이 분업을 계약에 명시한다.
- 반대시험: receipt 없는 케이스로 전이 시도 → 거부 · 계보 미해석 케이스 → 거부 ·
  표본 미달 → 거부 · verdict가 없는 caseRef 인용 → 거부.

### §4-4. 보임·주장·상관의 3층 효과 추적 (F4 — v2 `appliedMemoryRefs` 철회)

`admitted = applied` 오류를 이름에서부터 제거한다:

- **shownMemoryRefs**(사실): `[반영된 기억]`에 들어간 항목 ID — 프롬프트 입장 사실만 주장.
- **modelCitedRefs**(모델 주장): 새 통제 채널 `memory.cite {usedRefs}` — 모델이 이번 판단에
  실제로 쓴 기억을 자가 보고. 검증: usedRefs ⊆ shownRefs(허공 인용 거부). 이것은 **주장**
  으로 라벨링되어 저장된다.
- **correctionCorrelation**(통계): 사용자 정정 턴에서, 직전 턴의 shown∩cited 항목에
  상관 표식을 남긴다. **감쇠는 독립 상관 ≥2회부터**, 단발 감쇠 금지. 감쇠는 가역(원장·
  표면 노출·복원 가능).
- 완료 조건 정정: S5의 "무관 기억 오폭 0"은 반대시험으로 증명한다 — shown이지만 uncited인
  항목만 있던 턴의 정정 → 감쇠 0 · 상관 1회 → 감쇠 0 · cited이자 상관 2회 → 감쇠 발생.
- 정직 표기: 모델의 실제 내부 사용은 관측 불가능하다. 이 계약은 "사실(shown)·주장(cited)·
  통계(correlation)"를 이름으로 구분해 그 한계를 시스템에 새긴다.

### §4-6. 백그라운드 모델 호출의 실제 신분 검증 (F5)

구성 이름이 아니라 **호출 하나하나의 실체**를 증거로 만든다:

- 성장 호출 receipt(원장 저장)에 기록: 요청 connection id + 실제 요청 endpoint host +
  요청 model id + **응답이 보고한 model 신분** + usage. (P8: 라벨-실체 괴리 이력이 근거)
- 가드: 응답 model이 요청 model과 정확히 일치하지 않으면 그 호출의 산출물(요약·후보·
  verdict)은 **격리되어 어떤 전이의 증거로도 쓸 수 없고**, 성장 파이프라인은 자체 중단 +
  표면 경고(§4-1 격리와 같은 계약). fallback으로 다른 연결·모델이 잡힌 경우도 동일.
- 자격: 전경과 같은 저장 구성만 사용, 새 자격 경로·env 신설 금지. 입력 위생(민감 검출)·
  도구 0·예산(아래 §4-10)은 v2 유지.
- §4-3의 replay 전이 가드 ②가 이 검증을 참조한다 — 신분 미검증 receipt는 replay 증거 자격이
  없다.
- 반대시험: 응답 model 불일치 주입 → 산출물 격리·전이 거부·경고 발생.

### §4-7. ActiveWorkLane scope 신분 (F6)

- `scopeRef = {userRef, workspaceRef, artifactRefs}`
  - **userRef**: 채널 = channelUserId, 웹 = 로컬 단일 오너 신분(명시 상수) — "웹은 사용자
    신분이 없다"를 없애고 단일 사용자임을 계약으로 새긴다. 같은 userRef면 다른 표면이라도
    승계 후보 공급 가능(같은 사람), userRef 다르면 절대 미공급.
  - **workspaceRef**: 작업의 실제 대상 루트 — receipt의 파일 경로에서 파생(파일 손 허용
    루트 기준 상대화). 다른 workspaceRef의 lane은 공급하지 않는다.
  - **artifactRefs**: 산출물의 신분 `{path, digest}` — "최종본"이 가리키는 실체를 경로+내용
    digest로 특정한다.
- 원천 정정(재감사 지적): lane의 사실 필드(subject·artifactRefs·workspaceRef)는 **receipt
  (실행 사실)에서만** 파생한다. `activeGoal`은 모델/계획 산물이므로 durable 사실로 승격하지
  않고, lane에 `assumedLabel`(추정 표시)로만 부기한다 — "모델 추정의 durable 승격 금지"와
  정합.
- scope 미상(파생 불가) 항목은 **기본 거부**(공급 안 함).
- 반대시험: 같은 표면 다른 workspace lane 미노출 · 같은 userRef 채널↔웹 승계 공급 ·
  userRef 불일치 미공급 · artifact digest로 "최종본" 특정.
