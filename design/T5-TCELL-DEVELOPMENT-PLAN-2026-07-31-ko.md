## §0. 한 문단 요약

T-cell은 기억 기능이 아니라 **"추적 가능한 작동원리가 언제 행동에 영향을 줘도 되는가"를 다루는
기관**이다. 현재 코어에는 이미 그 골격 — 후보(candidates)·승격 단일 통로(confirmCandidate)·
입장 단일 관문(admittedContext)·기억 원장·rollback — 이 있다. 비어 있는 것은 네 곳이다:
① 가역 기억의 무마찰 반영과 1턴 철회(H01·H04 실패의 원인), ② 응답 뒤 백그라운드 관찰
(after-response 훅 부재), ③ 대화 경계를 넘는 작업 승계(세 제품 공통 미해결 — T5 차별 목표),
④ 실질 replay와 사후 교정(현재 runReplay는 문자열 부정형 검사 1개). 이 계획은 그 네 곳을
**기존 관문을 넓히는 방식**(매듭)으로 채우며, 슬라이스마다 사용자 문장 하나의 실제 끝이
달라지는 것으로만 완료를 판정한다.

## §3. 원칙 번역 (설계 불변식)

1. **retrieved ≠ admitted** — 관찰·회수는 영향 0. 입장은 `admittedContext` 단일 관문만.
2. **자동성이 의무** — 가역 로컬 기억은 승인 카드 없이 반영한다. 안전은 원장·표면 되돌리기·
   사후 교정으로 만든다. (실측: 카드가 지킨 위험 0 ×3회)
3. **admission 경계는 유지·강화** — OpenClaw H07 실측(비밀 원문 durable 저장)이 반례다.
   민감 경계(dab56f6)·observed 레인 차단·모델 추정 비승격은 회귀 금지선.
4. **현재 지시가 항상 우선** — 입장된 기억은 사실 공급이지 지시가 아니다. H03·H06 회귀 검사가
   모든 슬라이스의 통과 조건에 포함된다.
5. **전경 예산 0** — T-cell로 인한 전경 추가 모델 호출 0, 턴 내 durable I/O 추가 0.
   관찰·학습·정제는 응답 후 비동기 + 기존 tick(`AutomationScheduler`)에서만.
6. **모델 판단 비침범** — 런타임은 후보·근거·상태를 공급하고 해석은 모델이 한다. 키워드
   분기·서비스별 처방·자동 판정을 넣지 않는다. (승계 후보도 "이어받을 수 있는 작업" 사실로
   나열할 뿐, 어느 것을 잇는지는 모델이 판단)
7. **나비 방지** — 틀린 사실 공급은 공급 부재보다 나쁘다. 모든 입장 항목은 출처(세션·턴·
   원장)와 함께 들어가고, 반대시험은 "틀린 후보가 입장되면 드러나는가"를 포함한다.

## §4. 공통 계약 (구현 전 고정 — 감사 대상)

- **ObservationEvent**: receipt·TurnEvent에서 파생하는 관찰 단위
  `{eventId, at, sessionId, kind(repeat|correction|failure|success|preference_use), subject,
  evidence(receipt/발화 digest 참조), scopeRef}`. 저장은 memory.json 별도 레인
  `observations`(상한·감쇠), **admittedContext가 절대 읽지 않는 레인**(observed와 동급 차단).
- **ActiveWorkLane**: 세션당 파생 요약
  `{laneId, sessionId, subject(대상 파일·산출물·목표), state(fresh|active|suspended|done),
  lastReceiptRefs, updatedAt}`. 원천은 receipt·activeGoal — 모델 추정을 durable로 승격하지
  않는다(2축). 새 대화 조립 시 최근 lane 목록이 "이어받을 수 있는 작업" 사실 블록으로 공급.
- **기억 등급(admission tier)**: promoted 항목에
  `{tier(auto_reversible|confirmed|principle), influenceScope, decay, provenance}` 추가.
  tier별 입장 규칙: `auto_reversible`(무마찰 반영분)은 표면 되돌리기 상시 노출,
  `principle`은 실질 replay 통과 필수.
- **철회 채널**: 모델 통제 `memory.withdraw {target(statement|candidateId), reason}` —
  실행 도구가 아니라 propose와 같은 통제 채널. 런타임은 promoted/candidates에서 대상 특정,
  tombstone(closed)·원장 기록·표면 확인 문구.
- **실질 replay**: 원리 후보에 대해 과거 세션에서 positive(도움)·negative(모순)·boundary
  (무관 개입) 사례를 재생 판정. 판정자는 모델(백그라운드 호출), 런타임은 사례 선정·결과
  기록만. 통과 기준·표본 수는 계약에 고정(초안: p≥2, n=0, b 침범 0).
- 저장 스키마 변경은 migration + 손상 격리(기존 memory-store 관례) 동반.

## §5. 슬라이스 (순서 고정 — 각각 사용자 문장 하나가 달라져야 닫힘)

### S1. 무마찰 가역 기억 — "기억해줘"와 "취소해줘"가 한 턴에 끝난다

- 범위: `memory.withdraw` 채널 신설(접점 3) · 명시 선호 발화의 auto_reversible 승격
  (카드 제거, 발화 자체가 확인 — 단 **민감값·observed·비가역 영향은 기존 차단 유지**) ·
  표면 "기억했어요 · 되돌리기" 사후 노출 · H04의 오라우팅(기억 취소→파일 되돌리기 카드) 제거.
- 완료: H01 카드·클릭 0 반영 + 원장 `proposed→auto_promoted` · H04 1턴 철회·말-상태-원장
  일치 · H07 회귀 PASS · H03/H06 회귀 PASS.
- 반대 검증: 민감값 포함 선호가 auto 승격되면 실패하는 시험 · withdraw 대상 모호 시 후보
  나열(임의 선택 금지) 시험 · 카드 제거가 A2/A3 승인 경계를 건드리지 않는 시험.
- 라이브: 실제 서버·브라우저·gpt-5.1로 H01·H04 3회.

### S2. 응답 뒤 백그라운드 관찰 (shadow · 행동 영향 0)

- 범위: 턴 완료 후 비동기 ObservationEvent 적재(접점 4·5) · 같은 현상 묶음(원문·반례 보존) ·
  전경 지연 계측(턴 시간 회귀 검사).
- 완료: 사용자 가시 변화 **의도적으로 0** — 이 슬라이스만 예외적으로 "전경 실측 무변화 +
  관찰 적재 증거"가 완료 기준(다음 슬라이스들의 생산 경로 전제). 감사가 이 예외를 명시 승인해야 진행.
- 반대 검증: observations 레인이 admittedContext·프롬프트에 절대 안 들어가는 시험 ·
  전경 turn 시간 회귀(기준선 대비) 시험 · 크래시 시 관찰 유실이 턴 정합성을 해치지 않는 시험.

### S3. 대화 경계 승계 — "아까 그 최종본 이어서"가 새 대화에서 통한다

- 범위: ActiveWorkLane 파생·저장 · 새 대화 조립 시 lane 사실 블록 공급(접점 2, 입장 관문
  경유) · "이어서/아까 그" 판단은 모델(후보 나열 원칙).
- 완료: H05-new 성공(경로·ID 추측 0) · H06 무관 불개입 회귀 PASS · 이미 끝난 작업을 과도
  되살리는 반대 시나리오 PASS · 재시작 승계(기존 성공) 회귀 유지.
- 반대 검증: 후보 둘 이상일 때 임의 선택 없이 후보 제시 · suspended lane 자동 이어받기 금지 ·
  다른 scope의 lane 미노출.

### S4. 반복 경험 학습과 실질 replay — 3회 반복 뒤 새 대화에서 다시 묻지 않는다

- 범위: 관찰 묶음→원리 후보 제안(백그라운드 모델 호출, tick 경유) · `runReplay` 실질화
  (접점 1, §4 계약) · tier `principle` 제한 입장 · 성숙도(통계)와 행동 권한 분리.
- 완료: H02 시나리오(3회 반복→새 대화) 재질문 0 · 한 사례의 전역 규칙화 0(boundary replay가
  잡는 반대 시험) · H03 회귀 PASS.
- 반대 검증: 반례가 있는 후보가 승격되면 실패 · replay 미통과 원리가 입장되면 실패 ·
  백그라운드 호출이 전경 턴을 지연시키면 실패.

### S5. 사후 교정·성장 — 잘못 배운 것이 스스로 약해진다

- 범위: 적용된 기억·원리의 효과 감사(사용자 정정·재발 관찰) · 자동 감쇠·격리 ·
  표면 철회 UX(기억 찾기·되돌리기) 정리.
- 완료: 사용자 정정 뒤 같은 오적용 재발 0(라이브 시나리오) · 감쇠·격리가 원장에 남고
  표면에서 확인 가능.
- 반대 검증: 정정이 무관 기억까지 약화시키지 않는 시험 · 격리 항목의 입장 0 시험.

각 슬라이스 종료 시: 작업지시서 §6 다층 검증(계약·회귀·반대·통합·실제 모델·인간 시나리오·
변수복구·표면 도달) 증거 지도 제출 → Codex 독립 감사(문제 일괄 제출·A/B/C 분류) → 다음 슬라이스.

## §7. T-cell 이후 연결 (구현하지 않음 — 순서만)

T-cell(S1~S5) 봉인 → H01~H10 재측정(같은 계측기·gpt-5.1, 전후 비교) → 파일 손 별도 슬라이스

Agent(H10의 위임은 여기) → 이후는 흡수 보충 §16 순서.

## §8. 중단 신호 (하나라도 나오면 슬라이스를 다시 연다)

- 기억·학습 기능이 전경 턴 시간·질문·카드를 늘린다 (제품 회귀 정의)
- 키워드 분기·서비스별 처방·자동 판정이 코드에 들어온다
- observed·observations 레인이 프롬프트에 새어 들어간다
- H07·H03·H06 회귀가 깨진다
- 같은 시나리오가 통과 후 3회 재개봉된다 (§11 정체 회복 발동)

## §9. 종료 조건

S1~S5가 각각 위 완료·반대 검증·라이브 증거로 닫히고, H01~H10 재측정에서 §1 목표가 실측으로
확인되며, 42턴 판정과 같은 기준의 사람 판정이 수치를 뒷받침할 때 T-cell을 봉인한다. 문서·
테스트 수는 완료 근거가 아니다 — **사용자 문장의 끝이 달라졌는가만 근거다.**
