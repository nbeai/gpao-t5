## §0. 한 문단 요약

T-cell은 "추적 가능한 작동원리가 언제 행동에 영향을 줘도 되는가"의 기관이다. v2는 v1의 방향에
**구현 가능성**을 더한다: 응답 뒤 경계를 실측된 실제 구조(durable 산출물의 소비자) 위에 다시
정의하고, 사용자 선언의 신분 계약으로 자동 승격을 좁히며, 관찰→후보→replay→입장→감사→감쇠의
생산 상태기계와 재시작 계약을 명시하고, 적용 추적·저장 정직성·백그라운드 모델 신뢰 경계를
계약으로 고정한다. 재발 유형이었던 정본 투영 누락은 이 계획과 함께 기계 검사
(`npm run audit:docs`, 반증 시험 5건 포함)로 구조화했다.

## §3. 원칙 번역 (설계 불변식 — v1 유지 + 강화)

1. retrieved ≠ admitted — 관찰·회수는 영향 0. 입장은 `admittedContext` 단일 관문만.
2. 자동성이 의무 — 가역 로컬 기억은 카드 없이 반영, 안전은 원장·되돌리기·사후 교정으로.
3. admission 경계 유지·강화 — OpenClaw H07 실측이 반례. 민감 경계(dab56f6)·observed 차단·
   모델 추정 비승격은 회귀 금지선.
4. 현재 지시 항상 우선 — 입장 기억은 사실 공급이지 지시가 아니다. H03·H06 회귀 전 슬라이스 통과 조건.
5. 전경 예산 0 — §4-1의 기계 증명 방식으로 검사한다.
6. 모델 판단 비침범 — 후보·근거 나열, 해석은 모델. 키워드 분기·자동 판정 금지.
7. 나비 방지 — 모든 입장 항목은 출처와 함께. 반대시험에 "틀린 후보 입장 시 드러남" 포함.

## §4. 공통 계약 (구현 전 고정 — 감사 대상)

### §4-1. 응답 뒤 경계의 실제 정의 (v1 재발 1 교정)

"응답 뒤"를 코드 위치가 아니라 **불변식**으로 정의한다:

> T-cell 관찰·학습·정제는 턴 경로(`runAndPersistTurn` 본체·꼬리)에 코드를 **추가하지 않는다.**
> 관찰 파이프라인은 이미 저장된 durable 산출물(세션 파일·기억 원장)의 **소비자**이며(P2),
> 기존 tick(P3)에서 워커로 동작한다.

- 소비 계약: 워커는 `{lastProcessedRef}` watermark(관찰 레인 메타에 지속)를 읽고, 그 이후의
  세션 턴·원장 항목을 상한 N개까지 처리한 뒤 결과와 watermark를 **한 원자 쓰기**로 남긴다.
- 재시작·checkpoint: 크래시 시 watermark 이전으로만 되돌아간다. 모든 파생(ObservationEvent·
  묶음·후보)은 원천 참조 기반 결정적 ID로 멱등 — 재처리해도 중복이 생기지 않는다.
- 전경 예산의 기계 증명: (a) S2 diff가 턴 경로 파일들을 건드리지 않음을 감사가 diff로 확인
  (b) 기준선 대비 턴 시간 회귀 계측(기존 H 계측기 재사용) (c) 워커는 세션 큐를 잡지 않고
  `withMemory`만 사용(교착 반대시험 포함).

### §4-2. 발화 신분 계약 (v1 재발 2 교정)

자동 승격(auto_reversible)은 다음이 모두 성립할 때만 열린다:

1. 모델이 `memory.propose`에 `evidence: {utteranceQuote, speechAct: 'declaration'}`를 제출.
   speechAct 판단은 모델의 것(2축) — 런타임은 판단을 대체하지 않는다.
2. 런타임의 기계 검증: `utteranceQuote`가 **이번 턴 사용자 원문의 부분 문자열**인가(원문 보존
   대조 — P4의 원문이 진실). 아니면 auto 불가, 일반 후보로 강등.
3. kind = `preference`만 auto 가능. `operating_principle`·`recalled_context`는 기존 통로(확인
   또는 replay) 유지. 민감값 게이트(dab56f6)는 auto 경로에도 그대로 걸린다.
4. 반대시험 고정(전부 auto 승격 0이어야 통과): 질문형 "내가 목록으로 해달라고 했었나?",
   인용형 "친구가 '목록이 좋다'더라", 부정형 "표로 하지 말라는 건 아니야", 과거 회상형
   "예전엔 목록으로 했었지". 오판 시 안전망: 표면 "기억했어요·되돌리기" 상시 노출 +
   `memory.withdraw` 1턴 철회 + S5 효과 감사.

### §4-3. 생산 상태기계와 수명주기 (v1 재발 3 교정)

```
observation(영향 0, 감쇠·상한)
  → bundle(같은 현상 묶음 — 원문·반례 보존, 결정적 bundleId)
  → candidate(kind=operating_principle, 영향 0)
  → replay_pending → replay_passed | replay_failed(사유 보존)
  → admitted(tier=principle, influenceScope 제한)
  → effect_audit(적용 추적 기반, §4-4)
  → decayed | quarantined | withdrawn(사용자 철회)
```

- 전이 규칙: 모든 전이는 `withMemory` 직렬화 안의 원자 쓰기 + 현재 상태 가드(멱등) +
  `MemoryLedger` 기록. 전이 주체는 워커(tick) 또는 사용자 행동(확인·철회)뿐.
- 재시작: 상태는 전부 memory.json 레인에 durable — 워커는 재기동 시 각 항목의 현재 상태에서
  재개한다. `replay_pending`에 걸린 채 크래시 → 다음 tick에 같은 항목을 다시 집는다(멱등).
- 상한·감쇠: observations·bundles는 상한과 시간 감쇠를 계약에 고정(무한 성장 금지, §18 계열).
  수치는 구현 시 제안하고 감사가 확인한다.

### §4-4. 적용 추적 (신규 차단 교정)

- `[반영된 기억]` 블록에 들어간 항목의 ID 목록을 턴 증거(evidenceFacts)와 세션 원장에
  `appliedMemoryRefs`로 기록한다 — "이번 행동에 어떤 기억이 영향 줬는가"가 조회 가능해진다.
- S5 효과 감사는 이 trace로 정정을 귀속시킨다: 사용자 정정 턴에서 직전 턴의
  appliedMemoryRefs에 있던 항목만 감쇠 후보가 된다(무관 기억 오폭 방지 — 반대시험).

### §4-5. 저장 정직성 (신규 차단 교정 — P5)

- `MemoryStore.load()` 손상 시: 손상 파일을 격리 사본으로 보존하고, 상태에 `corrupted` 표식을
  올리며, 표면에 사람말 경고("기억 저장소에 문제가 있어 복구 전까지 새 기억을 반영하지
  않아요")를 낸다. **조용한 빈 상태 반환 금지.** 복구(격리본 확인·복원)는 표면에서 가능.
- 반대시험: memory.json을 일부러 깨뜨림 → 빈 상태 위장 없이 경고·격리·기존 promoted 비손실.

### §4-6. 백그라운드 모델 호출 신뢰 경계 (신규 차단 교정)

- 용도: bundle 요약·원리 후보 제안·replay 판정만. **도구 접근 0** (판정 전용 호출).
- 입력 위생: 백그라운드 프롬프트 페이로드 전체에 민감정보 검출(dab56f6 `containsSensitiveValue`)
  적용 — 감지 시 해당 조각 제외·기록. 비밀·자격은 어떤 경로로도 백그라운드 프롬프트에 넣지 않는다.
- 예산: tick당 호출 상한·일일 상한·kill switch(env)·모델 식별자와 usage를 원장에 기록.
  provider는 전경과 같은 구성만 사용(별도 자격 경로 신설 금지).
- 반대시험: 상한 초과 시 중단·이월, 비밀 포함 조각의 프롬프트 미유입.

### §4-7. ActiveWorkLane (신규 차단 교정 — scope 완결)

`{laneId, scopeRef{surface, channelUserId?, sessionOrigin}, subject, state(fresh|active|
suspended|done), lastReceiptRefs, provenance, updatedAt, ttl}`

- 원천은 receipt·activeGoal(모델 추정의 durable 승격 금지). 다른 scope의 lane은 조립에
  공급하지 않는다(채널·사용자 격리 — 기존 session origin 기준). suspended 자동 이어받기 금지,
  후보 2개 이상이면 나열(임의 선택 금지), TTL 경과 시 자연 재확인.

### §4-8. 수정 허용 영역 (v1 "접점 5곳"의 재정의 — 신규 차단 교정)

책임 영역으로 정의하고, 금지 구역을 명시한다(둘 다 감사 가능):

- **허용**: ① 기억·맥락 kernel(context-mesh, user-model, memory-store, model-control)
  ② 신규 T-cell 모듈(`src/kernel/l5-growth/tcell-*.js` 신설) ③ `server.js`의 기억 API·워커
  배선 구간 ④ l0-evidence 계약 확장(receipt 필드·TurnEvent) ⑤ `model-provider.js`의
  `[반영된 기억]` 렌더 ⑥ 웹 표면의 기억 UX ⑦ 테스트·스키마 migration
- **금지**: 턴 루프의 판단·도구 선택 로직(`turn.js`의 계획·실행 분기), 도구 실행기,
  승인 경계(authority), 파일 손(file-scope·locate — 별도 슬라이스 소유), 자동화 엔진의
  A3 계약. 금지 구역 diff가 생기면 그 슬라이스는 감사에서 자동 차단.

### §4-9. 정본 투영의 기계 검사 (v1 재발 4의 구조적 종결 — 구현 완료)

`npm run audit:docs`(`scripts/audit-docs.mjs`, 반증 시험 5건)가 진입 정본의 경로 투영·상태
선언 단일성·계획 지위의 인수인계 투영·퇴역 토큰 잔재를 기계로 검사한다. 이 계획을 포함한
모든 정본 변경 커밋은 이 검사를 통과해야 한다(작업 관례 + gate 편입은 감사 합의 후).

## §5. 슬라이스 (순서 고정 — 완료는 사용자 문장의 실측 변화)

### S1. 무마찰 가역 기억 + 저장 정직성 — "기억해줘"·"취소해줘"가 한 턴에 끝난다

  H04 오라우팅 제거 · §4-5 저장 정직성 · 표면 "기억했어요·되돌리기".
- 완료: H01 카드 0 · H04 1턴 철회(말·상태·원장 일치) · H07/H03/H06 회귀 PASS ·
  §4-2 반대시험 4형 전부 auto 0 · §4-5 손상 반대시험 PASS. 라이브 3회(gpt-5.1).

### S2. 응답 뒤 관찰 (shadow) — §4-1 소비자 워커
