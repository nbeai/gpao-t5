## 0. 왜 마크다운인가 (정직한 한계)

샌드박스 브라우저의 스크린샷을 저장소에 바이너리로 커밋하는 경로가 없다. 그래서 시각 증거를
**재현 절차 + 각 상태의 실제 렌더 내용**으로 남긴다. 아래 절차대로 `npm start` 후 그대로 재현되며,
감사자는 브라우저에서 직접 눈으로 확인할 수 있다(실행 감사 원칙).

## 1. 재현 절차

```bash
npm start          # http://localhost:4173
```

각 상태 입력:

| 상태 | 입력 | 조작 |
| --- | --- | --- |
| A 빈 첫 화면 | (없음) | 로드 직후 |
| B 단순 대화 | `안녕, 오늘 좀 피곤하네.` | 전송 |
| C 복합+근거 | `경쟁사 뉴스 조사해줘` | 전송 → "작업 기록" 펼치기 |
| D 인라인 승인 | `이 소식 슬랙에 올려줘` | 전송 → 승인 카드 |
| E 승인 후 실행 | (D에서) | [승인] → 답 + 작업 기록 |
| F 실행 불가 안내 | `이 초안 메일로 보내줘` | 전송(메일 발송 미준비) |
| G 차단 복구 | `이 페이지 차단된거 가져와줘` | 전송 → 미확인 + 다음 안전 행동 |

## 2. 상태별 렌더 명세 (라이브 확인)

### A · 빈 첫 화면 (데스크톱 1280×800)
- 좌: 사이드바 — `T5 GPAO-T5` 브랜드 + 검색(⌕) / 접힌 나브(더 보기·스킬·배운 작업·연결·자동화) /
  `＋ 새 대화` / 세션(`Work Chat · 지금`) / 하단(연결 점·설정·테마).
- 상단: `GPAO-T5 › Work Chat` 브레드크럼 + 우측 `준비됨` 칩.
- 중앙: 넓고 빈 조용한 채팅.
- 하단: `＋ GPAO-T5에게 메시지 입력` [보내기] / 아래 `beai5-stub · 준비됨` … `말하면 일이 이어집니다`.
- 판정: 대시보드 아님. 채팅이 전부. 상태는 칩으로 접힘. ✔

### D · 인라인 승인 카드
- 사용자 버블(우, 세이지): `이 소식 슬랙에 올려줘`.
- 대화 안 카드: **실행 전 승인이 필요해요** / `· 슬랙 게시 [A2] — 슬랙 게시 실행 (되돌릴 수 있음)` /
  [승인] [보내지 마].
- 판정: 모달 아님, 흐름 안 카드. 내부 id(`slack.post`) 비노출, 라벨 `슬랙 게시`만. ✔

### E · 승인 후 실행 + 접힌 작업 기록
- `GPAO-T5` 답: `확인한 것: 슬랙에 게시했어요.`
- 접힌 고기능: `▾ 작업 기록 · 도구 1개` → 펼치면 `확인: 슬랙에 게시했어요.`
- 판정: 답과 근거 분리·한자리. 승인은 재해석 아니라 보관된 계획 이어받음. ✔

### 모바일 (375×812)
- 사이드바가 햄버거(☰)로 접힘. 브레드크럼·상태칩 유지. 채팅 전폭. 하단 입력 유지. 작업 기록 접힘.
- 판정: 반응형 성립. ✔
