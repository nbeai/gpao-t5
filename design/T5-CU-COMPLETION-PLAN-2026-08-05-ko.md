**작성 2026-08-05 · 오너 지시로 착수**

## 1. 오늘 배운 것 — **결함은 일곱이 아니라 계열 여섯이었다**

증상별로 고쳤더니 **같은 계열이 다른 자리에서 또 났다.** 오늘 하루에 계열마다 2~3번씩.
그래서 이 계획의 뼈대는 칸(G/H/I/J) 나열이 아니라 **계열 봉쇄 → 그 위에서 칸**이다.

| 계열 | 무엇 | 오늘 몇 번 |
|---|---|---|
| **A · 신선도** | 신분(토큰·스냅샷·pid·앱목록)이 낡는데 그대로 쓴다 | 3 (F-38 · `list_apps` 낡음 · focus 실패) |
| **B · 사실 덮기** | 드라이버가 밝힌 것을 우리 추측으로 덮는다 | 3 (`refused` · `unverifiable` · `Missing required`) |
| **C · 없는 것 ↔ 못 본 것** | 조용한 0 과 그 거울상 | 3 (거르개 0 · 권한 게이트 · 값 못 찾음) |
| **D · 판정 두 벌** | 같은 질문에 두 곳이 다른 답 → 그 사이로 걸음이 빠진다 | 2 (F-34 · `rm -rf` 구멍) |
| **E · 문구로 재기** | 낱말·형태로 판정한다 | 2 (완료 주장 과거형 · 종류 필터) |
| **F · 하나 막히면 전부** | 갈 곳 없는 막힘 · 답 통째 갈아치우기 | 3 (F-32 · A02 후보 없음 · 웹 기본 문구) |

## 2. 계열 봉쇄 — **이 계획의 핵심**

각 계열마다 **구조 하나 + 그물 하나.** 그물은 "그 계열을 되살리면 문다"로 세운다.

### A · 신분은 **한 벌로만** 만든다
지금은 토큰·스냅샷·pid·창을 손 여러 곳에서 조립한다. **`신분(관찰, 대상)` 단일 함수**로 모으고,
그 밖에서는 못 만들게 한다. 신분은 **마지막 관찰**의 것이어야 한다.
*그물*: 조립 자리가 둘이 되면 문다 · 앞 회차 스냅샷을 쓰면 문다.

### B · 드라이버 답은 **한 자리에서 읽는다**
`거절인가()` 를 넓혀 **`드라이버답(r) → {거절 | 확인됨 | 모름 | 값}`** 하나로 만든다.
손은 그 넷만 본다. 우리 전후 추측은 **드라이버가 아무 말도 안 했을 때만** 쓴다.
*그물*: `refused`·`Missing required`·`unverifiable`·`launch_state` 각각을 되돌리면 문다.

### C · 빈 것은 **왜 빈지 함께** 낸다
목록을 내는 모든 자리가 `{총, 전체, 왜0}` 를 함께 낸다(거르개는 이미 함).
*그물*: 전체>0 인데 총0 이면서 이유가 없으면 문다.

### D · 판정은 **단일 진입점**
면제·분류·대조 각각 한 함수. 두 번째 판정자를 금지한다.
*그물*: 같은 질문을 두 곳에서 답하면 문다(오늘 `turn.js` 지름길이 그 모양이었다).

### E · 문구로 재는 자리를 **원장·구조로 옮긴다**
남은 자리를 먼저 **목록으로 만들고**(세는 것이 먼저다) 하나씩 이관한다.
*그물*: 새 문구 판정이 들어오면 문다.

### F · 막힘은 **다음 수를 반드시** 싣는다
*그물*: 막힘에 `다음수단`·`후보`가 없으면 문다.

### G · **옆에서 같이 한다 — 사용자 것을 안 뺏는다** (오너 지적 2026-08-06)
비교군(Hermes)이 축으로 세운 것인데 **내 계획에 통째로 없었다.**
그리고 **오늘 실측이 이미 된다는 것을 보여줬는데 내가 못 알아봤다** —
Finder 를 앞에 둔 채 계산기를 눌렀더니 `1 → 14` 로 들어갔다(배경 조작).
그래 놓고 몇 시간 뒤 오너께 *"컴퓨터 쓰시면 부딪힙니다"* 라고 답했다.
**손이 이미 안 뺏는데 뺏는다고 말한 것**이다.

이건 기능 하나가 아니라 **CU 의 성격을 가르는 축**이다 —
*"사용자 대신 컴퓨터를 뺏는 기능"* 인가 *"옆에서 같이 하는 기능"* 인가.

- 커서·앞 창·포커스를 **행동의 부작용으로 바꾸지 않는다.**
  `focus` 는 사용자가 그걸 시켰을 때만이고, 누르기가 그것을 끌고 오지 않는다.
- 값을 넣을 때는 **`set_value`** 를 먼저 쓴다(드라이버에 이미 있는데 손이 안 쓴다).
  네이티브 메뉴를 여는 클릭은 포커스를 뺏는다 — 비교군이 그래서 이 손을 따로 뒀다.

*그물*: 누르기·입력이 앞 창을 바꾸면 문다 · 값 넣기가 `set_value` 를 건너뛰면 문다.

> **이 일곱이 서기 전에는 새 칸을 열지 않는다.** 오늘 배운 것이 그것이다.

## 3. 슬라이스 — 순서·크기·각각의 닫는 문장

착수할 때 **첫 줄에 닫는 문장과 크기를 적는다.** 라이브에서 나온 결함은
**그 문장에 닿는 것만** 그 자리에서 고치고 나머지는 장부로 보낸다.

| # | 이름 | 크기 | 닫는 문장 |
|---|---|---|---|
| **CU-1** | 계열 봉쇄 + 안 뺏기 | Standard | 오늘 일곱 결함을 **코드로 되돌리면 각 계열의 그물이 문다** · 누르기가 앞 창을 안 바꾼다 |
| **CU-2** | 다른 앱 셋 | Standard | **메모·Finder·Safari** 에서 사람 문장이 끝까지 간다(사진 대조) |
| **CU-3** | 성능 | Lite | 클릭 한 번 **1,579ms → 800ms 이하**, 정확도는 안 떨어진다 |
| **CU-4** | E 의 나머지 | Standard | *"이 메일 보내줘"* → 새 상대면 한 번 확인, 아는 상대면 안 묻는다 |
| **CU-5** | 잠금(A21·A22) | Lite | 잠긴 화면에서 실행 0, 그 사실을 정확히 말한다 |
| **CU-6** | 배포(I) | Standard | 설치본만으로 CU 가 선다(cua 동봉·서명·권한 안내) |
| **CU-7** | 다른 OS | Lite | 계약은 OS 를 안 가린다 — **실측은 오너 환경이 필요하다**(정직하게 남긴다) |
| **CU-8** | 사람 시험(J) | 오너 | 오너가 실제로 쓰고 막힌 자리를 말한다 |

**CU-3(성능)은 CU-1 의 부산물이다.** 관찰 3회 중 둘은 A 계열 때문에 생긴 중복이다 —
신분을 한 벌로 모으면 관찰도 한 번으로 준다. 따로 최적화하지 않는다.

## 4. 비목표 — **안 한다**

- **G · 브라우저 통합** — T5 는 이미 웹 손이 있다. CU 로 브라우저를 또 모는 건 중복이고,
  같은 일을 두 길로 하면 판정도 두 벌이 된다(계열 D). 필요해지면 그때 연다.
- **som 모드 · 좌표 클릭** — 토큰으로 눌린다는 것이 실측으로 확인됐다. 안 쓴다.
- **스크린샷 상시화** — 모를 때만. 켜는 스위치도 두지 않는다.
- **새 반대시험 발명** — 정본 A01~A22 로 충분하다. 부족하면 그때 근거와 함께 올린다.

## 5-A. 비교군 대조 — **정정 하나**(2026-08-06)

오너가 준 비교군 문서는 *"권한이 cua-driver 자기 신원(`com.trycua.driver`)에 붙으니
T5 를 무엇이 띄우든 상관없다"* 고 한다. **우리는 그렇지 않다.** 오늘 실측한 귀속:

```
"attribution": "host", "embedded": false, "direct_runtime": true
"note": "Embedded mode: these booleans reflect the HOST app's TCC grant"
```

**드라이버 자기 신원이 아니라 호스트 신원을 물려받는다.** 그래서 F-30(누가 띄웠느냐에 따라
권한이 다름)이 우리에겐 **아직 안 사라졌다.** CU-6(배포)·CU-7(다른 OS)에서 정면으로 만난다.
그때 *"드라이버가 자기 신원을 갖게 할 것인가"* 를 정한다 — 지금 정하지 않는다(범위 밖).

비교군 넷의 실제 상태:

| | 상태 |
|---|---|
| ① som(번호 오버레이) | **안 함.** 토큰 클릭이 실측으로 되니 우선순위 낮다 — 안 한다(비목표) |
| ② 백그라운드 조작 | **된다**(실측). 다만 **축으로 안 세웠다** → 계열 G 로 세운다 |
| ③ `max_elements`+`total`·`truncated` | **이미 함**(`요소창{총·전체·다음·거르개가못물었다}`) |
| ④ `set_value` | 드라이버에 있는데 **손이 안 쓴다** → 계열 G 에서 채택 |

## 6. 비교군 공부 — 질문 넷, 자리 지정, 시간 상자

*(오늘 소스를 열어 놓고 흩어졌다. 그건 헤매기다. 질문을 못 박고 들어간다.)*

소스: `~/Developer/lab_un/openclaw-pure-2026-07-20/src` · `~/Developer/lab_un/hermes-agent`

| 질문 | 왜 |
|---|---|
| ① 도구 결과가 **낡았을 때** 어떻게 다루나 | 계열 A 가 우리 최다 결함이다 |
| ② **확인 못 한 것**을 사용자·모델에게 어떻게 말하나 | 계열 B·C |
| ③ 한 과업이 **여러 앱**에 걸칠 때 어떻게 나누나 | CU-2 가 그것이다 |
| ④ 관찰·왕복을 **어떻게 줄이나** | CU-3 |

**시간 상자: CU-1 착수 전 한 번, 질문 넷에 답이 나오면 끝.** 답이 안 나오면 "없다"고 적고 나온다.
이미 흡수한 것(승인 재사용 3계약 · live test 패턴 · `max_elements`+`total`/`truncated`)은 다시 안 판다.

### 공부 결과(2026-08-06 · 실물 grep)

| 질문 | 답 |
|---|---|
| ① 낡은 결과 | **없다.** Hermes 코어에 CU 관련 `stale`·`snapshot` 처리가 0건. cua 안에 있고 우리가 원본을 직접 읽었다 |
| ② 확인 못 한 것 | **없다.** `unknown never implies success` 는 cua 계약이고 이미 흡수했다 |
| ③ 여러 앱 과업 | **없다.** `toolset_distributions.py` 는 *데이터 생성용 툴셋 확률 분포*지 과업 분해가 아니다 |
| ④ 왕복 줄이기 | `trajectory_compressor` · `context_compressor` — **컨텍스트 압축**이지 CU 왕복이 아니다. **S9 자료**로 넘긴다 |

**결론: 비교군은 CU 계약을 갖고 있지 않다.** 코어에 화면 조작 코드가 0줄이라는 오너 판정이 맞다.
그러니 **CU-1~CU-4 에서 비교군에서 더 가져올 것은 없다.** 이 절은 여기서 닫는다 — 다시 안 판다.

## 7. 반복 금지 장치

- 착수 첫 줄에 **닫는 문장 + 슬라이스 크기**. 없으면 착수 아님.
- 라이브 결함은 **닫는 문장에 닿는 것만** 그 자리에서. 나머지는 장부.
- 갈림 기준: **뚫는 일**(§0 위반 — 떠넘김·거짓 성공·있는 걸 없다고 함)은 지금,
  **넓히는 일**(새 칸·통합·계약 정리)은 다음 슬라이스.
- 한 슬라이스가 **반나절을 넘으면 그 자체가 신호다** — 멈추고 오너에게 상태를 알린다.
