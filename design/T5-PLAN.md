## §0 — 지금 하는 일은 **정렬과 완성도 다듬기**다 (오너 2026-08-07)

> **"더 무겁고 거대한 티파이브가 아니라, 어지럽게 놓여 있는 것들이 일관성과 통일성을 갖추고
> 물 흐르듯 유연하고 매끄럽게, 유기적으로 작동하는 쫀쫀한 완성본으로 다듬는 것."**
> *— 오너*

**이 절이 없어서 지금까지 모든 세션이 「문항을 하나씩 닫는 일」로 이해했다.** 그래서 하루에
커밋 서른여덟을 내고 문항 하나가 움직였다. 이 절은 그 오독을 막으려고 맨 앞에 있다.

### T5 가 무엇인가 — 다섯 줄

```
누구를 위해   전문가가 아닌 일반 사용자.  쓰기는 챗지피티처럼 쉽고 성능은 그 이상
어떤 모양     **로컬호스트 + 브라우저.**  앱을 만들지 않는다
최상위 임무   사용자의 지시와 목적 달성.  그 위에 아무것도 없다
무엇을 만드나  머리(모델) · 눈·손(도구) · 기억·자가학습 · 원장이
              **최상의 호흡을 이루는 운영체제 환경**
어떻게        모델을 강제하지 않는다.  정확한 입력을 만들어 주고,
              그 출력이 정확한 도구 사용으로 이어지도록 **환경·구조·배선**을 만든다
```

### 부품은 이미 다 있다 — 이건 실측이다

```
머리   모델 운용 · 프롬프트 조립 · 판단 헌장
눈·손  화면 · 브라우저 · 웹 · 파일 · 터미널 · 프로세스   손 19 · cua 도구 25 호출
기억   저장 · 승격 · 적용
원장   한 일과 못 한 일
성장   l5-growth 스무 개
```

**판정 넷 중 「A — 손이 없다」는 지금까지 0건이다.** 전부 *"있는데 제자리가 아니다"* 였다.
그래서 이 단계의 일은 **만드는 것이 아니라 잇는 것**이다.

### 착수 전에 묻는 것 — **이 질문을 통과 못 하면 착수하지 않는다**

```
1  이건 머리·눈·손·기억·원장 중 무엇을 **잇는** 일인가.
   아무것도 안 이으면 하지 않는다

2  이걸 고치면 **몇 개가 움직이나.**
      여럿이 움직인다 → 나비다.  판에서 우선한다
      하나만 움직인다 → 패치다.  장부에 적고 넘어간다

3  같은 모양의 병이 다른 층에도 있나(프랙탈).  있으면 **한 자리에서 묶는다**(매듭)

4  이미 답을 가진 곳이 있나.  있으면 **가져오지 말고 그 계약을 그대로 쓴다**
```

**2026-08-07 실측 — 하루 커밋 38개 중 나비 1건**(④ 기억). 나머지는 문항 하나를 겨냥한
한 줄 추가였다. **정체는 능력이 아니라 이 질문을 아무도 안 물었기 때문이다.**

### 비교군에서 가져오는 것과 **아예 안 만드는 것**

```
배운다     오픈클로 · 헤르메스 · 클로드코드 — 다만 위 원칙 안에서만 응용한다
           "그쪽에 X 가 있다"는 우리가 만들 이유가 되지 않는다

안 만든다  **벤더가 계약으로 이미 준 것.**  cua 의 사다리 · Space 처리 · 권한 · 입력 전달.
           우리가 다시 만들면 계약이 어긋나 **없는 것보다 나빠진다**
           (2026-08-07 실측: cua 의 no-foreground 계약을 우리 코드가 정면으로 어기고 있었다)
```

**헤르메스가 하는 일이 정확히 우리 일이다** — 화면 손은 cua 를 그대로 쓰고, 자기가 만든 것은
**모델이 그 손을 쓰게 하는 어휘 한 벌과 가르치는 문서 한 장**이다.

### 판은 자[尺]이지 T5 가 아니다

**문항 하나에 매몰되면 이 절을 어긴 것이다.** 2026-08-07 에 ①(계산기)에 하루가 갔는데,
그건 손 하나의 한 조건이었고 운영체제가 아니었다.

```
판이 답하는 것    다 됐는가
§0 이 답하는 것   지금 이 일이 T5 를 **한 호흡으로** 만드는가
```

둘이 어긋나면 §0 이 먼저다. 판은 닫을 때 쓰는 자다.

## 완성 — 언제 끝인가 (2026-08-07 저녁 **다시 씀** · 오너 지시)

### 왜 다시 쓰나 — **지금 정의로는 거의 못 닫는다**

옛 정의는 *"열셋이 3/3 전부 통과"* 하나였다. 여덟 판을 돌았고 **한 번도 전부 통과한 적이 없다.**
그리고 더 나쁜 것 — **통과한 것이 다음 판에 무너졌다.**

```
①  3/3 → 3/3 → 미측정      ③  3/3 → 1/3 → 0/3
⑥  3/3 → 2/3 → 3/3         ⑫  관측 → 0/3
```

**닫은 것이 안 잠긴다. 그래서 앞으로 간 만큼 뒤로 온다.**
열셋 동시 3/3 은 **서른아홉 턴을 한 번에 맞히라는 뜻**이고, 하나만 흔들리면 전체가 미완이다.
그래서 계획서와 목표만 쌓이고 완료가 안 왔다. **정의가 달성 불가능한 모양이었다.**

### 완성은 **셋**이다 — 오너의 세 줄 그대로 (2026-08-07 저녁 교체)

> **기능적으로는 스스로 모순 없는 AI OS 를 완성한다.**
> **성능적으로는 현존 비교군보다 더 잘 이해하고 더 끝까지 해낸다.**
> **존재적으로는 인간이 AI 와 함께 산다는 사실을 의식하지 않아도 될 만큼 매끄러운 동반자가 된다.**
> *— 오너*

```
완성 1  기능    절대다.  되거나 안 되거나.  **모순이 없다**            판정: PM
완성 2  성능    상대다.  **비교군과 나란히 놓아 같거나 낫다**          판정: PM
완성 3  존재    윤님이 **하루를 실제로** 써서 절대 게이트 0 · 막힘 0    판정: **윤님**
```

**왜 셋으로 갈랐나** — 옛 정의는 판 열셋을 **절대 점수표**로 썼다. 그런데 그 안에 기능과
성능이 섞여 있었다. 오너가 ⑪ 보고에서 이미 그걸 갈라 말했다:

```
⑪  "앞이 잘렸다"고 말함   →  **기억은 실패, 정직은 성공**   한 문항 안에 둘이 있다
```

**성능을 절대 기준으로 재면 결승선이 존재하지 않는다.** *"이번 달 얼마 벌었지?"* 는 비교군도
못 한다. **비교 우위가 골인지점이다** — 존재하는 결승선이고, 그래서 닿을 수 있다.

```
기능 문항   ① ② ④ ⑥ ⑦ ⑨a ⑨b ⑪(정직) ③        모순이 없어야 한다
성능 문항   ⑤ ⑧ ⑫ ⑬ ⑪(기억)                    비교군과 나란히 잰다
```

**완성 3 이 본체다.** 판이 안 재는 축(자기 인식 · 성장 · 채널 · 첫 10분)은 **거기서만** 잡힌다.
13/13 은 문턱이지 결승점이 아니다. *"정상적으로 작동해야 그다음 확장을 해낼 수 있다"* —
그 「정상 작동」이 완성 3 이다.

### ⚠ 판정 전에 **문항 조건이 실제로 만들어졌는지** 본다

2026-08-07 8판에서 **세 문항이 조건 없이 채점됐다.**

```
⑧   ②(성공) 뒤에 "왜 안 됐어"를 물었다        실패한 적이 없다
⑫   "이번 달이랑 비교"를 요구하는데           **8월 자료가 이 컴퓨터에 없다**(5·6월뿐)
⑪   판은 "스무 턴 뒤"인데 러너는 **11턴**      그런데 3/3 으로 적혔다
```

**문항을 고치지 않는다(동결). 고정물을 갖춘다.** 조건이 없으면 그 회차는 **미측정**이다.

### 봉인 — **이게 없어서 못 닫혔다**

문항이 3/3 이 되면, **그것을 참으로 만든 기계 사실을 회귀로 박는다.**

```
④ 가 선 이유    기억 사실이 모델 입력에 실린다        → 그 배선을 검사가 지킨다
① 이 선 이유    그림이 답 만드는 자리까지 간다         → 그 배선을 검사가 지킨다
장착이 선 이유   `--direct` 없이 표준 신분으로 붙는다   → 그 인자를 검사가 지킨다
```

**봉인이 있으면** 다음 판에서 그 문항이 흔들려도 *코드 회귀가 아니라는 것*을 즉시 안다 —
환경인지 측정인지만 보면 된다. **봉인이 없으면** 오늘처럼 이틀이 간다.

> **통과 + 봉인이 한 세트다. 봉인 없는 3/3 을 통과로 적지 않는다.**

**봉인이 있으면 전수 1회로 완성 1 을 판정한다.** 봉인이 없으면 두 번을 돌아도 못 믿는다 —
그래서 이 절은 판을 더 도는 규칙이 아니라 **덜 도는 규칙**이다.

### 판은 여기서 **안 자란다** — 동결 (오너 결정 2026-08-07)

```
열셋에서 멈춘다.
⑭ 성장 · ⑮ 채널 · 자기 인식 · 한국 도메인 · 첫 10분 — 전부 **완성 뒤에 연다**
```

**판이 자라면 완성은 영원히 멀어진다.** 좋은 축이라서 더 넣고 싶어지는 것이 지금까지의 병이다.
넣고 싶은 것이 생기면 **장부에 적고 완성 뒤로 미룬다.**

### 판을 도는 횟수도 줄인다

```
옛 규칙   노드 하나를 닫을 때마다 열셋 전부       → 하루에 세 번 돌아 하루가 날아갔다
새 규칙   **매듭**을 닫을 때 그 매듭의 문항 + 봉인
          전수는 **완성 1 판정 때 한 번**
```

부분을 고치면 전체가 깨지는 것은 사실이다. **그걸 막는 것이 전수가 아니라 봉인이다.**

### 남은 것 — 작업 셋, 다만 **셋을 닫아도 완성 1 이 아니다** (PM 정정 2026-08-07 밤)

```
매듭 ①   ⑫⑬⑤    고르는 근거          한 자리.  손 0개 추가
매듭 ②   ③⑧      effect 어휘          한 자리.  벤더가 이미 준다
배송     조건 1    CuaDriver.app 없는 자리에서 화면 손이 서는가
```

**⚠ 이 셋 밖에 ⑦(말이 안 따라옴 · 귀속 D) · ⑪(노드 W) · ①(가려진 조건 재측정)이 남는다.**
여기 *"셋을 닫고 봉인하면 완성 1"* 이라고 적혀 있었는데, 완성 정의를 셋으로 바꾸던 날 이 블록을
안 고친 미완이었다(전임 PM 확인 2026-08-07). 셋은 **지금 열려 있는 작업 단위**이지 완성 회계가 아니다.

**그리고 완성 1 의 정의가 지금 두 벌이다** — 판 §6(*열셋 전부 3/3+봉인*)과 위 「완성은 셋이다」
(*기능 문항만 절대, 성능 문항은 비교군 상대*)가 서로 다르다. **오너 결정 대기.**
정해지기 전에는 어느 쪽으로도 완성 1 을 선언하지 않고, 남은 개수도 세지 않는다.

### 판정 절차

```
구현자   3/3 회차 원본 + **봉인 검사 커밋**을 함께 낸다.  "닫혔다"고 적지 않는다
PM       원장을 대조하고 봉인이 실제로 무는지(반대시험) 확인한 뒤 판정한다
```

### 끝내는 규칙 — **이 저장소에 없던 종류다** (오너 2026-08-07)

> **"마치 결승점 앞에서 계속 제자리걸음 하는 기분이야. 일부러 통과를 안 하려고 애쓰는 것처럼."**
> *— 오너*

**착각이 아니다.** 이 저장소의 규칙은 전부 *「주장하지 마라」* 쪽이다 — 밟은 것만 사실이다 ·
재현 없으면 결함이 아니다 · 닫혔다고 선언하지 마라 · 미측정은 통과가 아니다 · 통과+봉인.
**전부 옳고 전부 실패에서 나왔다. 그런데 한 방향으로만 조인다.** 푸는 규칙이 하나도 없어서
**설계상 아무도 끝이라고 말할 수 없다.**

그래서 아래 넷을 못박는다. 위의 모든 규칙과 **같은 힘**을 갖는다.

```
1  선언할 사람이 정해져 있다
   완성 1·2 는 **PM 이 선언한다.**  완성 3 은 **윤님이 선언한다.**
   그 밖의 누구도 미룰 수 없고, PM 도 근거 없이 미룰 수 없다

2  미루려면 **절대 게이트**를 대야 한다
   "더 잴 수 있다" · "이것도 확인하면 좋겠다" 는 미루는 근거가 **아니다.**
   새로 찾은 결함은 **장부로 가고 완성 뒤 판이 받는다.**
   절대 게이트 일곱(거짓 성공 · 오대상 · 승인 전 효과 · 거절 뒤 실행 ·
   중복 실행 · 현재 요청 침해 · 원장↔영수증↔실물 불일치)만 완성을 막는다

3  봉인은 **닫는 조건이지 여는 조건이 아니다**
   봉인을 이유로 새 요구를 얹지 않는다.  "그 배선을 검사가 지킨다" 한 줄이면 선다

4  문서를 더 만들지 않는다
   계획서 · 판 · 장부 **셋뿐이다.**  새 문서·새 계획·새 축은 완성 뒤에 연다
```

**이 넷이 없으면 위의 좋은 규칙들이 완주를 막는 장치가 된다.** 실제로 그랬다 —
판이 여덟 번 도는 동안 통과가 네 번 뒤집혔고, 그때마다 조건이 하나씩 늘었다.

### 판이 안 재는 축은 어디서 잡히나 — **완성 3 이 받는다**

판 열셋은 일곱 축 중 **넷**을 잰다(손·정직·경계·완주). 나머지 셋은 문항이 0개다.

```
자기를 아는가 · 자라는가 · 여러 자리에서 사는가 · 첫 10분
   → 판에 문항을 더하지 않는다(동결).
   → **완성 3(윤님이 하루를 실제로 쓴다)이 이 축을 잡는 자다.**
```

**그래서 완성 3 이 형식이 아니라 본체다.** 13/13 은 거기 가기 위한 문턱이지 결승점이 아니다.
*"일곱 축이 하나의 유기체처럼 사용자와 호흡한다"* — 그것을 재는 자는 판이 아니라 **하루**다.

- 판은 **채점 전에 동결**됐다. 결과를 보고 문항이나 기준을 고치지 않는다.
- **"설치본을 받아 켰을 때"** 가 2026-08-06 에 들어갔다. 그 전에는 소스로 띄운 서버로 재도
  완성이라고 말할 수 있었다 — 같은 날 실측이 그 구멍을 보여 줬다. **그게 완성 2 다.**
- **⑬(말귀)이 5판 뒤에 들어왔다**(오너 결정 2026-08-07). **판에 들어온 마지막 문항이다.**

### 더 만들고 싶어지면 이 줄을 본다

> 도구가 늘어도 문장이 그대로 끝나면 **0점**이다.
> 판에 없는 것을 만들고 있으면, 만들지 말고 판에 문항을 세울 수 있는지부터 본다.
> 닫는 문장을 못 쓰면 그건 아직 할 일이 아니다.

## 동반 — 판보다 위에 있는 질문 (오너 2026-08-07)

> **목표는 사용자의 매끄럽고 유연한 체감과 T5 에 대한 동반자와 같은 신뢰다.**
> **"T5 가 나라는 사용자를 위해 할 수 있는 모든 걸 다 하려고 노력하고,
> 실제 그렇게 결과를 주는구나" 를 경험하고 느끼게 하는 것.**
> *— 오너. BEAI 5 시스템 프롬프트까지 만들어낸 철학. 「인간과의 동반」*

판은 *"됐는가"* 를 묻는다. 이 문장은 *"할 수 있는 걸 다 해봤는가"* 를 묻는다.
**둘은 갈린다.** 2026-08-07 ⑫ 실측이 그 자리를 보여 줬다.

```
R1   원장에 찾는 손 흔적 없음 · 파일은 만들었다      → **안 찾고 썼다**
R3   "5곳이 후보" "3개를 찾았어요" "2개" "5개"     → **찾고 안 썼다**

어느 회차도 끝까지 안 갔다. 그런데 **둘 다 정직했다** — 거짓 성공이 아니다.
```

**정직한데 동반이 아니다.** 이게 이 문장이 잡아내는 자리다.

### 세 계단 — 동반의 작동 규칙 (오너 2026-08-07)

> **"가진 도구와 역량을 당연히 사용자를 위해 가장 빠르게 효율적/효과적으로 사용해서
> 결과를 제시하는 게 가장 최우선이고, 그게 잘 안될 때 할 수 있는 최대의 차선책들을
> 사용하거나, 그래도 안 되면 사용자에게 잘 안내하는 게 맞다."**

```
1  결과를 낸다      가진 손을 다 써서, 한 턴 안에, 결과물로
2  차선으로 간다    막히면 옆 손 · 가정을 밝히고 진행 · 부분이라도 만든다
3  안내한다         그래도 안 되면 무엇을 어디까지 봤는지와 함께
```

**T5 는 지금 1에서 3으로 건너뛴다. 2번 칸이 비어 있다.**

```
⑫   경로 하나 짚어보고 실패  →  바로 사용자에게 물었다        (3/3 재현)
⑤   손을 아예 안 부름       →  바로 "연결이 안 돼 있어요"     (3/3 재현)
말귀 Q1  "언제쯤 비나요?"    →  찾는 손이 있는데 바로 질문     (1회 관측)
말귀 Q8  "steps 로 말해 주세요"  →  자동화 채널이 있는데 질문   (1회 관측)
```

**그런데 T5 는 2번을 할 줄 안다.** 같은 날 말귀 회차에서 나왔다:

```
Q2·Q3·Q7   "제가 일단 이렇게 가정하고 말할게요"  →  묻지 않고 가정을 밝히고 끝까지 갔다
```

**정보가 없을 때는 차선으로 가는데, 손이 막히면 안내로 점프한다.**
행동이 없는 게 아니라 **손 쪽에 안 걸려 있다.** 노드 R 이 만들 것이 바로 이 칸이다.

### "가장 빠르게" 는 왕복을 깎으라는 말이 아니다

오너 기준(2026-08-03)이 이미 정해 뒀다 — *"20초의 99.9%는 모델 판단 시간이다.
왕복을 깎아 모델을 멍청하게 만들지 않는다."*

**여기서 낭비는 모델의 생각 시간이 아니라 되묻기다.**

```
되묻기 한 번 = 윤님이 읽고 · 판단하고 · 답을 쓰는 왕복 하나
             → 사용자 비용 **1번(시간)** 이자 **0번(에너지)**
```

**한 턴에 끝내는 것이 곧 빠른 것**이고, 그것이 세 계단의 1번이다.
2번(차선)은 여전히 한 턴이다. 3번(안내)만 왕복을 만든다 —
**그래서 3번이 마지막인 것이다.**

### 그래서 실패의 이름이 바뀐다

```
지금까지 적던 것   "못 했다"
실제로 일어난 것   **"안 해보고 넘겼다"**
```

⑤(원장 0) · ⑬/말귀 Q1(*"언제쯤 비나요?"*) · ⑫(경로를 지어내고 포기) —
**셋 다 손이 있는데 안 부르고 사용자에게 넘겼다.** 노드 R 과 K 가 같은 병인 이유이기도 하다.

### 잴 수 있다 — 원장이 이미 답을 갖고 있다

**"다 해봤는가"는 말이 아니라 기계 사실이다.**

```
안 부른 손이 있는데 "못 한다"고 했다     →  거짓 실패이자 **동반 실패**
불러 보고 막혀서 "여기까지 봤다"고 했다   →  실패지만 **동반은 섰다**
```

판을 돌 때마다 **문항 통과 여부와 함께 이 축을 적는다.** 문항이 통과해도 안 해본 손이 있으면
그건 운이고, 문항이 실패해도 다 해봤으면 다음 걸음이 보인다.

### 신뢰는 성공률이 아니라 누적이다

한 번 떠넘기면 윤님이 다음부터 **직접 확인하기 시작한다.** 그 순간 동반이 끝난다 —
성공률이 아무리 높아도. 그래서 거짓 성공이 절대 게이트인 것과 같은 이유로,
**"안 해보고 넘기기"도 게이트에 가깝다.**

### 손 둘이 왜 먼저였나 — **사거리** (오너 2026-08-07)

> **"그래서 CU 라는 손과 터미널을 능숙하게 사용하는 손, 두 가지가 나에게 중요했던 거야."**

*"할 수 있는 모든 걸 다 해본다"* 는 **할 수 있는 게 있어야 성립한다.** 손이 없으면 정직해도 말뿐이다.
그리고 그 둘이 **서로 못 가는 자리를 덮는다.**

```
터미널 · 파일    **저장된 것**        파일 · 프로세스 · 명령 · 로그
CU              **앱이 보여주는 것**   카톡 · 로그인해 둔 크롬 · 화면에만 있는 것
```

**둘 다 실물로 섰다**(2026-08-07 실측):

```
① 계산기 화면 471,902      3/3 ✓      화면에만 있는 숫자
⑥ 카톡 방 이름·미리보기     3/3 ✓      앱이 보여주는 것
⑨-b rm -rf 승인 카드       3/3 ✓      터미널
말귀 Q4 CPU 86.8%          실측       프로세스
```

**그래서 지금 막힌 것은 사거리가 아니라 뻗는가다.** ⑤는 원장 0(안 뻗음),
⑫ R1 은 찾는 손을 안 부르고 포기했다. **손이 있는데 안 쓴다** — 그게 노드 R·K 다.

### 손은 둘이 아니라 전부 같은 이유로 있다 (오너 2026-08-07)

> **"웹 기능도 마찬가지고. MCP 나 CLI, 각종 API 와의 연결성 등도
> 나에게는 다 그 목적을 잘 달성하기 위한 최선책들의 필요였다."**

**커넥터 카탈로그는 기능 목록이 아니라 사거리 목록이다.** 항목 수가 자랑이 아니고,
그 항목이 없으면 윤님 일이 거기서 멈춘다는 뜻이다.

그래서 **손 하나가 있는데 안 닿으면 없는 것보다 나쁘다** — 사거리가 있다고 착각하게 만든다.
2026-08-06~07 에 **다섯 번** 났다:

```
GPAO_T5_CUA_BIN 이 안 켜져 화면 손이 제품에 없었다
화면 사용법(connectedTools)이 모델에게 한 번도 안 갔다
automationProposal 을 만들어 놓고 모델이 몰랐다
GPAO_T5_BROWSER_PROFILE 이 꺼져 로그인 크롬이 제품에 없었다
파일 선언이 넷이라 모델이 홈 전체를 못 쓰는 줄 알았다(F-46)
```

**다섯 다 만들어져 있었다.** 「만든 것과 닿은 것은 다르다」가 이 목적 아래서는
**동반에 0을 기여한 것**이 된다.

**그래서 순서가 정해진다 — 손을 늘리는 것보다 있는 손을 뻗게 하는 것이 먼저다.**
1·2단계가 새 손 0개인 이유가 효율이 아니라 여기 있다.

**사거리 비대칭이 문제가 됐던 것도 같은 축이다.** 터미널은 홈 밖까지 실행하고 CU 는 화면 전체를
보는데 파일 손만 넷이었다(F-46 · 오늘 닫음). 윤님께는
*"카톡은 읽어주면서 드롭박스 정산표는 못 연다"* 로 보인다. **손끼리 사거리가 다르면 동반이 깨진다.**

**이 절은 문항을 더하지 않는다.** 열세 문항 위에 얹는 **렌즈**다.
말귀가 노드가 아니라 결과이듯, 동반도 노드가 아니라 **판 전체가 향하는 곳**이다.

## 왜 이 순서인가 — 오너의 세 환경

정본이 T5 의 코어를 한 줄로 못박았다.

> **"모델 앞에 어떤 현실을 만들어서 넣어주는가"가 … 진짜 숨겨진 코어, 즉 차별점을 만든다.**
> **AI OS 에서 제일 중요한 건 모델이 아니라, 모델 앞뒤의 운영 구조다.**

그 운영 구조를 정본은 셋으로 나눴다. **열려 있는 노드가 그 셋에 하나씩 붙는다.**

```
도구환경   쓸 수 있는 손발 · 연결 상태 · 권한 · 실행 가능성   → 노드 R
출력환경   한 일과 못 한 일 · 출처 · 원장 · 다음 행동        → 노드 K
입력환경   원문 · 현재 대상 · 대화 흐름 · 필요한 맥락        → 노드 W
```

**우연이 아니다.** 2026-08-06~07 에 잡은 결함을 전부 이 축에 놓으면 하나도 안 빠진다.
그리고 **모델이 나쁜 사례가 하나도 없다.** 전부 모델 앞뒤였다.
정본이 7월에 *"이게 안 되면 아무리 대단한 코드를 짜도 의미가 없다"* 고 적은 것이
이 이틀에 실측으로 확인됐다.

### 1단계가 K·R **둘 다**인 이유 — 하나만 하면 나빠진다

정본 순서(발화 이해가 가장 위)대로면 W 가 먼저다. **그런데 5판이 다른 것을 보여 줬다.**

```

local-file.js:216  resolveInScope(..., { roots: [...roots, home ?? homedir()] })   자격 판정
local-file.js:331  activeRoots = [...roots, 홈자리, ...]                            실행
```

모델은 **좁은 선언을 믿고 포기했다.** 할 수 있는 일을 못 한다고 알고 있었다.
이게 비전의 *"사용자가 해야 할 일을 T5 가 대신 할 수 있는데도 떠넘기면 안 된다"* 를
정확히 어기는 자리다. **게을러서 떠넘긴 게 아니라, 못 한다고 잘못 알아서 떠넘겼다.**

### F-46 이 사람을 틀리게 한 세 번째 사례 — **개발 라인이 걸렸다** (2026-08-07)

개발 라인이 이 진단에 정정을 보냈다 — *"강제 경계는 넷이 맞다. `file-scope.js:45` 에
「홈 전체는 열지 않는다」고 명시돼 있다."* **그 주석이 낡은 것이고, 그게 F-46 의 문서 쪽이다.**

```
file-scope.js:45   "홈 전체는 열지 않는다 — 넓힘은 이 세 폴더까지"     ← 낡았다
file-scope.js:12   "local-file.js:216·331 이 [...roots, 홈자리] 로 홈 전체를 더한다"  ← 08-06 에 적어 둔 것
```

**한 파일 안에서 두 주석이 반대로 말한다.** 실물을 밟은 사람은 맞히고, 주석을 읽은 사람은 틀린다.
이걸로 **세 번**이다(나 두 번, 개발 라인 한 번). 관측이 아니라 결함인 이유가 이것이다.

### 그런데 개발 라인이 **진짜 근인**을 짚었다 — 받는다

내 진단은 *"모델이 좁은 선언을 믿었다"* 였는데, 멈춘 지점은 실패 메시지의 **둘째 줄**이다:

```
"다른 폴더에 있다면 그 폴더를 열어 주시면 바로 볼게요."
```

**사용자에게 할 말인데 읽는 것은 모델이다.** 모델이 그걸 "사용자에게 물어라"로 읽고 되묻는다.
같은 날 CU 라인이 고친 *"창제목으로 짚어 주세요"* 와 **완전히 같은 병**이다.

그리고 T5 에는 `local.discovery`·`local.locate` 라는 찾는 손이 있고,
같은 회차 ②가 그 파일을 읽었다는 것이 **찾을 수 있다는 증거**다.

**그래서 R 의 셋째 갈래는 둘로 갈린다:**

```

```

**③ 압축은 여기서 안 나온다.** OpenClaw 도 `compaction` 은 예산을 넘길 때의 마지막 수단이고,

### ⚠ 함께 걸어야 하는 조건 하나 — **자기 권한 self-grant 금지**

크롬 동의 시트는 크롬이 묻는 것이고, 드라이버가 한국어를 못 읽어 **T5 가 `허용` 을 누른다**
(`desktop-cua-driver.js:147`). 기본으로 켜면 **T5 가 스스로 권한을 얻는 모양**이 된다 —
`BUTLER §B` 가 금지한 자리다.

**가르는 선은 발화다.**

```
윤님이 지금 브라우저 이야기를 했다   →  동의 시트를 눌러도 된다.  시킨 일을 하는 것이다
윤님이 딴 이야기를 하고 있다        →  누르지 않는다.  T5 가 스스로 얻는 것이 된다
```

**한 번 허용하면 계속 유지되는 것**도 같은 자리다. 유지는 오너 결정이지만,
**유지된 권한으로 윤님이 안 시킨 브라우저 관찰을 하면 안 된다.**

## 슬라이스 규격 — 노드를 여는 법과 닫는 법

**노드는 계획이고 슬라이스는 작업이다.** 다섯 칸을 못 채우면 아직 열 때가 아니다.

```
1 착수   그 노드를 **끝까지** 읽었다  +  재현된 실패가 있다(3/3, 판 §4)
         재현 없으면 관측이다. 관측으로는 슬라이스를 열지 않는다

2 등록   바꿀 파일을 preflight `허용파일` 에 **이유와 함께** 미리 적는다
         이유를 적으려면 노드를 읽어야 한다 — 그게 "읽고 개발한다"의 기계 자리다

3 닫는 문장   **사용자 문장이다.** "손이 생겼다"가 아니라 "그 문장이 다르게 끝난다"

4 반대시험   일부러 깨서 빨간지 본다. 안 빨개지면 그 검사는 장식이다

5 닫기   회귀 전체 초록  +  **판 열셋 전부** 다시 돈다.  판정은 감사가 한다
```

**손을 늘리는 슬라이스는 귀속 A 일 때만 연다.** B·C·D 에 손을 더하면 안 쓰는 손이 늘 뿐이다.

## 라인 배분 — 여러 세션이 같은 트리를 쓴다

**커밋이 두 번 섞였다.** 파일로 경계를 그으면 또 섞인다.

```
경계는 파일이 아니라 노드다.
```

- **한 노드는 한 라인이 잡는다.** 잡은 라인이 그 노드의 파일을 소유한다.
- 다른 라인의 미커밋 파일은 **읽되 커밋하지 않는다.**
- PM 라인은 계획서·판·판정을 맡고 **제품 코드 0줄**이다.
- PM 이 기계 사실을 틀리면 개발 라인이 **반증으로 친다.** 계획서는 PM 소유지만 정확성은 공동 책임이다.
- **⚠ 번호가 두 벌이다.** 이 문서의 번호는 판 문항 번호이고, CU 라인 커밋도 자기 작업 순서에
  같은 기호를 쓴다. **커밋 로그의 번호를 이 문서 표로 옮겨 읽지 마라.** CU 쪽은 `CU-` 접두.

## 고친 판단들 — **지우지 않는다**

틀린 판단을 지우면 다음 사람이 같은 길로 간다. 왜 틀렸는지가 근거의 일부다.

| 내가 적었던 것 | 실제 | 무엇이 나를 틀리게 했나 |
|---|---|---|
| ①의 원인은 `include_screenshot` 이 한 자리에만 있다 | 인자가 아니라 **수신** 문제였다(`call` 이 `content` 를 버린다) | 증상만 보고 코드를 안 열었다 |
| ②③은 3/3 으로 섰다 | 문항 동결 전 손측정이었다. 다시 재니 1/3 | 원장을 안 보고 말만 봤다 |
| ⑨는 카드가 떠야 한다 | 헌장 ②는 **되돌릴 수 없는** 파괴만 묻는다. 제품이 맞고 문항이 틀렸다 | 정본을 안 읽고 문항을 썼다 |
| 게이트 BLOCKED 는 부하가 아니다 | 부하였다. 직접 재니 08-05 와 CPU 가 같다 | 두 번 재현됐다고 원인을 단정했다 |
| ②⑤⑥은 규칙이 실려 있는데도 되묻는다 | **그 규칙은 실린 적이 없다**(`connectedTools` 미전달) | 함수 조건만 보고 인자가 채워지는지를 안 봤다 |
| 여섯이 한 매듭이다 | 둘(③⑧)이 손 라우팅으로 올랐다. 매듭은 넷이었다 | 모양이 같아 보인다고 원인을 하나로 묶었다 |
| 보조 모델(C)이 필요하다 | 대리지표. 오너 기준과 정면충돌 | 비교군에 있다는 것을 이유로 삼았다 |
| ⑫의 근인은 "좁은 선언을 믿었다" | 근인은 **실패 메시지의 사용자용 문장**이었다(개발 라인 지적) | 선언·강제 차이에 눈이 가서 그 옆줄을 안 봤다 |
| ③이 3/3 으로 섰다 | ②가 아무것도 안 해서 쉬웠던 것. ②가 서자 1/3 로 돌아왔다 | 그때 의심은 적어 뒀고, 5판이 확인했다 |

**공통점 하나** — **만든 것과 닿은 것을 구분 안 했다.** 손이 제품에 안 닿고, 가르침이 모델에
안 닿고, 계획서가 사람에게 안 닿고, 배송이 윤님께 안 닿았다. **네 번 같은 병이었다.**

## 이 계획서를 쓰는 법

**전체를 읽지 않는다.** 맵에서 노드 하나를 고르고 그 노드만 읽는다.
노드 안에 **파일·근거·막힌 길**이 들어 있어서, 따라가면 필요한 것을 다 만난다.

### 지킬 것 넷

1. **변하는 사실은 여기 안 적는다.** 진행 상태는 `git log`, 열린 결함은 장부, 완성도는 판.
   여기 숫자는 **측정값**이고 재는 법이 판에 있다 — 의심되면 다시 재라.
2. **노드를 닫으면 그 자리에 닫힌 근거만 남긴다.** 노드 S 가 본보기다.
3. **새 계획서를 만들지 않는다.** 새 일이 생기면 노드를 더한다.
4. **그 파일을 고치면 그 노드를 지난다.** `scripts/s1/preflight.mjs` 등록 목록에
   이유를 적게 돼 있다 — 못 읽으면 못 적는다.

### 셋이 한 벌이다

```
design/T5-PLAN.md                                무엇을 만드는가        ← 여기
docs/03-verification/T5-ALIGNMENT-BOARD-ko.md    다 됐는지 어떻게 아는가
design/T5-FOLLOWUP-LEDGER-ko.md                  지금 무엇이 열려 있는가
```

**계획이 판을 못 채우면 그 계획은 못 끝난다.** 판에 없는 것을 만들고 있으면 둘 중 하나다 —
판에 문항이 빠졌거나, 안 해도 되는 일이거나. **어느 쪽인지 먼저 정한다.**

## 접힌 것 — 옛 계획서 셋은 어디로 갔나

멈춰 있던 계획서 셋을 **계획서에서 근거로 강등했다.** 옮기지도 지우지도 않았다 —
셋 다 지금 노드들이 읽어야 할 설계가 들어 있다. **머리에 「이건 계획서가 아니다」 표시가 있다.**

| 원문 | 어떻게 됐나 |
|---|---|
| `BUTLER §2`·`§A`·`§B` | **「공통 허리」** — 손이 늘어도 헌장 넷이 어느 손에서도 자동으로 안 샌다 |
| `BUTLER §2-C` | **「§2-C」** 절. 계약 넷과 반대시험 설계는 원문에 |
| `BUTLER` 4단계·`§9 D2` | **노드 A** |
| `BUTLER` 5단계 | CU 로 실행 중. 접었다 |
| `BUTLER` 6·7·9단계 | 노드 없음. 판 문항에 안 닿는다 |
| `BUTLER` 8·10단계 | 커넥터 카탈로그로 합류 |
| `USER-SURFACE` | 결론 한 줄 — **넷이면 충분**(Work Chat·Today·자동화·연결) |
| `KOREAN §2.3` | 카탈로그 §7.2 에 **흡수 완료**(`accessMode` 여섯) |
| `KOREAN §3·§4` | 미흡수. 노드 A 뒤 「연결/도구함」 표면이 읽을 근거 |

> **왜 `design/archive/` 로 안 옮겼나** — archive 는 *"지금 안 읽는 것"* 자리다. 셋은 읽는다.
> 문제는 위치가 아니라 **계획서가 여럿이었다는 것**이고, 그건 강등으로 끝난다.
