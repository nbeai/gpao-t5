## 완성 — 언제 끝인가

```
사장님이 설치본을 받아 켰을 때, 정렬 판 열두 문항이 3/3 전부 통과
```

여덟이 통과하고 넷이 남으면 안 끝난 것이다. **부분 점수는 없다.**

- **"설치본을 받아 켰을 때"** 가 2026-08-06 에 들어갔다. 그 전에는 *"한 커밋에서"* 뿐이었고,
  그러면 내가 소스로 띄운 서버로 재도 완성이라고 말할 수 있었다. 같은 날 실측이 그 구멍을
  보여 줬다 — 소스에서는 화면 손이 서고 설치본에는 없었다. **5판에서 이 조건이 처음 충족됐다.**
- 판은 **채점 전에 동결**됐다. 결과를 보고 문항이나 기준을 고치지 않는다.
- 판은 **노드 하나를 닫을 때마다 열둘 전부** 돈다. 부분을 고치면 전체가 깨진다.

### 더 만들고 싶어지면 이 줄을 본다

> 도구가 늘어도 문장이 그대로 끝나면 **0점**이다.
> 판에 없는 것을 만들고 있으면, 만들지 말고 판에 문항을 세울 수 있는지부터 본다.
> 닫는 문장을 못 쓰면 그건 아직 할 일이 아니다.

## 왜 이 순서인가 — 오너의 세 환경

정본이 T5 의 코어를 한 줄로 못박았다.

> **"모델 앞에 어떤 현실을 만들어서 넣어주는가"가 … 진짜 숨겨진 코어, 즉 차별점을 만든다.**
> **AI OS 에서 제일 중요한 건 모델이 아니라, 모델 앞뒤의 운영 구조다.**

그 운영 구조를 정본은 셋으로 나눴다. **열려 있는 노드가 그 셋에 하나씩 붙는다.**

```
도구환경   쓸 수 있는 손발 · 연결 상태 · 권한 · 실행 가능성   → 노드 R
출력환경   한 일과 못 한 일 · 출처 · 원장 · 다음 행동        → 노드 K
입력환경   원문 · 현재 대상 · 대화 흐름 · 필요한 맥락        → 노드 W
```

**우연이 아니다.** 2026-08-06~07 에 잡은 결함을 전부 이 축에 놓으면 하나도 안 빠진다.
그리고 **모델이 나쁜 사례가 하나도 없다.** 전부 모델 앞뒤였다.
정본이 7월에 *"이게 안 되면 아무리 대단한 코드를 짜도 의미가 없다"* 고 적은 것이
이 이틀에 실측으로 확인됐다.

### 1단계가 K·R **둘 다**인 이유 — 하나만 하면 나빠진다

정본 순서(발화 이해가 가장 위)대로면 W 가 먼저다. **그런데 5판이 다른 것을 보여 줬다.**

```
4판   ② 0/3 (아무것도 안 함)  →  ③ 3/3     "안 했다"고 말하기가 쉬웠다
5판   ② 2/3 (실제로 읽음)     →  ③ 1/3     **한 일이 생기자 거짓 성공이 돌아왔다**
```

**R 만 고치면 T5 는 더 많이 하고 더 많이 거짓말한다.** ③이 그 증거다 —
4판의 3/3 은 실력이 아니라 **할 일이 없어서 나온 점수**였다.
**K 만 고치면 정직하지만 아무것도 안 한다.**

그래서 둘은 한 단계다. **닫는 조건도 하나다** — 일곱이 함께 3/3.
하나만 올라가면 그 단계는 안 닫힌 것이다.

**거짓 성공은 절대 게이트다.** 능력을 늘리면서 그 게이트를 열어 두는 것은
비전이 말한 *"위험은 기능 삭제가 아니라 승인·원장·보호·복구로 다룬다"* 의 반대편이다.

**선언은 넷(작업·다운로드·문서·바탕화면)인데 강제는 홈 전체다.** 밟아서 확인했다:

정확히 어기는 자리다. **게을러서 떠넘긴 게 아니라, 못 한다고 잘못 알아서 떠넘겼다.**

### F-46 이 사람을 틀리게 한 세 번째 사례 — **개발 라인이 걸렸다** (2026-08-07)

개발 라인이 이 진단에 정정을 보냈다 — *"강제 경계는 넷이 맞다. `file-scope.js:45` 에
「홈 전체는 열지 않는다」고 명시돼 있다."* **그 주석이 낡은 것이고, 그게 F-46 의 문서 쪽이다.**

```
file-scope.js:45   "홈 전체는 열지 않는다 — 넓힘은 이 세 폴더까지"     ← 낡았다
file-scope.js:12   "local-file.js:216·331 이 [...roots, 홈자리] 로 홈 전체를 더한다"  ← 08-06 에 적어 둔 것
```

**한 파일 안에서 두 주석이 반대로 말한다.** 실물을 밟은 사람은 맞히고, 주석을 읽은 사람은 틀린다.
이걸로 **세 번**이다(나 두 번, 개발 라인 한 번). 관측이 아니라 결함인 이유가 이것이다.

### 그런데 개발 라인이 **진짜 근인**을 짚었다 — 받는다

내 진단은 *"모델이 좁은 선언을 믿었다"* 였는데, 멈춘 지점은 실패 메시지의 **둘째 줄**이다:

```
"다른 폴더에 있다면 그 폴더를 열어 주시면 바로 볼게요."
```

**사용자에게 할 말인데 읽는 것은 모델이다.** 모델이 그걸 "사용자에게 물어라"로 읽고 되묻는다.
같은 날 CU 라인이 고친 *"창제목으로 짚어 주세요"* 와 **완전히 같은 병**이다.

그리고 T5 에는 `local.discovery`·`local.locate` 라는 찾는 손이 있고,
같은 회차 ②가 그 파일을 읽었다는 것이 **찾을 수 있다는 증거**다.

**그래서 R 의 셋째 갈래는 둘로 갈린다:**

```
말이 잘못 갔다   실패 메시지의 사용자용 문장을 모델이 지시로 읽는다   ← 근인. 여기부터
선언이 좁다      선언 넷 vs 강제 홈 전체 (F-46)                    ← 배경. 아래 오너 방향
```

### 오너 방향 — **파일 루트를 홈 전체로** (2026-08-07)

선언을 강제에 맞춘다. 지금까지는 강제가 넓고 선언이 좁아 **모델이 좁은 쪽을 믿었다.**

**보호는 루트와 독립이라 넓혀도 그대로 막힌다.** 밟아서 확인했다:

```
막힘   ~/.ssh/id_rsa · ~/.netrc · ~/.zsh_history · ~/.npmrc · ~/Library/Messages/chat.db
열림   ~/.gitconfig        ← 숨김 파일 중 유일하게 열린다. 넓히는 커밋에서 함께 본다
```

```
Pi 가 줄이는 것    하네스가 **덧붙이는** 것 — 도구 설명 · 규칙 · 보일러플레이트
노드 W 가 늘리는 것  사용자가 **말한** 것 · 도구가 **찾아온** 것
```

12턴에서 사장님 말이 잘려 사라지는 것과, 시스템 프롬프트에 규칙을 더 넣는 것은 반대 방향이다.
**Pi 도 사용자 대화를 3배 줄이지는 않는다.** W 는 그대로 간다.

**왜 지금 노드가 아닌가** — **닫는 문장을 못 쓴다.** 프롬프트가 2,051자든 4,000자든
사장님 문장이 다르게 끝나지 않으면 대리지표다. 오너 기준도 같다(2026-08-03):
*"왕복을 깎아 모델을 멍청하게 만들지 않는다."*

**언제 열리나** — K·R·W 를 닫은 뒤. 그때 *"무거워서 느리다"* 가 사장님 체감으로 나오면
닫는 문장이 생긴다. **재는 자가 없는 것도 문제다** — `preflight` 는 프롬프트 **해시**를
동결하지만 **길이 상한은 없다.** "한 줄만 더"가 쌓이는 것을 아무도 못 본다.

**여섯을 다 문항으로 세우면 판이 못 돈다**(지금도 12문항 × 3회 = 36턴 · 30분).
**재고 나서 하나씩 연다.** 만들지 말고 읽고 판정한다.

## 순서

```
1  노드 K + 노드 R     함께.  문항 일곱.  손 0개 추가.  **하나만 하면 나빠진다**
2  노드 W             문항 ⑪.  창을 알고 안 자른다
3  「§2-C」            재현부터.  CU 가 화면에서 한 것을 웹에
4  노드 A             ⑤의 진짜 답 + 카탈로그 0번.  **손은 이미 있다 — 켜는 일이다**
5  판에 없는 축        말귀 → 자기 인식 → 성장 → 채널 → 한국 도메인 → 첫 10분
```

**1·2 는 손을 하나도 안 늘린다.** 전부 이미 있는 것을 제자리에 놓는 일이다.

**정본 순서와 어긋난 것을 적어 둔다.** 정본은 *"가장 중요한 것은 발화 이해, 그 다음 대화 흐름"*
이라 W 가 먼저여야 한다. 5판이 그것을 뒤집었다 — **R 만 고치면 거짓 성공이 늘어난다**(③).
**절대 게이트가 열리는 쪽을 먼저 닫는다.** W 는 그 다음이다.

## 슬라이스 규격 — 노드를 여는 법과 닫는 법

**노드는 계획이고 슬라이스는 작업이다.** 다섯 칸을 못 채우면 아직 열 때가 아니다.

```
1 착수   그 노드를 **끝까지** 읽었다  +  재현된 실패가 있다(3/3, 판 §4)
         재현 없으면 관측이다. 관측으로는 슬라이스를 열지 않는다

2 등록   바꿀 파일을 preflight `허용파일` 에 **이유와 함께** 미리 적는다
         이유를 적으려면 노드를 읽어야 한다 — 그게 "읽고 개발한다"의 기계 자리다

3 닫는 문장   **사용자 문장이다.** "손이 생겼다"가 아니라 "그 문장이 다르게 끝난다"

4 반대시험   일부러 깨서 빨간지 본다. 안 빨개지면 그 검사는 장식이다

5 닫기   회귀 전체 초록  +  **판 열둘 전부** 다시 돈다.  판정은 감사가 한다
```

**손을 늘리는 슬라이스는 귀속 A 일 때만 연다.** B·C·D 에 손을 더하면 안 쓰는 손이 늘 뿐이다.

## 라인 배분 — 여러 세션이 같은 트리를 쓴다

**커밋이 두 번 섞였다.** 파일로 경계를 그으면 또 섞인다.

```
경계는 파일이 아니라 노드다.
```

- **한 노드는 한 라인이 잡는다.** 잡은 라인이 그 노드의 파일을 소유한다.
- 다른 라인의 미커밋 파일은 **읽되 커밋하지 않는다.**
- PM 라인은 계획서·판·판정을 맡고 **제품 코드 0줄**이다.
- PM 이 기계 사실을 틀리면 개발 라인이 **반증으로 친다.** 계획서는 PM 소유지만 정확성은 공동 책임이다.
- **⚠ 번호가 두 벌이다.** 이 문서의 번호는 판 문항 번호이고, CU 라인 커밋도 자기 작업 순서에
  같은 기호를 쓴다. **커밋 로그의 번호를 이 문서 표로 옮겨 읽지 마라.** CU 쪽은 `CU-` 접두.

## 안 만드는 것 — 차단선

```
✗ 판에 없는 문항을 위한 손         판에 문항을 세울 수 있는지부터 본다
✗ 귀속 B·C·D 에 새 손을 더하는 것   자기파악·스키마·인자·답 조립 문제다
✗ 새 계획서                       노드를 더한다
✗ 새 표면                         넷이면 충분하다 — Work Chat · Today · 자동화 · 연결
✗ 서비스 이름이 들어간 분기         커넥터는 카탈로그 데이터지 코드가 아니다
✗ 마찰로 사는 안전                 승인은 헌장 넷뿐이다. 다섯째를 만들지 않는다
✗ 보조 모델                       대리지표다. 요약을 싸구려로 하면 그 뒤 전부가 오염된다
✗ 대리지표                        프로세스 수·호출 수는 결과가 아니다. 사용자가 보는 문장이 결과다
```

## 고친 판단들 — **지우지 않는다**

틀린 판단을 지우면 다음 사람이 같은 길로 간다. 왜 틀렸는지가 근거의 일부다.

| 내가 적었던 것 | 실제 | 무엇이 나를 틀리게 했나 |
|---|---|---|
| ①의 원인은 `include_screenshot` 이 한 자리에만 있다 | 인자가 아니라 **수신** 문제였다(`call` 이 `content` 를 버린다) | 증상만 보고 코드를 안 열었다 |
| ②③은 3/3 으로 섰다 | 문항 동결 전 손측정이었다. 다시 재니 1/3 | 원장을 안 보고 말만 봤다 |
| ⑨는 카드가 떠야 한다 | 헌장 ②는 **되돌릴 수 없는** 파괴만 묻는다. 제품이 맞고 문항이 틀렸다 | 정본을 안 읽고 문항을 썼다 |
| 게이트 BLOCKED 는 부하가 아니다 | 부하였다. 직접 재니 08-05 와 CPU 가 같다 | 두 번 재현됐다고 원인을 단정했다 |
| ②⑤⑥은 규칙이 실려 있는데도 되묻는다 | **그 규칙은 실린 적이 없다**(`connectedTools` 미전달) | 함수 조건만 보고 인자가 채워지는지를 안 봤다 |
| 여섯이 한 매듭이다 | 둘(③⑧)이 손 라우팅으로 올랐다. 매듭은 넷이었다 | 모양이 같아 보인다고 원인을 하나로 묶었다 |
| 보조 모델(C)이 필요하다 | 대리지표. 오너 기준과 정면충돌 | 비교군에 있다는 것을 이유로 삼았다 |
| ⑫의 근인은 "좁은 선언을 믿었다" | 근인은 **실패 메시지의 사용자용 문장**이었다(개발 라인 지적) | 선언·강제 차이에 눈이 가서 그 옆줄을 안 봤다 |
| ③이 3/3 으로 섰다 | ②가 아무것도 안 해서 쉬웠던 것. ②가 서자 1/3 로 돌아왔다 | 그때 의심은 적어 뒀고, 5판이 확인했다 |

**공통점 하나** — **만든 것과 닿은 것을 구분 안 했다.** 손이 제품에 안 닿고, 가르침이 모델에
안 닿고, 계획서가 사람에게 안 닿고, 배송이 사장님께 안 닿았다. **네 번 같은 병이었다.**

## 이 계획서를 쓰는 법

**전체를 읽지 않는다.** 맵에서 노드 하나를 고르고 그 노드만 읽는다.
노드 안에 **파일·근거·막힌 길**이 들어 있어서, 따라가면 필요한 것을 다 만난다.

### 지킬 것 넷

1. **변하는 사실은 여기 안 적는다.** 진행 상태는 `git log`, 열린 결함은 장부, 완성도는 판.
   여기 숫자는 **측정값**이고 재는 법이 판에 있다 — 의심되면 다시 재라.
2. **노드를 닫으면 그 자리에 닫힌 근거만 남긴다.** 노드 S 가 본보기다.
3. **새 계획서를 만들지 않는다.** 새 일이 생기면 노드를 더한다.
4. **그 파일을 고치면 그 노드를 지난다.** `scripts/s1/preflight.mjs` 등록 목록에
   이유를 적게 돼 있다 — 못 읽으면 못 적는다.

### 셋이 한 벌이다

```
design/T5-PLAN.md                                무엇을 만드는가        ← 여기
docs/03-verification/T5-ALIGNMENT-BOARD-ko.md    다 됐는지 어떻게 아는가
design/T5-FOLLOWUP-LEDGER-ko.md                  지금 무엇이 열려 있는가
```

**계획이 판을 못 채우면 그 계획은 못 끝난다.** 판에 없는 것을 만들고 있으면 둘 중 하나다 —
판에 문항이 빠졌거나, 안 해도 되는 일이거나. **어느 쪽인지 먼저 정한다.**

## 접힌 것 — 옛 계획서 셋은 어디로 갔나

멈춰 있던 계획서 셋을 **계획서에서 근거로 강등했다.** 옮기지도 지우지도 않았다 —
셋 다 지금 노드들이 읽어야 할 설계가 들어 있다. **머리에 「이건 계획서가 아니다」 표시가 있다.**

| 원문 | 어떻게 됐나 |
|---|---|
| `BUTLER §2`·`§A`·`§B` | **「공통 허리」** — 손이 늘어도 헌장 넷이 어느 손에서도 자동으로 안 샌다 |
| `BUTLER §2-C` | **「§2-C」** 절. 계약 넷과 반대시험 설계는 원문에 |
| `BUTLER` 4단계·`§9 D2` | **노드 A** |
| `BUTLER` 5단계 | CU 로 실행 중. 접었다 |
| `BUTLER` 6·7·9단계 | 노드 없음. 판 문항에 안 닿는다 |
| `BUTLER` 8·10단계 | 커넥터 카탈로그로 합류 |
| `USER-SURFACE` | 결론 한 줄 — **넷이면 충분**(Work Chat·Today·자동화·연결) |
| `KOREAN §2.3` | 카탈로그 §7.2 에 **흡수 완료**(`accessMode` 여섯) |
| `KOREAN §3·§4` | 미흡수. 노드 A 뒤 「연결/도구함」 표면이 읽을 근거 |

> **왜 `design/archive/` 로 안 옮겼나** — archive 는 *"지금 안 읽는 것"* 자리다. 셋은 읽는다.
> 문제는 위치가 아니라 **계획서가 여럿이었다는 것**이고, 그건 강등으로 끝난다.
