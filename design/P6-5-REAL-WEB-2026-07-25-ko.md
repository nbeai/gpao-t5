# P6-5 · Real Web / Browser / Scraping (첫 슬라이스)

작성: 2026-07-25 · 상태: 구현·라이브 검증 완료, 깊은 감사 대기

WebToolDescriptor(§6.6)는 계약(inputSchema·sourcePolicy·sessionMode·assertWebEvidence·classifyWebFetch)까지
완성돼 있었다. 빠진 것은 그 계약을 **실제로 실행하는 fetch 어댑터**. 이 슬라이스가 그것을 얹는다.

## 다섯 축 → 구현

| 축 | 구현 |
| --- | --- |
| 실제 브라우징 | `makeWebCollector({fetchImpl})` — 실제 HTTP GET. 기본 `global fetch`, 테스트는 주입 |
| 출처 원장 | 성공 시 `makeSourceEvidence`(sourceUrl·title·excerptHash·confidence) 필수 |
| 로그인벽/차단 | `httpToFetchState` — 코드+본문 신호로 login_wall/bot_wall/robots/blocked/timeout 분리 |
| 스크래핑 정책 | 읽기 전용(GET) · `validateWebInput` maxPages cap(대량수집 금지) · robots 판정(주입) |
| 정직한 봤다/못봤다 | 봤으면 내용+출처, 못 봤으면 내용·출처 없이 상태만. ToolRunner `assertWebEvidence` 강제 |

## 핵심 불변식

- **봤다 → 출처 필수**: 성공 결과에는 반드시 SourceEvidence가 있다. 출처 없는 성공은 계약 위반(런타임 throw).
- **못 봤다 → 내용·출처 없음**: 로그인벽·봇벽·robots·차단·timeout은 `{blocked, fetchState, userSafeSummary}`만.
  "못 본 걸 본 척" 금지. 200이어도 본문이 로그인/캡차 페이지면 `login_wall`/`bot_wall`로 분류(정직).

## 어댑터 (`src/runtime/web-collector.js`)

- `httpToFetchState(status, {body})`: 401→login_wall, 429→bot_wall, 403→(본문신호) bot_wall|blocked,
  2xx→(본문신호) ok|login_wall|bot_wall|robots_disallow, 그 외→blocked.
- `makeWebCollector({fetchImpl, robotsCheck, now})`: validateWebInput → robots 판정 → fetch → 상태 분류 →
  ok면 title·excerpt 추출 + SourceEvidence, 아니면 정직한 실패. `sourceLedgerRequired:true`로 ToolRunner가 강제.
- freeform `{request}`에서 URL 추출(turn은 generic하게 request만 넘김 — 웹 로직은 어댑터에). 검색어 단독(SERP)은 후속.

## 배선 / 안전 규율

- 라이브 서버만 실제 어댑터를 쓴다: `makeServer({ tools: demoTools({ webCollector: makeWebCollector() }) })`.
- 기본 `demoTools()`는 offline 스텁 유지 → **테스트·기본 경로는 실네트워크를 치지 않는다**(결정적).
- 실브라우징 검증은 로컬 http 서버 + 실제 global fetch로 한다(외부 네트워크 없이 진짜 fetch 경로).

## 테스트 (9)

httpToFetchState 매핑 · 로컬서버 실fetch 성공(출처 포함) · 401 login_wall(내용·출처 없음) ·
200-로그인페이지 → login_wall · robots 불허(fetch 안 함) · 네트워크실패 timeout · URL 없음 정직 ·
freeform request URL 추출 · ToolRunner 통합(성공 sources / 차단 미확인).

반대 테스트: `httpToFetchState`에서 401→ok로 오분류 → login_wall·ToolRunner 테스트 2건 실패 → 상태 분류가
진짜 경계를 지킴. 복원 시 통과.

## 라이브 검증

`/turn "이 페이지 조사해줘 http://127.0.0.1:8890/"` → 실제 HTTP fetch → 제목 추출 → 출처 근거 →
원장 `confirmed: "공개 자료로 확인했어요: 라이브 대상."`(실제 페이지 제목). 진짜 브라우징 end-to-end.

## 시간 제한 (감사 보정 — 병합 blocker, 반영됨)

`global fetch`엔 기본 시간 제한이 없어 끝나지 않는 페이지가 Work Chat을 멈출 수 있었다. `makeWebCollector`에
`timeoutMs`(기본 15초, 라이브는 `GPAO_T5_WEB_TIMEOUT_MS`로 조정) + `AbortController`를 넣었다. fetch+본문
읽기 전체를 timeout race로 감싸 **signal을 무시하는 응답도** 멈추고, 실제 요청엔 abort 신호를 보낸다.
시간 초과 → `{blocked:true, fetchState:'timeout', result/sources 없음}`(정직하게 "못 봤다").
테스트: 끝나지 않는 fetch·본문 지연 → timeout 분류, 제한 안이면 정상 성공. 반대 테스트: race 우회 시 hang(가드 필요 입증).
라이브: 끝나지 않는 로컬 페이지 조사 → 1.5s(env)에 정직 반환, Work Chat 안 멈춤.

## 남은 후속 (선택)

- body size cap · content-type guard(HTML 아닌 대용량 응답 방어).
- 검색어 단독(SERP) 수집 — 정책·출처가 더 복잡(엔진 결과 vs 원문).
- 실제 robots.txt fetch·캐시(현재는 판정 주입). 다중 페이지·depth 크롤(cap은 이미 계약).
- 인증 세션(sessionMode: authenticated/user_approved)의 실제 자격 주입 — A2 경계와 함께.
- 헤더(User-Agent)·리다이렉트 정책 세밀화.
