# P-OP-3 공통 엔지니어링 탐색 계약

작성: 2026-07-28  
상태: 구현 착수 전 설계 · C 라이브 실패에서 출발

## 1. 왜 필요한가

실제 모델에게 `카페24 주문 가져와줘.`라고 했을 때 T5는 로컬 자료 이름을 찾았지만, 연결 근거를 찾는 일반형 탐색으로 이어지지 못했다. 그래서 사용자가 주문 파일을 내려받는 길이 가장 앞에 왔다.

문제는 카페24 지식의 부재가 아니다. T5가 아직 모르는 외부 서비스에 대해 **이미 이 컴퓨터에 있는 연결 단서**를 안전하게 탐색해 모델 앞에 놓는 손이 없다는 것이다.

## 2. 목표

`local.discovery`는 사용자가 부른 외부 대상의 기존 연결 단서를 읽기 전용으로 확인한다.

- MCP 호스트 설정에 등록된 서버 이름
- PATH에 있는 관련 명령 이름
- 안전하게 확인 가능한 설정/동기화 흔적의 존재
- 이미 선언·연결된 T5 커넥터 상태

결과는 후보와 근거다. 연결 성공, API 존재, 권한 보유를 뜻하지 않는다. 모델은 이 사실과 기존 웹·브라우저·터미널·연결 손을 보고 다음 길을 판단한다.

## 3. 하지 않는 일

- 서비스별 `if (카페24)`나 응답 문구를 넣지 않는다.
- 설정 파일의 토큰, env, 명령 인자, URL 쿼리, 쿠키, 비밀값을 읽거나 모델에 싣지 않는다.
- 자동 설치, 자동 로그인, 자동 연결, 도구 편입을 하지 않는다.
- 홈 전체를 훑거나 긴 파일 목록을 모델에 보내지 않는다.
- 사용자에게 설정 파일·터미널 명령·개발자 화면을 먼저 요구하지 않는다.

## 4. 계약

### 입력

```js
{ subject: string, purpose?: string }
```

- `subject`: 사용자가 부른 대상의 원문 일부. 서비스명인지 업무명인지 런타임이 판정하지 않는다.
- `purpose`: 모델이 이해한 목적의 짧은 표현. 실행 권한이나 계획이 아니다.

### 출력

```js
{
  subject: string,
  checked: ["mcp", "cli", "safe_local_signs", "known_connectors"],
  candidates: [
    { kind: "mcp" | "cli" | "local_sign" | "connector", label: string, evidence: string }
  ],
  limits: [string],
  checkedAt: number
}
```

- 후보는 최대 5개, 근거는 존재/이름 일치/실행 가능 상태뿐이다.
- 후보 0개도 성공한 읽기 결과다. `없음`은 `불가능`이 아니다.
- `subjectOf`는 탐색 대상을 다음 턴 후보로만 남긴다. 연결됐다는 사실은 남기지 않는다.

## 5. 실행 방식

1. 이미 있는 `local-signs`의 비밀 없는 MCP 서버 이름 조회를 재사용한다.
2. PATH의 실행 파일 이름만 제한적으로 조사한다. 값·환경변수·명령 실행은 하지 않는다.
3. 이미 선언된 커넥터와 그 확인 결과는 `connector-truth`에서 읽는다.
4. 입력 문자열을 정상화해 후보 이름과 비교하되, 어떤 서비스가 무엇을 뜻하는지 런타임에 하드코딩하지 않는다.
5. 모델은 필요할 때만 `web.collect` 등 다음 손을 고른다. discovery가 네트워크를 몰래 열지 않는다.

## 6. 사용자 흐름

```text
"카페24 주문 가져와줘"
  → 모델이 local.discovery로 현재 컴퓨터의 연결 단서를 먼저 확인
  → 후보가 있으면 그 근거에 맞는 연결/읽기 손으로 진행
  → 후보가 없으면 공개 경로·연결 가능한 길을 T5가 더 확인
  → 사용자에게 남기는 것은 동의·비밀 직접 입력·계정 권한처럼 진짜 사용자 몫뿐
```

## 7. 검증

- 단위: 서비스 이름 없이도 지어낸 대상의 MCP/CLI/커넥터 후보를 같은 계약으로 반환한다.
- 비밀: 설정 파일에 넣은 토큰·명령·env 값이 출력·원장·모델 입력에 없는지 검증한다.
- 반대: 후보를 지워도 연결됨/권한 있음이라고 말하지 않는지 확인한다.
- 라이브: C를 빈 흔적/기존 MCP/CLI만/권한 부족 네 조건으로 실행한다.
- 사용자 표면: `MCP`, `PATH`, 설정 경로가 카드·답변의 앞자리를 차지하지 않는지 확인한다.

## 8. 완료 정의

사용자가 미선언 서비스를 말했을 때, T5가 먼저 자기 컴퓨터의 연결 현실을 확인하고 근거 있는 다음 길을 만든다. 실제 계정 권한이나 연결 근거가 없으면 그 사실을 정직하게 말하되, 파일을 내려받거나 개발자 설정을 하라고 **첫 번째 길로** 떠넘기지 않는다.
