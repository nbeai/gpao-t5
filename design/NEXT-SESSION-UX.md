**판정 요지**(기획서 §0): 불편 스물몇의 뿌리는 셋이다.
```

   나머지 99.4%가 강제 동기 레이아웃. 「빠르다」「스크롤이 안 먹는다」「복사가 안 된다」가

② 「새 화면을 만들지 않는다」가 원칙으로 박혀 라우트 80개 중 24개가 화면 없음
③ 같은 원칙이 복사·수정·재생성 같은 기본 동작까지 삼켰다
```

## 1. ★ 먼저 할 일 — 도는 셋을 받아라

내가 조각 **A·C·E** 를 에이전트로 띄워 두고 세션을 넘긴다. 브랜치:
```
조각 A 스트리밍   worktree-agent-ab6a0fd39780b6771     ← 아직 돈다
조각 E 자동화 문   worktree-agent-ad3029d43132ee8be     ← 아직 돈다
조각 C 세션 제목   ✅ 병합 끝(4,020 초록) — 아래 「C 에서 배운 것」을 읽어라
```
**받는 절차**(오늘 여덟 번 했다 — 그대로 하면 된다):
```
git merge --no-commit --no-ff <브랜치>     충돌하면 손으로 푼다. 자동 병합으로 밀지 마라
npm test                                  전체 초록 확인(3,995+)
git commit --no-edit && git push
```
⚠️ **에이전트 보고를 그대로 믿지 마라.** 오늘 보고와 내 측정이 갈린 적이 있고,
**내 자가 틀린 적이 다섯 번**이었다(§4). 반대시험 값은 **네가 다시 재라.**

### ★ C 에서 배운 것 — A·E 도 같은 함정에 걸린다

**서버만 고치면 고친 게 아니었다.** C 는 제목을 갈라 놓고도 화면에서 똑같아 보일 뻔했다 —
`.sess .t` 의 `text-overflow:ellipsis` 가 **정확히 차수가 붙을 자리를 자른다.** 번호를
별도 칸으로 떼어서야 실제로 보였다. **오늘 세 번 겪은 「만든 것과 닿은 것은 다르다」의 네 번째다.**

그리고 **데이터가 설계를 뒤집었다.** 내가 준 선택지 셋 중 둘(발화에서 특징 추출 · 모델이 제목
작성)을 오너 실물 95개가 기각했다 — 겹친 12묶음 전부 **첫 발화가 글자 하나까지 같았다.**
무엇을 뽑아도 안 갈린다. **재기 전에 고르지 마라.**

셋이 같은 `<style>` 을 건드리면 충돌한다 — 기획서 §1 규약(맨 끝에 `/* 조각 X */` 로 덧붙이기)을
지켰는지 보고, 안 지켰으면 **그 자리만 손으로 정리**하라.
