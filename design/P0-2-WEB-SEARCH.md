# Phase 0-2 · 웹 검색 (URL 없이도 찾는다)

날짜: 2026-07-26 · 브랜치: `p0-2-web-search`
근거: v3.1 §21 Phase 0-2, §16-D 능력 완결, §17 의존성 0, §20 전역 안 할 것.

## 왜 지금

`web-collector.js:78` 에 이렇게 적혀 있다: *"이 슬라이스는 URL 직접 수집만. 검색어 단독(SERP
수집)은 후속"*. 능력 설명도 "검색어로 찾아 주는 기능은 아직 없다"로 정직하지만, **일반 사용자는
URL 을 들고 오지 않는다.** §16-B 가 금지한 "사용자가 부딪히는 후속"의 전형이다.

## 실측 (2026-07-26, 오너 실계정)

추정하지 않고 직접 두드려 확인했다.

| 경로 | 결과 |
|---|---|
| **ChatGPT 계정(Codex 백엔드) + `tools:[{type:'web_search'}]`** | **200 지원.** SSE 에 `response.web_search_call.{in_progress,searching,completed}` 이벤트가 흐르고, 답변에 **실제 출처 URL**(한국은행 공식 페이지)이 포함됨 |
| Gemini + `tools:[{google_search:{}}]` | 요청 형식은 수용되나 **오너 키 할당량 초과로 미검증** |
| 별도 검색 API(Brave/Tavily 등) | 새 키·새 연결이 필요 — 의존성 0 은 지키지만 사용자 부담 |

**결론: 이미 연결된 모델이 검색을 제공하면 추가 키 없이 검색이 된다.** 이게 가장 좋은 UX 이고
"개발자-떠넘김 금지"에도 맞다.

## 범위

**모델 내장 검색을 T5 의 도구 계약 안으로 흡수한다.** 새 검색 서비스를 붙이는 게 아니라,
연결된 모델이 가진 검색 능력을 T5 가 **알고·쓰고·출처를 기록**하게 한다.

1. **provider 선언에 검색 능력 추가**: `MODEL_PROVIDERS` 스펙에 `searchTool`(요청 본문 조각)과
   `searchEvents`(SSE 에서 검색 진행을 알아보는 표식)를 선언형으로 둔다. 지원하지 않는 provider 는
   필드가 없으면 그만 — 계약 파괴 없음(P-STR-1 `streamBody` 와 같은 패턴).
2. **자기인지 반영**: 지금 연결된 모델이 검색을 지원하는지 SelfState·능력 문서가 안다.
   지원하면 "검색해서 찾아 준다", 아니면 "주소를 주면 읽는다"로 **정직하게 갈린다**(§6.30·§6.31 계열).
3. **출처 계약**: 검색 결과로 답할 때는 **출처 URL 이 원장에 남아야 한다**. T5 는 이미
   `assertWebEvidence` 로 "출처 없는 성공"을 막는다 — 같은 계약을 검색 답변에도 적용한다.
4. **진행 표시**: 검색 중임을 사용자 언어로 흘린다(§6.11 스트리밍 위에, "찾아보고 있어요").
5. **실패 정직**: 검색이 결과를 못 찾음 / provider 가 검색 미지원 / 할당량 초과를 **각각 다르게**
   말한다. 못 찾은 걸 아는 척하지 않는다.

## 경계

- **새 검색 API 를 붙이지 않는다**(§20: 의존성 0, 마켓플레이스 금지). 연결된 모델의 능력만 쓴다.
- 모델이 검색을 지원하지 않으면 **없다고 말한다**. 대충 아는 걸로 답하지 않는다.
- 검색은 읽기(A1)다 — 승인 게이트를 새로 만들지 않는다. 다만 결과를 외부로 보내는 건 기존 A2.
- 검색 결과를 기억에 자동 반영하지 않는다(검색됨 ≠ 반영됨, v3.0 §0 불변식).

## 완결 정의 (§16-D — 쪼개서 반쪽을 내보내지 않는다)

> 사용자가 **URL 없이** 물으면 → T5 가 찾아서 → 읽고 → 정리해 → **출처와 함께** 답한다.
> 지원하지 않는 모델이면 그 사실을 정직하게 말하고 다음 행동을 준다.
