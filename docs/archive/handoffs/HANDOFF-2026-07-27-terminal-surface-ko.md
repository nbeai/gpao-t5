## 1. T5가 무엇인가 (이 한 절만은 몸으로 알고 시작해라)

우리는 AI 모델을 만들지 않는다. **모델의 한계를 보완하고 능력을 최대치로 끌어내는 AI 운영체제**를
만든다. 그런데 사용자는 AI OS도 **그냥 AI라고 느낀다.** 그래서 T5의 품질은 기능 목록이 아니라
**사용자가 말했을 때 얼마나 자연스럽게 이해하고, 이어받고, 실행하고, 정직하게 답하는가**로 정해진다.

순서가 있다:

```
사용자 발화 이해 → 대화 흐름 이해 → 모델 앞 현실 구성 → 실제 결과 구분 → 다음 턴 승계 → 기능
```

**"모델 앞에 어떤 현실을 만들어서 넣어주는가"가 LLM 운용의 핵심이다.**
AI OS에서 중요한 건 모델이 아니라 모델 앞뒤의 운영 구조다.

런타임이 할 일은 사용자의 말을 **대신 해석해서 닫아버리는 게 아니다**:

- 원문을 보존하고
- 현재 대상과 맥락을 주고
- 가능한 손발을 알려주고
- 실제 한 일과 못 한 일을 구분하고
- 위험 실행을 경계에서 막는 것

그 위에서 **해석과 판단은 모델이 하게 둔다.**

### 이게 추상이 아니라는 증거 (오늘 실측)

| 증상 | 처음 진단 | 실제 원인 |
|---|---|---|
| "터미널에서 `ls` 해서 붙여주세요" | 모델 말투 문제 | 폴더를 넓히는 길이 **아예 없었다** — 모델이 옳았다 |
| "리뷰 읽어봐"에 책 리뷰 블로그를 읽음 | 모델이 못 알아들음 | 런타임이 **모델이 고른 인자를 버리고** 발화 원문으로 실행 |
| "작업용SSD"에 침묵 | 실행 루프 상한 | 승인으로 멈출 때 **모델이 이미 한 말을 버림** |
| 같은 자리를 여러 번 훑음 | 모델이 비효율적 | **찾았다는 사실이 상태에 안 남아서** 다음 손이 몰랐다 |
| 볼륨이 붙어 있는데 "안 보여요" | 모델 판단 오류 | macOS가 NFD로 주는 이름을 NFC와 `===`로 비교 |

**다섯 번 다 "모델이 이상하다"로 시작해서 "런타임이 못 했거나 안 알려줬다"로 끝났다.**
이 패턴을 기억해라. 모델이 이상해 보이면 **원장부터 읽어라**(§8).

### 규칙으로 굳히면 모델이 멍청해진다 (§24)

**코드는 경계와 사실, 모델은 이해와 선택.** 오늘 두 번 증명됐다:

- 위험 명령을 목록으로 막으려 했더니 `find -delete` 하나에 뚫렸다. `python shutil.rmtree`,
  `perl unlink`, `osascript`, `eval`+백틱… 목록은 우리가 상상한 것만 막는다.
  **커널 샌드박스에 맡기니 상상 못 한 것까지 막혔다.**
- 헌장에 "명령어 말고 사람 말로"를 넣어도 안 고쳐졌다. **길을 만드니 고쳐졌다.**
  지킬 수 없는 규칙은 모델을 무시하게 만든다.

## 2. 오늘 어떻게 여기까지 왔나

**결과만 보면 판단을 못 한다.** 왜 파일 도구가 없는지, 왜 목록이 아니라 샌드박스인지,
왜 라이브가 먼저인지는 이 흐름 안에 있다.

### ① 아침 — 잘못된 처방 (전부 롤백됨)

라이브에서 T5가 **"터미널에서 `ls` 결과를 붙여 주세요"**라고 답했다. 진단은 정확했다 —
"떠넘김은 실패다". 그런데 처방을 **"터미널을 안 써도 되게 파일 도구를 늘린다"**로 잡았다.

`local.file` 에 `search`·`recent`·`patch`·`rename`·`copy`… 액션 11개를 만들고, 폴더를 여는
`local.scope`, 앱을 확인하는 `local.apps` 까지 다섯 단계를 하루에 쌓았다. 테스트 785건 통과.

**라이브에서 죽어 있었다.** 모델이 `{action:'open', path:'', name:'다운로드'}` 를 보내는데
`args.path ?? known?.path` 에서 **빈 문자열이 `??` 를 통과해** 이름으로 여는 길이 전멸했다.
내 테스트는 `path` 를 아예 빼고 불러서 그 경로를 한 번도 안 지나갔다.

### ② 오너의 질문 — "지금 이 개발이 의미가 있나?"

> "결국 사용자가 원하는 건 T5가 사용자 컴퓨터를 함께 움직이는 것이잖아.
> 지금 클로드코드 너나 코덱스가 터미널로 자유자재로 하는 것처럼."

이 한마디에 방향이 바뀌었다. 내가 만들던 건 **셸의 부분집합을 한국어 UX로 재포장한 것**이었다.
`list`/`read`/`search`/`patch` 는 `ls`/`cat`/`grep`/`sed` 한 줄이면 되는 것들이다.

**내가 매일 `Bash` 하나로 이 컴퓨터에서 일하면서, 그게 T5에 없다는 걸 이상하게 여기지도 않았다.**
그리고 뺄 때는 의견을 냈으면서(요약은 모델의 일이다) 더할 때는 안 냈다 — "지시서에 없다"를
방패로 썼다. → 그래서 §0의 6가지 자문이 생겼다.

**5단계 전부 롤백.** `보관/local-surface-2026-07-27` 에 있다.
`local-protection.js` 만 되살렸다 — 셸을 주면 **더** 필요해지기 때문이다.

### ③ 안전을 어떻게 할 것인가 — 목록 vs 커널

내가 처음 제안한 건 **allowlist**(안전 증명된 것만 자동)였다. 오너가 되물었다:
"최소한의 가장 위험한 부분만 승인받고 나머지는 자동이 맞지 않나?"

다시 생각하니 내 안이 반쯤 틀렸다. **Claude Code의 allowlist가 작동하는 이유는 사용자가
개발자이기 때문이다.** T5 사용자는 터미널을 치기 싫어서 T5를 쓴다. 그 사람에게
`find . -newermt "-7 days" -exec cp {} ~/정리/ \;` 를 보여주고 허락할지 물으면 판단할 수 없다.

**답은 셋째였다: 명령이 위험한지 문자열로 알아내려는 것 자체가 틀렸다. 돌려 보면 된다.**

```
1. 쓰기·네트워크·비밀읽기를 막고 먼저 돌린다(probe)
2. 성공했다 → 아무것도 안 바꿨다는 증명. 자동
3. 막혔다   → 뭔가 바꾸려 했다는 뜻. 그때 승인
```

실측으로 확인했다. 목록 설계였다면 이게 전부 뚫린다:
`find -delete` · `python shutil.rmtree` · `perl unlink` · `node fs.rmSync` · `osascript` ·
`sed -i` · `tee` · `dd` · `xargs` · ``eval `…` `` · `r""m` · `$(…)` · 백그라운드 · 임시 스크립트.

**커널은 우리가 상상 못 한 것도 막는다.** 반대 검증: 샌드박스를 끄면 30건 중 28건이 뚫린다.

## 3. T5식 개발 방식 (오너 정리)

### ① 사용자 목적이 개발의 최상위 기준이다

기능이 많아도 **사용자의 말을 못 알아듣거나, 방금 한 일을 이어받지 못하거나, 안 한 일을 했다고
말하면 제품적으로 실패다.** 모든 개발 판단은 이 질문에서 시작한다:

- 이 작업은 사용자의 말을 더 잘 알아듣게 하는가?
- 대화 흐름을 덜 끊는가?
- 현재 가능한 도구와 상태를 더 정확히 알게 하는가?
- 실제 한 일과 못 한 일을 더 잘 구분하게 하는가?
- 다음 턴에서 사실을 더 잘 이어받게 하는가?

### ② 모델을 고치려 하지 말고, 모델 앞뒤의 현실을 고친다

런타임이 할 일: 원문 보존 · 현재 대상과 맥락 · 가능한 손발 · 한 일과 못 한 일 구분 ·
위험 경계 · 원장 기록 · 다음 턴 승계.

**해석과 판단은 모델이 하게 두되, 모델이 판단할 현실은 런타임이 정확히 공급해야 한다.**

### ③ 기능 추가보다 단일 진실을 우선한다

T5에서 반복적으로 문제가 난 건 기능 부재보다 **진실이 여러 군데 흩어진 것**이었다.
도구 하나에 대해 이것들이 따로 존재하면 **반드시 어긋난다**:

```
descriptor · schema · capability line · UI 도구함 · CAPABILITIES 문서 · live tool list · handler
```

도구의 진실은 **descriptor와 실제 handler**에서 나오고, 모델 입력·도구함·문서·능력 설명은
전부 거기서 파생되어야 한다. **기능이 늘어날수록 더 중요해진다.**

> 오늘 이걸 세 번 어겼다 — `action-plan.js` 에 도구별 `if` 를 늘리다가 등급 판정 인자,
> 승인 문구, 판정 인자가 차례로 샜다. 결국 `previewOf(args)` 계약으로 바꿨다.
> **새 도구를 만들 때 커널을 고쳐야 한다면 그 구조가 잘못된 것이다.**

### ④ 게이트는 목록이 아니라 불변식이어야 한다

좋은 게이트는 "이 몇 개 테스트가 통과했다"가 아니라 **깨지면 안 되는 구조적 약속**을 잡는다:

- 없는 도구를 있다고 말하면 막는다
- **있는 도구를 없다고 말해도 막는다**
- handler 없는 descriptor를 막는다 / descriptor 없는 schema를 막는다
- 실행 가능 도구가 모델에게 노출되지 않으면 막는다
- 실행하지 않은 일을 했다고 말하면 막는다
- **안 해 본 일을 막혔다고 말하면 막는다**
- 안전 바닥이 자동 실행으로 흐르면 막는다
- 프롬프트가 과도하게 커지면 막는다

**중요한 것은 반대 방향까지 잡는 것이다.** 없는 것을 있다고 말하는 것도 문제지만,
**있는 것을 없다고 말하는 것도 AI OS에서는 똑같이 문제다.**

> 실측: `session.search` 는 손이 있는데 스키마가 없어서 모델이 "그 기능은 없습니다"라고 답했다.
> 읽기만 하는 heredoc이 승인 카드로 escalate돼 Codex·Claude Code가 늘 쓰는 관용구를 T5만 못 썼다.
> 둘 다 "있는 것을 없다고 말한" 쪽이다.

### ⑤ 테스트 통과와 제품 완료를 구분한다 → §4

### ⑥ 반대 검증을 개발 습관으로 삼는다

게이트나 테스트를 추가했으면 **그것이 실제로 깨진 상태를 잡는지** 확인해야 한다:

```
1. 수정 전 실패를 먼저 본다
2. 수정 후 통과를 본다
3. 일부러 되돌려 다시 실패하는지 본다
4. 원복 후 다시 통과를 본다
```

**이 과정을 거치지 않으면 테스트는 장식이 될 수 있다.** 오늘 다섯 번 장식이었다(§4).

> ※ 오너가 정리해 주신 원문 7번("AI에게 맡기되, 인간이…")이 전달 중 끊겼다.
> **미수록 — 받는 대로 이 자리에 넣을 것.**

## 4. 완료 기준 (오너 지시, 2026-07-27 변경)

> 완료는 실제 T5 라이브 시나리오, 테스트/게이트, 반대 검증, 사용자 실사용 기준을 **모두** 통과해야 한다.
> Codex도 예외가 아니다. **확인하지 못한 것은 확인하지 못했다고 말해야 한다.**
> 보고서와 숫자로 서로 통과시켜주는 방식은 중단한다.

**테스트 통과는 완료 근거가 아니다. 회귀 방지 장치다.**

### 왜 이렇게 됐는가 — 이 표를 보면 안다

| 결함 | 그때 테스트 |
|---|---|
| `cwd: ""` 가 `??` 를 통과해 엉뚱한 자리에서 실행 | 785건 통과 중 |
| 사용자 데이터를 `src/surface/processes.json` 에 저장 | 776건 통과 중 |
| 서버 켜기가 승인 없이 실행 | 799건 통과 중 |
| 등급 판정이 모델이 고른 인자를 안 봄 | 799건 통과 중 |
| 승인 카드에 "실행 중인 것 실행" | 799건 통과 중 |
| 읽기만 하는 heredoc이 승인 카드로 escalate | 815건 통과 중 |
| 한글 볼륨 이름 NFC/NFD 불일치 | 815건 통과 중 |

**단위 테스트는 내가 상상한 경로만 지나간다. 라이브가 진짜 검사다.**

### 반대 검증은 선택이 아니라 조건이다

**게이트가 다섯 번 약했다.** 전부 반대 검증에서만 잡혔다:

1. `blocked` 만 보다 파일이 없어서 막힌 것(ENOENT)까지 "보호 작동"으로 셈
2. 게이트가 `status`(읽기)만 불러서 파일이 안 생겼고, 경로가 소스 트리로 잡혀도 초록
3. locate 게이트가 폴더 **이름**만 맞아도 통과 → 업무 자료 판정을 통째로 빼도 초록
4. `;` 로 이어 붙인 명령이 쓰기 실패를 묻어서 적대적 검사가 통과
5. 우선순위 수정을 검사가 못 잡음

**통과했다는 사실만으로는 검사가 돌았다는 뜻이 아니다.**

### 판정 규칙

- `npm test` 와 `npm run gate` **두 명령만** 판정에 쓴다. `node --test test/` 같은 임의 명령으로
  "통과했다"고 하지 않는다
- 출력은 파이프하지 말고 **파일로** 받는다
- 30초 넘으면 코드 실패인지 실행 방식 문제인지 **분리해서** 보고한다
- 게이트를 통과시키려고 검사를 약하게 만들지 않는다
- 라이브를 안 봤으면 **"라이브 미확인"**, 반대 검증을 안 했으면 **"반대 검증 미실시"**라고 말한다

## 5. 오늘 무엇이 열렸나

### 방향 전환 하나 — 먼저 알아야 한다

오전에 만든 **Local Surface 5단계(파일 도구 11개 액션)를 전부 롤백했다**(오너 지시).
셸의 부분집합을 손으로 재구현한 것이었다. 보관: `보관/local-surface-2026-07-27`.
`local-protection.js` 만 되살렸다 — 셸을 주면 **더** 필요해진다.

**교훈:** "터미널 떠넘김이 실패"라고 진단해 놓고 처방을 "터미널을 안 써도 되게 파일 도구를
늘린다"로 잡았다. 진단은 맞았는데 처방이 정반대였다. 내가 매일 `Bash` 하나로 일하면서
그게 T5에 없다는 걸 **이상하게 여기지도 않았다.**

### 열린 손발

| 파일 | 무엇 |
|---|---|
| `src/runtime/sandbox.js` | probe(쓰기·네트워크·비밀읽기 차단) / granted(비밀만 차단) 프로파일 |
| `src/runtime/terminal-run.js` | 셸 실행. 출력 접기·타임아웃·stdin 차단·환경변수 마스킹·`executionBlock()` |
| `src/runtime/local-terminal.js` | 도구. probe로 등급을 정하고, 막히면 승인 요청. `previewOf` |
| `src/runtime/local-process.js` | 장기 프로세스. start/status/logs/stop. **살아있는지 커널에 묻는다** |
| `src/runtime/process-store.js` | 켠 것을 파일에 기록(T5 재시작 후에도 기억) |
| `src/runtime/lifecycle-guard.js` | T5 자기 프로세스·데이터·launchctl 보호 |
| `src/runtime/local-locate.js` | 작업 대상 후보 + 근거·확신도. `places()`. 이름→자리 승계 |
| `working-state.js` | 지금 자리·방금 실행·켠 것·찾은 자리·볼 수 있는 자리를 사실로 투영 |
| `turn.js` | 한 턴에 손을 이어 쓰는 실행 루프(최대 4걸음) |

### 안전은 네 겹이다 (건드리기 전에 이해할 것)

```
① 커널 샌드박스   probe 통과 = 아무것도 안 바꿨다는 증명 → 자동(A0)
                  granted = 승인 후. 변경·네트워크 열되 **비밀은 여전히 닫힘**
② 보호 영역       secret(읽기까지) / system(변경만). 루트·승인과 독립
③ lifecycle guard T5 자기 프로세스·데이터·launchctl. 샌드박스가 못 잡는다(시그널은 파일쓰기가 아님)
④ 승인 등급       A0~A3. terminal 읽기 자동 · process start는 A2+안전바닥 · status/logs 자동 · stop A1
```

**`executionBlock()` 은 안전 판정이 아니다.** 사용자에게 뭐라고 말할지(샌드박스 차단 / 실행 환경 /
코드 실패)를 고르는 것뿐이다. 안전은 이미 커널이 보장했다. 틀려도 최악은 승인을 더 묻는 것이다.

## 6. W3 현재 상태

목표: **사용자가 경로를 복사하거나 터미널을 치지 않아도, T5가 볼 수 있는 장소 후보를 제시하고,
사용자가 이름으로 고르면 그 자리에서 다시 찾고 이어서 실행한다.**

W3는 "폴더 선택 기능"이 아니다. **말로 장소를 고르고 이어가는 능력**이다.

### 진행된 것

- 볼 수 있는 자리를 매 턴 사실로 제공(`places()` → `workingState`) — 다음 턴에도 살아남는다
- 이름으로 고른 자리를 실제 경로로 승계(`a4d6cf8`) — **W3 주 경로**
- 한글 볼륨 이름 NFC 정규화(`4de189d`) — 붙어 있는 볼륨을 "안 보인다"고 하던 것
- 승인으로 멈출 때도 말한다(`64a7634`) — 내가 "빈 답변"이라 오진했던 것의 진짜 원인
- 찾은 자리를 다음 걸음의 자리로 승계(`fd9ce1a`)
- 읽기만 하는 heredoc이 승인으로 가던 것(`1f58e28`) — Codex·Claude Code가 늘 쓰는 관용구

### 필수 라이브 시나리오 — **다시 돌려서 확인할 것**

```
1. "외장하드에 있는 정산 자료 봐줘"
2. "어떻게 알려주면 돼?"
3. "작업용SSD"
4. "그 안에서 다시 찾아봐"
```

**실패 기준:** "경로를 복사해서 붙여넣으세요" / Finder 우클릭 / Option / 경로명 복사 /
"터미널에서 이 명령을 실행해서 결과를 붙여주세요"가 나오면 실패.

**통과 기준:** 볼 수 있는 장소 후보를 말한다 · 이름으로 답하면 그 후보를 선택한다 ·
선택한 장소에서 다시 찾는다 · 찾은 것/못 찾은 것/어디까지 봤는지가 원장과 답변에 남는다.

**마지막 전체 통과 기록이 없다.** 개별 수정은 각각 확인됐지만 4개 연속 흐름은 다시 봐야 한다.

## 7. 반복한 실수 — 같은 함정을 또 밟지 마라

### `??` 는 빈 문자열을 통과시킨다 (3회)

**모델은 안 쓰는 인자도 `""` 로 채워 보낸다.** `path: ''`, `cwd: ''`, `from: ''`.
`blank()` 헬퍼가 `local-terminal.js`·`local-locate.js` 에 있다.
**`??` 를 쓸 때마다 빈 문자열을 의심할 것.**

### `git checkout` 이 미커밋 작업을 지운다 (2회)

반대 검증에서 고의로 망가뜨린 뒤 되돌리다 **아직 커밋 안 한 작업까지 날렸다.**
**반대 검증 전에 반드시 커밋한다.** 테스트·게이트가 통과했으면 커밋할 근거는 이미 있다.

### 커널에 도구별 `if` 를 늘리면 새 도구가 조용히 샌다 (3회)

`action-plan.js` 에서 등급 판정 인자 → 승인 문구 → 판정 인자, 세 번 샜다.
결국 **`previewOf(args)` 계약**으로 바꿨다(도구가 자기 미리보기를 낸다).
**새 도구를 만들 때 커널을 고쳐야 한다면 그 구조가 잘못된 것이다.**

### 답변만 보고 원인을 단정했다

내가 직전 인수인계서에 "실행 루프 상한에서 빈 답변"이라고 **확신에 차서 틀린 진단**을 적었다.
원장을 읽었으면 `kind: 'approval'` 인 걸 바로 봤을 것이다.
**내 문서에 "원장을 읽어라"고 써놓고 내가 안 했다.**

### python heredoc 에서 따옴표 이스케이프

`python3 - <<'PY'` 안에서 JS 문자열의 따옴표를 다루다 파일을 깨뜨려 테스트 72건이 죽었다.
**큰 문자열을 넣을 땐 Write 도구를 쓸 것.**

hdiutil create -size 20m -fs APFS -volname "작업용SSD" /tmp/작업용SSD.dmg -quiet

## 10. 개발 태도

T5는 **답답한 AI가 되면 안 된다.**

사용자가 할 수 있는 일을 대신하게 만드는 것이 목표가 아니다.
**T5가 할 수 있는 일을 사용자에게 떠넘기지 않는 것**이 목표다.

안전은 중요하다. 하지만 **안전은 능력 축소의 핑계가 아니다.**

좋은 설계는:

- 더 많이 할 수 있게 만들고
- 필요한 순간에만 승인을 받고
- 실제로 한 일을 원장에 남기고
- 막힌 이유와 다음 길을 정직하게 말하고
- 다음 턴에서 그 사실을 이어받게 한다

이 원칙을 어기면 기능이 많아도 T5답지 않다.

**작업 시작 전에 §0의 두 문서를 읽어라. 그리고 오너의 지시를 기다려라.**
