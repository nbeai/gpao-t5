# T5 일곱 영역 기능·성능 정밀 보고

- 기준일: 2026-08-02
- 방법: 코드·계약 시험·돌연변이·실제 OAuth 모델·실제 브라우저 사용 대조
- 척도: 5=설치 사용자에게 안정 제공, 4=강한 개발 완성도, 3=유용하지만 사용자 가시 공백

## 총평

T5는 모델을 강제로 규칙 기계로 만드는 앱이 아니라, 모델 앞에 현실·기억·권한·손·영수증을 놓아
사람의 목적을 실제 결과로 이어 주는 로컬 AI OS다. 기억, 자동화, 제한 에이전트, 파일·웹·문서 손,
승인과 복구의 본체가 제품 경로로 섰다. 이번 90항 보강으로 이전 승인 혼입, 자동화 계약 변조,
추측 경로 사실화, 형식 수정의 빈 확인말을 닫았다.

현재는 **강한 개발 완성체이자 설치 전 사용자 검증 단계**다. 대중 완성품이라 부르기 전에 설치·업데이트
생명주기, 장기 순수 대화 합의, 도구 턴 지연을 더 다뤄야 한다.

## 1. Selfhood / 자기파악 — 4.1

- 제품 정체와 현재 모델을 구분하고 실제 연결·실행 손·승인 필요 손·로컬 환경을 파생한다.
- 실제 브라우저에서 OAuth `gpt-5.5`, 가능한 손, 승인 범위, 비용 미집계를 사실대로 설명했다.
- 한계: 실행 중 연결 변경 직후의 설명 갱신, 역할별 모델과 기본 모델의 사전 설명 차이, 비용 직접 집계는 제한적이다.

## 2. BEAI5 Model Operation / 모델 운용 — 4.3

- 현재 요청·이력·기억·작업상태·도구·권한·시간·표면을 역할별 사실 블록으로 조립한다.
- OpenAI API/OAuth, ChatGPT OAuth, Anthropic, Gemini, 호환 서버와 역할별 바인딩을 지원한다.
- 텍스트와 tool call 스트리밍을 함께 보존하고 미지원 경로는 가장하지 않는다.
- 한계: 일반 자동 failover와 모든 모델의 기능 동등성은 없다. 모델별 이행률은 OS 구조 판정과 분리해야 한다.

## 3. Intent / Context / T-cell — 3.8

- 축약 후속, 대명사 대상, 현재 요청 우선, 한 턴 예외, 정정, 보류·재개가 작동한다.
- 관찰→묶음→후보→replay→확인→입장→정정 상관→가역 감쇠·복원 회로가 제품 경로에 있다.
- 형식·길이 수정은 예고 턴을 쓰지 않고 같은 내용을 즉시 고치도록 보강했고 실제 브라우저에서 성립했다.
- P1: 30턴 순수 대화에서 최근 이력 밖의 합의 일부가 종합에서 빠졌다. 출처·수정·철회를 가진 대화 작업상태가 필요하다.

## 4. ActionPlan / Authority — 4.5

- A0~A3, 자동 진행·승인·거절·resume, 인자·대상·경로 대조와 완료 계약이 있다.
- 현재 발화 행동을 TurnRef·요청 digest에 묶어 과거 삭제가 새 요청에 다시 승인되는 경로를 닫았다.
- 자동화 활성화 계약은 요청 본문을 믿지 않고 후보 action·활성 skill·담당 profile에서 서버가 파생한다.
- 실제 브라우저에서 삭제 승인 1건, 다음 무관 턴 버튼 0, 원본 보존을 확인했다.
- 한계: 일반 자연어 프로젝트 성공기준과 진행률 표면은 파일 산출물만큼 기계적으로 강하지 않다.

## 5. Router / Execution — 4.2

- 파일 탐색·읽기·쓰기·버전, PDF·DOCX·XLSX·HWPX, 터미널·프로세스·웹·검색·MCP/API/CLI/OAuth,
  Slack/Telegram, 자동화, 제한 에이전트를 연결한다.
- 런타임 HOME과 표준 폴더를 실행 직전에 결합해 모델의 추측 절대 경로를 실행하지 않는다.
- 실패 인자는 확인된 호출과 분리하고 외부 전송 민감값은 발신 전에 가린다.
- 실제 브라우저에서 격리 Downloads 목록과 정확한 삭제 대상까지 관통했다.
- 한계: 로그인된 사용자 브라우저·데스크톱 GUI 일반 조작, 일부 외부 커넥터, 장기 다중 에이전트는 제한적이다.

## 6. Work Surface / UX — 3.8

- 대화 스트리밍, 세션·연결 설정, 승인, 기억 성장, 자동화 설정·취소 표면이 있다.
- 자동화는 setup 조회 후 skill·담당·일정을 고르고 서버 파생 계약으로 활성화한다. 옛 취소 409 표류를 닫았다.
- 데스크톱·모바일 첫 화면과 승인 카드 생명주기를 실제 브라우저로 확인했다.
- 한계: 자동화·에이전트·복구를 한곳에서 관리하는 통합 작업면, 접근성 체계 검증, 긴 대화 탐색은 부족하다.
- 도구 턴 첫 글자가 약 42초까지 걸려 현재 가장 큰 사용자 체감 성능 문제다.

## 7. Truth Ledger / Recovery / Growth — 4.1

- TurnRef, ToolReceipt, 호출 신분, 출처, blocked/awaiting, 자동화·AgentRun 원장과 재시작 복구가 있다.
- 성공 호출은 `calledWith`, 실패 시도는 `attemptedWith`로 분리한다. 추측 절대 경로는 성공 사실로 승격하지 않는다.
- single-writer·파일 직렬화·해시·소스 지문으로 동시 저장과 검증 오염을 막는다.
- 한계: 일반 사용자가 전체 사건·복구·다음 행동을 한눈에 보는 통합 원장 화면과 설치 서비스 재시작은 미완이다.
