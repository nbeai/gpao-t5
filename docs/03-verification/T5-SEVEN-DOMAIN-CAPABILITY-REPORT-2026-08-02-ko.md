- 평가 척도: 5=설치 사용자에게 안정적으로 제공 가능, 4=강한 개발 완성도, 3=유용하지만 사용자 가시 공백, 2=부분 구현, 1=개념 수준

## 결론

T5는 기능을 나열한 채팅 앱이 아니다. 모델이 현실을 보고 판단하고, 실제 손으로 실행하고, 승인과
영수증을 남기며, 실패 뒤 이어 가는 로컬 AI OS의 본체가 이미 섰다. 특히 실행 안전·권한·원장·파일
손발·제한 위임은 현재 코드 규모보다 높은 완성도를 보인다.

그러나 **설치 가능한 완성품과 동일한 뜻은 아니다.** 실제 30턴 브라우저 시험에서 도구 실행이 없는
오래된 대화 합의가 최종 종합에서 빠졌고, 자동화 화면은 현재 백엔드 계약을 완전히 채우지 못한다.
따라서 현재 지위는 `T5_W6_DEVELOPMENT_PASS`를 유지하되, 사람 사용 품질은 지속 검증 단계다.

## 1. Selfhood / 자기파악 — 4.1

**현재 기능**

- T5 정체와 현재 모델을 분리한다. 제품은 GPAO-T5이고 모델은 현재 판단 두뇌다.
- 실제 연결·실행 가능한 손·막힌 손·승인 필요 손을 descriptor에서 파생한다.
- 현재 대화의 작업 상태, 로컬 실행, 브라우저 응답 표면, 루프백 노출, 비용 미집계를 말한다.
- 사용자가 지은 이름과 SOUL/CAPABILITIES 사용자 편집을 재시작 뒤에도 보존한다.

**실측**

- 실제 브라우저에서 OAuth `gpt-5.5`가 정체/모델, 실행 손, 한계, 승인 범위, 실행 환경을 구분했다.
- 로컬 쓰기 요청은 승인 카드로 멈췄고 거절 뒤 파일은 없었다.
- 자기상태·언어 계약 돌연변이 5종이 모두 지정 검사를 실패시켰다.

**한계**

- 상세 능력 문서는 부팅 시 파생되므로 실행 중 연결 변화 직후에는 갱신 지연 가능성이 있다.
- 역할별 모델 바인딩이 기본 모델과 다를 때 호출 영수증은 정확하지만 호출 전 자기 설명은 기본 프로필과
  어긋날 가능성이 있다.
- 브라우저 실측 한 턴에서 T5가 한 일을 사용자가 한 일처럼 표현한 주체 귀속 오류가 있었다.
- 호출 비용을 직접 집계하지 않는다. 이번 보강은 모른다는 사실을 정확히 말하게 한 것이다.

## 2. BEAI5 Model Operation / 모델 운용 — 4.2

**현재 기능**

- 정체·현재 요청·최근 대화·기억·작업상태·도구·권한·시간대·표면을 역할별 사실 블록으로 조립한다.
- OpenAI API/OAuth, ChatGPT OAuth, Anthropic, Gemini, OpenAI 호환 서버를 지원한다.
- 역할별 모델 바인딩, 실제 호출 신분 영수증, 도구 호출, 스트리밍과 단발 경계를 가진다.
- 모델이 의미·정정·범위를 판단하고 OS가 권한·증거·상태 전이를 기계적으로 집행한다.

**성능**

- 공식 게이트의 프롬프트는 2,159자(고정 2,130 + 가변 29), 헌장 1,700자 상한을 지킨다.
- OpenAI 계열 도구 스트리밍은 텍스트와 tool call을 함께 보존한다. 파서가 없는 경로는 가장하지 않는다.
- H02 교차에서 `gpt-5.1` 4/6, Claude Opus 3/3으로 모델별 이행 차이를 기록했다.

**한계**

- 연결은 여러 개지만 실패 시 모델을 자동 전환하는 일반 failover 정책은 없다.
- 모델별 도구 스트리밍·추론 effort·역할 프로필의 기능 동등성은 완전하지 않다.
- 모델 품질 변동을 OS 결함처럼 계속 보정하면 프롬프트가 비대해질 위험이 있다. 구조 장부와 모델 이행
  장부를 계속 분리해야 한다.

## 3. Intent / Context / T-cell — 3.7

**현재 기능**

- 축약 후속, 대명사 대상, 현재 요청 우선, 한 턴 형식 예외, 정정, 보류/재개를 처리한다.
- 최근 대화 12개 메시지·4,000자, workingState, activeGoal, lane, 사용자 기억, 검증된 원리를 조립한다.
- T-cell은 관찰→묶음→후보→replay suite→사용자 확인→입장→정정 상관→가역 감쇠/복원까지 갖췄다.
- 민감 발화는 관찰·묶음에 원문을 복제하지 않으며, 잘못된 원리보다 미학습을 택한다.

**실측**

- T-cell H01~H07 봉인. H02는 주 모델 4/6 제한부, Claude 교차 3/3.
- 실제 30턴 대화에서 수정값 우선, 날짜 오류 교정, 한 턴 표 예외, 22턴 뒤 보류 작업 재개가 성공했다.
- 30턴 동안 빈 답과 무관 문맥 누출은 0이었다.

**P1 한계: 장기 순수 대화 합의**

- 최종 종합에서 행사명, 인원, 수정 예산, 메뉴 합의 일부가 빠졌다.
- 원인은 단순히 모델이 가끔 잊은 것으로 볼 수 없다. `workingState.subjects`는 실제 도구 영수증 중심이고,
  순수 대화 합의는 구조화되지 않는다. 최근 이력 12개 메시지를 벗어나면 오래된 합의가 사라지고
  `activeGoal`은 최근 요청에 의해 교체된다.
- 다음 보강은 무제한 요약이나 키워드 추출이 아니라, **합의/수정/미정/완료의 출처와 철회 가능성을 가진
  대화 작업상태**를 설계하고 A/B 브라우저 시험으로 검증하는 일이다.

## 4. ActionPlan / Authority — 4.3

**현재 기능**

- A0~A3 권한 등급, 자동 진행/승인, 미리보기, 만료, 거절, resume, 인자·대상·경로 범위 대조가 있다.
- 파일 생성·변경, 외부 전송, 삭제, 서버·터미널 작업이 서로 다른 위험과 되돌리기 사실을 말한다.
- ActionPlan의 완료 계약과 실제 write 영수증 신분이 결합돼 말뿐인 완료를 막는다.
- AgentRun 자식 권한은 부모의 부분집합이며 쓰기·전송·장기기억·재귀 위임을 얻지 못한다.

**실측**

- 실제 브라우저 승인/거절, 별도 결과물 생성, EACCES 복구, 원본 해시 불변이 제품 경로에서 확인됐다.
- 승인 카드 없이 위험 작업이 실행되는 돌연변이와 권한 확대 돌연변이를 스윕이 차단한다.

**한계**

- successCriteria가 일반 자연어인 작업은 파일 산출물 계약만큼 기계적으로 완료를 증명하지 못한다.
- 한 턴 실행 걸음 상한은 6이다. 복잡한 프로젝트는 durable job/agent/automation으로 넘어가야 한다.
- 사용자에게 계획 진행률과 완료 근거를 한눈에 보여주는 전용 프로젝트 표면은 아직 얇다.

## 5. Router / Execution — 4.1

**현재 기능**

- 파일 탐색/읽기/쓰기/버전 비교, PDF·DOCX·XLSX·HWPX 본문 추출, 터미널, 프로세스, 웹 수집,
  검색, MCP/API/CLI/OAuth 커넥터, Slack/Telegram, 자동화, 제한 에이전트가 연결돼 있다.
- robots, 로그인벽, 봇 차단, timeout, 출처 영수증을 구분한다.
- H10은 실제 OAuth 모델에서 두 제한 자식이 사용자 지정 폴더를 병렬로 읽고 통합한 경로가 있다.

**성능**

- 회귀 1,844건, 돌연변이 203건, 공식 게이트 CPU 24.8초/벽시계 16.5초.
- 런타임 외부 의존성 0, Node 20+ ESM이며 빌드 변환 없이 시험한 소스가 패키지에 들어간다.

**한계**

- 브라우저 손은 읽기/관찰과 임시 프로필 중심이다. 로그인된 사용자 브라우저·데스크톱 GUI 조작은
  일반 기능으로 완성되지 않았다.
- 메일 실행 손과 일부 커넥터는 연결 선언/준비 수준이거나 외부 자격에 의존한다.
- AgentRun은 안전한 읽기 위임에 강하지만 장기 프로젝트형 다중 에이전트 운영은 아직 제한적이다.

## 6. Work Surface / UX — 3.4

**현재 기능**

- 대화 스트리밍, 세션, 모델/커넥터 설정, 테마, 승인 카드, 기억 성장 표면, 취소/복원 버튼이 있다.
- 첫 인사를 한 문장으로 줄이고 능력 나열·자동 도움 제안·고정 안내 문구를 제거했다.
- 실제 브라우저에서 설정·테마·새 대화·승인 거절·파일 결과 확인이 동작했다.

**P1 한계: 자동화 표면 계약 불일치**

- 화면의 자동화 승인 요청은 현재 `candidateId`와 `expiresAt`만 보낸다.
- 백엔드는 활성 `skillId`, `agentProfileId`, `trigger`, `authorityEnvelope`를 요구한다. 따라서 현재
  제안 카드만으로는 canonical 자동화를 온전히 켤 수 없다.
- 작업 목록·실행 이력·일시정지·재개·취소를 한 화면에서 관리하는 사용자 흐름도 완성되지 않았다.

**그 밖의 한계**

- 장기 대화 탐색, 에이전트 자식별 진행/취소, 실패와 복구의 통합 표면이 부족하다.
- 키보드·스크린리더·초점 이동 등 접근성은 체계적 실측이 없다.
- 반복되는 “좋아” 같은 시작말과 긴 답이 실제 30턴에서 남았다.

## 7. Truth Ledger / Recovery / Growth — 4.0

**현재 기능**

- TurnRef, ToolReceipt, 호출 신분, 출처, 실패 분류, blocked/awaiting, 완료 결과, 자동화/AgentRun 원장이 있다.
- crash/restart, claim heartbeat, stale owner, 취소, skip/catch-up-once, archive/restore, pin/decay를 다룬다.
- single-writer·파일 직렬화·HMAC/해시·소스 지문으로 동시 저장과 검증 오염을 막는다.

**실측**

- 자동화 코어는 재시작 뒤 terminal run을 재실행하지 않고 stale claim을 복구한다.
- T-cell 감쇠→입장 제외→복원→재입장, 성장 표면의 붙듦/치움/복원이 제품 경로에서 관통했다.
- 돌연변이 스윕은 임시 사본에서만 203건을 주입했고 활성 소스 지문이 전후 동일했다.

**한계**

- 원장은 여러 저장소와 화면에 분산돼 일반 사용자가 “무슨 일이 있었고 다음에 무엇을 할지”를 한 곳에서
  보기 어렵다.
- 스케줄러는 현재 서버 프로세스 수명 안에서 돈다. 설치 서비스와 OS 부팅 후 복구는 배포 단계다.
- 성장 신호 중 모델의 cite/correction 호출률은 완전하지 않다. 안전한 무반응은 보장하지만 반드시
  학습되는 것은 아니다.

## 우선순위

1. **P1 장기 대화 작업상태**: 합의·수정·미정·완료를 출처와 함께 보존하고 30~50턴 A/B로 증명.
2. **P1 자동화 사용자 흐름**: 후보 계약 편집/확인→활성화→일시정지/재개/취소→실행 원장까지 한 표면.
3. **사람 사용시험 상시화**: smoke, 장기 대화, 프로젝트 완료, 자동화, 에이전트를 서로 다른 시나리오로
   순환하고 같은 원인 두 번이면 측정을 멈춰 제품 결함 하나로 올린다.
4. **설치 생명주기**: 서명 패키지, background service, 업데이트, 제거/복구.
5. **구조 보강은 행동 보존 전제**: `server.js`, `turn.js`, `tcell-grow.js` 책임 분리는 실사용 P1을
   가리지 않는 별도 작업으로 진행한다.
