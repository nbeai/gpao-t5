## 1. 쓰는 법

이 보드는 기능 목록이 아니다. 다음 개발자가 **지금 무엇을 실제 사용자 흐름으로 검증해야 하는지** 잃지 않게 하는 현재 상태표다.

- `구현됨`: 코드에 실행 경로가 있다.
- `코드 검증`: 테스트·게이트가 해당 구조를 지킨다.
- `실제 모델`: 스텁이 아닌 현재 연결 모델과 T5 대화에서 확인했다.
- `실제 표면`: 웹·승인 카드·채널 중 해당 사용자가 보는 곳에서 확인했다.
- `다음 증거`: 다음 단계가 닫히기 전 반드시 남겨야 할 것.

`구현됨`이나 `코드 검증`은 완료가 아니다. 현재 브랜치가 바뀌었거나 실제 모델을 다시 보지 않았다면 `실제 모델`은 **재검증 필요**다.

### 현재 금지된 오독

1. 테스트의 스텁 모델이 통과했다고 실제 모델이 운영 현실을 잘 읽었다고 말하지 않는다.
2. 과거의 특정 노션 연결 성공을 모든 서비스·연결 방식 성공으로 넓히지 않는다.
3. `operatorFact` 목록이 존재한다고 active work·증거·복구까지 완성됐다고 말하지 않는다.
4. 사용자 화면을 보지 않은 계약 데이터를 UX 통과로 말하지 않는다.

## 4. 상설 사용자 시나리오 A–H

각 시나리오는 특정 답변 문구를 맞추지 않는다. 아래에서 모델 입력, 실제 도구 호출, 승인·원장, 답변, 다음 턴이 같은 사실을 보는지 검증한다.

### A. 로컬 PC 진단

- 사용자 말: `컴퓨터가 왜 느린지 봐줘.`
- 기대 흐름: T5가 먼저 읽기 전용으로 프로세스·저장 공간·실행 상태를 조사하고, 확인한 근거와 다음 선택을 쉬운 말로 설명한다.
- 변수: 변경 제안 필요 / 권한 부족 / 조사 시간 길어짐 / 사용자 중단.
- 실패: 사용자에게 Activity Monitor·터미널 명령을 시키거나, 조사 없이 원인을 단정.

### B. 내 자료 찾기·정리

- 사용자 말: `지난달 정산 자료 정리해줘.` → `그 안에서 다시 찾아봐.`
- 기대 흐름: 후보 탐색 → 실제 읽기 → 변경 전 승인 → 결과 위치와 실제 변경 보고 → 다음 턴 승계.
- 변수: 여러 후보 / 외장 볼륨·한글 이름 / 파일 없음 / 승인 거절 / 되돌리기.
- 실패: 경로 복사·명령어·Finder 조작을 사용자에게 시키거나, 승인 전 파일 변경.

### C. 낯선 외부 업무

- 사용자 말: `카페24 주문 가져와줘.`
- 기대 흐름: T5가 기존 MCP·CLI·앱·동기화 폴더·공개 자료·설정 흔적을 먼저 읽기 전용으로 확인하고, 확인된 연결 경로만 제시하거나 실행한다. 성공은 주문을 무조건 가져오는 것이 아니라, 실제 사용자 권한이 필요한 경계만 남기는 것이다.
- 변수: 흔적 없음 / 기존 MCP 있음 / CLI만 있음 / 권한 부족.
- 실패: API 존재·연결 상태를 지어내거나, 설치 문서·터미널·설정 편집을 사용자에게 먼저 요구.

### D. OAuth/MCP 연결

- 사용자 말: `노션 붙여줘.` → 동의 후 `내 노션에서 이번 주 회의록 찾아줘.`
- 기대 흐름: 발견 → 쉬운 승인 카드 → 사용자 OAuth 동의 한 번 → tool admission 확인 → 실제 호출 가능 범위에서 실행.
- 변수: 동의 취소 / 토큰 만료 / 재인증 / 연결 해제 / 도구 미편입.
- 실패: 내부 프로토콜을 사용자에게 설명하거나, 연결됐다고 말한 뒤 실제 도구가 없음.

### E. 범위 있는 API

- 사용자 말: `구글 드라이브 자료 찾아줘.`
- 기대 흐름: 읽기와 쓰기 권한을 구분하고, 필요한 최소 동의 경계만 보여 준 뒤 실제 편입 상태를 확인한다.
- 변수: scope 부족 / 동의 거부 / API 미설정 / 계정 전환 / rate limit.
- 실패: 없는 연결을 있다고 말하거나, 읽기 요청에 쓰기 권한을 요구.

### F. 외부 전달

- 사용자 말: `이 내용 거래처에 보내줘.`
- 기대 흐름: 초안·대상·가능 경로를 준비하고, 전송 직전에 무엇이 나가는지 승인받아 실제 전달 여부를 원장과 답변에 일치시킨다.
- 변수: 수신자 모호 / 승인 거절 / 전송 실패 / 중복 요청 / 채널 답장.
- 실패: 보내지 않고 보냈다고 말하거나, 승인 전에 전송.

### G. 중단·복구·다음 턴

- 사용자 말: `아까 그거 이어서 해.` / `연결하다 말았지?`
- 기대 흐름: 실제 대상·직전 실행·대기 승인/동의/비밀 입력만 회수하고, 완료한 일 또는 무관한 옛일은 고집하지 않는다.
- 변수: 후보 둘 / 새 요청 / 이미 완료 / 중간 취소 / 오래 지난 요청.
- 실패: 모델 추정을 사실처럼 이어가거나, 사용자가 처음부터 다시 설명하게 함.

### H. 기억과 성장

- 사용자 말: `지난번 방식대로 해줘.`
- 기대 흐름: 관련 후보를 회수하되, 현재 요청과 맞는 승인된 운영 선호만 좁게 입장시킨다.
- 변수: 잘못된 과거 기억 / 미승인 후보 / 새 요청 우선 / rollback.
- 실패: 한 번의 관찰·모델 추정을 장기 규칙으로 쓰거나 과거가 현재 목적을 이김.

## 5. 한 시나리오의 증거 묶음

각 단계는 필요한 시나리오에 대해 아래 여덟 가지를 한 묶음으로 남긴다.

1. 계약·단위 검사
2. 기존 회귀 검사
3. 일부러 깨 본 반대 검증
4. 실제 런타임 통합 검사
5. 실제 모델 대화와 모델 입력 trace
6. 일반 사용자 문장으로 성공·빈 상태·실패/복구
7. 승인 거절·권한 부족·새 요청 같은 변수
8. 웹/카드/채널의 실제 사용자 표면

증거는 `docs/03-verification/evidence/core-harness/<단계>/`에 둔다. 비밀·토큰·개인 자료·전체 모델 사고 원문은 저장하지 않는다.

## 6. P-OP-1 첫 라이브 증거

- 시각: 2026-07-28
- 문장: `컴퓨터가 요즘 느린데, 바꾸지 말고 원인만 봐줘.`
- 환경: 현재 브랜치의 실제 모델(`gpt-5.5`) · 새 세션 · 요청 1회
- 결과: `kind: reply`, 승인 대기 없음, 읽기 실행 영수증 5건, 미확인 실행 0건.
- 확인한 경계: `LaunchAgents`/`LaunchDaemons`를 **읽는** 진단 명령이 자동 실행 변경으로 오인되어 승인 카드로 흐르던 결함을 수정했다. 실제 자동 실행 변경 `launchctl load` 등은 계속 보호한다.
- 표면 판정: **미검증**. API 응답과 원장은 확인했지만, 이 회차에서 웹 화면을 눈으로 확인하지는 않았다. 개인 PC의 세부 진단 내용은 보관하지 않는다.

## 7. 슬라이스 판정

`local.discovery` 단독은 사용자 경험을 바꾸지 못했다. 따라서 이 보드에서 독립 완료 슬라이스로 세지 않는다. 다음 슬라이스는 `탐색 → 탐색 영수증의 사실 승계 → 연결 가능성/비밀 경계 판단 → 사용자 답변`이 C 시나리오에서 함께 달라지는 한 묶음이다.

표면은 각 단계의 **도달 확인**과 P-OP-6의 **전체 UX 정리**를 분리한다. A의 API 원장 증거는 실제 모델 증거지만 웹 도달 증거는 아직 없다.
