# T5 T-cell 재착수 전 정본 브리핑

- 상태: `CURRENT`
- 대상: Claude 구현선, Codex 감사선, 새 세션 인수자
- 목적: 현재 코어를 보존하면서 새 T-cell 계획을 사용자 성과에서 출발시키기 위한 단일 공유점

## 1. 확인된 현재 사실

1. 과거 TG/CX 구현은 `77d42d4`에서 롤백됐고 현재 제품 사실이 아니다.
2. 새 T-cell 개발 계획은 아직 없다. 퇴역 명세를 고쳐 재개하지 않는다.
3. 현재 코어는 P-OP-7 최종 판정과 Automation AC-1을 유지한다.
4. 현재 기억 원장은 내용 digest만 남기지만 `memory.json`에는 기억 문장이 평문으로 저장된다.
5. 롤백 과정에서 비밀 모양 기억 문장을 막던 경계가 함께 사라졌고, 사용자 발화·모델 제안·검색 반영·
   사용자 모델 API가 민감한 값을 저장할 수 있었다.
6. 전체 테스트 CPU 기준은 40초이고 최근 기록은 36.8초다. 큰 변동 주장은 동일 조건에서 아직 독립
   재현되지 않았으므로 임계치를 올리지 않는다.
7. 전체 제품 인간 시나리오는 존재하지만 새 T-cell 계획 전후를 같은 자로 재는 핵심 10개 기준선은
   별도로 없었다.

## 2. 이번 준비 보강

### 현재 코어 안전 복구

- `src/kernel/l0-evidence/sensitive-text.js`에 의미 판정과 분리된 저장 안전망을 둔다.
- 모델 제안과 정규식 후보는 서버의 기억 저장 직전 같은 경계를 지난다.
- `/search/admit`, `/user-model/traits`, `/user-model/preferences`도 같은 경계를 쓴다.
- 웹·채널 모두 assistant transcript를 지속하기 전에 민감한 `memorySuggestion`을 걷는다.
- 검색 출처 메타데이터와 추정 근거 배열도 같은 경계를 지나며, 과거 오염 후보는 승격을 거부하되
  사용자가 지우는 길은 유지한다.
- UUID 같은 일반 식별자는 허용하고, 알려진 키·JWT·PEM·명시적 자격 값·주민번호·제로폭 우회는 차단한다.
- 차단 시 원문을 저장하지 않고 사람말로 `장기 기억에는 남기지 않았어요`라고 알린다.
- 정상 선호·기억·검색 반영 동작과 T-cell 코드는 바꾸지 않는다.
- 이 보강은 **장기 기억 저장 경계**다. 사용자가 입력한 대화 원문은 현재 T5의 맥락 복원 계약에
  따라 세션 transcript에 보존된다. 이를 범용 비밀 금고나 transcript 마스킹 완료로 과장하지 않는다.
- transcript의 민감정보 토큰화·보관 정책은 현재 코어의 별도 개인정보 슬라이스다. T-cell 계획에
  섞거나, 기억 저장 차단을 근거로 완료됐다고 쓰지 않는다.

### 성능 게이트 교정

- `scripts/gate-baseline.json`의 40초를 변경하지 않는다.
- `node scripts/calibrate-gate.mjs --runs 5`로 동일 커밋·동일 시험 집합을 반복 측정한다.
- CPU와 벽시계, 정확성 실패를 분리하고 median·p95를 기록한다.
- 시험 증가를 이유로 유효한 검사를 줄이거나 기준선을 자동 상향하지 않는다.
- 2026-07-30 첫 5회 측정은 높은 부하(load average 8.19→15.26)에서 CPU 48.35~52.40s,
  벽시계 18.47~20.54s였다. 이는 조용한 기준값이 아니며 40초 상향 근거가 아니다.
- 최종 보강 작업트리 3회 반복은 정확성 1,219건 전부 통과, CPU 41.07~41.73s
  (median 41.10s, p95 41.73s), 벽시계 14.76~14.87s였다. 낮은 부하의 동일 조건 A/B는
  보강 전 24.85s·보강 후 22.12s, 5회 통제 측정은 median 24.05s·p95 24.44s였다.
  Codex 독립 재실행도 CPU 22.9s·벽시계 12.1s로 공식 gate PASS를 확인했다.
  40초 기준과 검사 수는 바꾸지 않았으며 초과 원인은 환경 부하로 판정한다.

### 인간 기준선

- `T5-TCELL-CURRENT-CORE-HUMAN-BASELINE-2026-07-30-ko.md`의 H01~H10을 새 계획보다 먼저 실행한다.
- 질문·카드·클릭·완료 턴·첫 진행 표시·가장 긴 공백·총 시간·목표 달성·승계·정정·복구를 측정한다.

## 4. 금지

- 퇴역 TG/CX 문서나 커밋을 현재 구현 지시로 사용하지 않는다.
- 내부 계약·테스트 수·상태 객체를 사용자 성과로 보고하지 않는다.
- T-cell을 전경 심사 기관이나 카드 생성기로 만들지 않는다.
- 정규식·대본·금지문으로 모델의 말귀를 대신하지 않는다.
- 안전을 이유로 가역 로컬 작업·조사·초안·학습·성장을 반복 승인으로 막지 않는다.
- CPU 단발 측정으로 기준선을 올리거나 검사를 줄이지 않는다.
- 후보·replay·게시·입장 중 어느 한 조각만 만들고 생산 수명주기라고 보고하지 않는다.

## 5. 역할과 완료 언어

- Claude: 새 계획 승인 뒤 구현, 생산 배선, 실제 화면·모델·사용자 시나리오 증거.
- Codex: 현재 사실·비교 근거·시나리오·계획 정합성 감사, 구현 뒤 독립 실행 감사.
- 오너: 제품 철학, 우선순위, 실제 권한, 새 계획 확인.
- 개발팀·감사팀은 터미널·브라우저·버튼·화면·성능 측정과 재현을 직접 수행한다. 오너 조작은 로그인,
  동의, 비밀 입력, 비용·외부 권한, 대체 불가능한 최종 제품 판단에만 요청한다.
- 이 문서와 준비 보강은 T-cell 완료가 아니다. `재착수 준비`로만 부른다.
