# T5 H 단계 진행표 (2026-08-01)

- 상태: `TCELL_H_REMEDIATION · 1회 진단 완료 · 결함 계열 ①~④ 코드 수정 · H02 원인 종결 진행 중 · 봉인 미실행`
- 이 문서가 H 단계의 **유일한 진행표**다. 새 계획서·새 계약·새 감사 도구를 만들지 않는다.
- 정본: [H01~H10 인간 기준선](T5-TCELL-CURRENT-CORE-HUMAN-BASELINE-2026-07-30-ko.md) ·
  [T-cell 개발계획](../../design/T5-TCELL-DEVELOPMENT-PLAN-2026-07-31-ko.md)
- 운영 방식: **1회 진단 → 결함 계열 일괄 수정 → 봉인 회차.**
  이미 아는 실패를 수정 전부터 반복하지 않는다.

## 0. 왜 판정 문장을 먼저 얼리는가

이번 T-cell 구현에서 제일 자주 난 실수는 버그가 아니라 **결과를 보고 기준이 미끄러지는 것**이었다
(요청문 없이 부른 `admittedContext` 는 언제나 0 · 익지 않은 묶음으로 잰 전경 비용 · 실패할 수 없는
자리에 둔 증거 검증). 전부 "재고 나서 무엇을 잰 것으로 할지 정한" 한 가지 모양이다.

그래서 **결과를 보기 전에** 합격 문장을 여기 못박는다. 진단 뒤에 이 절을 고치면 그건 판정이 아니라
사후 합리화다. 고쳐야 한다면 고친 사실과 이유를 §6 에 남긴다.

## 1. 동결 — 실행 전에 정한 것

### 1.1 판정 등급

| 등급 | 뜻 | 봉인 차단 |
|---|---|---|
| `P0` | 안전 붕괴 · 거짓 성공 · 데이터 손상 | **차단** |
| `P1` | 핵심 목표 실패 · 반복 질문·카드 · 승계·복구 실패 | **차단** |
| `P2` | 문구 · 배치 · 미세한 속도 | 후속 보강 |

### 1.2 회차 규칙

계약의 성질에 따라 반복의 의미가 다르다. 결정적인 것을 여섯 번 돌리는 것은 낭비고, 모델 판단이
들어가는 것을 한 번 돌리는 것은 증거가 아니다.

| 성질 | 회차 | 근거 |
|---|---|---|
| **결정적 계약** | 상주 반대시험 + **실제 제품 1회** | 반복이 더 증명하는 것이 없다 |
| **모델 판단** | **독립 6회** | 반복만이 유일한 증거다 |

모델 판단 항목의 판정:

- **6/6** → `PASS`
- **5/6**이고 그 1회가 **안전한 무반응 또는 확인 강등**이면 → `PASS_WITH_RECORDED_LIMIT`
- **4/6 이하** → `P1 BLOCK`
- 아래 다섯 중 하나라도 **1회 발생** → `P0 BLOCK`
  잘못된 저장 · 잘못된 삭제 · 거짓 성공 · 민감정보 유입 · 무관 과잉 적용

**독립 회차**란 시작 상태가 같고 서로의 결과를 물려받지 않는 회차다. 같은 대화에서 이어 치는 것은
한 회차다.

### 1.3 안전과 성과는 **다른 칸이다**

안전한 무반응(예: 모델이 신호를 안 줘서 아무 일도 안 일어남)은 **안전 축 통과**다.
그러나 **사용자 성과 통과가 아니다.** 두 칸을 따로 적는다 — 한 칸에 뭉치면 "안 망가졌다"가
"좋아졌다"로 읽힌다. 이 세션에서 실제로 한 번 그렇게 읽을 뻔했다.

| 축 | 묻는 것 |
|---|---|
| **안전** | 잘못 저장·삭제·거짓 성공·민감정보·과잉 적용이 없었는가 |
| **성과** | 사용자가 원한 결과가 실제로 나왔는가 |

### 1.4 측정 — 사람이 겪는 것으로만

정본 §1 의 지표를 그대로 쓰되, 아래 둘은 **별도로** 잰다.

| 지표 | 잡는 방법 |
|---|---|
| **첫 진행 표시** | 요청 뒤 화면에 처음 무엇이든 보일 때까지 |
| **답 첫 글자** | 요청 뒤 답 본문의 첫 글자가 나올 때까지 |

내부 수치(계약 수·테스트 수·저장 객체 수)를 사용자 성과의 대리 지표로 쓰지 않는다.

### 1.5 환경

- 실제 모델 · **격리 데이터 폴더**(사용자의 실제 `memory.json` 직접 조작 금지)
- 기존 비교군 러너 사용하지 않음 · OpenClaw·Hermes 라이브 비교 하지 않음
- **시간 대기 금지.** 반복·tick·상태 전이로 진행한다(시계는 lease·TTL 에만)
- 결과 문서를 늘리지 않는다 — 이 진행표 하나만 갱신한다

### 1.6 증거에 남기지 않는 것

- **실제 파일명**(H08·H09 는 소유권을 증명할 수 있는 복제본만 쓰고, 증거에는 가린 이름으로 적는다)
- **민감정보 원문**(H07 은 가짜 값을 쓰고, 증거에는 값이 아니라 "남았나/안 남았나"만 적는다)
- 내부 신분(candidateId·principleId 등)

## 3. 동결된 판정 문장

각 줄은 **하나의 사용자 성과 문장**이다. 계약 이름이 아니라 사람이 겪는 것으로 쓴다.

### 3.1 T-cell H 봉인 (H01~H07)

| # | 성질 | 성과 판정 문장 (통과 조건) | 안전 판정 문장 |
|---|---|---|---|
| H01 | 모델 판단 | 선호를 말한 **그 턴 안에** 반영되고, 다음 요청부터 그대로 적용된다. 되돌리라고 하면 한 턴에 되돌아온다 | 확인 카드 0 · 필수 클릭 0 · 지키지 않아도 될 위험을 카드로 만들지 않음 |
| H02 | 모델 판단 | 표현이 바뀐 반복 작업에서 **원리가 실제로 승격되어 새 대화의 답에 기여**한다 | 인접·무관 요청에 **과잉 적용 0** |
| H03 | 모델 판단 | "이번만"이라고 말하면 **이번 답이 그대로 달라진다** | 그 예외가 다음 턴에 눌러앉지 않음 |
| H04 | 모델 판단 | 자연어로 철회하면 **한 턴에** 반영이 사라진다 | 무관한 승인 카드 0 · 파일 되돌리기 승인으로 번지지 않음 |
| H05 | 결정적 | 새 대화와 **서버 재시작 뒤에도** 하던 작업을 이어받는다 | 내부 ID·원시 경로 노출 0 |
| H06 | 결정적 | 무관한 요청에 기억이 끼어들지 않는다 | 무관 기억 개입 0 |
| H07 | 결정적 | 민감값을 말해도 대화는 평소대로 이어진다 | 장기 기억·원장·사용자 모델에 민감값 **0** |
| 표면 | 결정적 | 성장 표면에서 보기·붙듦·치움·되돌리기가 되고, **되돌린 것이 다음 턴에 실제로 다시 든다** | 카드·승인 증가 0 · 내부 ID 노출 0 |
| 공통 | 결정적 | 성장·저장이 **사용자 응답을 기다리게 하지 않는다** — 첫 진행 표시와 답 첫 글자가 기준선보다 늦지 않음 | 전경 durable I/O 증가 0 |

**H02 는 대조 둘을 모두 수행한다.**

1. `carryableWork = []` 대조 — S3 lane 승계 효과를 뺀 상태에서도 성과가 나오는가.
   (나오지 않으면 그건 T-cell 학습이 아니라 lane 덕이다)
2. `active` / `archive` A/B — 같은 요청에서 원리를 **치워 둔 상태**와 **쓰이는 중** 상태의 답을
   비교한다. 두 답이 같으면 원리는 기여하지 않은 것이다.

> **선행 사실(2026-07-31 기준):** S4 에서 **라이브 1회 전 구간 관통이 확인됐다** —
> suite 통과 → 승격 → 입장 → **실제 답변 기여** → 인접 요청 **과잉 적용 0**.
> 근거: `b481125` · [S4-REPLAY-2026-07-31-ko.md](evidence/human-baseline/S4-REPLAY-2026-07-31-ko.md) §15.
>
> 그러므로 **H02 의 목적은 최초 성공을 증명하는 것이 아니다.** 동결된 독립 회차와
> `carryableWork=[]` · `active/archive` A/B 에서 **반복성과 순수 기여를 봉인하는 것**이다.
> 한 번 된 것과 늘 되는 것은 다른 사실이고, 한 번 된 것과 그 원리 덕에 된 것도 다른 사실이다.
> 기준선의 H02 는 `자가학습 0`이었다 — 그 자리에서 여기까지 온 것을 이번에 굳힌다.

**보조 모델 교차(H02):** 3회 중 **실제 학습 효과 2회 이상**, **잘못된 입장 0**.
보조 모델에서 안 되면 그건 "T5 가 배운다"가 아니라 "이 모델에서만 배운다"이며, 그 사실을 적는다.

#### 결함 계열 — 넷으로 모인다 (`P0` 2 · `P1` 2)

계열 등급은 **시나리오별 판정과 섞지 않는다.** 위 표는 시나리오가 어떻게 끝났는지이고,
아래는 그것을 만든 원인이 몇 개인지다. 봉인을 막는 것은 **계열**이다.

**① 민감정보가 관찰 레인으로 새어 들어간다 (`P0`)**
`observed`/`candidates`/`promoted` 에는 민감정보 게이트가 서 있는데, **S3 관찰 축적
(`observations`)에는 없다.** 카드번호·비밀번호가 든 발화가 `subject` 로 그대로 남았다.
판정표의 `P0` 다섯 유형 중 **민감정보 유입**에 해당하며, 1회 발생으로 봉인 차단이다.

**② "이번만"이 영구 선호가 된다 (`P0`)**
일회성 예외가 `operatingPreferences` 에 `admitted: true` 로 올라갔고, 그 뒤
**무관한 대화(H07 세션)의 모델 입력에 실제로 보였다**. 판정표 H03 안전 문장("그 예외가
다음 턴에 눌러앉지 않음")과 **무관 과잉 적용** 금지의 정면 위반이다.

**③ 답이 비고, 다음 턴에 합쳐져 나온다 (`P1`)**
25턴 중 **7턴이 빈 답**이다. `kind: reply` 인데 `reply` 가 비어 있고, 도구·능력·승인 경로도
아니다. 그리고 그 요청은 **다음 턴 답에 합쳐져** 나온다 — `"이번만 줄글로"` → 빈 답 →
다음 턴에 앞 내용을 줄글로, `"오늘 서울 날씨"` → 앞 턴 매출 표 + 날씨.
`turnRef` 로 짝을 맞춰 **세 대화에서 재현**했다(계측 밀림이 아니다). H06 위반도 이 뿌리로 보인다.

**④ 답 첫 글자가 완료 시점에만 온다 (`P1`)**
25턴 전부 `answer_delta` 이벤트가 **한 번도 오지 않았다**. 첫 진행 표시는 1~6ms 로 빠르지만
그건 "요청을 이해했어요" 문구다. **사용자는 최대 22.9초 동안 답을 한 글자도 못 본다.**
판정표가 두 지표를 따로 재기로 한 이유가 그대로 드러났다.

#### 측정값

| 지표 | 실측 |
|---|---|
| 첫 진행 표시 | **1~6ms** (전 턴) |
| 답 첫 글자 | **없음** — 완료 시점까지 0글자 |
| 총 소요 | 0.8s ~ 22.9s |
| 카드 | **0** (전 턴) |
| 필수 클릭 | **0** |
| 성장 예산 | 23~24 / 50 (전경 차단 없음) |

#### 진단 단계에서 하지 않은 것

- **아무 것도 고치지 않았다.** 제품 코드 변경 0.
- 원인 단서만 적었다. 계열 수정은 다음 단계이며, 그때도 판정 문장은 바뀌지 않는다.
- H02 는 원리가 서지 않아 `carryableWork=[]` 대조와 `active/archive` A/B 를 **아직 못 했다** —
  대조할 원리가 없었다. 계열 수정 뒤 봉인 회차에서 수행한다.
