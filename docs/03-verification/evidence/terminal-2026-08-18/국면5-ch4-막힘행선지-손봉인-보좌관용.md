# 국면 5 · CH4 흐름 ① 막힘 행선지 — 손 봉인 1통

> 판정: **방향 성립 · 와이어 미달 · 정직 봉인**
> 수신: 보좌관 · 전달: 세션 메신저 부재로 원장 등재

## 1. 만든 것

외부 링크를 `canOpen`과 분리된 `blockedOpen` 사실로 보존했다. 관찰 결과에는 ref·이유·민감
질의값을 뺀 주소·공개 원문으로 이어갈 수 있다는 사실이 실린다. 외부 링크 자체는 열리지 않고,
승인 정책과 `toolKind:read`는 불변이다.

클릭 시도 갈래도 이동 0을 유지하며 blocked 영수증으로 내리도록 만들었다. 첫 구현은 웹 blocked
계약에 금지된 `result·sources`를 실어 표적 관통 검사에서 `failed`로 강등됐고, 기존 blocked
영수증의 `막힌곳·다음수단` 칸을 쓰는 방향으로 고쳤다.

## 2. 자 정정

이전 `재시도·전환 0/5`는 blocked 사건 0이라 분모 미성립이었다. recovery와 composition을
분리했고, 오너 지시대로 Codex 자신의 도구 운전 순서를 자에 반영했다.

```
선제 전환  observe 경계 사실 뒤 다른 웹 손으로 목적 달성
복구 전환  act blocked 뒤 다른 웹 손으로 목적 달성
composition 손 가족 둘 이상 + 목적 달성(막힘과 무관)
```

첫 배치 외부 5회는 모두 실제 목적 사실에 도달했다. g1 marker 과잉과 n4 경로 상실도 다음 배치
전에 정정했다.

## 3. 최종 판정

최종 배치에서 blocked receipt 자체는 4회 섰지만, 다음 턴 조립이 `막힌곳` 객체에서 TypeError로
끊겼다. 외부 5회 전량 미달이다. 내부 비경계 5회는 전량 목적 사실을 유지했다.

따라서 닫는 문장 「막히면 왜 막혔는지와 어디로 가면 되는지를 말하고, 그 다음 손으로 간다」는
아직 미성립이다. 경계 사실과 손 전환 방향은 섰지만 사용자 문장이 끝나지 않았다.
