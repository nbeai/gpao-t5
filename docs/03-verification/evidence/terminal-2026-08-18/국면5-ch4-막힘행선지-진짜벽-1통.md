# 국면 5 · CH4 흐름 ① 막힘 행선지 — 진짜 벽 1통

> 수신: 오너·보좌관 · 전달: 세션 메신저 부재로 원장 등재

## 결론

방향은 맞고 와이어 모양 한 곳이 틀렸다. 외부 링크 경계 사실을 받은 모델은 실제로 다른 웹 손으로
전환해 목적 사실에 도달했다. 그러나 blocked 영수증에 실은 `막힌곳·다음수단`의 구조가 기존
와이어 계약과 달라 최종 배치 외부 5회 중 4회가 같은 TypeError로 끊겼다.

이번 배치는 미달 그대로 봉인한다. 제품 수리를 더 얹지 않는다.

## Codex가 같은 도구를 쥐었을 때의 순서

```
관찰 → 경계 후보·실제 주소 확인
  ├─ 이미 다음 주소가 사실로 있으면 실패 클릭을 고집하지 않고 원문 읽기 손으로 전환
  └─ 사용자가 클릭을 명시하거나 시도했다면 blocked 영수증을 받고 원문 읽기 손으로 복구
→ 목적 사실 확인 → 답
```

첫 10회에서 모델은 외부 5회 모두 `observe → act → web.collect`로 갔고 실제 `푸른종`에 5/5
도달했다. 이는 기능 수가 아니라 결과 사실이 다음 손을 부른 실물이다. 첫 자가 이 성공을
`blocked 사건 없음`으로만 읽은 것이 좁았다.

## 최종 배치 미달

```
외부 경계 5회   목적 완결 0/5
                TypeError 4 · 전환 없이 종료 1
내부 비경계 5회 목적 사실 5/5 · blocked 0
회귀            4,398/4,398 · 실패 0
게이트          PASS · CPU 86.9s · 유휴 13.5s · 벽시계 42.5s
```

TypeError 실물:

```
task-context.js:700  for (const m of r?.막힌곳 ?? [])
제품이 낸 값         막힌곳: { kind, address }          ← 객체라 반복 불가
기존 계약            막힌곳: [{ url, fetchState, ... }] ← 배열
```

`다음수단`도 기존 계약은 `{ 방법:'read_url', url, 왜 }`인데 제품은 `{ kind, address }`를 냈다.

## 다음 한 자리

다음 세션은 새 설계 없이 기존 와이어 모양으로 맞춘다.

```
막힌곳:  [{ url: address, fetchState:'blocked', reason:'external_link' }]
다음수단:[{ 방법:'read_url', url: address, 왜:'화면 밖 공개 원문 주소' }]
```

그 뒤 같은 외부 5·내부 5 배치를 새 폴더에서 다시 잰다. 승인 정책·외부 링크 개방·toolKind·
웹 수집 구현은 건드리지 않는다.

쉬운 설명: 길 안내판은 생겼고 AI도 그 안내를 따라 다른 길로 갔다. 다만 안내판을 원장에 꽂는
커넥터 모양을 네모 대신 동그라미로 만들어 다음 턴 조립기가 멈췄다.
