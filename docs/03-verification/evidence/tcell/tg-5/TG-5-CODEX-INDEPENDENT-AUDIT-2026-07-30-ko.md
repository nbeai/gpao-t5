## 2. 차단 결함

### TG5-CX-01 · 모델 제안을 사용자 명시 지시로 오인해 장기 기억을 자동 반영한다

- **등급:** P1 · TG-5 봉인 차단
- **재현:** 격리 서버에서 사용자는 `안녕`만 입력했다. 모델이
  `memory.propose(preference, "사용자는 항상 답을 한 문장으로 원한다")`를 제출하자,
  응답에 `memoryAutoApplied`가 생기고 `/memory`의 `promoted`에 해당 선호가 즉시 저장됐다.
- **코드 사실:** `server.js`의 자동 반영 호출은 모든 `memorySuggestion`에
  `explicit: true`를 공급한다. 제안의 출처가 정규식인지, 사용자의 명시 발화인지, 모델 추정인지
  구분하는 지속 사실이 없다.
- **영향:** 모델의 잘못된 추정이 사용자 확인 없이 이후 대화에 영향을 준다. 되돌릴 수는 있지만,
  사용자가 만들지 않은 장기 선호가 먼저 적용된다.
- **위반 계약:** 결정문 §12의 `explicit + reversible + bounded + user-controlled` 자동 반영 조건,
  절대원칙 §0-A-2의 사용자 현재 지시 우선.
- **종료 조건:** 명시하지 않은 일반 발화와 모델의 임의 `memory.propose`가 장기 기억에 자동 반영되지
  않고, 실제 명시 선호만 자동 반영되는 생산 관통 증거.

### TG5-CX-02 · 백그라운드 성장 큐에 지속 checkpoint와 재시작 복구가 없다

- **등급:** P1 · TG-5 봉인 차단
- **재현/코드 사실:** 성장 진행 상태는 서버 수명의 `Map` 하나이며
  `{running, pending}`만 가진다. 저장된 checkpoint, 부팅 시 미처리 관찰 재개, 완료 위치 전진 경로가
  코드와 검사에 없다. Observation append 뒤 extraction 전에 프로세스가 끝나면 새 서버는 그 관찰을
  다시 깨우지 않는다.
- **영향:** 정상 응답 뒤에도 학습 근거가 재시작 경계에서 조용히 유실된다. 사용자는 실패를 알 수 없고,
  같은 경험을 반복해도 성장이 시작되지 않을 수 있다.
- **위반 계약:** 결정문 §6 백그라운드 불변식 1·4, §7 진입 순서 1, §8
  `재시작 중단 → 미처리 checkpoint부터 정확히 한 번`.
- **종료 조건:** append와 checkpoint의 순서, 프로세스 중단, 재시작 후 정확히 한 번 재개를 실제
  저장소와 새 서버로 관통한 증거.

### TG5-CX-03 · `M1 → M2` 구조 감사가 실제 승격 없이 PASS한다

- **등급:** P1 · TG-5 봉인 차단
- **재현/증거:** 제출 문서 자체가 “승격은 아직 일어나지 않는다”고 기록한다. 제품 검사에는 자연어
  경험에서 시작해 실제 registry의 M1이 M2가 되는 생산 관통이 없고, 구조 감사는
  `transitionCell`·`makeReplayCase` 호출 횟수만으로 `m1_replay_m2_production_lifecycle`을 PASS한다.
- **영향:** 중앙 성장 수명주기가 작동하지 않아도 네 GAP이 모두 닫힌 것으로 보고된다. TG-5B 진입
  판단이 실제 제품 상태보다 앞설 수 있다.
- **위반 계약:** 결정문 §6 불변식 6, §8
  `자연어 경험 → Observation → M1 → replay → M2 → snapshot → 다음 턴 admission`.
- **종료 조건:** 수동 M2 fixture 없이 실제 사용자 경험에서 생성된 M1이 저장 근거·replay를 거쳐
  M2로 전이되고 다음 게시본에 나타나는 관통 증거. 해당 경로가 끊기면 구조 감사도 실패해야 한다.

### TG5-CX-04 · 생산 승격 세포의 역할이 항상 가장 낮은 역할로 게시된다

- **등급:** P1 · TG-5B 진입 차단
- **재현:** M3 세포의 `allowedInfluence`가
  `none, candidate_context, supporting_context, plan_hint, default_value`여도 게시 결과 역할은
  항상 `supporting_context`였다.
- **코드 사실:** 게시자가 허용 목록에서 `SNAPSHOT_ROLES`에 처음 걸리는 값을 사용한다.
  생산 전이의 영향 목록은 낮은 역할부터 높은 역할 순서다.
- **영향:** M3가 검증되어도 `plan_hint`와 `default_value`가 생산 게시본에서 도달 불가능하다.
  TG-5B를 열어도 계획·기본값 개선 성능을 낼 수 없다.
- **위반 계약:** T-cell 성숙도별 영향 역할 계약과 결정문 §10의 게시 역할 계약.
- **종료 조건:** 생산 전이로 만들어진 각 성숙도·원리 유형이 허용된 역할을 정확히 게시하고,
  상한 밖 역할은 게시하지 않는 양방향 관통 증거.

## 3. 비차단이지만 함께 닫아야 할 정합성

### TG5-CX-05 · 자동 반영 사실이 대화 화면에 도달하지 않고 설정 문구도 옛 계약이다

- **등급:** P2
- **실화면 재현:** 명시 선호와 임의 모델 선호 모두 대화에는 일반 답만 보였고,
  `memoryAutoApplied`는 렌더되지 않았다. 설정을 직접 열면 반영된 선호와 되돌리기 버튼은 보였다.
  같은 화면의 설명은 여전히 “기억은 확인한 것만 반영”이라고 표시됐다.
- **영향:** 사용자는 무엇이 자동 반영됐는지 당시에는 알기 어렵고, 화면 설명은 실제 동작과 다르다.
- **위반 계약:** 답·상태·사용자 표면이 같은 사실을 본다는 P-OP 계약, 결정문 §12 사용자 소유권.
- **종료 조건:** 자동 반영의 실제 사실과 사후 제어 설명이 대화·설정에서 모순 없이 보이고,
  되돌리기까지 실제 버튼으로 관통.

### TG5-CX-06 · 게시 대상 성숙도 범위가 정본과 다르다

- **등급:** P2
- **재현:** `projectScopeSnapshot`은 M2·M3뿐 아니라 M4·M5도 게시했다.
- **위반 계약:** 결정문 §10.1의 “principles는 M2/M3” 범위.
- **종료 조건:** 정본이 의도한 게시 대상과 코드·검사가 같은 집합을 사용한다는 양방향 증거.

## 4. 이미 정직하게 열린 범위

아래는 제출자가 공개했으며 이번 감사에서도 닫히지 않은 것으로 확인했다.

- `importLegacyMemory()` 생산 소비자 0
- T-cell 원리 보기·수정·고정·일시정지·범위 축소·rollback·restore 사용자 표면 없음
- active registry count/byte budget과 archive/compaction 생산 경로 없음
- TG-5B 실제 모델 입력 영향 미개방

이 항목들은 숨은 결함이 아니라 현재 미완료 범위다. 다만 결정문 §8의 TG-5B 선행 종료 조건에
포함되므로, 열린 채로 TG-5 전체를 봉인하거나 TG-5B에 진입할 수는 없다.

## 5. 종합 판정

전경 무 durable I/O, 불변 게시본, 세션별 in-memory lane, 회귀·게이트 성능은 확인됐다.
그러나 **사용자 명시성 오판**, **재시작 유실**, **실제 M1→M2 미증명**, **생산 역할 도달 불가**가
남아 있다.

따라서 `84c3c54`는 **유효한 중간 구현 기준선**이지만 TG-5 봉인 기준선은 아니다.
판정은 `RETEST`이며, 인수인계에는 완료가 아니라 위 네 차단과 열린 범위를 현재 사실로 남긴다.
