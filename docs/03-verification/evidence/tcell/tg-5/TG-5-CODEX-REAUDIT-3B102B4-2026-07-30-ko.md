## 2. 판정

### TG5-CX-01 · 명시 기억의 말귀와 무마찰 계약이 모델 습관에 종속된다

- **등급:** P1 · TG-5 봉인 차단
- **생산 관통 1:** 사용자가 `보고서는 항상 글로 받는 게 좋아`라고 명시했지만 모델이
  `memory.propose`를 내지 않으면 자동 반영 0, pending 후보 1이 된다. 즉 카드와 확인 클릭이
  다시 필요하다.
- **생산 관통 2:** 사용자가
  `“보고서는 항상 글로 받는 게 좋아”라고 내가 말한 적 있어?`라고 질문했고 모델이 질문 전체를
  `memory.propose`로 되돌리면, 질문 전체가 `memoryAutoApplied`되어 장기 기억에 저장된다.
- **코드 사실:** 자동 반영의 `user_declared` 신분은 정규식 후보와 모델 후보의 정규화 문자열이
  정확히 같을 때 만들어진다. 선언·질문·인용·부정이라는 의도 사실은 없다.
- **영향:** 같은 사용자 지시가 모델의 도구 호출 습관에 따라 무마찰 자동 반영 또는 카드·추가 클릭으로
  갈린다. 반대로 모델이 질문을 잘못 읽으면 질문 자체가 장기 영향이 된다.
- **위반 계약:** 명시 지시는 같은 범위의 확인, 질문·카드·클릭 비증가, 말귀를 문자열·정규식으로
  되돌리지 않음, 현재 사용자 의도 우선.
- **종료 조건:** 선언·질문·인용·부정·철회와 `memory.propose`를 내지 않는 모델을 모두 실제
  `/turn → /memory`로 관통해, 선언만 모델 계열과 호출 습관에 무관하게 무마찰 반영되고 나머지는
  장기 영향 0임을 증명한다.

### TG5-CX-02 · 다중 묶음은 같은 묶음만 무한 재처리하고 다른 묶음을 굶긴다

- **등급:** P1 · TG-5 봉인 차단
- **재현:** 한 세션에 `파일-A`와 `파일-B` subject의 실패 관찰을 각각 2건씩 남기고 서버를 세 번
  재시작했다.
- **실제 결과:** 세 번 모두 추출 입력은 `파일-A, 파일-A`뿐이었다. `파일-B` 처리 0,
  checkpoint 파일 0, checkpoint 전진 0이었다.
- **코드 사실:** 여러 새 묶음이면 checkpoint를 전진하지 않지만, 다음 재개에서 이미 처리한 묶음을
  제외하거나 다른 묶음을 선택하는 지속 신분이 없다. 매번 같은 최고점 묶음을 고른다.
- **실패 경계:** 손상 checkpoint JSON은 `{sessions:{}}`로 위장되고, checkpoint 쓰기 실패도
  `{sessions:{}}` 성공값처럼 반환된다. 호출자는 완료 여부와 기록 실패를 구분할 수 없다.
- **영향:** 한 묶음은 무한 모델 호출·비용을 만들고, 다른 묶음은 영구히 성장 기회를 잃는다.
  손상·쓰기 실패에서는 중복 처리와 조용한 유실을 구분할 수 없어 정확히 한 번 계약도 성립하지 않는다.
- **위반 계약:** 세션별 백그라운드 성장, 미처리 checkpoint부터 정확히 한 번 재개, 실패를 빈 사실로
  위장하지 않음.
- **종료 조건:** 서로 다른 여러 묶음, 재시작 반복, 처리 중 중단, checkpoint 손상·읽기·쓰기 실패를
  포함해 각 묶음이 누락·기아·중복 없이 처리되고, 완료 사실과 저장 실패가 구분되는 생산 관통 증거.

### TG5-CX-03 · 실제 M1 후보가 확인·승격되는 생산 수명주기가 없다

- **등급:** P1 · TG-5 봉인 및 TG-5B 진입 차단
- **제출자 공개 사실:** replay suite는 통과하지만, 먼저 생긴 미확인 후보와 나중의 명시 지시를
  결합하는 경로가 없다. 후속 추출은 duplicate로 끝난다.
- **독립 코드 확인:** 제품 코드에서 `ConfirmationStore.record()` 소비자는 0이다. 자연어 경험에서
  시작해 기존 M1이 확인·M2 전이·게시되는 관통 경로도 없다.
- **감사 공백:** 구조 감사는 `transitionCell`과 ReplayCase 호출 개수만으로
  `m1_replay_m2_production_lifecycle`을 PASS한다.
- **영향:** T-cell의 핵심 성장 수명주기가 멈춰 있어도 제품과 감사 모두 완료처럼 보일 수 있다.
- **위반 계약:** 자연어 경험 → Observation → M1 → replay → M2 → snapshot → 다음 턴 admission.
- **종료 조건:** 수동 M2 fixture나 호출자 주장 없이 실제 사용자 경험과 저장 근거만으로 기존 M1이
  확인·M2 전이·게시되고 다음 턴에 조회되며, 그 연결을 끊으면 구조 감사도 실패하는 생산 관통 증거.
