## 3. 헌장 대조 — 넷 밖의 정지

```
승인 카드      7과목 전체 0회        ← 카드로 과잉 차단하지는 않았다
구조적 정지    1 (L6 자동화 등록)     ← 헌장 넷(비밀·불가역 파괴·새 상대 첫 전송·돈)에
                                     해당하지 않는데 대화로는 영영 못 한다
되묻기        L5 clarify 3회         ← 완주는 했으나 왕복 3회. 별도 관측
```

**판정: 자동화 등록의 사용자 클릭 강제는 헌장 위반이다.** 예약 등록은 되돌릴 수 있고
(pause·cancel), 돈·비밀·새 상대 전송이 아니다. 헌장 원문 — *"코드와 헌장이 어긋나면
코드가 결함이다."*

## 4. 고치면서 지금 안전을 유지할 수 있나 — **가능하다(조사 근거)**

- 기존 자동화 봉인은 **실행 축**이다: "승인 전 실행 0"(후보는 실행이 아니다) ·
  D1 "승인된 자동화라도 tick 이 파일을 지우지 않는다" · `isJobRunnable` 불변식.
  **등록 축을 여는 것과 충돌하지 않는다.**
- "job 은 사용자 클릭으로만 생긴다"를 단정하는 검사는 **찾지 못했다**(grep 0).
  즉 등록 손 신설로 빨개질 기존 봉인이 현재 발견되지 않는다.
- 그래서 설계는 이렇게 갈린다:
  ```
  등록(가역)      → 자동.  모델이 부른다.  헌장 넷 아님
  실행 시점 경계   → 그대로.  tick 이 헌장 넷 행동을 무인 실행하지 않는다(D1 봉인 유지)
  안전은 카드가 아니라  표면 가시성(자동화 화면 즉시 반영)·원장·되돌리기 한 번으로 산다
  ```
- 남는 위험(정직 고지): 사용자가 모르는 예약이 조용히 생길 수 있다 → 방어는 **가시성**이지
  카드가 아니다. 이 방어가 실물로 서는지는 수리와 함께 봉인으로 물어야 한다.
