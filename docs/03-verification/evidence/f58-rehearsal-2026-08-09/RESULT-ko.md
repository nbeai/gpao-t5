## 수리 둘 (봉인 포함)

① **실질의 창은 모델 신고가 아니라 탐침이 본 창이다.** probe 가 실제로 본 창(`본창`)을
기계 사실로 반환(못 찾은 반환 포함)하고, previewOf 가 신고 부재 시 그것으로 열쇠를 세운다.
press_key·hotkey 는 창 신분만 탐침(요소 탐색 0 · 등급 불변). 봉인 4(본창 열쇠 · 엔터 본창 ·
좌표 금지 유지 · 탐침 창신분).

② **걸음 증발(F-20 계열 세 번째 · P0급).** 걸음 경로의 `승인면제`가 헌장 ③을 채널
손(target)으로만 알아서, 화면 손의 아는 상대는 경계="승인 필요" vs 분기 안 계획="자동"으로
어긋나 grants 빈손 break — **카드도 실행도 원장도 없이** 걸음이 사라졌다. 모델은 영수증
없이 answerOnly 로 몰리자 *"이 환경에선 막혀 있어서"* 를 지어냈다(거짓 실패 서사의 제조
자리 — dae9273 계열. 앞서 "모델이 재전송을 거부한다"로 관측한 것의 뿌리가 **제품**이었다).
수리: 면제에 ②-b(화면 실질 열쇠) — 선빨강(실물 모양: 관찰→신고 없는 type, 걸음 경로) →
수리 → 초록 · 절단 시 그 봉인만 빨강 확인.

## 남은 빨강 한 칸 — PM 판정 요청

**미신고 `press_key`(엔터).** 미상 등급이라 조건 없이 카드다(규율: 모름은 확인 쪽).
기계는 창(본창)을 알고, 칸의 내용도 알 수 있다(탐침이 요소 값을 읽으면). 그러나 미상
걸음에 「기계 확인 실질 + 아는 상대」 면제를 여는 것은 **"미상은 항상 카드" 규율을 넘는
정의역 확장**이라 개발 선에서 넓히지 않았다(같은 자리 세 번째 갈림 — 멈추고 PM).
갈래: (a) 탐침이 칸 내용까지 읽어 실질을 세우고 면제 허용 (b) 닫는 문장을 "type 무음 +
엔터 1카드"로 재정의 (c) 다른 길. 어느 쪽이든 안전 대차표 선행.
