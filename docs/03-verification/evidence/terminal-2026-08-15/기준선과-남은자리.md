## 0. 가장 중요한 사실 하나 — **모델 문제가 아니다**

같은 질문을 두 곳에 넣었다(오너 실측 2026-08-15).

```
질문   "작업 폴더에서 제일 긴 문서가 뭐야?"

클로드코드 + 소넷 4.6 (최저 사양)
  → 셸 명령 2개로 전부 재고 1위 3,590줄 · 2·3위까지 답함

T5 + gpt-5.1 (더 강한 모델)
  → local.file 9회 · 두 개만 재고
     "시작문서 폴더 안은 아직 안 쟀는데 겉보기로는 짧을 가능성이 큽니다.
      필요하면 정확히 찾아볼게요"
```

**더 약한 모델이 더 좋은 답을 냈다. 차이는 터미널을 썼느냐 하나다.**
`wc -l` 한 줄이면 끝날 일을 T5 는 파일 손으로 하나씩 열다가 두 개에서 멈췄다.

→ **부품 문제가 아니라 배선 문제다.** 이 한 줄이 오늘의 결론이다.

## 1. 시험 방법 — **지어내지 마라**

`scripts/terminal-qualification/그냥써본다.mjs`

```bash
node scripts/terminal-qualification/그냥써본다.mjs "작업 폴더에 뭐가 들어있는지 좀 봐줘" "그 중에 제일 긴 문서가 뭐야?"
```

가짜 집·채점 축·「옳은행동」 정의·멀티턴 대본 **전부 없다.**
격리 방에 **이 저장소의 진짜 문서**를 넣고, **오너가 클로드코드에게 하는 말을 그대로** 친다. 판정은 사람이 답을 읽고 한다.

> **오너 지시(2026-08-15)**: *"티파이브의 테스트는 오픈클로나 헤르메스나 클로드코드가 할 줄 아는 걸 하느냐와 똑같은 거야. 그냥 똑같은 시스템 만드는 거야. 거기에 티파이브의 특성을 입히는 거고."*
> *"내가 비개발자라고. 너에게 이것저것 요구하고 있고 너는 그걸 수행하고 있잖아. **이게 기본이다.**"*

**지어낸 과업 다섯(`tasks.mjs`)은 개발자 시험이었다** — node 버전·CPU 아키텍처·csv 필터링. 비개발자 제품에 개발자 시험지를 만든 것이고, 그게 하루를 잡아먹었다. 같은 실수를 반복하지 마라.

## 3-b. ★ 2026-08-15 심야 — **가설을 그만 고르고 양 끝을 쟀다. 범인이 측정값으로 확정됐다**

네 번 실패한 방법(가설 하나 고르기 → 한 겹 고치기 → 라이브 → 안 움직임)을 버리고,
**맨몸 대조군 + 겹 얹기 이분탐색**으로 바꿨다. `scripts/terminal-qualification/맨몸판.mjs` —
같은 격리 방(진짜 문서)·같은 모델(gpt-5.1)·같은 오너 발화 2턴을, 커널 겹을 다 뺀
「기본 다섯 줄」 루프에 넣고 팔만 바꾼다. 3회 반복.

```
팔                                        터미널 호출        판정

⚠️ **이 자로 쓸 수 있는 숫자는 터미널 호출 수 하나다** (손 관리자 정정 2026-08-15).
「답 정답」은 이 자로 못 본다 — 진값은 `wc -l`(줄 수)인데 모든 팔이 바이트로 답했고,
줄 수 1위(새-세션에게-보낼-메세지.md 232줄)는 바이트 1위(AGENTS.md 16,051B)와 다르다.
게다가 7개 「정답처럼 보인」 회차 중 시작문서 안까지 실제로 잰 것은 한 회뿐이다 —
나머지는 최상위만 보고 답했다. **오너가 지적한 그 얕음을 맨몸 팔도 저질렀다.**
「터미널을 잡는다」는 배선이고 「끝까지 재고 답한다」는 손이다 — 후자는 별도 라이브가 잰다.

그리고 F-116(터미널 선언 수리)이 걸린 작업트리에서 `그냥써본다.mjs` 실측:
**터미널 0회 · local.file 6회** — 팔 D 예측과 일치. **F-116 단독으로는 안 산다.**

**결론**: 죽이는 겹은 「**파일 손 선언이 자기를 과대 선언하고 한계를 말하지 않는 것**」이다.
가설 1·2·3 이 전부 터미널 쪽만 보고 있었다 — 범인은 옆에 있는 **파일 손의 선언**이었다.
- `demo-context.js:774` capability — "한 번에 한 자리" 뒤에 집계(여러 파일 세기·훑기)의 한계가 없다
- `demo-context.js:790` schema — "읽기는 이 컴퓨터의 홈 전체" 과대 선언
수리는 E 팔에서 검증된 그대로 **빠진 사실 채우기**(유도): *"여러 파일을 한꺼번에 세거나
줄 수를 재거나 훑는 일은 이 손으로 하나씩 하면 오래 걸린다 — 그런 일은 터미널이 명령
하나로 끝낸다."* 증거 원본: `맨몸대조군-*.json` (이 폴더).

가설3(무서운 문구)은 **단독 범인은 아니다**. 다만 B 와 D 가 같은 0 이라 문구의 추가 효과는
경쟁에 가려 미측정이다 — F-116 수리는 사실 정합(선언=실물)으로서 그대로 가치가 있다.

## 7-b. F-118 — 성공한 probe 관측이 「추정」으로 분류되던 원장 (한 칸 나아갔다)

**선빨강**: A0 계약("probe 성공 = 그대로 답한다")으로 사용자에게 답한 관측이,
applied:false 하나로 확인된사실에서 떨어져 projectReceipts 의 **estimated
("호출 없이 모델 지식으로만 답한 경우")** 로 갔다 — 턴 사실 스트림(turn-surface.js:71)과
최종 답 분류 5곳이 같은 판정을 쓰므로 한 제품에 두 진실이 섰다.

**수리(유도·사실 채움)**: applied 의 뜻은 불변(2026-08-03 재개봉 방지).
실행기(terminal-run.js)가 **실제로 sandbox-exec 로 감쌌을 때만** `sandboxed` 증명을 내고,
성공 갈래는 그 증명이 있는 probe 에만 `probeChangedNothing` 을 실으며, 원장은 그 사실이
있으면 확인으로 센다. 라벨(mode)·가용성(sandboxAvailable)은 발동 조건이 아니다 —
샌드박스 없는 호스트에선 probe 라벨로도 생 zsh 가 돌기 때문(손 관리자·감시자 동시 지적).
확인 문장은 손의 원문("확인만 했어요 — 아직 아무것도 바꾸지 않았어요")이 그대로 실린다 —
커널 작문은 넣지 않았다.

### 7-z-0. ★ 범위 — **거짓말은 사라졌고 마찰은 남았다** (전임 검증 지적 2026-08-15)
「해결했습니다」는 과하다. 밟은 사실을 두 줄로 **가른다**:
```
거짓 문구            3/3 → **0/3**   ← 닫혔다. 카드가 안 바뀌는 것을 바뀐다고 말하지 않는다
사용자가 답을 받은 회차  **1/3**       ← **마찰은 그대로다.** 읽기 명령인데 2/3 이 카드로 갔다
```
**이 구분을 지우지 마라.** 안 남기면 다음 세션이 「이 자리는 닫혔다」로 읽고 남은 마찰을 안 본다.
마찰이 남는 이유는 설계대로다 — 증거가 없으면 「모른다」이고 모르면 카드다(fail-closed).
그 카드를 줄이려면 **판정을 더 정확하게** 만들어야지 문턱을 낮추면 안 된다(그건 조작이다).

## 7-aa. 표적 2(파일 이름 변경 무카드) — **선빨강이 안 선다. 결함이 아니다**

전임 지시로 이 자리를 먼저 열었다(방향이 위험한 쪽이라서). ① 선빨강부터 밟았고 **무죄로 끝났다.**

### 7-aa-1. 밟은 기계 사실
```
라이브 원본 12-28-18  "여기 md 파일들 이름 앞에 오늘 날짜 좀 붙여줘"
                    손순서 file:list ×2 → **file:move ×2** · kind=reply · 카드 0
등급               `fileKind` 는 move 를 **이미 `write`** 로 준다(action-plan.js:20).
                   등급이 새는 것이 아니다
자동이 난 이유       헌장 ②(authority.js:222) — `write` 는 **되돌릴 수 있다고 밝히면 자동**이다.
                   "백업이 있다는 것은 손이 밝혀야 하는 사실" · 로컬 파일 손은 휴지통을 선언한다
★ 그 선언이 참인가   **참이다. 내가 실제로 돌려 확인했다** —
                   move 로 `AGENTS.md` → `2026-08-15 AGENTS.md` 실행 후 방에 새 이름만 남고,
                   `undo` 한 번에 **`AGENTS.md` 로 되돌아왔다**("되돌렸어요" · parked:false)
```
**즉 「막아야 할 것이 통과했다」가 아니다.** 되돌릴 수 있는 로컬 정리를 카드 없이 하는 것은
오너 여섯 제품 법(카드·클릭 최소 · 최소 안전 최대 자동화)과 헌장 ② 그대로다.
`local-file.js:110 undoEntry` · `:522 undo` · `undo-log.json` 이 그 배선이다.

### 7-aa-2. 그래서 이 슬라이스는 **열지 않는다**
```
선빨강 없음  → 수리 없음. 「없는 결함」을 만들지 않는다(오너 원칙)
안 연 것    승인이 열리는 방향의 수리는 **시작도 안 했다** — 반대시험을 세울 대상이 없다
```

### 7-aa-3. 다만 그 회차에 **진짜 남은 것**은 따로 있다 (표본 1 · 승격 안 함)
```

## 7-ag. 두 빨간 칸의 **공통 뿌리** — 집게 둘이 아니라 손 하나 (오너 지시 2026-08-16)

> 오너: *"못한다는 말을 쉽게 하지 마라. 케이스별로 땜빵하듯 개발하지 마라.
> **손을 손답게 만드는 것이지 전용 집게를 만드는 게 아니다.**"*

### 7-ag-1. ①과 ⑤를 따로 고치면 집게 둘이 된다
```
① 집계 범위    `wc -c AGENTS.md README.md` — 폴더 안을 안 보고 답했다.
              **성공했는데 목적 미달**이다(도구는 정상 종료했다)
⑤ 실패 후 완주  tar 세 번 막히자 사용자에게 명령을 넘겼다.
              **실패했는데 다른 수단을 안 골랐다**(zip 도 파일 손도 있었다)
```
겉모습은 다르지만 **같은 함수의 이웃한 두 줄**이 비어 있다. 손 관리자가 정의한 손의 함수:
```
사용자 목적 → 현실 관측 → 수단 선택 → 권한 판정 → 실행
→ **사후 관측 → 목적과 결과 대조 → 미달이면 다른 수단** → 원장이 달성 확인 → 답
                ↑ ①이 여기서 끊긴다        ↑ ⑤가 여기서 끊긴다
```
**정본 §5 순서 6번 「결과 기반 손 전환」이 바로 이 칸이고, 8줄 중 2줄만 배선돼 있다.**
즉 이건 새 발견이 아니라 **계획에 이미 있는 미완 칸**이다 — 그 칸을 세우는 것이 영역 수리다.

## 7-ah. ⑤ 선빨강 **확정** — 실패가 장부에 안 적혀 사다리가 안 돈다 (기계 사실)

내 실행값(격리 방 · 실제 손·실제 샌드박스):
```
손.handler({ command: 'tar -czf backup.tar.gz .', cwd: <임시방> })
  exitCode      **1**            ← 실패했다
  failureState  **undefined**    ← 그런데 장부에는 실패가 없다
  blocked/needsGrant undefined
nextRung([그 영수증], ['local.file','local.terminal'])  →  **null**
```
**사다리는 존재하는데 켜지지 않는다.** `nextRung` 은 `failureState ?? 'none'` 이 'none' 이 아닌
영수증만 본다(recovery-ladder.js:187·196). 그래서 라이브에서 T5 는 tar 를 세 번 시도하고
**다른 수단을 한 번도 안 고른 채** 사용자에게 명령을 넘겼다 — 모델이 포기한 것이 아니라
**커널이 「다음 수단」을 제안할 기회 자체를 안 만든 것**이다.

§3-6 이 기록한 *"exit≠0 이면서 looksBlocked 아닌 갈래도 … failureState 는 막지 않는다"* 가
**여기서 사용자 피해로 실물화됐다.** 그때는 "사용자면에서 거짓이 없다"고 안 열었는데,
이번 대조가 **거짓이 아니라 미완**이라는 것을 보여 줬다(비교군은 같은 자리에서 zip 으로 갈아타 끝냈다).

**닫는 문장(선등록에 쓸 것)**: ✗ *"압축이 막히면 zip 으로 바꾼다"*(집게) →
✓ **"요구가 안 끝났으면 다른 수단으로 끝까지 간다"**(손). 갈래마다 특례 금지 — 규칙 하나로.

**다음 세션이 첫 30분에 할 일**: 이 선빨강을 검사로 고정 → 착수 검문(영역인가 집게인가) →
선등록 → 수리 → 같은 방·같은 여섯 발화로 정면 대조 재판정(§7-ae 조건 그대로 · 비교군 답이 본이다).
⚠️ 조건 비대칭(T5 는 회차마다 새 세션 · 비교군은 한 세션)을 **재판정 때 맞춰라** — §7-af-0.

## 7-ai. ★ 조준 정정 — 「장부에 실패가 안 남는다」는 **일반 결함이 아니었다** (감시자 실측)

내 §7-ah 진단은 한 칸 넓었다. 감시자가 같은 방에서 대안 수단들을 밟아 뒤집었다:
```
zip -r backup.zip .        blocked **true** · needsGrant **true**  → 장부에 남고 **사다리가 이미 켜진다**
cp a.md a-copy.md          blocked **true** · needsGrant **true**  → 같음
tar -czf backup.tar.gz .   blocked 없음 · exit 1 · kind **code/failed**  ← **이 한 갈래만 샌다**
```
**배선은 살아 있다.** 끊긴 이유는 `failureState` 배선이 아니라,
`tar` 의 샌드박스 **쓰기 차단이 `Permission denied` 를 안 내고**
`tar: Failed to open 'backup.tar.gz'` 로 나와 **`code/failed` 로 오분류**된 것이다.
그래서 승인 경로도 사다리도 **둘 다 안 열렸다.**

**즉 지금 특별 취급되고 있는 것이 tar 다.** 새 일반 규칙을 세우는 게 아니라
**다른 손들이 이미 쓰는 차선에 tar 만 못 올라탄 것**을 올려 주는 일이다.

### 7-ai-1. 내 첫 수리안은 종료 조건에 **닿지 않는다** (감시자 검증)
```
"exit≠0 → failureState=failed" 를 그대로 세우면
 (ㄱ) `grep -q 없는말` (exit 1 · 정상 비영 종료)도 **실패가 된다**
 (ㄴ) 사다리가 retry → (같은 지문 2회) **ask_user** → "다른 방법을 알려 주시면 그걸로 해볼게요"
      = **라이브에서 이미 나온 그 증상(사용자에게 떠넘김)과 같은 문장**이다
그 상태로 구현하면 그때는 중단 권고 — 감시자 명시
```

### 7-ai-2. 다시 겨눈 표적 — **목록이 아니라 이미 있는 구문 규칙의 확장**
```
`tar: Failed to open '<자리>'` 의 `<자리>` 는 **명령이 지목한 자리**다(`backup.tar.gz` 가 명령에 있다).
§7-y 에서 이미 세운 규칙 `명령이지목한자리인가` 가 **그대로 적용된다** —
  막힌 자리를 명령이 지목했으면 → 쓰려 한 증거 → blocked/needsGrant → **사다리가 켜진다**
  명령에 없는 자리에서 막혔으면 → 모른다 (그대로)
**tar 문자열을 목록에 넣는 것이 아니다.** 「막혔다고 말하는 문장 모양」이 하나 더 있었을 뿐이고,
가르는 근거는 여전히 **자리**다 — 이 저장소가 이미 쓰는 그 축(`sandbox.js`: 목록은 항상 뚫린다)
```

### 7-ai-3. 착수 전에 채울 것 셋 (감시자 조정)
```
① 반대시험 신설 — **정상 비영 종료**(`grep -q 없는말`)에서 사용자면에 실패 문장·재시도 제안이
   안 나가는가. 지금 이 칸이 비어 있다. **이게 이 수리의 제일 큰 위험이다**
② 기존 반대시험 하나가 **자명하게 초록**이다 — handler 는 성공에서도 failureState 를 안 낸다.
   수리 후에도 통과하므로 아무것도 안 지킨다. 실질을 무는 것으로 바꾼다
③ §2 정정 — "배선 1자리"는 과소 표현이다. 소유 파일은 하나여도 `failureState` **소비처가 다수**다
   (turn-budget 실패창 · work-event-store 성공 영수증 throw · 읽은척차단 · delivered 판정 ·
    모델 입력 「미확인」 표식). 회귀가 여기서 울릴 수 있다
안전면    사다리는 **문장만 만든다**(소비처 4곳 전수 확인) — 승인 증가 우려는 **기각**됐다
종료 판정  같은 방 라이브에서 **T5 가 실제로 파일을 만들었는가(디스크 확인)**. 답 문장이 아니다
```

## 7-aj. 다음 이음새 — 「막혔다를 안다」 → 「다른 수단을 골라 실행」 (밟은 자리만 적는다)

§7-ai 수리로 커널은 이제 **막힘을 안다**(라이브에서 승인 카드가 뜬다). 그런데 파일은 여전히
안 만들어진다(3/3). 그 사이 구간을 밟은 값:
```
사다리 소비처는 turn.js 넷뿐이고 전부 **문장만** 만든다(감시자 전수 확인)
turn.js:501  const 알아본계단 = 계단 && **계단.from !== 'blocked'** ? rungMessage(계단) : undefined;
             ← `blocked` 갈래는 이 자리에서 **따로 취급**된다.

후자라면 그것이 다음 이음새다 — 커널이 알고도 **모델에게 말하지 않는 것**.
⚠️ 아직 결론이 아니다. `blocked` 분기를 따라가 **한 자리로 확정한 뒤** 선빨강을 세워라.
⚠️ 그리고 이번에도 규칙은 하나여야 한다 — 압축 전용 처리 금지(오너 2026-08-16).

### 7-t-6. 선언 오류 1건 — 서식을 고친다 (대응이 아니라 원인 제거)

## 7-ak. ★ 조준 정정 2 — **§7-aj 가설은 기각. 이음새는 그 위에 있다** (2026-08-16 · 기계 실측)

§7-aj 는 *"사다리 소비처 넷은 전부 문장만 만든다 — 그 문장이 모델의 다음 걸음 입력으로 가는지
사용자 표시로만 끝나는지를 가르라"* 고 넘겼다. **갈랐고, 기각됐다.**

### 7-ak-1. 사다리 문장은 모델 입력으로 **간다** (코드로 밟음 · 세 자리 연속)
```
turn.js:2598 · 3212 · 3486   recoveryHint: 다음길(turnReceipts, 있는손(), 손설명())
task-context.js:891          recoveryHint: p.recoveryHint
model-provider.js:669        커널블록.push(`[막힌 것과 다음 길]\n${tc.recoveryHint}`)
```
turn.js:501 의 `계단.from !== 'blocked'` 제외는 **어느 문장을 쓸지**만 고른다 —
:534 가 `알아본계단 ?? 쓸도구말 ?? rungMessage(계단)` 로 결국 받아낸다.
**turn.js:501·2569 는 이음새가 아니다. 다음 세션은 여기를 다시 파지 마라.**

### 7-ak-2. §7-ah 의 근거 하나가 **계측 오류**였다 — handler 반환값은 영수증이 아니다
```
§7-ah 가 한 것   손.handler({command:'tar -czf backup.tar.gz .', cwd})  → failureState **undefined**
                → "장부에 실패가 안 남는다" 로 읽었다
사실            `failureState` 는 handler 가 아니라 **ToolRunner 가 붙인다**
                tool-runner.js:176  `if (out && out.blocked) return receipt({ failureState: FAILURE.BLOCKED, … })`
다시 잰 값       live.tools.run('local.terminal', 같은인자, selfState) → failureState **"blocked"**
```
§7-ai 가 그 진단을 이미 한 칸 좁혔지만, **좁힌 이유도 같은 오염된 자로 잰 값**이었다.
규율: **영수증을 재려면 `tools.run` 을 지나라. `handler` 직접 호출은 영수증이 아니다.**

### 7-ak-3. 진짜 자리 — 단일 변수로 갈랐다 (격리 방 · 실제 손·실제 샌드박스)
원본: `docs/03-verification/evidence/terminal-2026-08-16/probe-말투가른다.mjs` + `-실행값.txt`
```

② cd 작업 && tar -czf backup.tar.gz .            failureState **blocked** · nextRung other_tool
③ tar -czf backup-$(date +%Y%m%d).tar.gz .      failureState **none**    · nextRung **null**
④ cd 작업 && tar -czf backup-$(date +…).tar.gz . failureState **none**    · nextRung **null**  ← 라이브가 친 모양
⑤ zip -r backup.zip .                           failureState **blocked** · nextRung other_tool
⑥ cd 작업 && zip -r backup-$(date +%s).zip .     failureState **blocked** · nextRung other_tool

```

### 7-ak-4. 기제 — 「막혔다」의 두 말투 중 **한쪽에만 폴백이 없다** (terminal-run.js)
```
말투 A  stderr 가 `Permission denied` 계열        :325 갈래
        자리 증명 성공 → sandbox/write
        자리 증명 실패 → **sandbox/blocked_unproven**   ← 폴백이 있다. zip·cp 가 여기로 산다
말투 B  stderr 가 `Failed to open '<자리>'`        :363 갈래 (§7-ai 가 신설)
        자리 증명 성공 → sandbox/write
        자리 증명 실패 → **{kind:'code', why:'failed'}**  ← 폴백이 없다. 그대로 떨어진다
떨어지면  looksBlocked false → 승인도 사다리도 안 열리고 영수증이 **성공(failureState none)** 으로 남는다.
        `$(date …)` 로 만든 이름은 명령 문자열에 리터럴로 없어 `명령이지목한자리인가` 가 항상 거짓이다
```
**즉 특례는 tar 가 아니라 「말투 B 에만 폴백이 없다」는 비대칭이다.**
수리는 규칙을 새로 만드는 것이 아니라 **한쪽에만 있던 비대칭을 없애는 것**이다(오너 2026-08-16 · 규칙 하나).

## 7-al. 착수 검문 결과 — **둘 다 조건부 통과. 조준을 또 좁혔다** (2026-08-16)

### 7-al-1. 감시자 — 판정 **조정**
```
맞다      제품 경로 재현 · 단일 변수 격리 · 사실 2/5 를 스스로 뒤집어 적은 것은 유지하라
틀렸다 ①  「특례 제거」가 아니라 **정의역 확대**다. 두 갈래의 전제가 다르다 —
          :325 는 게이트가 `Permission denied` 라 **stderr 자체가 막힘을 이미 증명**한 뒤의
          「행위자 모름」이고, :358 은 `failed to open` 이라 **막힘이 증명되지 않았다**(ENOENT 도 같은 말투).
          폴백을 그대로 복사하면 **읽다 실패한 진짜 오류가 승인 카드로 간다** — 헛클릭
틀렸다 ②  내가 격리한 단일 변수는 tar 도 cd 도 아니라 **`$(…)` 확장 때문에 리터럴 대조가
          불가능해진 것**이다. 「대조 불능」과 「대조했는데 지목 안 함」은 **다른 사실**이다
틀렸다 ③  기대 효과를 "T5 가 파일을 만들게 된다"로 쓰면 **지배 변수 오귀속**이다 —
          0/3 → 2/3 을 만든 것은 제품 수리가 아니라 **승인 배선(계측)** 이다
순서      **(다) 하네스 → (가) 선빨강 → (나) 수리.** (다) 없이는 (나)의 효과를 잴 자가 없다
예산      이건 같은 문제의 **두 번째 수리**다(33d744fb → 14920b71 → 40f16021 → 지금).
          **세 번째는 즉시 중단 신호** — 패치를 더 붙이지 말고 재설계·오너 결정으로 올려라
```

### 7-al-2. 손 관리자 — 판정 **관절만 움직였다** (착수 조건 0번 미충족 · 조건부 착수 허용)
손 관리자가 **직접 잰 값**(격리 방 · 실제 `runCommand`+`executionBlock`)이 내 표를 넓혔다:
```
명령                                        stderr                              지금 판정
tar -czf backup.tar.gz .                    Failed to open 'backup.tar.gz'      sandbox/write
tar -czf backup-$(date +%s).tar.gz .        Failed to open 'backup-178….tar.gz' **code/failed**  ← 표적
awk -f /nonexistent/x.awk a.txt (순수 읽기)  awk: can't open file /nonexist…     code/failed
sqlite3 "$(echo mine-$$.db)" "create …"     unable to open database file        **code/failed**  ← 미탐
unzip -l nonexistent.zip                    cannot find or open …               code/failed
grep zzzz a.txt                             (없음)                              code/failed
```
★ **오탐 행의 정규식 포획값은 경로가 아니라 낱말 `file` 이었다**(terminal-run.js:357).
**판별의 입구가 자리가 아니라 문자열 어법이라는 기계 증거다.**
```
칸       ⑥(실패 후 다른 수단)이 **아니다.** 이 수리가 여는 것은 손 함수의 **④권한 판정** 칸이다 —
         `code/failed` 면 카드 자체가 안 생겨 「승인해도 못 하는 일」이 된다. 그걸 되돌린다
경계     모델은 exitCode·stderr 를 **이미 받는다**(회차 3 이 증거) → 「다음에 뭘 할까」는 모델 자리.
         「이 실패가 승인으로 풀리는 종류인가」는 **커널만 아는 사실** → 그 칸을 채우는 것은 유도
요구 폭  10칸 중 **2칸의 일부.** 한 칸도 통째로 못 덮는다
경고     입구가 어법이라 목록이 이미 한 번 자랐다(`Permission denied` → `failed to open`).
         **이번이 세 번째 자람이다** — 한 층 위에서 「말투 목록」을 만들고 있다
```

### 7-al-3. 두 검문이 못 박은 **선등록 조건 다섯** (전부 지킨다)
```
① 「영역을 닫았다」고 적지 마라 — **어법 하나를 더한 것**이다
② 오탐 반대시험을 **먼저** 세워라 (`awk -f 없는파일` 이 승인 카드로 가면 안 된다)
③ 종료 조건에 **개입 횟수**를 넣어라 — 비교군은 **0 개입**으로 96,723B 를 만들었다.
   파일만 재면 **카드로 산 초록**이 남는다
④ 전후 대조는 **같은 하네스**로. 하네스 없던 3/3 과 하네스 있는 2/3 을 비교하면
   그 숫자는 **하네스를 잰 것**이다
⑤ 기대 효과는 "회차 1 모양(포기·파일 없음) 하나를 없앤다" 로 **축소**해 적는다
```

### 7-al-4. 정의역 세 줄 — **수리 모양을 고르기 전에 열거한다** (감시자 요구)
```
(ㄱ) 명령에 셸 확장이 있다(`$( )`·백틱·`$VAR`·glob)  → 리터럴 대조가 **원리적으로 불가능**
     지금: code/failed          ← **라이브가 밟은 것은 이것 하나뿐**
(ㄴ) 확장이 없는데 이름이 명령에 없다                → 대조를 했고 **결과가 「지목 안 함」**

**수리는 (ㄱ) 한 줄만 연다.** 폴백을 통째로 복사하면 (ㄴ)까지 열려 헛클릭이 난다(감시자 ①).

### 7-al-5. 정직하게 신고하는 값 — 이 수리가 **못 고치는 것**

뿌리  입구가 stderr 어법인 한 목록은 계속 자란다. **네 번째 자람은 없다** —
      다음은 재설계 후보로 올린다: 「어법으로 알아맞히지 말고 **커널에게 물어본다**」

```

## 7-an. ★ 판정 — **미달. 멈춘다** (라이브 전후 대조 · 2026-08-16)

### 7-an-1. 또 재는 자가 틀렸다 — 먼저 신고한다

### 7-an-3. **선등록대로 멈춘다** — 패치를 더 붙이지 않는다
종료 조건(§7-ai-3 · 「같은 방 라이브에서 실제로 파일을 만드는가」)은 **미달**이다.
감시자가 착수 검문에서 못 박은 재개봉 예산이 정확히 이 자리를 가리킨다:
```

"이번 수리 뒤에도 라이브가 미달이면 패치를 더 붙이지 말고 **재설계 또는 오너 결정 사안으로 올려라**"

**그래서 세 번째 수리를 하지 않는다.** 아래 §7-an-5 를 오너 결정으로 올린다.

### 7-an-4. 라이브에서 새로 본 것 — **결함으로 승격하지 않는다**(표본 부족)
```
관측 ①  수리 후 회차에서 모델이 `cd ..` 로 **상위 폴더**를 압축 대상으로 고르는 모양이 늘었다.
        상위에는 보호 대상(`gpao-t5-channel-secret-*`)이 있어 진짜로 막히고, 거기서 막다른 답이 났다.
        ⚠️ 수리가 그 선택을 유도했는지는 **미측정**이다. 인과로 쓰지 마라 — 표본 2
관측 ②  회차 4 는 모델이 자기 cwd 를 잘못 알아 `cd ..` 뒤에 없는 폴더를 압축하려 했다.
        exit 1 은 **진짜 명령 오류**이고 `code/failed` 판정이 옳다 — 이 수리의 누수가 아니다
관측 ③  「미상 카드를 승인하면 실제로 도는가」는 **못 갈랐다.** 스텁 모델 probe 를 세웠는데
        **대조군(자리를 지목한 명령)도 같이 실패**해서 자가 무효였다(라이브에서는 그게 돈다).
        무효인 자로 낸 값은 안 쓴다 — 이 물음은 **열린 채로 넘긴다**
```

### 7-an-5. ★ 오너 결정으로 올리는 것 — **어법으로 알아맞히기를 그만둘 것인가**
```
지금 구조   「이 실패가 우리 샌드박스 때문인가」를 **stderr 문자열 어법**으로 가른다.
           목록이 이미 세 번 자랐다: `Permission denied` → `Failed to open` → `대조 불능`.
           그리고 지금도 샌다(실측 미탐: `sqlite3 … unable to open database file`)
왜 계속 새나 어법은 도구마다·판마다·로케일마다 다르다. **목록은 항상 뚫린다** —
           이 저장소가 `sandbox.js` 첫 문단에서 이미 버린 방식이다
후보       **커널에게 물어본다.** 이 저장소가 네트워크에 이미 쓰는 구조 그대로다
           (`네트워크만열어볼까` → `reach` 재실행으로 **알아맞히지 않고 밟아서 안다**).
           쓰기 판은 「버릴 수 있는 자리에서 쓰기만 열고 한 번 더 돌려 본다 —
           그때 되면 우리가 막은 것이고, 그때도 안 되면 진짜 명령 오류다」
비용       왕복이 하나 늘고, 버릴 자리를 만드는 값이 든다. **공수·안전 판단은 오너 몫**이다
```

## 7-ao. ★ 오너 결정 — **어법 외우기 금지** · 밟아서 안다 (2026-08-16)

> 오너: *"외우기 금지하자."*

§7-an-5 로 올린 결정이 내려왔다. 「이 실패가 우리 샌드박스 때문인가」를 **stderr 어법으로
알아맞히는 것을 그만둔다.** 이건 새 발상이 아니라 `sandbox.js` 첫 문단으로 **돌아가는 것**이다:
*"명령이 위험한지 알아맞히지 않는다. 돌려 보고 안다. 목록은 항상 뚫린다."*

### 7-ao-1. 타당성 스파이크 — **갈라낸다** (진단 · 제품 코드 0줄)
사본을 만들고 거기서 쓰기를 열어 한 번 더 돌린 실행값:
```
사례                              probe exit   사본에서 exit   판정            사용자자리
tar -czf b-$(date +%s).tgz .          1           **0**      우리가 막았다      불변
sqlite3 "$(echo m.db)" "create …"     1           **0**      우리가 막았다      불변  ★ 어법이 못 잡던 미탐
awk -f /nonexistent/x.awk a.md        2            2         진짜 오류         불변
tar --그런옵션없음 -czf x.tgz .         1            1         진짜 오류         불변
grep -q zzz a.md                      1            1         안 막았다         불변
```
**5/5 정확**하고, 그 안에 §7-al-2 가 「못 고쳤다」고 신고한 `sqlite3` 미탐이 들어 있다.
어법 목록이 세 번 자라고도 못 잡던 것을 **한 규칙이 잡는다.**

### 7-ao-2. 왜 이것이 「규칙 하나」인가
```

바꾸면  갈래가 없다. 물음이 하나다 — **「쓰기를 열어 주면 되는가」**

## 7-as. `find` 자리 — 착수 전 실측 (오너 지시 2026-08-16 「파인드 자리 먼저 정리하고 (나) 가자」)

### 7-as-1. 네 축을 놓고 (A)의 **마찰 비용을 먼저 쟀다** (제품 코드 0줄)
축: (A) exit 0 이어도 stderr 에 막힘 자국이 있으면 본다(기존 말투 A 정규식 **재사용** · 새 어법 아님)
   (B) `실패를삼킴` 목록에 `find` 를 더한다 — **방금 얼린 그 병.** 안 한다
   (C) 쓰기 거부/읽기 거부를 `unlink(` 같은 문자열로 가른다 — 같은 병
   (D) 카드는 안 띄우고 「막힌 자국이 있었다」만 답·원장에 싣는다(마찰 0 · 거짓 0 · 목적은 미달)

(A) 를 걱정한 이유는 **읽기 거부로 「Permission denied」를 뱉는 명령까지 카드로 갈까**였다. 쟀다:
```
사례                       probe exit  stderr 막힘자국   (A) 적용 시
ls -la                        0          없음           그대로 무카드
find . -type f                0          없음           그대로 무카드
du -sh .                      0          없음           그대로 무카드
wc -c b.md 시작문서/a.md        0          없음           그대로 무카드
grep -r zzz .                 **2**      있음           **이미 실패 갈래** — 안 바뀐다
★ find … -delete             **0**      **있음**        **새로 카드**  ← 표적 하나뿐
★ find … -exec rm {} ;        1          없음           이미 처리됨
★ ls *.md | xargs rm          1          있음           이미 처리됨
```
**내 걱정은 기우였다** — `grep -r` 은 exit 2 라 exit-0 갈래에 **애초에 안 들어온다.**
측정된 마찰 증가는 **0**이고 새로 잡히는 것은 표적 하나다.

### 7-as-2. (A) 가 「외우기 금지」와 어긋나지 않는 이유
```
새 어법을 안 만든다   이미 있는 말투 A 정규식을 **그대로 재사용**한다
목록을 안 키운다     `실패를삼킴`(명령 이름 목록)에 손대지 않는다 — 그 목록에 기대는 것을 **줄인다**
근거가 증거다        「exit 0 인데 우리 막음 자국이 stderr 에 있다」 = **실패를 삼켰다는 기계 증거**.
                  이름으로 알아맞히는 것이 아니라 밟은 자국을 보는 것이다
```
⚠️ 그래도 이것이 **어법의 완전한 탈출은 아니다** — 자국을 못 남기고 삼키는 명령은 여전히
`실패를삼킴` 목록에 기댄다. 그 한계를 적고 간다. **목록을 키우지 않을 뿐이다.**

## 7-at. `find` 자리 수리 — **특례를 더한 게 아니라 없앴다** (2026-08-16)

### 7-at-1. ★ 내가 틀렸던 것 — 감시자 정정 (커밋된 검사 문구에 박혀 있었다)
