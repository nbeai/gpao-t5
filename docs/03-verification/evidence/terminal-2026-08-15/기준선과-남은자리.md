## 0. 가장 중요한 사실 하나 — **모델 문제가 아니다**

같은 질문을 두 곳에 넣었다(오너 실측 2026-08-15).

```
질문   "작업 폴더에서 제일 긴 문서가 뭐야?"

클로드코드 + 소넷 4.6 (최저 사양)
  → 셸 명령 2개로 전부 재고 1위 3,590줄 · 2·3위까지 답함

T5 + gpt-5.1 (더 강한 모델)
  → local.file 9회 · 두 개만 재고
     "시작문서 폴더 안은 아직 안 쟀는데 겉보기로는 짧을 가능성이 큽니다.
      필요하면 정확히 찾아볼게요"
```

**더 약한 모델이 더 좋은 답을 냈다. 차이는 터미널을 썼느냐 하나다.**
`wc -l` 한 줄이면 끝날 일을 T5 는 파일 손으로 하나씩 열다가 두 개에서 멈췄다.

→ **부품 문제가 아니라 배선 문제다.** 이 한 줄이 오늘의 결론이다.

## 1. 시험 방법 — **지어내지 마라**

`scripts/terminal-qualification/그냥써본다.mjs`

```bash
node scripts/terminal-qualification/그냥써본다.mjs "작업 폴더에 뭐가 들어있는지 좀 봐줘" "그 중에 제일 긴 문서가 뭐야?"
```

가짜 집·채점 축·「옳은행동」 정의·멀티턴 대본 **전부 없다.**
격리 방에 **이 저장소의 진짜 문서**를 넣고, **오너가 클로드코드에게 하는 말을 그대로** 친다. 판정은 사람이 답을 읽고 한다.

> **오너 지시(2026-08-15)**: *"티파이브의 테스트는 오픈클로나 헤르메스나 클로드코드가 할 줄 아는 걸 하느냐와 똑같은 거야. 그냥 똑같은 시스템 만드는 거야. 거기에 티파이브의 특성을 입히는 거고."*
> *"내가 비개발자라고. 너에게 이것저것 요구하고 있고 너는 그걸 수행하고 있잖아. **이게 기본이다.**"*

**지어낸 과업 다섯(`tasks.mjs`)은 개발자 시험이었다** — node 버전·CPU 아키텍처·csv 필터링. 비개발자 제품에 개발자 시험지를 만든 것이고, 그게 하루를 잡아먹었다. 같은 실수를 반복하지 마라.

## 3-b. ★ 2026-08-15 심야 — **가설을 그만 고르고 양 끝을 쟀다. 범인이 측정값으로 확정됐다**

네 번 실패한 방법(가설 하나 고르기 → 한 겹 고치기 → 라이브 → 안 움직임)을 버리고,
**맨몸 대조군 + 겹 얹기 이분탐색**으로 바꿨다. `scripts/terminal-qualification/맨몸판.mjs` —
같은 격리 방(진짜 문서)·같은 모델(gpt-5.1)·같은 오너 발화 2턴을, 커널 겹을 다 뺀
「기본 다섯 줄」 루프에 넣고 팔만 바꾼다. 3회 반복.

```
팔                                        터미널 호출        판정
A  터미널만 · 중립 선언                     2·2·2·2 (4표본)  부품 무죄 — 비교군과 같은 손놀림

E  파일 손이 **자기 한계를 말함** + 중립     1 · 2 · 3        ★ 전부 살아남 (한 회차는 두 손을 섞어 씀 — 유도의 증거)

```

⚠️ **이 자로 쓸 수 있는 숫자는 터미널 호출 수 하나다** (손 관리자 정정 2026-08-15).
「답 정답」은 이 자로 못 본다 — 진값은 `wc -l`(줄 수)인데 모든 팔이 바이트로 답했고,
줄 수 1위(새-세션에게-보낼-메세지.md 232줄)는 바이트 1위(AGENTS.md 16,051B)와 다르다.
게다가 7개 「정답처럼 보인」 회차 중 시작문서 안까지 실제로 잰 것은 한 회뿐이다 —
나머지는 최상위만 보고 답했다. **오너가 지적한 그 얕음을 맨몸 팔도 저질렀다.**
「터미널을 잡는다」는 배선이고 「끝까지 재고 답한다」는 손이다 — 후자는 별도 라이브가 잰다.

그리고 F-116(터미널 선언 수리)이 걸린 작업트리에서 `그냥써본다.mjs` 실측:
**터미널 0회 · local.file 6회** — 팔 D 예측과 일치. **F-116 단독으로는 안 산다.**

**결론**: 죽이는 겹은 「**파일 손 선언이 자기를 과대 선언하고 한계를 말하지 않는 것**」이다.
가설 1·2·3 이 전부 터미널 쪽만 보고 있었다 — 범인은 옆에 있는 **파일 손의 선언**이었다.
- `demo-context.js:774` capability — "한 번에 한 자리" 뒤에 집계(여러 파일 세기·훑기)의 한계가 없다
- `demo-context.js:790` schema — "읽기는 이 컴퓨터의 홈 전체" 과대 선언
수리는 E 팔에서 검증된 그대로 **빠진 사실 채우기**(유도): *"여러 파일을 한꺼번에 세거나
줄 수를 재거나 훑는 일은 이 손으로 하나씩 하면 오래 걸린다 — 그런 일은 터미널이 명령
하나로 끝낸다."* 증거 원본: `맨몸대조군-*.json` (이 폴더).

가설3(무서운 문구)은 **단독 범인은 아니다**. 다만 B 와 D 가 같은 0 이라 문구의 추가 효과는
경쟁에 가려 미측정이다 — F-116 수리는 사실 정합(선언=실물)으로서 그대로 가치가 있다.

## 7-b. F-118 — 성공한 probe 관측이 「추정」으로 분류되던 원장 (한 칸 나아갔다)

**선빨강**: A0 계약("probe 성공 = 그대로 답한다")으로 사용자에게 답한 관측이,
applied:false 하나로 확인된사실에서 떨어져 projectReceipts 의 **estimated
("호출 없이 모델 지식으로만 답한 경우")** 로 갔다 — 턴 사실 스트림(turn-surface.js:71)과
최종 답 분류 5곳이 같은 판정을 쓰므로 한 제품에 두 진실이 섰다.

**수리(유도·사실 채움)**: applied 의 뜻은 불변(2026-08-03 재개봉 방지).
실행기(terminal-run.js)가 **실제로 sandbox-exec 로 감쌌을 때만** `sandboxed` 증명을 내고,
성공 갈래는 그 증명이 있는 probe 에만 `probeChangedNothing` 을 실으며, 원장은 그 사실이
있으면 확인으로 센다. 라벨(mode)·가용성(sandboxAvailable)은 발동 조건이 아니다 —
샌드박스 없는 호스트에선 probe 라벨로도 생 zsh 가 돌기 때문(손 관리자·감시자 동시 지적).
확인 문장은 손의 원문("확인만 했어요 — 아직 아무것도 바꾸지 않았어요")이 그대로 실린다 —
커널 작문은 넣지 않았다.
