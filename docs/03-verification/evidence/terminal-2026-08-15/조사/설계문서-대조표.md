## 6. 오너가 다음에 공부하면 좋을 자리 셋

**① `task-context.js` 의 마지막 갈래 — 「접는 자가 손 목록에서 자란다」**
갈래 넷(브라우저·화면요소·목록·파일본문) + 나머지 전부가 `JSON.stringify`.
**터미널이 그 나머지로 떨어진다.** 그리고 화면 갈래는 **정확히 같은 병으로 만들어졌다** —
*"손은 카톡 대화 65개를 읽었는데 모델은 못 받았다. 화면 갈래가 없어서 JSON 접기로 떨어졌다."*
**같은 병을 화면에서 한 번 고쳤고 터미널은 안 고쳤다.** 손이 늘 때마다 갈래를 안 만들면 조용히 떨어진다 — T5 의 구조적 재발 축.

**② 이음매 ⑧ 과 F-70 — 「지었는데 켤 수 없다」의 해부**
자동화 코드 1,265줄인데 **모델이 예약을 등재하는 손이 없다.** 등록은 사용자 클릭 전용.
F-70 안의 비교 사실: *"헤르메스는 cronjob 을 기본 활성 도구로 갖고 모델이 CRUD 한다(같은 과업 17 호출로 완주). **도구 개수 차이가 아니라 도달 구조 차이다.**"*

**③ `ledger.js` 의 `applied !== false` — 「자가 참인 것을 거짓으로 셀 때」**
오늘 과업4에서 probe 가 `exitCode 0 · stdout "v24.14.0"` 을 실제로 받았고 모델이 맞게 답했는데
사다리는 `실행 FAIL — 실제로 돈 영수증 0건`. 그 규칙은 **정당한 이유로** 들어왔다(쓰기가 막힌 probe 가 exit 0 을 내던 자리).
그런데 **읽기 목적의 probe** 는 그 자로 재면 영원히 0이다.
이 저장소는 이 병을 다섯 번 밟았고(S2·J6·X5·X6·F-95) 매번 **자의 정의역**을 고쳐 나왔다.
그 다섯을 나란히 읽으면 T5 의 방법론이 한 번에 보인다.
