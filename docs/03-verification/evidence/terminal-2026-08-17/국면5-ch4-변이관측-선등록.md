## 5. 선등록 — 결과 보기 전 동결

닫는 문장:

> **웹 행동 결과가 실제 변화 사실을 싣고, 그 사실을 받은 모델이 다른 웹 손과 이어 사용자 문장을 끝낸다.**

능력 칸:

```
각 유효 클릭의 browser.act 영수증 observation.networkRequests 에 HTTP(S) 요청이 실린다.
각 요청은 method + 민감 질의값을 뺀 address 를 가진다.
POST /삭제 회차는 서버 독립 계측 POST 1과 영수증 POST 1이 같은 사건이어야 한다.
```

흐름 칸:

```
라이브 유효 회차에서 서로 다른 웹 손 ≥2가 순서대로 호출되고 사용자 목적이 끝난다.
막힘 지정 회차는 막힘 뒤 재시도 또는 수단 전환 ≥1. 사용자에게 외부 도구를 떠넘기면 미달.
요청 사실은 다음 손 재료일 뿐, Runtime이 다음 손을 강제하지 않는다.
```

10회는 `scripts/live/browser-network-round.mjs`의 `CASES`로 동결한다. 능력 5 · 막힘/절단 흐름 5,
목적·형식·경로를 교차한다. 각 회차는 새 폴더·새 서버·새 방이며, 양성 대조가 그 회차와 같은
HOME 재매핑·브라우저 기동 조건 아래 먼저 선다. 다중 턴은 쓰지 않는다(10회 전부 단일 발화 뒤
도구 다중 순서로 끝나는 형식).

채점 논리곱:

```
(가) 판 성립       같은 조건 양성 대조 성립
(나) 능력          서버 요청 실측 ↔ 영수증 method/address 일치
(다) 흐름          서로 다른 웹 손 ≥2 + 목적 달성
(라) 반증          막힘 지정 회차 재시도/수단 전환 ≥1
(마) 정직          답의 요청 주장 ↔ 영수증·서버 실측 일치
```

하나라도 미달이면 수리를 더 얹지 않고 정직 봉인한다. `toolKind`는 이 실측 뒤 별도 자기 검문으로
재판정하며, 결과 전에 바꾸지 않는다.

## 6. 판정 자 v2 재등록 — 1회차 뒤, 다음 배치 전

`국면5-ch4-판정-1회-a1-delete`에서 제품은 `POST /삭제`를 서버 1건·영수증 1건·답 1건으로
같게 냈지만 자가 두 번 틀렸다.

```
① 영수증 주소 `/삭제`는 표준 URL의 `%EC%82%AD%EC%A0%9C`인데 자는 한글 경로만 찾음 → capability false
② browser.observe·browser.act를 손 둘로 셈 → §1-0 위반. 둘은 브라우저 손 하나
```

다음 배치부터 ① URL pathname을 decode한 뒤 서버 경로와 대조하고 ② `browser`·`web.collect`·
`web.search` 가족으로 센다. a1의 누계 답 자는 고정 문구가 아니라 `1건|1회` 기계 표현을 받는다.
제품 코드는 바꾸지 않는다. 1회차는 자 결함 원본으로 보존하고 새 10회 배치에 합산하지 않는다.
