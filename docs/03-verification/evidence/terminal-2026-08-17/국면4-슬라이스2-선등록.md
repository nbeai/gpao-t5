## 0. 영역 선언 — **손이 아니라 관절이다**

승인·권한 층 ↔ 채널 표면의 **이음새**다. **신설 능력 0** — 밖에서 안 되던 것은 「능력」이 아니라
**관문 하나**다(라이브 실측: 채널 발화가 계획·손 선택·probe·카드 세우기까지 이미 전부 통과한다).

**관절의 자는 「관절이 움직였나」가 아니라 「관절 너머 손들이 밖에서 목적을 끝내나」다.**

---

## 1. ★ 델타 — **하나가 아니라 둘이다. ②를 명시 배제한다**

내 착수 제출문은 「델타는 하나(안내 → 텔레그램 안 집행)」였다. **기계 사실과 어긋났다**(공정감시자):

```
① 이번 대기 1건 집행                                    ← 채택
② allow-always 성격의 **미래 카드 억제를 durable 커밋**   ← ★ 명시 배제
   turn.js:1074-1088  「`input.approve` 는 사용자가 카드를 직접 누른 경로이고,
                       **그것만이 미래를 열 수 있다**」
   → rememberCounterpart / 상대열쇠 → knownCounterparts
   → turn.js:1907·2068·3295·3355 buildActionPlan → **다음부터 카드를 안 띄운다**
```
②는 1회성이 아니고 조용히 남는다. **다음번엔 카드 자체가 안 뜬다.** 되돌아볼 자리가 사용자면에
없다. 그리고 (가)안에서 그 판단 주체는 **모델**이 된다.

**배제 방법(turn.js 무접촉 · 내가 실측으로 확인)**: `ctxForSession`(server.js:1527)이
`new Set(session.knownCounterparts)` 를 만들고 채널 턴이 :4045 에서 되쓴다. **채널 승인 집행
갈래에서만 턴 전 스냅샷으로 되돌린다.** ②가 안 남는다.

### ★ 이 배제가 만드는 표면 비대칭 — **의도된 경계로 등재한다**

```
웹 승인    상대 기억 커밋 ○
채널 승인   상대 기억 커밋 ✕      ← 의도된 비대칭
```
**결함이 아니다.** (가)안은 pendingId 지목 주체가 모델이므로, 오지목의 **폭발 반경을 집행 1건에
묶는** 보수적 선택이다. ⚠️ **다음 세션은 이걸 「고치지」 마라** — 낡은 지도 병의 사촌이다.
**재검토 조건**: 채널 승인의 상대 기억 커밋은 **별도 슬라이스에서 화면 회수 수단과 함께**.

## 3. 설계 갈래 — (가) 채택 · (나) 기각 · (다) 안 산다

```
(가) 모델 통제 채널로 pendingId 를 **결정적으로 지목**해 집행   ← 채택
     전례: ctx.modelControls(server.js) 에 skill.propose·automation.control 등이 이미 있다
     유도다: 모델이 「이 발화가 저 카드에 대한 승인인가」를 **판단하게** 된다
     ★ 두 조각으로 가른다 — 「무엇을 승인하는가」의 해석은 **모델**,
       「그것이 승인 자격을 갖췄는가」의 판정은 **코드**(여기는 강제여야 한다)
(나) 발화 텍스트에서 승인 의도를 파싱   **기각**
     키워드 규칙 = 강제 = 정본 §1-0 위반. 「승인」·「그거 승인할게」·「네 진행해주세요」를
     다 잡으려면 규칙이 무한히 는다 — **실측 3종이 증거**(2회차 3/3 동일 결과)
(다) 짧은 코드 되받기   **안 산다**
     ②를 명시 배제하면 (다)의 마찰이 살 것이 없다(자동성이 의무다 · 승인으로 안전을 사지 마라)
```

## 4. ★ 지배 사실 — **논리곱 다섯** (하나로는 사건 하나를 닫는 것이다)

```
(가) 세상이 바뀌었다          표적 부재
(나) 사용자가 그 방에서 안다   완료 문장이 채널로 갔다 + 전달 원장 delivered
                            자리는 **server.js:4123**(채널 턴 회신) — ⚠️ :3849 가 아니다.
                            그 호출처는 :2521 **웹 경로 한 곳뿐**이다(내 착수문 오기재 정정)
(다) ★ 그 문장이 참이다       회신 내용 ↔ 실제 상태 대조.
                            「지웠어」인데 남아 있으면 빨강 · 「못 지웠어」인데 지워져도 빨강
(라) 승인한 것 = 집행된 것     카드가 보여준 명령 ↔ 원장에 실행된 명령 문자열 일치
(마) 위생                    그 **pendingId** 가 사라졌다(개수가 아니라 id)
```

### (다)·(라)가 필수인 이유 — **반례가 이미 원본에 있다**

```
(라) 카드 동일성 반례  2회차 변형1 — 1턴 카드 `rm "지울것.md"` vs 2턴 카드 `rm -f 지울것.md && ls`
                    **명령이 다른데 pending 개수는 1→1.** 「대기 1개」는 「같은 카드」가 아니다
(다) 회신 거짓 관측   3회차 양성대조 — 표적이 **실제로 지워졌는데**(true→false) 채널 회신은
                    「권한 때문에 지울 수 없습니다(Operation not permitted)」 ·
                    「존재하지만 삭제 불가한 파일로 전제하고 진행하겠다」
                    ⚠️ **웹 approve 경로에서 났다 — 이 슬라이스가 만든 것이 아니다.**
                    표본 1이라 **결함 승격 금지 · 관측 등재.** 다만 이 슬라이스가 밖을 열면
                    **같은 거짓이 텔레그램으로 나간다** → (다)를 판정선에 넣는 근거다
```

## 8. 회계 — 0번은 곱셈이되 **밟은 것만 센다**

승인 관문은 한 손의 기능이 아니라 **`SAFETY_FLOOR_KINDS` 9종의 공통 병목**(authority.js:32)이다.
관문이 열리면 「밖에서 되는 일 = 승인 안 걸리는 일」이 「밖에서 되는 일 = 전부」로 바뀐다 —
**이것이 곱셈이다**(내 착수문의 「슬라이스1+슬라이스2」 덧셈 논거는 폐기).

⚠️ **반대급부**: 같은 관문이 **위험의 공통 병목**이기도 하다. 라이브가 밟는 것은 9종 중
**2종(delete/write · send)** 이다. **「곱셈이라 아홉이 낫는다」고 적으면 안 된다.**

## 11. ★ 착수 직후 재소집 조건 발동 — **구현 전에 멈췄다** (2026-08-17 · 제품 0줄 유지)

공정감시자가 선등록 확정 시 이렇게 못박았다:
> 「②를 turn.js 손 안 대고 배제 못 한다는 사실이 나오면 그 시점에 **즉시 재소집** — 구현 중
>  범위 흡수 금지」

**같은 조건이 ② 가 아니라 ①(집행 경로)에서 먼저 걸렸다.** 기계 사실:

```
src/kernel/l2-plan/model-control.js:132·521   통제 채널은 여기서 **선언·파싱**된다
src/kernel/turn.js:1241-1261                  그런데 **라우팅은 turn.js 가 이름별로 한다**
                                              (let automationControl = null → 분리?.automationControl
                                               → ctx.automationControl → 결과에 실음)
```
⇒ (가)안의 `approval.decide` 통제를 세우려면 **`turn.js` 를 고쳐야 한다.**
그런데 `turn.js` 는 선등록 §7 의 **보존(무접촉)** 파일이다(승인 집행 몸통 :1042·:1116 · A3 레인).

### 그리고 구조 사실 하나 더 — 두 걸음이 불가피하다

`input.approve` 는 **턴 입력**이라 턴 중간의 통제로는 **소급이 안 된다.**
⇒ (가)안은 필연적으로 **두 번의 runTurn**이다: ① 발화 턴(모델이 pendingId 지목) →
