## 2. 착수 전 반드시 고정할 것 — 상한 문장이 **둘**이다 (이름으로 닫기 차단)

## 3. 신설 위험 — 전제 하나는 반증됐다

· 「유일하게 새로 만드는 것 · 회귀 방어가 약하다」는 **채널 경로에 해당하지 않는다**:
  `test/` 에 채널·전달 계열 **17파일**, `handleChannelMessage` 를 실제로 태우는 검사 **7개**.
  신설분은 「조회 손 1 + 결과가 대화로 돌아오는 왕복」뿐이고 감싸는 표면에 계약이 이미 걸려 있다.
· 박아 둘 선 셋: ① 요건 일곱을 한 슬라이스에 다 넣지 않는다 ② 종료 조건은 **사용자 문장 하나가
  다르게 끝나는 것** ③ ★ **새 상태 파일을 만들지 마라** — 요건 1·3·4 가 이미 세 파일로 갈려
  있다(`channel-bindings.json`·`telegram-offset.json`·allowlist). 네 번째를 만들면 요건 4 의
  정의역이 넷으로 늘고 그 순간 이 슬라이스가 **요건 4 를 다시 연다**(재개봉).

## 4. ★ 사용자 대면 이름 충돌 (종료 조건에 직접 걸린다)

「보관함」은 **이미 점유돼 있다** — `src/surface/web/index.html` 탭 「보관함」 = 숨긴 대화 ·
사용자 문장 `server.js` 「보관함에서 다시 꺼낼 수 있어요」. 오너 결재 문안은 「채널 **우편함**」,
정본·부채대장은 「채널 **보관함**」. 종료 조건이 「사용자 문장 하나」라면 이 충돌이 **종료 조건
자체에 걸린다**(말귀 최우선). 갈래는 착수 세션이 고르고 **근거를 등재**하라(상신 넷 아님).

## 5. C 후보(§7-ch 채널 표면 기억 통제 소비자 0)와의 관계 — **별건 유지**

이번 정의역(조회 손·요건 2·요건 6)과 접촉면이 없다 · 라이브 재현 0 이라 승격 금지.
조건부: 조회 결과를 채널 턴 결과에 실으려고 `server.js` 채널 표면 블록을 건드리게 되면 **같은
블록이라 그 순간 접촉한다** — 그때는 고치지 말고 「이 관측을 열지 않고 지나갔다」를 등재하고 지나가라.

## 6. 착수 전 더 잴 것 여섯 (검문 지정)

1. `node scripts/state-probe.mjs` 의 `channel-inbox` 항 실행값(양성대조 `telegram.send` 포함)
   — **이것이 수정 전 기저선이다. 새 계측기 금지.**
2. `test/inbound-gate.test.js` 가 `dedup_new` 를 이미 기대하는지 — 계약에서 나온 검사인지
   구현 모양에서 나온 검사인지 갈리는 자리.
3. `handleChannelMessage` 소비 검사 7개가 고정하는 계약 목록 — 「수정 안 할 파일」이 아니라
   **「깨면 안 되는 계약」**으로 적을 것.
4. slack·mail 수신 경로 유무(현재 offset 저장은 텔레그램 전용) — 요건 3·4 를 채널별로 반복할지가
   여기서 갈린다.
5. 「보관함」 사용자 대면 문장 전수 — 위 4번 충돌 확인.
6. ⚠️ **로컬 `main` 포인터가 8 뒤다** — `main..HEAD` 숫자를 근거로 쓰면 오독한다.
   고치기: `git fetch origin && git update-ref refs/heads/main origin/main`
