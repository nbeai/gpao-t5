## 0. 몇 개를 낫게 하나 — 영역 문장

**곱셈이다.** 클릭은 웹 영역 전체의 관문이다 — 리서치·리뷰·목록 펼치기·SPA 이동이 전부
「가리킨 것을 누른다」 위에 선다. 지금 T5 는 눌 수 있는 것이 탭·펼침뿐이라, 사용자가
「그거 눌러 봐」라고 하는 순간 웹 손 전체가 스크롤+본문 안에 갇힌다.
닫는 문장은 사건이 아니라 영역이다(§1-0): **「웹 화면에서 가리킨 것을 눌러 목적까지 간다」.**

## 2. 경계 재선언 — 비넷 판정(§6-0 형식: 판정+근거+진행)

현 제한은 옛 오너 지시(「탭, 더보기, 스크롤 정도로 제한」 — browser.js:588 주석, 관찰
슬라이스 시점)다. 이것을 여는 것이 새 방향 결정인가? **아니다 — 이미 결재된 방향의 집행이다**:
① 오너가 국면 4 닫힘과 함께 **「동시에 5국면 개발 시작」**을 결재했다(최종회계 §4-a)
② 그 국면의 준비 정본(보좌관판 · 오너 지시로 작성)이 브라우저 1순위 · 슬라이스 ① 일반
클릭을 지목한다 ③ 오픈북 격차표가 「일반 클릭 ✕」를 첫 행으로 못박았다.
진행한다 — 뒤집으려면 한마디면 된다.

## 3. 설계 — 유도·균일 차선 (§4-d 구현 경로)

```
수리 자리   browser.js click 판정: 「수집된 actionable 전부」로 확장 — 경계는 수집 필터가 진다
           (외부 링크 제외·submit/POST 제외 **유지**). 링크 클릭은 도착 url 이 영수증에 남는다
           (관찰 재실행이 url 을 싣는다 — 원장 정직).
           browser-tool.js canOpen: kind 에 link·button 추가(상한 12 유지 — 손실 수리는
           슬라이스 ② 몫). 경계말 갱신(거절 정의역이 바뀐다).
           §4-d ①: descriptor/결과에 「누를 수 있는 것·없는 것」이 사실로 실린다(이미 canOpen
           문장이 그 자리 — 정의역만 넓어짐).
안 하는 것  CSS 셀렉터 도입 금지(ref 전용 계약 유지 — 오픈클로 훔칠 축과 같은 방향) ·
           submit 클릭 개방 금지 · 외부 링크 클릭 개방 금지 · 좌표 클릭 금지 ·
           web.collect/web.search 무접촉 · 관찰 정직성 축(seen/unseen/thin) 무접촉(㉣)
```

## 4. 결승선 문장 (선등록 후보 — 검문 뒤 §선등록에서 동결)

「웹 화면에서 "그거 눌러 봐 / 들어가 봐"가 통한다 — 링크·버튼·탭을 T5 가 스스로 눌러
사용자가 물은 내용까지 가져오고, 상태를 바꾸는 걸음(폼 제출·바깥 사이트 이탈)은 여전히
스스로 하지 않는다.」
