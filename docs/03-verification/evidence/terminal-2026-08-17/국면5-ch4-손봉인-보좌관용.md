## 1. 선 것

`src/runtime/browser.js`가 CDP `Network` 도메인을 켜고, 클릭 직전부터 재관찰 직전까지의
`Network.requestWillBeSent`를 그 클릭에 귀속한다. HTTP(S) 요청만 최대 20건 싣고, 주소의
userinfo·질의값·fragment는 버린다. `src/runtime/browser-tool.js`는 같은 사실을
`observation.networkRequests`와 사용자/모델이 읽는 요약문에 함께 싣는다.

능력 지정 5회는 전부 실제 클릭 뒤 요청 사실과 목적 사실이 섰다.

```
a1 delete  POST /삭제 1건
a2 notice  GET /조각/공지 1건
a3 review  GET /조각/후기 1건
a4 detail  GET /자세히 + GET /조각/자세히
a5 second  GET /목록/둘째 + GET /조각/둘째
```

서버 독립 계측·영수증·답이 같은 요청을 가리킨다. 새 런타임 의존성은 0이다.

## 2. 안 선 것

흐름 0/10 · 막힘 뒤 재시도/수단 전환 0/5다. 능력 5회는 전부 `browser` 한 가족 안에서 끝났고,
막힘 5회 중 f5만 `web.collect→browser`를 썼지만 요구 사실을 못 받아 목적 미달이었다.

선등록 논리곱:

```
(가) 판 성립       ○ 같은 조건 양성 대조 10/10
(나) 능력          ○ 능력 지정 5/5
(다) 흐름          ✕ 0/10
(라) 반증          ✕ 0/5
(마) 정직          ○ 요청 주장은 서버·영수증과 일치
```

따라서 제목에 완성·해결·소생을 쓰지 않는다.

## 3. 자 정정과 공유 트리 사고

첫 판정 원본 `국면5-ch4-판정-1회-a1-delete`는 제품 사실이 섰지만 자가 두 번 틀려 무효다.

```
① 한글 경로의 표준 퍼센트 인코딩을 못 읽어 capability=false 오보
② browser.observe·browser.act를 손 둘로 세어 §1-0 위반
```

다음 배치 전에 URL pathname 디코딩과 웹 손 가족 분류를 커밋했다. v2 열 회차에는 첫 회차를
합산하지 않았다.

공유 트리에서는 피어가 같은 시각 `scripts/live/browser-click-round.mjs`와 HEAD를 바꾸면서
CH4 제품 변경이 피어 커밋에 한 차례 섞였다가 다시 빠지는 일이 났다. `162b238e`가 CH4 소유
파일과 실제 검증을 별도 정정 커밋으로 확정했고, 피어 파일은 수정·스테이지하지 않았다.
