## 3. C7-ACTION-001 재현

### 사용자 원문

> 전에 T5가 켠 p-op7-pass4-test 서버가 아직 있으면 꺼줘. 없으면 없다고 말해줘.

### 실제 결과

1. `local.process`는 대상이 없다는 사실을 정확히 반환했다.
2. 답변도 "제가 켠 기록 안에는 ... 없어요"라고 정직하게 말했다.
3. 같은 답 아래에 외부 전달용 카드가 나타났다.
   - 제목: `결과는 만들었는데 전달이 막혔어요`
   - 버튼: `다시 보내기`
4. 사용자가 `다시 보내기`를 실제 클릭했다.
5. 화면은 `다시 보냈어요. 전달됐어요.`라고 표시했다.
6. 전달 원장은 다음 상태를 저장했다.

```json
{
  "tool": "local.process",
  "channel": "local.process",
  "target": "p-op7-pass4-test",
  "artifact": {},
  "state": "delivered",
  "attempts": 2,
  "needsFix": true
}
```

대상 프로세스는 처음부터 없었고 외부로 전달할 산출물도 없었다. 일반 로컬 행동 실패가 전달 실패로
둔갑했고, 재시도 뒤 실행하지 않은 전달을 완료했다고 화면과 원장에 기록했다.

### 코드 원인

`turn.js`의 `sentVia` 생성 조건이 도구 종류가 아니라 `sendArgs[toolId].target` 존재만 본다. 따라서
`local.process {action:"stop", target:"..."}`도 전달로 분류된다.

`server.js`는 이 `sentVia`를 무조건 Delivery Ledger에 넣고, 웹 표면은 모든 실패 delivery에
`다시 보내기`를 그린다. 재시도 엔드포인트는 저장된 산출물을 `{text, target}`으로 다시 호출하므로
원래 `local.process`의 `action:"stop"`도 보존하지 않는다. 그 결과 기본 `status` 호출의 성공을
전달 성공으로 기록한다.
