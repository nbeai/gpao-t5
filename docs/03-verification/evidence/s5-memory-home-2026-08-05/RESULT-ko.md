# S5a 결과 — 기억이 집에 산다. 사용자가 지우면 T5 가 잊는다

2026-08-05 · 라이브 실모델 · 격리 증명 PASS

## 무엇이 없었나

사용자가 자기 기억에 대해 할 수 있는 것은 **"이걸 기억할까요?"에 예/아니오** 뿐이었다.
**못 하는 것**: 지금 무엇을 기억하는지 통째로 보기 · 직접 고치기 · 직접 지우기.

암호화돼 있어서가 아니다 — `memory.json` 은 평문이다(v2.5 정정에서 확인).
**볼 자리가 없었을 뿐이다.** 비교군은 기억이 그냥 파일이라 셋 다 공짜로 된다.

## 닫는 문장 (기계 사실)

집에 `~/GPAO-T5/기억.md` 가 생기고, 승격된 기억이 사람이 읽는 한 줄로 놓인다.

```
- 나는 커피 대신 홍차를 마신다 <!-- t5:m-tea -->
```

사용자가 그 줄을 지웠다(파인더로 열어 지우는 것과 같다). 다음 턴:

| | `promoted` | `closed` |
|---|---|---|
| 지우기 전 | `['나는 커피 대신 홍차를 마신다']` | `{}` |
| **지운 뒤** | `[]` | `{'m-tea': 'withdrawn_by_user_file'}` |

원장에도 남았다 — HMAC 지문과 함께:
```json
{"event":"withdrawn","candidateId":"m-tea","at":1785868943574,"digest":"6311030cffac0061"}
```

**철회 계약이 파일까지 따라갔다.** 이 칸에서 볼 것은 그것 하나였다.

## 규율 넷

1. **원장은 안 건드린다.** `memory-ledger.json` + HMAC 지문은 철회의 복원 불가능성을 지키는
   자리이고 내용과 이미 분리돼 있다. 여기서 옮긴 것은 **내용**이고 철회는 기존 경로를 그대로 탄다.
2. **파일이 없으면 아무것도 안 지운 것이다.** 빈 Map 을 돌려주면 첫 실행에 기억이 통째로 날아간다.
3. **신분은 표식이 들고 문장은 사용자의 것이다.** 사용자가 문장을 다듬어도(고쳐도) 그 기억은 산다 —
   문장으로 대조하면 다듬은 것을 지운 것으로 읽는다.
4. **사용자가 쓴 구역은 다시 만들어도 안 지운다**(CAPABILITIES.md 와 같은 규율).

## 안 한 것 (정직하게)

**전용 채널은 그대로다.** `memory.propose`·`memory.cite`·`memory.correction`·`memory.withdraw`
넷이 아직 있고, `userFacingModelText` 가 그 이름을 화면에서 걷는 일도 그대로다.
계획 S5 의 닫는 문장(*"채널 이름이 원천적으로 나올 수 없다"*)은 **아직 안 닫혔다** → S5b.

**곁가지 관측**: 라이브에서 `"내가 뭘 마시는지 알아?"` 에 T5 가 "몰라"라고 답했다.
기억은 파일에도 있고 `promoted` 에도 있었다 — **입장 판정(`admittedEntries`)이 이 발화와
관련 없다고 본 것**이다. S5a 가 만든 문제가 아니고 이 칸의 정의역도 아니다. 관측으로 적는다.

## 회귀 29건이 잡은 진짜 사고 — 남의 집 파일이 이쪽 기억을 지운다

배선하자마자 회귀 **29건**이 깨졌다. 원인은 검사 실수가 아니라 **제품 결함**이었다:

> 집은 **홈에 하나**인데 기억 저장소는 **데이터 자리마다 다르다.**
> 검사는 임시 폴더를 상태로 쓰면서 홈은 개발자의 진짜 홈이다. 그 둘은 한 설치가 아닌데,
> 내 코드는 그 집 파일을 진실로 읽고 **거기 없는 기억을 전부 철회했다.**

제품에서도 같은 사고가 난다 — 데이터 자리를 옮기거나 두 벌로 돌리면 한쪽이 다른 쪽 기억을 지운다.

**짝을 두 겹으로 맞췄다:**
① **같은 홈에 속하는가** — 상태 자리가 홈 밖이면 한 설치가 아니다. 동기화하지 않는다.
② **표식이 같은가** — 파일에 저장소 자리를 심고 다르면 진실로 읽지 않는다.

반대시험 ⑦ 이 그것을 문다: 표식이 다른 파일로는 기억을 지우지 않는다.
