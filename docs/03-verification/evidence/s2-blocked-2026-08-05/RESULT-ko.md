# S2 결과 — 차단이 모델에게 돌아간다. 그리고 그 답을 런타임이 버린다

2026-08-05 · 라이브 실모델 `gpt-5.1` · 격리 증명 PASS · 계측 `GPAO_T5_PROMPT_DUMP`(입력+출력)

## 1. 구조 계약은 섰다

모델이 낸 호출은 **어떻게 됐든** 모델 자신의 행동 이력으로 돌아간다.

- 실행됐지만 실패한 호출 → 교환에 `failureState` 와 함께(플래그 없이)
- **실행 전에 막힌 호출도** → `제안한호출` 의 신분으로 교환에
- 모델이 낸 적 없는 것(손 자체가 없음)만 서술로 — 그건 모델의 행동이 아니다

라이브 덤프가 확인한다:
```
→ 입력  도구=22 교환=0
← 출력  [single/tools] 글자=0 도구=['web.collect']
→ 입력  도구=22 교환=1          ← 차단 사유가 모델에게 갔다
← 출력  [single/tools] 글자=453 도구=[]
```

**그 22개가 무엇이었나**(귀속을 가르려면 이름이 있어야 한다 — §10 규율 9):

```
web.collect · local.file · local.discovery · local.terminal · local.system · local.process
local.locate · local.capsule · session.search · browser.observe · browser.act
connector.connect · connector.declare · agent.delegate · skill.propose · automation.propose
agent.propose · work.state · memory.propose · memory.cite · memory.correction · memory.withdraw
```

**`browser.observe` 와 `browser.act` 가 들어 있었다.** 즉 모델은 자바스크립트로 그려지는
페이지를 **실제로 열어 볼 수 있는 손을 쥐고 있었고**, 쓰지 않고 "네가 캡처해서 올려 줘"라고 했다.

→ 귀속은 **A(손이 없다)가 아니라 B(안 골랐다)** 다. 이 구분이 S8 의 전제를 바꾼다(아래).

## 2. 모델은 제대로 답했다

교환으로 차단을 받은 뒤 모델이 쓴 453자:

> 네이버 모바일 검색 결과 페이지는 내가 직접 내용을 못 읽게 막혀 있어서, 링크 안쪽 화면은
> 지금 바로는 볼 수가 없어. 대신 이렇게 해볼 수 있어:
> 1. 링크 열어서 나온 화면을 캡처해서 올릴 수 있으면(텍스트만 복붙해도 좋고) …
> 2. 특히 짬뽕애호가가 사람/가게/커뮤니티 중 뭘 가리키는지 …

정직하고, 구체적이고, 대안까지 있다. **원리 ⑤ 가 하려던 바로 그 결과다.**

## 3. 그런데 사용자가 본 것은 이것이다

```
그 사이트가 수집을 허용하지 않아요. 주소를 다시 확인해 주시겠어요?
```

**런타임이 모델의 답을 버리고 자기 문장으로 갈아치웠다.**
오너가 지적한 *"모델을 제한적으로 답하게 하고 있다"* 가 이것이고, 이제 기계 사실로 확정됐다.

## 4. 어디서 — F-15

`src/kernel/l2-plan/recovery-ladder.js:325` · `읽은척차단`

```js
if (!출처못댐(receipts, 출처계약손) && !내용서술.test(String(reply ?? ''))) return null;
```

`출처못댐` 은 **출처 계약 손이 실패했고 출처가 0개면 true** 다. 그 하나로 답이 교체된다 —
**모델이 무슨 말을 했는지 보지 않는다.** 그래서 "못 읽었어"라고 정직하게 말한 답도 버려진다.

### 왜 그렇게 만들었나 (그 판단은 그때 옳았다)

주석이 근거를 든다 — 실측 2026-08-03: `web.collect` 두 번 실패, 출처 0인데 답이
*"국세청 … 안내를 기준으로 정리하면 아래와 같습니다"* 로 기관 문서를 인용하고 날짜를 단정했다.
문구 정규식이 못 잡아 그대로 나갔고, **목록을 늘리는 대신 기계 사실로 판정**하도록 바꾼 것이다.

### 그런데 그 사고의 원인이 S2 가 방금 고친 것이다

그때 모델은 **자기 호출이 실패한 사실을 못 받았다** — 차단 호출은 교환에 안 들어갔고
(플래그 OFF), 산문으로만 있었다. 모르니까 지어냈다.
지금은 차단이 교환으로 간다. 위 §2 가 그 증거다 — **알려 주면 정직하게 말한다.**

즉 `출처못댐` 단독 차단은 **모델에게 사실을 안 주던 시절의 보상책**이고,
지금은 정직한 답을 죽이는 쪽으로만 작동한다.

## 5. 지금 안 고친 이유

**P0 절대 게이트(거짓 성공 0)를 급하게 약화시키지 않는다.**
- `내용서술` 정규식만 남기면 2026-08-03 사고 문구("정리하면 아래와")를 **못 잡는다** — 실제로 확인했다.
- 목록을 늘리는 것은 §4-6 금지다(늘리면 다음 문구에서 또 샌다).
- 그래서 **구조로 판정하는 대체 그물**이 필요하고, 그건 반대시험과 함께 세워야 한다:
  ① 모델이 차단을 받고 정직하게 답하면 그 답이 그대로 나간다
  ② 모델이 차단을 받고도 내용을 지어내면 **여전히 막힌다**(국세청 문구로 반대시험)

F-15 로 장부에 세웠다. **다음 칸이다.**

## 6. 이 결과가 바꾸는 것

S2 는 "차단을 모델에게 돌린다"는 구조 계약을 세웠고 그건 섰다.
그런데 **사용자가 보는 문장은 아직 안 바뀌었다** — 계약 관통은 닫힘이 아니다(§10 규율 6).
따라서 S2 는 **부분 완료**다. F-15 가 닫혀야 사용자 문장이 바뀐다.
