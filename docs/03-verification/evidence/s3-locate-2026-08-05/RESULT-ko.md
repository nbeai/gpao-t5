# S3 결과 — 커널이 확신을 지어내지 않는다

2026-08-05 · 원인 확정과 수정 · 검사 6건

## 라이브에서 있었던 일

```
사용자   그럼 이 파일 찾아서 내용 보여줘. YOON.md
locate   NEXT-REVIEW.md            why:"이름이 맞아요 · 0달 전"  confidence:"high"
         WHAT-IS-NOT-DONE.md       why:"이름이 맞아요 · 0달 전"  confidence:"high"
         WHAT-WE-ARE-BUILDING.md   why:"이름이 맞아요 · 0달 전"  confidence:"high"
         gpt-t3-qa-chat-…md        why:"이름이 맞아요 · 0달 전"  confidence:"high"
         gpt-t3-qa-chat-…md        why:"이름이 맞아요 · 0달 전"  confidence:"high"
```

**YOON 은 어디에도 없다.** 확장자만 같았다.

## 원인

`낱말('YOON.md')` → `["yoon","md"]` 로 쪼갠 뒤 **하나라도 포함되면 맞다**고 봤다(`.some(포함)`).
`md` 가 모든 `.md` 에 걸린다. `계약서.pdf` → `["계약서","pdf"]` 도 같아서
**모든 PDF 가 "이름이 맞아요"** 가 된다. 파일 후보의 확신은 무조건 `high` 였다.

**커널이 프로세스에게 거짓말한 것이다.** 모델은 그 위에 판단을 쌓을 수밖에 없었고,
실제로 "YOON.md 는 없고 이 중에 있냐"고 사용자에게 되물었다 — 없는 선택지를 준 것이다.

## 고친 방향 — 목록이 아니라 구조

**확장자는 낱말이 아니다.** 부른 말이 `이름.확장자` 꼴이면 그 확장자는 **이름에 딸린 것**이지
독립된 낱말이 아니다. 다만 사용자가 확장자 자체를 물으면("pdf 파일") 그건 확장자 질문이므로
그대로 둔다 — 가르는 기준은 문구가 아니라 **꼴**이다.

## 검사 6건 (양방향)

- ① 확장자만 같은 파일을 "이름이 맞아요"라고 하지 않는다 — **라이브 그 사고 재현**
- ② 확장자만 같은 후보에 확신 high 를 주지 않는다(`계약서.pdf`)
- ③ **진짜 있으면 정확히 찾는다** — 과잉 교정 금지
- ④ 이름의 일부로 불러도 찾는다("정산") — 사람은 그렇게 부른다
- ⑤ 확장자로만 물으면 확장자로 찾는다 — 통째로 무시하지 않는다
- ⑥ 못 찾으면 못 찾았다고 하고 얼마나 훑었는지를 준다 — 조용한 0 금지

③④⑤ 가 없으면 이 수정은 손을 죽이는 방향으로 넘어간다. 그래서 같이 세웠다.
