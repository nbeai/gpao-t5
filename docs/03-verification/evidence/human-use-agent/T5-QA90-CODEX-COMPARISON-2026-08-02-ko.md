# T5 90항 사람 사용·Codex 비교 보고서

- 실행일: 2026-08-02 (Asia/Seoul)
- T5 환경: 격리 HOME·격리 상태 폴더, 제품 웹 화면, 실제 OAuth `gpt-5.5`
- 비교 환경: 같은 사용자 문장을 받은 Codex 5.6 Sol
- 시험 정본: `scripts/human-use/qa90-criteria.json`
- 방식: 에이전트 3선(90항 정본화·Codex 블라인드 응답·코드/경쟁제품 조사)과 본선의 실제 브라우저 조작

## 1. 이 시험이 실제로 잰 것

90개 문항은 90개의 독립 채팅이 아니다. 실제 사용자 여정은 자연어 17턴과 승인 버튼 1회이며,
그 여정에서 말귀·형식·기억·승인·파일·웹·자동화·정직성·복구·화면을 90개 관측 기준으로 나눴다.
같은 행동에서 파생되는 문항은 중복 관계를 정본 JSON에 기록했다. 따라서 이 보고서의 숫자는
대화 횟수를 부풀린 점수가 아니라, 한 제품 여정을 여러 품질 각도에서 읽은 결과다.

Codex 비교는 같은 환경에서 답할 수 있는 질문만 동일 문장으로 진행했다. T5의 격리 Downloads,
승인 카드, 원장, 재시작 같은 제품 고유 행동을 Codex가 실행한 것처럼 가장하지 않았다.

## 2. 핵심 결론

T5는 이미 일반 채팅, 후속 정정, 파일 읽기·판단·산출물 생성, 민감정보 거절, 승인 전 효과 0에서
실제품 수준의 강점을 보인다. 반면 사용자 체감은 세 계열에서 Codex보다 뒤진다.

1. **답보다 절차가 앞서는 순간**: 형식 수정에 확인만 하거나, 복구·다음 행동 문장이 답 뒤에 붙었다.
2. **오래된 작업이 현재 요청을 침범하는 순간**: 이전 삭제 후보가 재등장하거나 축약된 파일 대상이 풀리지 않았다.
3. **도구 턴 지연**: 평문은 2~8초지만 파일은 20~45초, 브라우저 확인은 한 회차 97초였다.

이번 보강은 모델의 말투를 정규식으로 교정하지 않았다. 답 완결 계약, 사실 공급, 승인 표면,
민감정보 저장 경계처럼 OS가 책임질 구조만 고쳤다. 실제 제품에 영향을 주지 못한 실험 코드는 남기지 않았다.

## 4. 이번에 제품에 반영한 보강

### 답변 표면

- 후속 형식·길이 수정은 현재 답에서 실제 내용을 다시 쓰고, 확인·예고로 한 턴을 소비하지 않는다.
- 성공 영수증이 있는데 모델 설명만 비었으면 사용자에게 같은 요청을 다시 시키지 않는다.
- 모델 통제 채널(`memory.*`, `skill.propose` 등)의 정확한 접두사는 사용자 답에서 제거한다.
- 모델 답이 있으면 복구 안내를 기계적으로 뒤에 덧붙이지 않는다.
- 일반적인 후속 병합은 조용히 처리하고, 실제 중단·전환만 상태로 알린다.

### 승인과 화면

- 승인 카드는 별도 봇 말풍선과 같은 말을 두 번 하지 않는다.
- 기본 `smart` 모드 설명은 숨기고, 사용자가 고른 수동·엄격 모드만 표시한다.
- 승인 카드의 파일 위치는 원시 절대 경로 대신 `Downloads/파일명`처럼 사람이 아는 자리로 보인다.
- 여러 후보 행동이 한 턴에 섞일 때 현재 요청이 요구한 행동만 승인 대상으로 남긴다.

### 정직성과 민감정보

- 민감 발화는 제목과 durable transcript에 원문 대신 비저장 표식을 남긴다.
- 민감 턴은 가리기 전 원문이 스트리밍되지 않게 하고, 모델이 값을 되풀이해도 저장 전에 차단한다.
- 최종 답만 필요한 재호출은 `손을 다 썼다`고 거짓말하지 않고 `answerOnly` 사실을 공급한다.

## 7. OpenClaw·Hermes에서 가져올 원칙

OpenClaw는 [SOUL과 운영 규칙을 분리](https://docs.openclaw.ai/concepts/soul)하고,
[진행 표시를 한 자리에서 갱신](https://docs.openclaw.ai/concepts/progress-drafts)하며,
[실행 승인 모드](https://docs.openclaw.ai/tools/exec-approvals)를 별도 경계로 둔다.
Hermes도 [personality](https://hermes-agent.nousresearch.com/docs/user-guide/features/personality)와
[prompt assembly](https://hermes-agent.nousresearch.com/docs/developer-guide/prompt-assembly)를 분리하고,
[진행 표시·승인 설정](https://hermes-agent.nousresearch.com/docs/user-guide/configuration/)을 사용자가 조절하게 한다.

T5에 맞게 번역하면 다음 다섯 가지다.

1. 말투는 짧은 Voice Charter로, 실행 규칙은 권한·원장 구조로 분리한다.
2. 답할 수 있으면 내용부터 말하고 `하겠습니다`만으로 턴을 소비하지 않는다.
3. 짧은 작업은 진행 표시를 생략하고, 긴 작업도 진행 표면 하나만 갱신한다.
4. 승인은 위험한 외부효과에만 쓰고, 카드와 말풍선으로 같은 사실을 반복하지 않는다.
5. 기억은 관련된 것만 공급하며, 현재 요청과 충돌하면 현재 요청이 이긴다.

이 원칙은 경쟁제품의 문구를 복제하는 것이 아니라, T5의 목표인 **최소 안전·최대 자동화,
모델을 멍청하게 만들지 않기, 기억을 많게가 아니라 자연스럽게 만들기**를 응답 표면에 적용한 것이다.

## 8. 다음 향상 순서

1. pending approval을 모델 추론 대상이 아니라 서버 사실로 공급해 상태 질문과 실행 요청을 분리한다.
2. 파일 후보의 TurnRef·도구 영수증을 후속 대명사(`그중 예전 파일`)에 결합한다.
3. 읽기·찾기 턴의 추가 모델 판정을 계측해 답 첫 글자 지연의 실제 비용을 줄인다.
4. 웹·자동화는 실행 영수증이 없으면 완료형 문장을 만들 수 없게 한다.
5. carryableWork는 새 대화 관련성 대조를 통과한 경우에만 공급한다.

이 다섯 항목은 이번 90항 시험에서 드러난 실제 사용자 체감 순서다. 새 규칙을 많이 넣는 계획이
아니라, 현재 요청·실행 사실·사용자 표면을 서로 어긋나지 않게 만드는 후속 보강 목록이다.
