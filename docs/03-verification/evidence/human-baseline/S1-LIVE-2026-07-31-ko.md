### 3회차 미달의 원인과 판단

모델이 인용은 정확히 실었는데 statement 를 요약했다("…정리해달라고 선호한다"). 게이트는
계약(`statement === utteranceQuote`)대로 확인 통로로 강등했고, 사용자는 봉인 기준선과 같은
카드를 한 번 봤다. **거짓 반영 0·오작동 0**이며 실패 방향이 안전한 쪽이다.

이는 봉인 기준선이 H03(2/3)·H09·H10 에서 기록한 것과 같은 **모델 변동**이다. 도구 설명에
기계 규칙을 정확히 알린 뒤 6회 중 5회가 축자 인용으로 왔다(설명 보강 전에는 3회 중 1회).

남은 선택지는 감사 판정 사항으로 남긴다: 인용은 정확한데 statement 만 요약된 경우
**모델의 요약 대신 인용문 자체를 반영**하면 변동이 사라진다. 다만 이는 계획 §4.2 의
`statement === utteranceQuote` 조건을 "인용을 저장한다"로 바꾸는 계약 변경이라 구현선이
단독으로 하지 않았다.

## 3. 라이브가 잡은 결함과 수정 (전부 라이브 재측정으로 확인)

1. **`evidence`가 선택 항목이었다.** 계약이 요구하는 근거를 스키마에서 선택으로 둬서 모델이
   생략할 수 있었다 → `required: ['statement', 'evidence']`로 고정.
2. **모델이 인용은 정확한데 statement를 요약했다.** 게이트는 설계대로 확인 통로로 강등했지만
   사용자에게는 카드가 남았다. 게이트 계약(`statement === quote`)은 그대로 두고, 그 **기계
   규칙을 도구 설명에 정확히 알렸다**(금지문이 아니라 현실 공급 — 2축). 보강 전 1/3 → 보강 후 5/6.
3. **승인 턴에서 기억 사실이 화면에 안 나왔다.** 철회는 됐는데 표면이 침묵해 사용자에게는
   "안 지워졌다"와 구분되지 않았다 → 승인 경로에서도 기억 카드를 렌더한다.

이 셋은 모두 코드에서는 통과하던 것이 **실제 모델·실제 화면에서만 드러났다.**

## 4. 오너 판정으로 닫은 항목 — 무관 파일 승인 카드

이전 측정에서 H04 턴마다 `local.file` 되돌리기 승인 카드가 함께 떴다(3/3). 오너 판정(2026-07-31)
으로 S1 안에서 좁은 충돌 해소를 넣어 닫았다.

- 규칙: **모델이 `memory.withdraw` 를 실제로 부른 턴**이고 **모델이 파일 도구를 직접 고르지
  않았을 때**만, 정규식 폴백이 만든 `local.file` undo 오탐을 계획에서 걷는다.
- 능력은 그대로다: "방금 만든 파일 되돌려줘" 같은 실제 요청은 여전히 승인을 거친다(반대시험 포함).
- 실측: 6회 전부 무관 승인 카드 0. 반증(충돌 해소 제거) 시 해당 검사가 실패한다.
- 이 과정에서 기존 구멍도 드러났다 — 도구가 도는 턴의 최종 응답 경로가 기억 철회 사실을
  서버로 전달하지 않았다. 제안과 같은 자리에서 철회도 전달하도록 한 줄을 맞췄다.
