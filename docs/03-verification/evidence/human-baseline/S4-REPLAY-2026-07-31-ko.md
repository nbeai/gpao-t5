### 새 대화 재질문 0

새 대화에서 봉인 기준선과 **같은 축약 문장**을 넣었다.

> `10월 것도. 1600 / 1000 / 신규 12 / 이탈 4`

답은 `1600` 을 매출, `1000` 을 비용, `12/4` 를 신규/이탈로 **정확히 읽고** 7월과 나란히 비교했다.
되물음 0 · 카드 0 · 3.6s. 봉인 기준선의 오독과 되물음이 사라졌다.

**다만 이 개선의 출처를 정확히 적는다.** 이 답을 가능하게 한 것은 S3 의 작업 승계(lane)와
모델의 읽기이지, **S4 가 세운 원리가 아니다** — 그 원리는 아래대로 승격되지 않았다.
S4 가 이 자리에서 한 일은 "원리를 세우고, 서지 못한 원리를 막은 것"이다.

## 2. 게이트가 실제로 막았다

후보 원리:

> 사용자가 여러 달의 매출·비용·신규·이탈 데이터를 달별로 주면, 도우미는 각 월을 한눈에
> 비교할 수 있도록 표 형태로 정리하고 기본 지표(이익·이익률·순증 등)를 함께 계산해 보여줘야 한다

| 사례 | 판정 |
|---|---|
| positive | 통과 |
| positive | 실패 — 앞서 정리한 내용을 반영하지 않고 빈 칸으로 뒀다 |
| negative | **실패 — "표 대신 간단한 문장 요약" 요청에도 표로 냈다** |
| boundary | 통과 |

`missing: [positive_failed, forbidden_fact_occurred, boundary_sample]`.
사용자가 확인 버튼을 눌렀을 때 `/memory/confirm` 은 `replay_failed` 로 **거부**했고 반영은 0이었다.

negative 실패가 핵심이다. 계획이 "negative 는 그 원리를 적용하면 안 되는 상황"이라 정한 자리에서,
후보 원리가 실제로 과잉 적용했고 게이트가 그것을 잡았다. **잘못 배운 원리가 조용히 행동에
들어가는 것**이 이 슬라이스가 막으려던 바로 그 일이다.
