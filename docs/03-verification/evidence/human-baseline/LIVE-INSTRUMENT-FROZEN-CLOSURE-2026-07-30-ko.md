## 1. 종료 범위

이번 회차의 종료 범위는 아래 네 건으로 고정한다.

1. 자격·제품 상태용 `HOME`은 분기별로 격리하되, 제품이 보는 `~/Downloads`와
   `~/Developer`는 T5 기준선과 같은 실제 사용자 폴더여야 한다.
2. 실행 원문과 흐름은 봉인된 기준선에서 기계로 유도한다. 16개 원문 전체와 출처,
   9개 분기·21턴의 ID·세션·순서를 실행 전과 실행 영수증에서 모두 대조한다.
3. 이미 존재하는 회차 증거 폴더 때문에 실행을 거부할 때 그 폴더의 경로와 바이트를
   하나도 바꾸지 않는다.
4. 제품이 fixture를 수정·삭제·교체한 사실은 제품 성능 결과로 남긴다. 계측기 자체의
   안전한 정리 실패만 구조 무효다.

## 2. 실제 배선

- `user-view.mjs`와 `session_lifecycle.py`가 격리 홈 안에 `Downloads`·`Developer`
  링크를 만들며, 링크가 다른 대상을 가리키거나 끊어져 있으면 시작을 차단한다.
- OpenClaw와 Hermes 계측기는 모두 같은 사용자 시야를 사용한다. 자격 변수와 제품 상태는
  격리 홈 밖에서 상속하지 않는다.
- `h-scenarios.json`이 16개 원문과 `sealed|extension` 출처를 보관하고,
  `h-branches.json`이 9분기·21턴을 참조한다. `compare_contract.py`는 전체 원문 지도의
  SHA-256과 모든 소비 관계를 검사한다.
- 두 runner는 시작 전에 정본 감사를 직접 호출하고, `verify_run.py`는 21개 실행 행의
  원문·출처·분기·세션을 정본과 다시 대조한다.
- fixture 정리는 생성 신분(anchor·device·inode·hash)을 확인한다. 제품 변경은 스냅샷과
  결과 코드로 보존하며, 다른 inode로 교체된 사용자 파일은 건드리지 않는다.

## 3. 반대 검증

- 16개 원문 중 임의 한 건 변경 → 실행 전 계약 감사 실패.

- 제품이 fixture 내용을 변경 → 실행 결과에 `content_modified_by_product`, 회차 VALID.
- fixture 정리 자체를 실패시킴 → `unsafe_cleanup_failure`, 회차 INVALID.
