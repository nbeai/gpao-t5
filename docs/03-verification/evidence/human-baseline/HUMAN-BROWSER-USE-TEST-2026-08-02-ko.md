## 시험이 잡은 결함과 수정

1. 잘못 짐작한 경로의 실패가 같은 턴의 실제 읽기 성공 뒤에도 최종 미해결로 남았다.
   원장에는 시도 사실을 보존하되 사용자 투영에서는 실제로 해소된 범위 실패만 제외한다.
2. 없는 파일을 같은 폴더 목록·이름 찾기로 이미 확인한 뒤에도 `다른 경로로 찾아볼게요`를
   다시 약속했다. 수행한 복구는 최종 다음 행동으로 반복하지 않는다.
3. 방금 읽은 내용을 파일로 만들라는 요청에 충분한 문맥이 있는데도 본문을 다시 물었다.
   FILE 계약의 유일한 미충족이 본문일 때 모델이 `local.file write`와 원본 근거를 선택하게 하고,
   기존 계획·권한·승인 경계를 그대로 통과시킨다.
4. 첫 화면이 실제 연결 조회 전에 `beai5-stub · 준비됨`이라고 표시했다. 중립 상태에서
   `/model/connection`을 즉시 조회한 뒤 실제 연결만 표시한다.

## 경계와 증거

- 실패 영수증 원문은 삭제하지 않았다. 최종 사용자 화면의 미해결 투영만 현재 사실에 맞췄다.
- 보호 차단·쓰기 실패·다른 폴더 실패는 뒤 성공으로 숨기지 않는다.
- 파생 파일 쓰기는 여전히 원본 근거와 사용자 승인을 요구한다.
- 브라우저 콘솔 오류 0건. 비밀번호 입력이 form 밖에 있다는 Chromium 안내 1건은 제품 오류가 아니다.
