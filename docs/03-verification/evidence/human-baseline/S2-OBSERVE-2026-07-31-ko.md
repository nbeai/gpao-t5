# S2 증거 — 응답 뒤 관찰 shadow

- 날짜: 2026-07-31 (Asia/Seoul) · 실행: 구현선 Claude
- 슬라이스 성격: **사용자 체감 기능을 늘리지 않는다.** 관찰은 이미 저장된 durable 산출물의
  소비자이며 기존 tick 위에서 돈다. 범위는 observation·bundle 까지다 —
  candidate·replay·admitted·기억 영향·성장 모델 호출은 S2 범위 밖이며 구현하지 않았다.

## 1. 구조 증명 — "응답 뒤"는 코드 위치가 아니라 불변식

턴 경로에 관찰 코드가 **한 줄도 없다**(기계 확인):

| 검사 대상 | `observeSessions` 호출 | 관찰 워커 호출 |
|---|---|---|
| `runAndPersistTurn` (웹·SSE 턴 전체) | 0 | 0 |
| `runChannelInboundTurn` (채널 턴 전체) | 0 | 0 |

관찰이 불리는 자리는 `server.js:238` 하나뿐이고, 그것은 `runTrustedTick` 안이다.

## 2. 라이브 실측 (실제 서버 · 실제 `gpt-5.1`)

사용자 턴 3회(월별 정리 요청)를 실제로 보낸 뒤 측정:

| 시점 | 관찰 | 묶음 | promoted(기억 영향) |
|---|---|---|---|
| 턴 3회 직후 | **0** | **0** | 0 |
| tick 1회 뒤 | 3 | 0 | **0** |
| tick 재실행 | **3 (증가 0)** | 0 | **0** |

- 전경 턴 시간: 7.76s · 4.43s · 4.35s. 이 수치는 모델 응답 지연이 지배하므로 n=3 의
  시간 A/B 로 성장 비용을 논하지 않는다. 전경 무영향의 근거는 **§1 의 구조 증명과
  "턴 직후 관찰 0"** 이다.
- watermark: `{ 9a3422d4-…: 3 }` — 세션별 지도. 재실행에서 새 관찰 0(중복 0).
- 묶음 0 은 정상이다 — 세 발화의 주제가 서로 달라 묶을 반복이 없었다(묶음은 같은 주제 2건
  이상에서만 생긴다).
- **promoted 0** — 관찰이 기억·프롬프트에 전혀 닿지 않았다.
