# Claude Code · Codex 운용 방식 대조 — 실제 실행 기록 근거 (재작업판)

- 상태: `PASS_WITH_PREP_CORRECTION` — 실행 근거 대조는 감사 통과, 라이브 실행표의 횟수 계산은 준비 단계에서 정정한다.
- 대조 축(오너 지정): 터미널 운용 · 맥락 유지 · 계획·복구 · 에이전트 위임·회수·통합

## 0. 앞선 판의 사실 오류 — 정정

**틀린 보고**: `Codex CLI 는 없다(which codex → 없음, ~/.codex 없음). 저장소 산출물로만 대조했다.`

**실제 사실**:
- `codex-cli 0.146.0-alpha.3.1` 이 설치돼 있다
  (`~/.local/bin/codex` → `/Applications/Codex.app/Contents/Resources/codex`,
  실행 가능한 사본 `~/.codex/plugins/.plugin-appserver/codex`)
- `/Users/jyp/.codex` 가 존재한다 — `config.toml`(203줄) · `auth.json` · `automations` ·
  `browser` · `computer-use` · `plugins` · `archived_sessions` **578건(37GB)**

**내 오류의 원인**: `ls ~/.codex ~/.claude | head -12` 를 썼다. `ls` 가 인자를 알파벳순으로 정렬해
`.claude` 헤더와 항목이 12줄을 다 차지했고 `.codex` 는 잘려 나갔다. **잘린 출력을 "없음"으로 읽었다.**
`which codex` 가 못 찾은 것도 심볼릭 링크 대상이 내 샌드박스 밖이어서였고, 그것도 "없음"으로 읽었다.
두 번 다 **확인하지 않은 것을 확인했다고 썼다.**

**그래서 이번 판은 저장소 산출물이 아니라 실제 실행 기록으로 대조한다.**
표본: 최근 12개 세션 rollout(각 최대 2,500 레코드) + 최신 1세션 전수(4,000 레코드).
비밀값은 이 문서에 남기지 않는다(구조·도구 이름·정책값만 인용).

## 1. 터미널 운용

| | 근거 |
|---|---|
| **Codex** | 터미널이 압도적 주력이다. 최근 12세션 도구 집계: `exec_command` **1,998** · `apply_patch` 101 · `write_stdin` 14 · `wait` 9 · `exec` 7. 즉 **명령 + 표준입력 주입 + 대기**를 한 벌로 쓴다. 최신 1세션의 명령 첫 토큰: `sed` 144 · `git` 75 · `rg` 29 · `npm` 23 · `jq` 17 · `find` 13. 파일 편집은 `apply_patch` 라는 **전용 패치 도구**로 하고 셸 리다이렉트로 하지 않는다. |
| **Claude Code** | 이번 세션 자기 실행 근거: 작업 디렉터리 지속, `timeout`(최대 600s), `run_in_background`(턴을 넘겨 계속 도는 작업), 조건 대기(`until <check>; do sleep 2; done` — 짧은 `sleep` 연쇄는 하네스가 **차단**), 샌드박스 기본. 파일 편집은 읽기 선행을 강제하는 전용 편집 도구. |
| **T5 현재** | 터미널이 있으나 파일 손의 허용 루트가 `~/GPAO-T5` 하나(`file-scope.js:19`). 읽기 조사에도 `터미널 A2` 카드가 붙은 회차가 있었다(H10 1/3). |

**공통점**: 둘 다 **긴 명령을 기다리는 수단**(`wait` / `run_in_background`)과 **전용 패치 편집**을 갖는다.
T5 에는 둘 다 없다.

## 2. 맥락 유지

| | 근거 |
|---|---|
| **Codex** | 두 축이다. (a) 턴마다 `turn_context` 레코드를 남기는데 키가 이것이다: `cwd` · `workspace_roots` · `current_date` · `timezone` · `approval_policy` · `approvals_reviewer` · `sandbox_policy` · `permission_profile` · `file_system_sandbox_policy` · `model` · `comp_hash` · `personality` · `collaboration_mode` · `multi_agent_version` · `realtime_active` · `effort` · `summary`. **현실·권한·모드가 턴마다 명시적으로 실린다.** (b) 긴 대화는 `compacted` 레코드로 접는다(최신 세션 10건). 그리고 `world_state` 레코드(13건)가 따로 있다. |
| **Claude Code** | (a) 대화가 길어지면 요약으로 접고 이어간다(이번 세션이 그렇게 진행됐다). (b) 대화 밖 **파일 기억**: `~/.claude/projects/<프로젝트>/memory/` 에 사실 하나당 파일 하나 + `MEMORY.md` 색인. 이번 세션에서 6건을 실제로 썼고 새 세션에서 다시 실린다. |
| **T5 현재** | 같은 대화 안에서는 유지(H02·H05 재시작 성공), **새 대화에서 끊긴다**(H05 3/3 실패). |

**T5 가 볼 것**: 두 도구 다 **접기(compaction)와 대화 밖 지속**을 함께 갖는다. 그리고 Codex 의
`turn_context` 는 T5 가 이미 하려는 것(현실·권한을 턴마다 명시)의 완성형에 가깝다.
다만 **이것이 새 대화 의미 승계의 성공 증거는 아니다** — Codex 의 실제 승계 성과는 별도 측정 대상이다.

## 3. 계획·복구

| | 근거 |
|---|---|
| **Codex** | 계획이 **도구**다. `update_plan` 호출이 최근 12세션에 12회 있고, 인자가 단계 배열 + 상태다(실제 관측: `[{step:…,status:"completed"},{…,status:"in_progress"}]`). 승인 정책은 `approval_policy: "on-request"` 가 521회로 지배적이고, 세분 정책 6회(`request_permissions: true`, `sandbox_approval: false`). 샌드박스는 `workspace-write` + `writable_roots` 명시, 일부는 `network_access: false`. 협업 모드 지시문에 이런 문장이 실제로 실린다: **`In Default mode, strongly prefer making reasonable assumptions and executing the user's request rather than stopping to ask questions.`** |
| **Claude Code** | 계획 모드 진입·이탈과 작업 목록 상태(생성·진행중·완료)를 갖는다. 복구는 "다시 읽고 A/B 로 재기"가 기본 — 이번 세션에서 게이트 CPU 41초를 두 커밋 A/B 로 재서 코드 비용 0·부하 원인을 분리했다(24.85s vs 22.12s). |
| **T5 현재** | 실패 뒤 다른 길이 회차마다 갈렸다(H09 정직 1/3). 1회차는 **거짓 성공** — 원장은 `blocked` 인데 화면은 지어낸 양식을 보여줬다. |

**T5 가 볼 것**: Codex 의 `on-request` + `강한 가정 선호` 조합은 오너의 자동성 방향과 같은 자리다.
그리고 계획을 **상태 있는 도구**로 두면 긴 작업의 진행감이 자연히 나온다(T5 H10 의 공백).

## 4. 에이전트 위임·회수·통합

| | 근거 |
|---|---|
| **Codex** | `turn_context.multi_agent_version` 이 **모든 표본에서 `v1`**(527회)로 켜져 있고 `collaboration_mode` 가 별도 축으로 실린다(`Default` / `Plan` 두 모드가 지시문에 명시). 즉 **다중 에이전트 운용이 런타임 계약에 있다.** 다만 이번 표본에서 실제로 하위 에이전트를 띄운 호출은 관측되지 않았다 — `spawn`·`delegate` 계열 도구 호출 0. **계약은 있고 이 표본에서의 실사용은 확인되지 않았다.** |
| **Claude Code** | 위임이 도구 계약으로 있다: 하위 에이전트 띄우기(유형·모델·추론 강도·격리 지정, 기본 백그라운드), 완료 알림으로 회수, 이름·id 로 맥락 유지한 채 이어 부르기, 여러 개 동시 실행, `worktree` 격리, 그리고 결정적 오케스트레이션(파이프라인/병렬, 구조화 출력 스키마 강제, **중단 뒤 이어받기** 캐시). 하위 에이전트 결과는 사용자에게 직접 가지 않고 **호출자가 합친다.** |
| **T5 현재** | 위임 명시 허락에도 에이전트 언급 0 · 갈래 나눔 0 · 통합 0. |
| **OpenClaw** | `sessions_spawn(runtime:"subagent")` · `agents_wait` 도구 존재. |

**T5 가 볼 것**: ①띄우기 ②완료 대기·회수 ③호출자가 합치기 — **세 조각이 한 벌**이라는 점.
Claude Code 의 `worktree` 격리와 **중단 뒤 이어받기**는 T5 성장 큐가 두 판 실패한 지점과 같은 문제다.

## 5. 코드·설정 존재를 성과로 쓰지 않는다 — 라이브 실행표 (실행 전 확정)

앞선 판에서 **기억 파일이 로드된다 / 승인 게이트가 기본 OFF다 / 위임 도구가 있다**를 근거로
H01·H05·H10 을 라이브 대상에서 뺐다. **그 근거는 성립하지 않는다.** 파일이 실려도 새 대화에서
사용자가 원하는 의미가 이어지는지는 다른 사실이고, 게이트가 OFF 라도 실제로 조용히 반영되는지는
다른 사실이고, 도구가 있어도 모델이 그것을 실제로 나눠 쓰고 합치는지는 다른 사실이다.
**H01~H10 전부를 라이브 대상으로 되돌린다.**

## 6. 오너에게 드리는 단일 요청 — 격리·준비는 키 입력 직전까지 끝내 둔다

**준비 완료 상태로 만들어 둘 것(내가 먼저 한다)**
- Hermes: 전용 홈(`HERMES_HOME` 류)을 임시 폴더에 만들고 `.venv`(Python 3.11.15) 동작 확인까지.
- OpenClaw: 전용 워크스페이스를 임시 폴더에 만들고 실행 진입점 확인까지.
- 두 제품의 fixture(`~/Downloads/견적서_*.csv`)는 T5 측정과 동일하게 만들고 **측정 뒤 삭제.**
- 계측 스크립트·실행표를 위 §5 대로 고정.

**오너가 한 번만 해 주실 것**
- 두 제품에 **모델 자격 입력**. 모델은 T5 기준선과 같은 **`gpt-5.1` 하나**로 맞춘다
  (비교군마다 다른 모델을 쓰면 모델 변동이 비교를 오염시킨다).

**비용**
- 최초 68턴 추정은 철회한다. 정확한 실행 턴·모델 호출 수·예상 토큰은 fixture schedule과 두 제품의
  실제 모델 진입점 확인 뒤 산출한다. 금액은 오너 계정 단가에 달려 있어 단정하지 않는다.

**측정 뒤 정리**
- 임시 홈·워크스페이스 삭제, fixture 삭제, 자격 파일은 오너 지시대로 유지 또는 삭제.

**하지 않을 것**
- 코드·설정 존재를 라이브 성과로 적지 않는다.
- 자격을 내가 만들거나 T5 에서 복사하지 않는다.
- 이 문서에 비밀값을 남기지 않는다.
