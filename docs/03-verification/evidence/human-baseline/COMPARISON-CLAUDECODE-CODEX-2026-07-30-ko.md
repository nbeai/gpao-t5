# Claude Code · Codex 운용 방식 대조 — 코드·실행 근거

- 상태: `CODE_AND_EXECUTION_EVIDENCE` — 라이브 H 시나리오 성과 아님. 판정은 감사·오너 몫.
- 대조 축(오너 지정): 터미널 운용 · 맥락 유지 · 계획·복구 · 에이전트 위임·회수·통합
- 근거 성격
  - **Claude Code**: 이번 세션의 **자기 실행 근거**(실제로 부른 도구·만든 파일·측정값)와 도구 계약
  - **Codex**: 이 저장소에 남긴 **실제 산출물**(커밋 54건의 `Dual-Role` 표기, 검증 스크립트 코드)
  - 로컬에 Codex CLI 는 없다(`which codex` → 없음, `~/.codex` 없음). ChatGPT.app 에 Codex
    Framework 번들만 있다. 그래서 Codex 쪽은 **저장소 산출물**로만 대조했다. 내부 구현은 미확인.

## 1. 터미널 운용

| | 근거 |
|---|---|
| **Claude Code** | 명령 실행이 1급 도구다. 이번 세션에서 실제로 쓴 것: 작업 디렉터리 지속, `timeout`(최대 600s), `run_in_background`(세션을 넘겨 계속 도는 작업), 조건 대기(`until <check>; do sleep 2; done` — 짧은 `sleep` 연쇄는 하네스가 **차단**한다), 샌드박스 기본. `~/.claude/shell-snapshots` 3건 — 셸 상태를 스냅샷으로 남긴다. |
| **Codex** | 저장소 산출물로 보면 터미널을 **검증 도구를 만들어 돌리는 방식**으로 쓴다: `scripts/calibrate-gate.mjs`(같은 시험 집합 반복 실행), `scripts/audit-project-entry.mjs`(작업장 정본 감사), `scripts/gate.mjs`(공식 게이트). 즉 일회성 명령이 아니라 **재현 가능한 스크립트로 고정**한다. |
| **T5 현재** | 터미널이 있으나 파일 손의 허용 루트가 `~/GPAO-T5` 하나다(`file-scope.js:19`). 읽기 조사에도 `터미널 A2` 승인 카드가 붙는 회차가 있었다(H10 1/3). |

**T5 가 가져갈 것**: 검증을 **스크립트로 고정**하는 Codex 방식. 한 번 재고 끝내지 않고
`--runs`·median·p95 로 남긴다.

## 2. 맥락 유지

| | 근거 |
|---|---|
| **Claude Code** | 두 층이다. (a) 대화가 길어지면 **요약으로 접고 이어서 작업**한다 — 이번 세션이 실제로 그렇게 진행됐다. (b) 대화 밖 **파일 기억**: `~/.claude/projects/<프로젝트>/memory/` 에 사실 하나당 파일 하나, `MEMORY.md` 가 색인이다. 이번 세션에서 실제로 6건을 썼고(개발철학·슬라이스 기준·자동성 의무·역할 경계 등) **새 세션에서 그 파일이 다시 실린다.** |
| **Codex** | 맥락을 **저장소 문서로 고정**한다: 인수인계 §0(현재 진실 패킷), 권위 지도, 재착수 브리핑. 새 세션이 그 문서를 읽고 시작하도록 `AGENTS.md` 필독 순서로 강제한다. 즉 에이전트 내부 상태가 아니라 **리포지토리가 기억**이다. |
| **T5 현재** | 같은 대화 안에서는 유지되고(H02·H05 재시작 성공), **새 대화에서 끊긴다**(H05 3/3 실패). 승계 수단은 사용자가 직접 누르는 `지난 대화 찾기` 뿐이다. |

**T5 가 가져갈 것**: 두 비교군과 Claude Code 가 공통으로 쓰는 구조 — **맥락을 대화 밖 파일에 둔다.**
Claude Code 의 형태가 특히 참고된다: *사실 하나당 파일 하나 + 색인 한 장 + 새 세션 자동 적재.*
이건 T5 의 H05 공백을 그대로 겨눈다.

## 3. 계획·복구

| | 근거 |
|---|---|
| **Claude Code** | 계획을 **상태로** 갖는다: 계획 모드 진입·이탈, 작업 목록(생성·진행중·완료 갱신). 복구는 "다시 읽고 A/B 로 재기"가 기본이다 — 이번 세션에서 게이트 CPU 41초를 두 커밋 A/B 로 재서 **코드 비용 0 · 부하 원인**을 분리했다(24.85s vs 22.12s). |
| **Codex** | 복구를 **판정 언어로** 고정한다. 커밋 54건에 `Dual-Role: Codex (impl+audit — needs independent audit)` 표기가 있다 — 자기가 구현한 것은 **독립 감사가 필요하다고 스스로 표시**한다. 감사 보고서는 `문제·재현·영향·위반 계약·등급·종료 조건` 만 담고 **구현 해법을 지정하지 않는다.** 게이트는 `기준선을 자동 갱신하지 않는다`(`gate.mjs:791`)로 회귀 압력을 코드로 막는다. |
| **T5 현재** | 실패 뒤 다른 길이 회차마다 갈렸다(H09 정직 1/3). 1회차는 **거짓 성공**이 났다 — 원장은 `blocked` 인데 화면은 지어낸 양식을 보여줬다. |

**T5 가 가져갈 것**: Codex 의 두 장치가 정확히 H09 를 겨눈다 —
(a) **자기 구현에 "독립 확인 필요" 표시를 붙이는 관행**, (b) **기준선 자동 완화 금지**.
T5 의 거짓 성공은 원장과 화면이 어긋난 것이므로, `원장이 실패면 답도 실패여야 한다`를
게이트로 고정하는 방향이 같은 계열이다.

## 4. 에이전트 위임·회수·통합 — **T5 의 H10 공백을 정면으로 채운다**

| | 근거 |
|---|---|
| **Claude Code** | 위임이 도구 계약으로 있다. 하위 에이전트를 띄우고(유형·모델·추론 강도·격리 지정 가능, 기본은 백그라운드), 끝나면 **알림으로 회수**하고, 같은 에이전트를 이름·id 로 **맥락 유지한 채 이어서** 부른다. 여러 개를 한 번에 띄워 **동시 실행**한다. 격리는 `worktree` 옵션으로 **git 워크트리를 새로 떼어** 병렬 편집 충돌을 막는다. 그리고 결정적 오케스트레이션 계층이 따로 있다 — 파이프라인/병렬, 단계별 구조화 출력 스키마 강제, **중단 뒤 이어받기**(같은 스크립트·같은 인자면 앞선 결과를 캐시로 재사용). 하위 에이전트의 최종 텍스트는 사용자에게 직접 안 가고 **호출자가 받아 합친다**. |
| **Codex** | 이 저장소에서는 위임 흔적이 없다. 감사·통합을 **자기 한 갈래로** 수행하고 산출물을 문서·스크립트로 남긴다. 내부 위임 능력은 **미확인**(로컬 소스 없음). |
| **T5 현재** | 위임을 명시 허락해도 에이전트 언급 0 · 갈래 나눔 0 · 통합 0. 계획만 세우고 다음 턴으로 미루며 되물었다. |
| **OpenClaw**(1차 대조) | `sessions_spawn(runtime:"subagent")` · `agents_wait` 로 띄우고 기다려 회수한다. |

**T5 가 가져갈 것**: Claude Code · OpenClaw 가 공통으로 가진 **세 조각이 한 벌**이라는 사실 —
①띄우기 ②완료 대기·회수 ③호출자가 결과를 합치기. T5 에는 세 조각 모두 없다.
Claude Code 쪽에서 특히 참고할 것은 **격리(워크트리)** 와 **중단 뒤 이어받기**다 —
긴 작업이 끊겨도 앞선 결과를 버리지 않는다(T5 의 성장 큐가 두 판 실패한 지점과 같은 문제).

## 5. 라이브 실행이 반드시 필요한 H 시나리오 — 최소화

지금까지 코드 사실로 **차이가 이미 확정된** 항목은 라이브 측정이 필요 없다.

| ID | 라이브 필요? | 이유 |
|---|---|---|
| H01 기억 카드 | **불필요** | Hermes `gate off (default) → allow` 로 기본 자동임이 코드로 확정. T5 는 3/3 카드. 차이가 명확하다. |
| H02 자가학습 | **필요** | Hermes 의 fork 자기평가·큐레이터가 **실제로 무엇을 배우는지**는 코드로 알 수 없다. 반복 3회 뒤 무엇이 남는지 봐야 한다. |
| H03 현재 지시 우선 | **불필요** | T5 변동(2/3)은 모델 습관 문제다. 비교군을 재도 같은 모델 변동이 섞인다. |
| H04 정정·되돌림 | **필요(축소)** | Hermes journey `edit/delete` 가 **대화로 닿는지**가 핵심이다. T5 는 대화로 닿지 못한다. |
| H05 새 대화 승계 | **불필요** | 둘 다 대화 밖 파일로 해결함이 코드로 확정(`system_prompt.py:488`, `MEMORY.md`). |
| H06 무관 불개입 | **불필요** | T5 3/3 통과. 비교 불필요. |
| H07 민감정보 | **불필요** | T5 3/3 통과(장기 기억 범위). |
| H08 파일 손 범위 | **필요** | 두 비교군의 실제 허용 경계를 코드로 특정하지 못했다. |
| H09 실패 뒤 다른 길 | **필요** | 거짓 성공은 코드로 안 보인다. 같은 접근 불가 파일로 실제 응답을 봐야 한다. |
| H10 위임 | **불필요** | OpenClaw 도구 존재가 코드로 확정. T5 는 0. |

**라이브가 필요한 것은 4개(H02 · H04 · H08 · H09)** 이고, 그중 H02·H09 가 핵심이다.

## 6. 오너에게 드리는 단일 요청 (자격 필요 시점)

아래를 **한 번에** 정리했다. 허락하시면 진행하고, 아니면 코드 사실 대조 상태로 남긴다.

**필요한 것**
- Hermes: 모델 자격 1개. `~/.hermes` 설정 필요(현재 없음). `.venv` 는 이미 동작(Python 3.11.15).
- OpenClaw: 모델 자격 1개. 설정 위치 미확인.

**어느 모델**
- T5 기준선과 같은 조건으로 맞추려면 **`gpt-5.1` 하나**면 된다(T5 3회 전부 이 모델).
  비교군마다 다른 모델을 쓰면 모델 변동이 비교를 오염시킨다.

**어떤 시나리오만**
- H02(반복 3회 + 새 대화 1회) · H04(정정 1회) · H08(파일 찾기 1회) · H09(접근 불가 1회)
- 제품당 6턴 × 2제품 = **약 12턴.** 3회 반복이 필요한 것은 H02 뿐이다.

**비용 추정**
- 턴당 수천 토큰 규모의 일반 대화·도구 호출이다. T5 3회 측정(약 40턴) 대비 작다.
  정확한 금액은 오너 계정 단가에 달려 있어 제가 단정하지 않는다.

**격리 방법**
- 두 제품 모두 **전용 홈/워크스페이스**를 임시 폴더에 만들고 그 안에서만 돌린다
  (Hermes 는 `HERMES_HOME` 류 환경변수, OpenClaw 는 워크스페이스 디렉터리 지정).
- H08 fixture 는 T5 측정과 같은 `~/Downloads/견적서_*.csv` 를 쓰고 **측정 뒤 삭제**한다
  (앞선 3회에서 실제로 그렇게 했다).
- 자격은 **오너가 직접 입력**한다. 제가 T5 의 저장된 자격을 복사하지 않는다.
- 측정 뒤 임시 홈·워크스페이스를 삭제하고, 자격 파일도 오너가 원하면 함께 지운다.

**하지 않을 것**
- 코드 사실을 라이브 성과로 대신 적지 않는다.
- 자격을 제가 만들거나 옮기지 않는다.
- 이 문서 어디에도 비밀값을 남기지 않는다.
