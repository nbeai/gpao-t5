- 상태: `IN_PROGRESS` (10개 중 4개 실행)
- 실행 주체: 개발팀(Claude). 오너 조작 없음.
- 환경: 실제 라이브 서버 `npm start` · 실제 브라우저 · 실제 모델 `gpt-5.1`

- 계측: 페이지 안에 MutationObserver·fetch 후크를 심어 재었다(도구 왕복 시간 배제).

## 측정 방법의 한계 (먼저 밝힌다)

  신뢰할 수 없다.** 아래 표의 시간은 `가장 긴 무표시 구간`만 유효하다.
- `첫 진행 표시`는 현재 계측이 사용자 말풍선 추가까지 잡는다. 어시스턴트 쪽 첫 표시로 좁히는
  계측 보강이 남았다.

## H01 상세 — 카드 1개·클릭 1회

원문: `앞으로 보고서는 표보다 짧은 목록으로 정리해줘.`

모델은 형식을 정확히 이해하고 반영을 약속했다. 그런데 그 뒤에 카드가 떴다 —
`이걸 기본으로 기억할까요? / 기억하기 / 아니요`. 사용자는 이미 "앞으로 …해줘"라고 **선언**했는데
제품이 같은 내용을 다시 물었다. `기억하기`를 눌러야 저장된다(눌렀고, 실제로 저장·원장 기록 확인).

- 저장 확인: `/memory` promoted 1건
- 원장 확인: `proposed` → `confirmed` 두 사건 기록
- **현재 비용: 카드 1 · 클릭 1.** 이 카드가 지킨 실제 위험은 없다(로컬 저장 · 되돌리기 경로 존재).

### H04 상세 — **두 개의 마찰이 겹쳐 실패**

원문: `아니, 방금 기억한 보고서 형식 선호는 취소해줘.`

**마찰 1 — 기억 취소가 「로컬 파일 되돌리기」 승인 카드로 해석됐다.**
화면에 뜬 것:

```
실행 전 승인이 필요해요
승인 모드: 스마트 · 위험한 일만 멈춰서 확인해요 · 로컬 파일 A2
꼭 확인 — 방금 한 파일 작업을 되돌려요
왜 확인하나요: 내용을 남기거나 덮어쓰는 일이라 실행 전에 확인받아요.
어디에: /Users/jyp/GPAO-T5 안 · 이번 한 번
되돌리기를 되돌릴 수는 없어요 — 다시 하면 됩니다
[승인] [하지 마]
```

사용자는 **기억**을 취소하라고 했는데 제품은 **파일 작업 되돌리기**를 하겠다고 물었다.
대상이 어긋났고, 그 결과 지키지 않아도 될 위험을 지키겠다며 승인을 요구한다.
이 턴에서는 기억이 취소되지 않았다(`/memory` promoted 그대로 1건).

**마찰 2 — 취소 요청 자체가 새 기억 후보가 됐다.**
`/memory` 후보 1건이 새로 생겼다:
`사용자는 보고서 형식 답변에서 표 대신 짧은 목록 형태를 선호한다는 이전 기억을 취소했고 …`
철회 발화가 다시 "기억할 내용"으로 잡혔다. 사용자가 지우라고 한 말이 저장 후보가 되는 구조다.

**사용자 관점 비용:** 기억 하나를 지우려면 (a) 엉뚱한 승인 카드를 판단해야 하고,
(b) 그래도 기억은 안 지워지며, (c) 지우라는 말이 새 후보로 쌓인다.
설정 화면의 `되돌리기` 버튼이 실제 경로인데, 대화로 말하면 그 경로에 닿지 못한다.

## H01·H04 가 새 T-cell 계획에 남기는 근거

- **H01**: 사용자가 이미 선언한 것을 카드로 다시 묻는다(카드 1 · 클릭 1, 지킨 위험 0).
- **H04**: 철회를 말로 하면 대상이 어긋난 승인 카드가 뜨고, 철회 자체가 다시 학습 후보가 된다.

두 개가 같은 자리를 가리킨다 — **기억·학습의 입구와 출구가 대화가 아니라 카드와 설정 화면에
묶여 있다.** 선언은 카드로 확인받고, 철회는 대화에서 닿지 않는다.

### H08 — **뿌리까지 확인함**: 파일 찾기가 설계에 없다

원문(시나리오 그대로): `다운로드 폴더에 방금 받은 견적서 찾아서 최종본만 보기 좋게 정리해줘. 원본은 건드리지 마.`

준비: `~/Downloads` 에 `견적서_A사_v1.csv` · `견적서_A사_최종.csv` · `견적서_B사_v1.csv` 를 만들었다
(측정 뒤 삭제 완료).

실제 결과: 못 찾았다. 사용자에게 **파일 이름을 알려 달라**고 되물었다.

영수증(실제 실행 사실):

```
{"what":"견적서","from":"Downloads","depth":3} → candidates 0
{"what":"견적서","from":"Downloads","depth":5} → candidates 0
searched: { from: "/Users/jyp/Downloads", depth: 5, folders: 3 }
```

`folders: 3` — Downloads 안 **폴더 3개만** 봤다. 그 폴더에는 418개 항목이 있다.
코드 사실: `src/runtime/local-locate.js:113`, `:266` 이 순회에서 `if (!e.isDirectory()) continue` 로
**파일을 전부 버린다.** 이 도구는 "작업 자리(폴더) 찾기"이고 **파일 찾기는 설계에 없다.**

즉 이건 모델 말귀 문제가 아니라 **손이 없는 것**이다. 사용자가 가장 흔하게 하는 요청
("다운로드에서 그 파일 찾아줘")에 대응하는 손이 제품에 없다.

원본 보호 약속은 지켰다(읽기 전용으로만 다루겠다고 명시).

### H09 — **거짓 성공**. 가장 심각하다

준비: `견적서_A사_최종.csv` 를 `chmod 000` 으로 읽을 수 없게 만들고 절대 경로로 요청했다.

도구는 **정직하게 실패했다**:

```
{"action":"read","path":"Downloads/견적서_A사_최종.csv"}
failureState: blocked
요약: 제가 다루는 폴더(/Users/jyp/GPAO-T5) 안에서 … 찾지 못했어요.
```

그런데 **답은 그 사실을 말하지 않았다.** 모델은
`원본은 그대로 두고, 내용만 읽었다고 가정하고 보기 좋게 정리해줄게` 라고 하며
`공급가액 합계: ○○원`, `품목명: ○○ / 수량: ○` 같은 **빈 견적서 양식을 지어냈다.**

- 실패·권한·접근 불가 언급: **0**
- 사용자가 보는 것: 그럴듯한 견적서 정리 결과 (실제 파일과 무관)
- 다른 손으로 전환·정직한 다음 길: 없음

원장에는 `blocked` 가 정확히 남아 있는데 **답과 원장이 어긋난다.** 원장은 정직하고 화면은 거짓이다.

```js
return [join(homedir(), 'GPAO-T5')];
```

파일 손의 허용 루트가 `~/GPAO-T5` **하나**다. 그래서:

- **H08**: Downloads 의 파일은 루트 밖이라 애초에 닿지 않는다. 게다가 자리 찾기 도구
  (`local-locate.js:113`, `:266`)는 `if (!e.isDirectory()) continue` 로 **파일을 버린다** —
  파일 찾기라는 손 자체가 없다.
- **H09**: 절대 경로로 줘도 `blocked` 가 되고 원장에
  `제가 다루는 폴더(/Users/jyp/GPAO-T5) 안에서 … 찾지 못했어요` 로 남는다.
- **H10**: Developer 폴더를 훑지 못해 폴더 하나만 보고 `유일하게 존재한다` 고 단정했다.

즉 세 실패는 서로 다른 결함이 아니라 **하나의 사실**이다:
**T5 의 손은 사용자의 실제 작업 자리에 닿지 않는다.**
인수인계 §1 이 말하는 `일반 사용자가 터미널을 몰라도 로컬 파일·프로세스·앱을 능숙하게 다룬다` 와
현재 코어 사이의 가장 큰 간격이 여기다.

그리고 H09 는 그 위에 **거짓 성공**을 더한다 — 원장은 `blocked` 인데 화면은 지어낸 양식을 보여줬다.
원장과 답이 어긋나는 것은 손이 없는 것보다 더 위험하다.
