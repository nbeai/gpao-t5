## 2. 흡수할 구조 (T5 방식으로 번역)

1. **가역 로컬 기억의 무마찰 반영 + 사후 철회** (G1·G2): 저장·철회를 승인 카드 없이 한 턴에,
   원장·되돌림으로 보호. 이는 이미 오너 철학("자동성이 의무다")이며 비교군이 실증했다.
   T5 번역: memory.propose의 카드 확인을 가역 기억에 한해 사후 확인형으로 — 반영은 즉시,
   표면에 "기억했어요·되돌리기" 노출.
2. **응답 뒤 백그라운드 관찰·기억** (G3, 코드 사실: Hermes 응답 후 자기평가·유휴 큐레이터,
   OpenClaw 일일 메모리): 전경 지연 0으로 관찰을 쌓고, 다음 대화의 입장은 admission 경계로.
   OpenClaw의 H07 실패가 이 경계의 필요를 실증한다(아래 3-1).
3. **대화 경계를 넘는 작업 승계** (G3): 세 제품 모두 실패한 지점 — sessions.json(세션키→ID)
   류의 **디스크 진실 + 작업 단위 요약**을 다음 대화 입장 후보로. T5의 ConversationLane
   계약과 결합하면 비교군에 없는 차별점.
4. **실패 사실의 정확한 공급** (G5): 권한·존재·범위 실패를 receipt로 정확히 모델에 주면
   정직한 폴백이 나온다는 OpenClaw 실측 — T5 운영 순환 ⑥·⑦칸 강화 근거.
5. **장기 작업 완주력** (G6): 240s를 넘는 정당한 작업의 진행 표시·계속 실행. 위임(멀티
   에이전트)은 그 다음 — 두 비교군 모두 위임 없이도 완주했다.

## 3. 흡수하지 않을 요소

1. **무경계 자동 기억** — OpenClaw는 "이 키 기억해둬"에 **비밀 원문을 durable 기억 파일에
   저장했다**(H07 실패, `memory/2026-07-30.md` grep 확인). T5·Hermes는 거부. T5의
   민감정보 저장 경계(dab56f6)와 retrieved≠admitted 원칙이 정당함을 실측으로 입증 —
   자동 기억을 흡수하되 admission·민감 경계 없이 흡수하지 않는다.
2. **기억을 이유로 한 전경 지연** — OpenClaw H02-new 52.9s·H07 41.6s는 기억 파일 조작이
   전경 턴을 늘린 사례. T5는 백그라운드로 옮긴다(계획 필수 결과 2항).
3. **표면·브랜딩·채널 폭** — 기존 흡수 보충 문서의 비흡수 목록 유지.
4. **순위 주장** — 이 비교에서 어떤 성능 순위도 만들지 않는다(모델 상이·1회 관찰).
