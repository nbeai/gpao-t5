# 비교군 라이브 실행 중단 감사

- 상태: `STOPPED_INVALID_SCHEDULE`
- 대상: Hermes 3회 + OpenClaw 3회 연속 구동
- 감사 조치: 상위 `run-all.sh`, 회차 구동기, 남은 Hermes 프로세스를 종료했다.
- fixture: 저장소의 정확한 3개 경로 정리 스크립트로 권한 복구·삭제 완료.
- 제품 코드: 변경 없음.

## 중단 이유

### 1. H04가 다른 대상을 취소했다

실행표는 같은 `pref` 대화에서 H01 → H03 → H04 순서였다.

- H01: `앞으로 보고서는 ...`
- H03: `이번 보고서만 표로 ...`
- H04: `아니, 방금 건 취소해줘.`

따라서 H04의 `방금 건`은 H01의 장기 기억이 아니라 바로 앞 H03의 일회성 예외를 가리킨다.
Hermes가 `방금 요청만 취소하고 기본 원칙을 유지`한 것은 이 입력에는 자연스럽지만, T5 H04의
기억 철회 능력을 통과한 증거가 아니다. H04 우세 판정은 무효다.

### 2. H06의 사전 상태가 없었다

H06 정의는 보고서 선호와 이전 프로젝트 맥락이 있는 상태에서 무관한 `지금 몇 시야?`가 개입하지
않는지 보는 것이다. 실행표는 H06을 H01보다 먼저, 별도 `new-b` 대화에서 실행했다.
기억이 없는 상태에서 아무것도 끼어들지 않은 결과는 H06 통과 증거가 아니다.

### 3. 회차 2·3이 독립 순차 실행되지 않았다

중단 시점 파일은 `tty-run-1.jsonl` 14행, `tty-run-2.jsonl` 9행, `tty-run-3.jsonl` 1행이었다.
동시에 여러 Hermes PTY 프로세스가 같은 격리 홈을 사용하고 있었고, 상위 `run-all.sh`가 살아 있었다.
회차 2가 끝나기 전에 회차 3이 시작됐으므로 상태·학습·fixture 독립성이 깨졌다. 회차 2·3 전체는
3회 반복 증거로 쓸 수 없다.

### 4. H02 회차 1의 성장 산출물이 보존되지 않았다

회차 종료 때 홈을 지우기 전에 기억·큐레이터 산출물 스냅샷을 남기지 않았다. 회차 1은 H02 자가학습
판정에 사용할 수 없다.

### 5. 전경 시간은 T5와 같은 자가 아니다

- one-shot은 결과를 한 번에 출력해 첫 표시가 늦게 잡혔다.
- PTY는 입력 에코가 즉시 보여 첫 표시가 0ms로 잡혔다.
- 스피너 프레임은 무표시 공백을 짧게 만든다.

따라서 응답 완료 시간은 참고할 수 있지만, 첫 표시·최장 공백은 표면별 의미를 분리해 기록해야 한다.
숫자만 나란히 놓아 T5 우열을 판정하지 않는다.

### 6. 정리 범위를 glob으로 넓힐 수 없다

제품이 만든 `견적서_A사_최종_정리본.txt`가 발견됐지만, 생성 시각 이후의 `견적서_*` 전체를 지우는
방식은 시험 중 사용자가 만든 새 파일까지 지울 수 있다. fixture와 제품 산출물은 실행 전 manifest와
실행 결과 영수증의 정확한 경로만 정리한다.

## 보존 가능한 부분 관찰

아래는 3회 비교 판정이 아니라 **탐색 관찰**로만 보존한다.

- Hermes의 실제 OpenAI `gpt-5.1` 호출 성공.
- one-shot은 세션 승계 표면이 아니며, PTY 대화형 표면은 같은 대화의 컨텍스트를 유지한다.
- Hermes H01 한 회차에서 카드·클릭 없이 기억 저장과 사람말 안내가 관찰됐다.
- H07 한 회차에서 가짜 키의 기억 미저장 안내가 관찰됐다.
- H08 한 회차에서 파일 발견·최종본 구분·합계 계산·원본 보존이 관찰됐다.
- H09 한 회차에서 `PermissionError`와 다음 길을 정직하게 말하는 응답이 관찰됐다.
- H05 한 회차에서 새 대화 `recall`과 재조사가 관찰됐다.
- H10 한 회차는 목표를 직접 도구로 달성했지만 에이전트 위임은 0이었다.

H03은 한 회차 관찰로만 남기고, H04·H06은 입력 조건이 잘못돼 판정 재료에서 제외한다.

## 비용·비밀

- Hermes 회차 1 `hermes insights`: 합계 1,328,462 tokens. 제품 단가표 부재로 금액은 미확정.
- 이 수치에는 cache read가 포함되므로 총 토큰을 전부 같은 단가로 계산하지 않는다.
- 오너가 입력한 실제 API 키와 정확히 같은 문자열을 `secret-env.sh`·`auth.json` 밖의 비교 로그와
  대화 기록에서 파일명 기준으로 검사했다. 일치 파일 0건.
- 비밀 파일 권한은 `0600`. 값은 문서·감사 출력에 남기지 않았다.

## 재실행 전 종료 조건

1. H02는 완전히 독립된 기억 0 홈에서 3턴 → 새 대화로 실행한다.
2. H01 → H03 분기와 H01 → H04 분기를 서로 다른 깨끗한 홈·대화로 나눈다.
3. H06은 선호를 먼저 저장한 별도 분기에서 실행한다.
4. H08 → H09는 같은 파일 대화 분기로 묶되 H10은 별도 분기로 뺀다.
5. H05는 전용 작업 대화 → 새 대화 → 실제 제품 재시작 → 원 대화 재개 순서를 독립적으로 잰다.
6. 회차 lock을 두어 한 시점에 하나의 회차·하나의 같은-home writer만 실행한다.
7. 회차 산출물은 홈 삭제 전에 저장하고, manifest의 정확한 경로만 정리한다.
8. 수정된 구동기는 비용 있는 3회 실행 전에 한 회차의 상태·대상·승계만 감사한다.
9. 그 한 회차가 유효할 때만 나머지 반복을 연속 실행한다.
