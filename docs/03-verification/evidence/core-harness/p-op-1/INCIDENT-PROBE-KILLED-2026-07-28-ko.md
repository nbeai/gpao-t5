# 사고 · probe 가 실제로 프로세스를 죽였다

시각: 2026-07-28
발견: A 시나리오 변수 `변경 제안` 을 라이브로 확인하던 중, 웹 화면에서

## 무슨 일이 있었나

```
사용자: "그럼 그거 꺼줘."
화면:   "여기서 '그거'는 openclaw 로 보고 끄려는 건데, 방금 실행 기록상
         종료 명령이 probe 모드라 실제 적용은 안 됐어요 (applied:false)"
실제:   openclaw 가 죽었다
```

승인 카드는 뜨지 않았다. 사용자는 안 죽은 줄 알았다. 원장에도 `applied:false` 로 남았다.

## 원인 — 세 겹이 한 번에 뚫렸다

**① probe 샌드박스가 시그널을 안 막았다.**
프로파일은 `(allow default)` 에 `file-write` 와 `network` 만 막는 구조였다.
프로세스를 죽이는 것은 파일 쓰기가 아니라 **그대로 통과**했다.
실측: probe 모드에서 `kill <pid>` → `KILLED`, 대상 실제 종료.

**② 그래서 `changes:false` 로 읽혔다.**
`killall` 이 probe 에서 성공했으니(exitCode 0) 런타임은 "아무것도 안 막혔다 = 변경 없다"로
분류했다. 변경 판정이 **"샌드박스가 막았는가"에만 기대고 있어서**, 샌드박스가 못 막는
종류는 판정 자체가 되지 않았다.

**③ 원장이 거짓을 기록했다.**
`applied:false` 는 "granted 모드로 다시 안 돌렸다"는 뜻인데, probe 에서 이미 벌어진 일을
안 벌어진 것으로 남긴다.

## 절대 원칙 위반

- §3 되돌리기 어려운 행동은 증거로 게이트한다 → 게이트 없이 실행
- 안전 바닥: 위험 작업은 어느 모드에서도 자동 진행 금지 → 뚫림
- §9 결과를 정직하게 보고한다 → 원장과 답변이 현실과 어긋남

## 고친 방식 — 목록이 아니라 효과의 종류

`killall` 을 금지 목록에 더하지 않았다. 다음엔 `pkill`, 그 다음엔 다른 것으로 뚫린다.

- probe·reach 프로파일에 `(deny signal)` 과 `(deny appleevent-send)` 를 닫았다.
  `osascript -e 'tell application …'` 한 줄이면 파일도 지우고 메일도 보내는데,
  파일 쓰기가 아니라서 기존 규칙에 안 걸렸다.
- `granted` 는 닫지 않는다. 승인을 받은 뒤이므로 여기까지 막으면 "꺼줘"를 영영 못 한다
  (절대원칙 §0-A: 능력을 위험 이유로 지우지 않는다).
- 막힌 사실을 정확한 이름으로 부른다. 셋이 각각 다르게 말하므로 도구 이름이 아니라
  **무엇을 하려다 막혔는지**로 잡는다:
  `kill … failed: operation not permitted` / `killall: warning: kill -term …` /
  `pkill: signalling pid …`
  이제 승인 카드가 `돌고 있는 프로그램을 끄는 일이라` 라고 말한다 — 파일 얘기를 하지 않는다.

## 검증

- 회귀 1032건 · 게이트 PASS
- **진짜 프로세스를 만들어 확인한다.** 이 사고는 대역으로는 안 잡혔다 — 샌드박스가 실제로
  무엇을 허용하는지가 문제였기 때문이다. 검사가 `sleep` 을 띄우고 `kill`·`killall`·`pkill`
  셋을 probe 로 돌린 뒤 대상이 살아있는지 본다.
- 반대 검증: `(deny signal)` 을 빼면 검사 2건이 실패한다.

## 남은 한계

- `osascript` 로 AppleEvent 를 보내려다 막히면 `-600`(앱이 실행 중이 아님)으로 보여
  `code/failed` 로 분류된다. 효과는 막히지만 사용자에게 "막혔다"고 말하지는 못한다.
- 이 회차는 macOS 기준이다. 다른 OS 의 샌드박스는 확인하지 않았다.
