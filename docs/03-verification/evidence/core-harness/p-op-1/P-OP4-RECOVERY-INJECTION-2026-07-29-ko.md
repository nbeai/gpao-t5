## ① 기존 복구 자산 커버리지

| 실패 | 담당 자산 | 계약 |
|---|---|---|
| 도구 핸들러 예외 | ToolRunner catch | failed 영수증 · 내부 오류 비노출(진단면 분리) · nextSafeAction |
| blocked/failed 분류 | ToolRunner + 핸들러 계약 | permanent(blocked)와 transient(failed) 분리 |
| 실행 불가 도구 호출 | isToolExecutable 게이트 | 호출 0 · blockedReceipt |
| 웹 차단 종류별 다음 길 | recovery-ladder | robots/login/bot/timeout/429 → 계단(다른 도구·모델 검색·재시도·사용자) |
| 파일 범위 밖 | out_of_scope 계단 | 손 있으면 다른 손, 없으면 범위 요청 — 없는 손 약속 금지 |
| 사용자를 시키는 문장 | 다음길 검열(시키는말) | 막히지 않은 손이 있으면 시키는 문장 금지 |
| 같은 실패 반복 | 지문(같은 손+인자 1회) | "같은 일을 되풀이하려 해서 멈췄어요" |
| 숨은 재시도 | 기본 없음 · 자동화만 명시 백오프 | maxAttempts 초과 시 정직하게 failed |
| 걸음 상한 | MAX_TOOL_STEPS + toolBudgetSpent 사실 | 상한을 "능력 없음"으로 번역하지 않음 |
| 모델 실패 | ModelProviderError 정규화 + 서버 catch + doctor | 한 일 있음/없음을 구분한 정직한 안내 |
| 채널 전송 실패 | channel-sender 분류 + Delivery 재전달 | auth/429/timeout 분리 · 재전달은 재생성 없음 |
| 터미널 위험 | sandbox probe/granted | 돌려 보고 판정 · 비밀 경로는 승인 후에도 차단 |

## ②③ 주입 판정 — 수정 전 전부 현재 계약 통과

| 주입 | 결과 |
|---|---|
| A. 도구 예외(모델이 같은 명령 3회 고집) | 실행 **1회**(지문이 차단) · 실패 원장 1건 · `EIO` 진단 비노출 |
| B. 끊긴 원격 손(전송층 사망) | 성공 조작 0 · `ECONNREFUSED` 비노출 · 정직한 답 |
| C1. 첫 호출부터 모델 사망 | 도구 실행 0 · 답 조작 없이 정직한 실패 전파 |
| C2. 걸음 도중 모델 사망 | 이미 한 걸음의 영수증 보존(서버가 "기록에 남겼어요"로 구분) |

## ⑤ 라이브 대표 (실모델 gpt-5.5 · `/turn` · 원장 대조)

**도구 실패** — `http://127.0.0.1:9/nope 읽어줘`:
못 읽었다고 정직하게 + 로컬 주소·포트라는 근거 + 다음 길(서버 주소 재확인/파일 위치).
원장: 성공 0 · 실패 1(`주소를 다시 확인해 주시겠어요?`). 사용자를 시키는 명령어 없음.

**연결 끊김** — 저장된 딥위키 선언의 주소를 도달 불가로 바꿔 재시작:
- 주입 주소가 SSRF 경계(안쪽 주소 차단)에 걸려 **선언 재검사 탈락** 경로가 드러났다 —
  의도했던 전송층 사망이 아니라 **무효 선언의 조용한 소멸**을 발견(아래 발견 ①).
- 그 상태에서 `딥위키에서 svelte 저장소 찾아줘` → 모델이 없는 손을 지어내지 않고
  **web.collect 로 전환**해 출처 있는 답(원장: `찾아서 읽었어요: sveltejs/svelte | DeepWiki`).
  사다리 2단(다른 도구)이 실모델에서 그대로 작동.
- 전송층 사망 자체는 격리 주입 B가 덮는다(성공 조작 0 · 진단 비노출).
- 복구 후 재시작: `[connector] 사용자가 올린 서비스 딥위키` · 진실 표면 복귀 확인.

**모델 실패** — 자격을 건드리지 않고 `GPAO_T5_MODEL_HTTP_TIMEOUT_MS=1` 재시작:
`지금은 답을 만드는 연결이 잠시 불안정해요. 방금 요청은 아직 실행하지 않았어요.` ·
도구 실행 원장 0건 · 지어낸 답 없음. 정상 재시작 후 회복 확인.

## 발견과 분류

1. **무효화된 저장 선언의 조용한 소멸** — 재검사에서 떨어진 사용자 선언이 로그 0 ·
   표면 0으로 사라진다(선언 파일은 남으므로 데이터 손실은 아님 — 투영 공백).
   최소 보정: 부팅 로그 한 줄(`저장된 선언 재검사 탈락: <서비스> — <이유>`) 지금 반영.
   사용자 표면("붙일 수 없음 · 이유")은 **P-OP-6 연결 표면**의 지정 후속.
2. **관찰(C)**: 원격 손 전송층 사망이 일반 `failed`("잠시 후 다시")로 분류된다 —
   연결 사실로 분류돼 재연결 경로를 안내하면 더 정확하다. 사용자 피해 재현 전까지
   사다리에 종류를 추가하지 않는다.
3. **관찰(C)**: retry 계단의 "다시 한 번 해볼게요"는 같은 턴에서 지문에 막힌다(다음 턴 재시도는
   가능) — 문구와 실제 시점의 결이 조금 다르다. P-OP-6 문구 정리에서 함께.

## 감사 보충 (2026-07-29, 같은 날) — 봉인 증거 2건 + 입력 사실 1건

독립 감사 판정: 핵심 계약 통과 · 최종 봉인 증거 2건 보충 필요. 새 복구 코드 없이 증거만 보강했다.

1. **편입된 손의 실제 전송 사망**(B′) — 흉내(주입 B)가 아니라 진짜 관통: 로컬 루프백에 실제
   HTTP MCP 서버를 세우고 → `openHttpMcp` 로 초기화 → `admitMcpTools` 로 편입 → **살아 있을 때
   1회 실제 호출 확인**(연결≠사용) → 소켓까지 실제로 끊음 → 같은 업무 요청(모델이 같은 호출
   2회 고집): 승인 경계 → 승인 → **호출 정확히 1회**(지문이 재시도 차단) · 거짓 성공 0 ·
   `ECONNREFUSED`/`fetch failed` 비노출 · 정직한 답.
2. **걸음 성공 후 모델 사망의 서버 관통**(C2′) — `/turn` 으로: 응답 `기록에 남겼어요`(한 일
   있음 구분) · 세션 파일에 걸음 영수증 보존 · 저장된 대화의 답과 응답이 동일(응답·원장·저장 일치).
3. **입력 사실** — 도구 실패 뒤 **다음 모델 입력**에 실패 영수증(`그 폴더를 읽지 못했어요`)과
   복구 단서(recoveryHint)가 실제로 실린다. 런타임의 책임은 모델 교정이 아니라 실패 현실
   공급이라는 원칙을 검사로 고정(스텁 모델의 정직한 답에 기대지 않음).

## 판정

P-OP-4 의 세 실패 계열(도구·연결·모델)은 **격리 주입 + 실전송 사망·서버 관통 보충 + 실모델
라이브 대표 각 1회**로 봉인.
복구 자산의 빈 곳은 발견 ①(최소 보정 완료 + P-OP-6 이관)뿐이었다. 기억 이중 기록 경계
봉인과 합쳐 P-OP-4 는 닫힌다. 실패 주입의 사용자 화면 도달(경고·문구 배치)은 P-OP-6 범위.
