## 시험 흐름

```
원래 업무를 말함 → 승인 카드 → **승인하지 않고 서버 재시작**
→ `아까 하던 거 이어줘` → 대기 복원 · 원래 업무 복원
→ 승인 → 보관된 계획이 정확히 한 번 실행
```

### 대기 상태의 실제 내용 (승인 전)

```
대기 승인: 1 건
  원래 업무: 컨텍스트세븐에서 리액트 훅 문서 찾아줘. MCP 주소는 https://mcp.context7.com/mcp야.
  승인 대상: connector.declare
  길이: 1739 · 비밀값 흔적: 없음
  만료: 15:12:59
활성 목표: (없음)
```

승인 전 `declared-connectors.json` 에는 딥위키만 — **외부 효과 0.**

### 재시작 뒤

```
[connector] 사용자가 올린 서비스 딥위키
대기: 1 건
```

같은 대화를 열면 승인 카드가 그대로 있고 버튼이 살아 있다. 죽은 버튼이 아니다.

## 첫 회차 실패 — 승인 카드가 둘이 됐다

`아까 하던 거 이어줘` 에 T5 는 원래 업무를 정확히 이어받았다(같은 서비스, 같은 주소, 사용자가
원문을 다시 말하지 않았다). 그런데 **대기 중이던 승인을 재사용하지 않고 새로 만들었다.**

```
대기 승인: 2 건
  f7e3ed3e · connector.declare · 원업무: 컨텍스트세븐에서 리액트 훅 문서 찾아줘. MCP 주소는
  0f4a8af8 · connector.declare · 원업무: 아까 하던 거 이어줘.
```

화면에 같은 일을 묻는 카드가 둘 남았고, **둘 다 누르자 `connector.declare` 가 두 번 돌았다.**

```
영수증: connector.declare, connector.declare
declare 실행 횟수: 2
```

이번엔 선언이 같은 id 를 덮어써서 사용자 피해가 없었다. 그러나 전송·페이지 생성처럼 되돌릴 수
없는 행동이었다면 **그대로 두 번 나간다.** "결과가 같았다"는 이유로 통과시키지 않는다.

## 고침 — 한 대화에 살아 있는 승인 요청은 하나다

턴은 첫 승인에서 멈춘다. 그러므로 **동시에 둘이 살아 있을 이유가 없다.** 새 대기를 만들 때
이전 대기는 지난 것이 된다. 한 계획 안의 여러 승인은 `needsApproval` 배열 하나에 들어가므로
이 규칙에 걸리지 않는다.

검사가 실제로 잡는지 확인했다 — 그 한 줄을 끄자 회귀 검사가 실패하고, 되돌리면 통과한다.

## 재검증 (수정 후, 같은 흐름)

```
새 대화 → 승인 카드 → 대기 1건
재시작 → 대화 열기 → 카드 살아 있음
`아까 하던 거 이어줘` → 대기 **1건 유지**(둘로 늘지 않는다)
승인 → connector.declare 1회 → 컨텍스트세븐 연결 → 다음 걸음(Resolve Context7 Library ID)
옛 버튼을 눌러도 → "그 승인 요청을 찾지 못했어요. 다시 말씀해 주세요."
영수증: connector.declare  ·  declare 실행 횟수: 1
```

## 화면의 죽은 버튼 — 발견하고 같은 회차에서 닫았다

서버 대기는 1건인데 **화면에는 승인 버튼이 2개** 보였고 `지난 승인 요청` 표시는 0개였다.
누르면 "그 승인 요청을 찾지 못했어요"로 끝나 **중복 실행은 나지 않았지만**, 사용자는 누르기
전까지 그것이 지난 카드인지 알 수 없었다. 죽은 버튼이다.

원인은 좁았다. 대화를 **다시 열면** 서버의 `activePendingIds` 로 옛 카드를 지난 것으로 그렸다.
그런데 실시간으로 받은 결과는 그 자리에 **덧붙이기만** 해서, 같은 화면에서는 옛 카드가 계속
살아 보였다(새로고침하면 맞았다 — 같은 화면에서만 틀렸다).

고침: 대화 한 벌을 **한 함수로만** 그린다. 턴·승인·거절이 끝나면 서버에서 대화를 다시 받아
통째로 투영하고, 화면은 승인 상태를 따로 추측하지 않는다 — `activePendingIds` 가 단일 진실이다.
다만 **마지막 결과만 현재**로 그린다: `historical` 은 비밀 입력면·기억 제안처럼 지금 필요한
자리까지 숨기므로, 전부 과거로 그리면 방금 열린 입력창이 사라진다.

후속 독립 감사에서 마지막 결과를 현재로 둔 것이 **마지막 만료 승인까지 활성으로 보이게 할 수 있는
교차점**을 확인했다. 현재 결과 여부와 승인 활성 여부를 분리했다. 마지막 결과는 비밀 입력면·제안을
위해 현재로 유지하되, 승인 버튼은 모든 결과에서 서버의 `activePendingIds`만 따른다.

### 최소 검증 7단계 (전부 통과)

```
① 첫 카드 생성 → ② 재시작
③ `이어줘` 로 새 카드 → 이전 카드 즉시 `지난 승인 요청`, 버튼 없음
   (승인 버튼 1개 · 지난 승인 요청 1개)
④ 새 카드만 승인 가능
⑤ 새로고침 뒤에도 동일 (승인 버튼 1개 · 지난 요청 1개)
⑥ 승인 → connector.declare **1회**
⑦ 회귀 1090건 · 게이트 PASS
```

## 증거 등급

- 위 흐름은 **표면 도달 · 실모델 라이브** 증거다.
- 중복 방지 회귀 검사는 **회귀 안정성** 증거다. 둘은 서로를 대신하지 못한다.

- 무관한 새 요청이 이전 작업을 밀어내기
- 오래된 작업 감쇠
