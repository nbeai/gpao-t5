# 사고 기록 · 올린 서비스를 거둘 수 없었다 (여섯 번째 못 지킬 약속)

- 시각: 2026-07-28
- 발견: 병합 검증 흐름을 **끝까지** 돌리던 마지막 단계
- 고친 커밋: `5e07e0e`
- 발견 당시 상태: 테스트 1080건 전부 통과 · 게이트 PASS

## 무슨 일이 있었나

승인 카드가 사용자에게 이렇게 약속했다.

> 되돌리기 — `"연결 끊어줘"라고 하시면 지워요 — 지금은 아무 값도 저장되지 않아요`

사용자가 그대로 말했다: `컨텍스트세븐 연결 끊어줘.`

T5 의 답:

> 컨텍스트세븐은(는) 지금 연결돼 있지 않아요. 끊을 것이 없어요. 다른 걸 도와드릴까요?

그리고 `declared-connectors.json` 에는 컨텍스트세븐이 **그대로 남아 있었다.**

## 왜 그랬나

세 가지가 서로 다른 상태인데 해제 계약이 앞의 둘만 봤다.

| 상태 | 무엇인가 | 재시작 뒤 |
|---|---|---|
| 연결 상태(`live` 세션) | 지금 붙어 있는 MCP 세션 | 사라진다 |
| 저장된 자격 | 0600 파일의 토큰·키 | 남는다 |
| **사용자 선언** | 사용자가 올린 서비스 자체 | **남는다** |

무인증 원격 MCP 는 저장할 자격이 없다. 그래서 재시작 뒤에는 **세션도 자격도 없고 선언만
남는다.** 그 상태에서 해제 자격 검사는 "붙어 있지도 않고 자격도 없다 → 끊을 것이 없다"로
읽었다. 기술적으로는 참이었다. 그런데 사용자가 지우고 싶은 것은 **선언**이었다.

## 왜 이것이 중요한가

사용자가 만든 것을 사용자가 거둘 수 없으면, T5 는 되돌릴 수 없는 상태를 사용자 컴퓨터에
계속 쌓는다. 한 번 올린 서비스가 영영 남는다.

그리고 이건 그날 여섯 번째로 만난 같은 병이다 — **못 지킬 약속.** 앞의 다섯은 문구 층에
있었고(되돌리기·거절·승인 이유·카드 이름·원장), 이건 **능력 층**에 있었다. 카드가 할 수 있다고
말한 일을 시스템이 못 했다.

## 어떻게 고쳤나

끊기를 선언 지우기까지 이었다. 그리고 경계를 명확히 했다.

- `declared: true` — 사용자가 올린 것: 끊으면 선언까지 지운다
- 소스에 적힌 선언(노션·네이버·깃허브…): 세션·자격만 지우고 **선언은 남긴다**

소스 선언까지 지우면 다시 붙일 자리가 없어진다. 두 경우를 회귀 검사 둘로 고정했다.

승인 자격도 함께 넓혔다: 붙어 있지 않아도 **올린 것이면** 지울 수 있어야 한다.

## 여기서 생긴 불변식

> **사용자가 만든 것은 사용자가 거둘 수 있어야 한다.**
> 연결 해제는 세션 종료만이 아니라, 사용자 소유 선언의 회수 가능성까지 본다.

## 어떻게 잡혔나

단위 검사 1080건이 **전부 통과한 상태**에서, 검증 흐름을 화면에서 일곱 단계 끝까지 돌리다
마지막 단계에서 나왔다. 각 층은 각자 옳았다 — 해제 자격 검사도, 선언 저장소도, 승인 카드도.
합쳐진 화면에서만 틀렸다.

구조 개발 원칙 §2-A 가 말하는 그대로다: **철학은 결함을 찾지 않는다. 화면과 원장이 찾는다.**
