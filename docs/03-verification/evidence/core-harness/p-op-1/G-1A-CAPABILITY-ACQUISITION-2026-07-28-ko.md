## 첫 회차는 실패했다 — 그 사실을 남긴다

같은 문장으로 먼저 돌린 회차의 원장:

```
[connector.declare] 컨텍스트세븐에 연결했어요. 이제 2개를 바로 쓸 수 있어요.
[web.collect]       찾아서 읽었어요: How to Use React Hooks – freeCodeCamp
```

승계는 됐지만(사용자가 반복하지 않았다) **붙인 손을 쓰지 않았다.** T5 는 그 사실을 스스로
밝혔다 — "이번에 실제로 읽은 문서는 Context7 내부 문서가 아니라 웹 검색으로 찾은 글이에요."

**연결만 하고 멈추거나 다른 손으로 때우면 G-1A 실패다.** 결과가 나왔다는 이유로 통과시키지
않는다.

## 원인 — 모델 선택이 아니라 현실 조립

`selfState` 는 턴 시작 때 한 번 만드는 사진인데, 편입은 `ctx.env.connections` 를 제자리에서
갱신한다. 그래서 편입 뒤에도 `toolSchemasFor(selfState)` 는 옛 목록을 준다.

재현:

```
편입 전 모델이 보는 손: 5
편입 후 (턴 시작 사진 그대로): 5   ← 새 손이 안 보인다
편입 후 (다시 만들면): 6
```

`live-context.js` 주석은 "편입은 제자리 갱신이라 **그 턴부터 모델이 본다**"고 적혀 있었다.
그 약속이 지켜지지 않았다 — **코드가 자기 주석에 한 거짓말**이다.

모델이 익숙한 손을 고른 것이 아니었다. 새 손이 입력에 없었다.

## 고침 — 하나의 작동원리

> **도구 현실이 변하면 그 현실에서 파생되는 모든 표면을 한 번에 다시 만든다.**

`refreshRuntimeReality(ctx)` 하나가 `selfState` · `externalReality` · `capabilityCounts` ·
`selfStateSummary` · 모델 도구 스키마를 함께 만든다. 판단하지 않고 도구를 추천하지도 않는다 —
살아 있는 레지스트리를 다시 읽어 같은 현실의 투영본만 만든다.

**변화 감지를 두지 않는다.** 처음에는 손 개수 비교로 막았는데 그것은 **교체를 놓친다**
(하나 내리고 하나 올리면 개수가 같고, 같은 id 로 세션만 갈리는 재연결도 못 잡는다).
손이 스무 개 남짓이고 한 턴의 실행 횟수도 상한이 있어 매번 다시 만드는 비용이 아주 작다.
성능이 실제로 측정될 때 레지스트리에 `capabilityRevision` 을 두고 편입·교체·해제마다 올린다
(오너 판정 2026-07-28).

## 회귀 검사 — 노출까지만 보지 않는다

네 가지 변화 반대시험 + 관통 검사:

| 검사 | 무엇을 잡나 |
|---|---|
| ① 손 하나 추가 | 편입이 모델 목록에 닿는가 |
| ② 손 하나 해제 | 내린 손이 사라지는가 |
| ③ **하나 내리고 하나 올림** | 개수가 같아도 목록이 달라지는가 — 개수 비교로는 못 잡는 자리 |
| ④ **같은 id 로 세션·스키마 교체** | 재연결이 실제로 반영되는가(옛 세션이 남지 않는가) |
| ⑤ 관통 | 기존 손 실행 → 편입 → 같은 턴 입력에 새 손 → 모델이 선택 → 승인 → **실제 실행** → 영수증 각 1건 |

**검사가 실제로 잡는지 확인했다.** `refreshRuntimeReality` 호출을 일부러 빈 함수로 바꾸자
⑤가 실패했다("편입 뒤에도 모델이 새 손을 못 본다: web.collect, local.file, …"). 복구 후 통과.

## 증거 등급

- 이 문서는 **표면 도달 · 실모델 라이브** 증거다.
- 네 반대시험과 관통 검사는 **회귀 안정성** 증거다. 둘은 서로를 대신하지 못한다.

## 이 회차에서 분리해 둔 것

`자기 도구함을 안 보고 웹으로 갔다`(D 증거의 미분류 관찰)는 이 패치에 **묶지 않았다.**
그 건은 원인 분리 시험이 필요하다 — 턴 시작부터 붙어 있던 손이 모델 입력에 다 들어갔는지,
새 손과 기존 손을 구분해 같은 질문을 걸었을 때 어떻게 갈리는지, 웹 검색 허용/불허 비교.
그 결과가 나오기 전에는 새 규칙이나 `toolbox.query` 같은 손을 만들지 않는다.

## 한계 — G 에서 아직 닫히지 않은 것

이 문서는 G 의 첫 조각(승계 순환)만 닫는다. 남은 것:

- G-1B: 연결 도중 중단 → 재시작 → `아까 하던 거 이어줘`
- 후보 둘일 때 짧은 선택 요청 / 완료된 일을 "아까 그거"로 되살리지 않기
- 중간 취소 뒤 재실행 없음 / 무관한 새 요청이 이전 작업을 밀어내기
- 재시작 뒤 실제 대기만 복원 / 오래된 작업 감쇠 / 승인·외부 효과 중복 실행 방지
- 주소 없이 서비스 이름만 준 **능력 획득 관찰**은 별도 회차로 남긴다(G 통과 조건에 섞지 않는다)
