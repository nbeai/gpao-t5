# P-OP-1 A · 읽기 진단이 사용자에게 떠넘기지 않고 끝난다

시각: 2026-07-28
표면: **웹 화면에서 직접 확인**(감사자가 아니라 구현자가 화면을 봤다)

## 검증한 사용자 흐름

문장: `컴퓨터가 요즘 느린데, 바꾸지 말고 원인만 봐줘.`
환경: 실제 모델(`gpt-5.5`) · 새 대화 · 요청 1회 · localhost:4173

## 이전과 무엇이 달라졌나

| | 이전(같은 문장, 같은 모델) | 지금 |
|---|---|---|
| 답 | `ps랑 top이 operation not permitted로 막혀서 확인이 안 됐어` | `openclaw 136.2%` · `Codex Renderer 434.9%` · `WindowServer 38~44%` |
| 끝맺음 | **`Activity Monitor에서 CPU 탭 보면 돼`** (사용자에게 떠넘김) | **`원인만 보면 openclaw + Codex Renderer CPU 폭주`** |
| 승인 카드 | `ps -p …` 가 카드로 감. 카드 문구: `내용을 남기거나 덮어쓰는 일이라` (거짓) | 없음 — 읽기니까 |

## 원장

```
local.system    지금 돌고 있는 것 500개 중 … Codex (Renderer)
local.system    …
local.terminal  ps 은(는) 이 자리에서는 띄울 수 없는 도구예요 — 아무것도 실행되지 않았어요
local.system    … openclaw(CPU 136…)
승인 대기: 없음
```

모델이 터미널 `ps` 를 한 번 시도했다가 **정직한 메시지를 받고 새 손으로 돌아갔다.**
막다른 답도, 거짓 승인도 없었다.

## 고친 것 둘

1. **`local.system`** — `/bin/ps` 는 setuid root 라 `sandbox-exec` 가 실행 자체를 거부한다
   (실측: `(allow default)` 만 있는 프로파일에서도 동일). 규칙으로 못 여는 자리다.
   셸·샌드박스를 안 거치되 명령·인자를 T5 가 고정 조립해 주입 자리를 없애고, `comm` 만 읽어
   **명령 인자에 섞인 비밀(`--token=…`)을 안 본다.**

2. **실행 거부 ≠ 변경 시도** — 셸이 막았다고 말한 이름이 **명령 자리**면 아무것도 안 돈 것이다.
   리다이렉트 대상이면 쓰기 시도다. 목록이 아니라 사실로 가른다.
   `echo x > /usr/bin/ps` 처럼 실행 파일 경로에 쓰는 것도 명령 이름(`echo`)과 달라 쓰기로 남는다.

## 검증

- 반대 검증: 8가지 명령 분류(읽기 3 · 쓰기 3 · 설정 변경 1 · 평범한 읽기 1) 전부 기대와 일치
- 검사에 실제 시스템 변경은 없다 — `run` 을 주입해 권한 거부만 재현한다

## 한계

- 이 회차는 macOS 기준이다. 다른 OS 의 setuid 거부 신호는 확인하지 않았다.
- B(자료 탐색·정리)와 C(미선언 서비스)는 여전히 미통과다.
- 개인 PC 의 구체 프로세스 목록·세션 식별자는 보관하지 않는다.
