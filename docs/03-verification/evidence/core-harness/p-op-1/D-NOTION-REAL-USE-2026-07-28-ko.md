# P-OP-1 D · 노션 실제 사용 라이브 증거

- 시각: 2026-07-28
- 실행 기준선: `c63ab18` (브랜치 `claude/p-op-1-a-system-view`)
- 표면: 웹 화면(localhost:7331) · 실제 모델 `gpt-5.5` · 오너 실계정 노션
- 회귀 기준: 테스트 1082건 통과 · 게이트 PASS

## 무엇이 닫혔는가

**D 전체가 아니다.** 닫힌 것은 **실제 사용과 재시작 기능 복원**이다.

D 의 앞 절반(동의 → 손 20개 편입 → 재시작 지속)은 이전 회차에서 확인됐다.
이 문서는 **뒷 절반의 첫 조각** — 붙은 손을 실제로 쓰는 것 — 을 닫는다.

> **붙는 것과 쓰는 것은 다른 사실이다.** 붙었다고 D 를 닫지 않는다.

## ① 실제 노션 읽기 — 올바른 영수증

사용자 원문: `내 노션에서 이번 주 회의록 찾아줘.`

승인 카드 두 장(서로 다른 손이라 각각 물었다):

```
· Query Notion meeting notes A2 — 노션에서 Query Notion meeting notes
  어디에  노션 에서 · 이번 한 번
  무엇을  filter: operator and, filters 1개

· Search Notion and connected sources A2 — 노션에서 Search Notion and connected sources
  무엇을  query: 회의록 meeting notes 회의 notes 미팅 · query_type: internal
          · filters: created_date_range … · page_size: 10 · max_highlight_length: 250
```

원장 영수증:

```
[mcp.notion.notion-query-meeting-notes] 찾은 게 없어요.
[mcp.notion.notion-search]              찾은 게 없어요.
```

**`web.collect` 는 없다.** 편입된 노션 MCP 손이 실제로 돌았다.

답변: "이번 주 기준을 2026-07-27~2026-08-03으로 잡고 … 검색 결과가 없어요.
다음엔 범위를 넓혀서 …"

그 주에 회의록이 실제로 없는 것이 사실이다. **0건도 사실이고, 무슨 조건으로 찾았는지와
다음 길을 함께 말한다.**

## ② 실제 결과 회수 — 0건만으로는 부족하다

①만으로는 "손이 돌았다"까지다. **실제 데이터가 돌아오는지**는 별개라 결과가 있는 질의를 걸었다.

사용자 원문: `그럼 노션에 있는 문서 아무거나 3개만 제목 알려줘. 기간 제한 없이.`

원장: `[mcp.notion.notion-search] 3건을 찾았어요.`

화면에 실제 문서 제목 3건이 나왔다(오너 워크스페이스의 실제 문서다 — 제목은 개인 자료라
이 문서에는 건수와 형태만 남긴다).

## ③ 재시작 뒤 실제 재호출 — 기능 복원

프로세스를 죽이고 다시 띄웠다.

```
[connector] 사용자가 올린 서비스 딥위키
[connector] notion 다시 연결됨 — 손 20개
[connector] naver 다시 연결됨 — 손 1개
```

**로그와 손 목록만으로 통과시키지 않는다.** 실제로 다시 불렀다.

사용자 원문: `노션에서 "사장의 교본" 문서 찾아서 제목 확인해줘.`

```
· Search Notion and connected sources A2 — 노션에서 Search Notion and connected sources
  무엇을  query: 사장의 교본 · query_type: internal · page_size: 5 · max_highlight_length: 120
```

원장: `[mcp.notion.notion-search] 5건을 찾았어요.` — 실제 제목 5건이 화면에 나왔고,
모델이 그중 가장 문서 제목다운 것을 짚었다.

재시작 뒤 **재로그인 없이** 저장된 자격으로 붙어 실제 호출까지 이어졌다. 기능 복원이 닫힌다.

## 만료·자동 갱신·폐기·재인증 — 격리 통합 증거

**오너 주계정 토큰을 시험 fixture 로 쓰지 않는다.** 공식 노션 MCP 는 OAuth PKCE 와 토큰
갱신을 요구하고, 갱신 시 refresh token 도 함께 회전한다. 자격 파일을 백업했다가 되돌리는
방식은 **안전한 rollback 이 아니다** — 서버에서 이미 회전된 토큰을 로컬이 다시 들게 된다
(오너 판정, 2026-07-28).

이 계약은 표준 OAuth 가짜 서버로 격리 검증한다 — `test/remote-mcp-oauth.test.js`:

| 검사 | 무엇을 지키나 |
|---|---|
| 만료된 토큰은 조용히 갱신한다 | 사용자에게 재로그인을 시키지 않는다 |
| 서버가 자격을 폐기하면 스스로 재인증하고 이어간다 | 폐기 뒤에도 작업이 끊기지 않는다 |
| 재인증도 실패하면 연결됐다고 하지 않는다 | 실패를 성공으로 기록하지 않는다 |
| 끊으면 저장된 자격도 사라진다 | 말과 디스크가 어긋나지 않는다 |
| 승인하지 않으면 연결이 아니다 | 동의 없는 연결을 만들지 않는다 |
| PKCE verifier 는 나가지 않고 challenge 만 | 비밀이 통로를 지나지 않는다 |
| state 가 다른 콜백은 코드를 받지 않는다 | CSRF |

이건 **격리 통합 증거**다. 실제 노션 서버에서의 폐기·재인증 라이브 증거가 아니다.
둘은 서로를 대신하지 못한다.

## 증거 등급

- ①②③ — **표면 도달 · 실모델 · 실계정 라이브**
- 만료·갱신·폐기·재인증 — **격리 통합**
- 테스트 1082건 · 게이트 PASS — **회귀 안정성**(게이트는 스텁 모델을 쓴다)

## 한계 — D 에서 아직 닫히지 않은 것

- **실제 서버 폐기·재인증**: 전용 시험 workspace 가 준비되면 권한 철회 → T5 재인증 →
  실제 호출 복구로 확인한다. 주계정에서는 하지 않는다.
- **실제 주계정 연결 해제**: 로컬 자격 삭제·도구 제거에 더해 원격 토큰 폐기까지 갈 수 있다.
  실제 영향을 오너가 알고 승인해야 실행한다.
- **동의 취소 UI**: 동의 화면에서 사용자가 거절했을 때의 실패 계약은 격리 시험으로만 확인됐다.

## 미분류 관찰 — 요청 충실도는 통과가 아니다

②에서 **실데이터가 나왔다는 이유로 요청 충실도까지 통과시키면 안 된다.** 이 회차의 판정은
셋으로 갈라야 한다.

| 항목 | 판정 |
|---|---|
| 실제 노션 데이터 회수 | **통과** |
| 사용자의 "아무거나" 의도 보존 | **미달** |
| 적합한 노션 손 선택 | **원인 미분류** |

무슨 일이 있었나. 사용자는 `노션에 있는 문서 아무거나 3개만 제목 알려줘. 기간 제한 없이.`
라고 했다. T5 는 이렇게 불렀다.

```
query: 회의 OR meeting OR notes OR 프로젝트 OR 업무 · query_type: internal · page_size: 3
```

**"아무거나"를 키워드로 번역했다.** 앞 턴의 회의록 맥락이 그대로 검색어에 실렸고, 사용자가
명시적으로 푼 조건("기간 제한 없이")만 지켰다. 결과 3건은 실제 문서였지만, 그것은 그 키워드에
걸린 문서지 "아무거나"가 아니다.

### 편입된 20개 손의 실제 계약 (수정 전 확인)

`/connectors/truth` 로 실제 편입 계약을 읽었다. 20개 전부 `inModelSchema: true` 다.

- **최근 문서·임의 문서를 그냥 나열하는 손은 없다.** 목록에 가장 가까운 것은
  `notion-query-data-sources`(SQL 로 데이터소스를 질의 — 정렬 가능)인데, 먼저 `notion-fetch`
  로 데이터소스 URL 을 얻어야 한다는 전제가 능력 문장에 적혀 있다.
- `notion-search` 는 **랭크된 검색**이다. 능력 문장은 "One question or topic per call" 이라고
  말한다. 빈 질의나 최근순 정렬을 지원한다는 언급은 없다.
- 능력 문장은 **영어 원문 그대로** 모델에게 간다. 역할·제한은 들어가 있다.

따라서 셋 중 세 번째에 가깝다 — **그런 손이 실제로 없다.** 그렇다면 T5 는 임의 키워드를
지어낼 것이 아니라, 한계를 말하고 가장 가까운 안전한 방법을 골랐어야 한다.

### 같은 계열의 두 번째 관찰

`노션에 붙어 있는 기능 중에서, 최근 문서를 그냥 나열하는 기능이 있어? 검색 말고.` 라고 물었다.

원장:

```
[web.collect] 찾아서 읽었어요: Notion 내 검색 – Notion (노션) 도움말 센터.
[web.collect] site:notion.com/ko/help … Navigate Notion with the sidebar
```

**자기 손 20개를 안 보고 노션 도움말 센터를 웹 검색했다.** 답은 `홈` 한 단어였다.

자기 도구함에 대한 질문인데 도구함을 읽지 않았다. 이건 ②와 같은 뿌리로 보이지만
**여기서 단정하지 않는다** — 원인은 셋 중 어느 것일 수도 있다(모델 선택 / 능력 문장의 밀도 /
자기 손 목록이 모델 입력에 실리는 방식). 관찰로만 남긴다.

### 왜 지금 고치지 않는가

결함을 하나 봤다고 구조를 고치지 않는다(구조 원칙 §1-C — 매듭은 두 번째 현상에서 확인된다).
지금은 **두 관찰이 같은 뿌리인지 아직 모른다.** 다음 사람이 "실데이터가 나왔으니 정확히
수행했다"고 오독하지 않도록 미분류로 남긴다.

## 곁가지로 확인된 사실

승인 카드의 도구 이름은 아직 MCP 서버가 준 영어 그대로다(`Search Notion and connected
sources`). 모델에게 한글 라벨을 짓게 하면 삭제 도구가 "정리"로 보일 수 있어 열지 않았다 —
카드의 1차 사실은 런타임이 쥔다. 인자는 사람이 읽는 모양으로 나온다
(`query: 사장의 교본 · page_size: 5`).

개인 워크스페이스의 문서 제목·내용·세션 식별자는 이 문서에 남기지 않는다.
