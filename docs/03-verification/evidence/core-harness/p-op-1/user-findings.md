# P-OP-1 사용자·감사 지적의 회귀 번역

## 2026-07-28 승인 경로 회귀

- 지적: 읽기 전용 `LaunchAgents` 확인을 자동으로 풀면서, `launchctl setenv`처럼 OS 권한에 막힌 설정 변경도 승인 없이 실패로 끝났다.
- 실제 실패: probe 결과 `Not privileged`가 `changes: false`로 해석돼 승인 카드가 나오지 않았다.
- 원인: `executionBlock`이 권한 부족을 변경 시도의 별도 종류로 분류하지 않았고, `looksBlocked`도 샌드박스 쓰기만 변경으로 봤다.
- 불변식: 권한 부족으로 멈춘 설정 변경은 읽기 성공이 아니다. 사용자 승인을 받을 수 있는 경로를 잃지 않는다.
- 회귀 검사: `권한 부족으로 막힌 설정 변경도 승인 경로를 잃지 않는다`.
- 반대 방향: `ls ~/Library/LaunchAgents`, `launchctl list` 같은 읽기는 자동으로 계속 통과해야 한다.

## 감사 메모

P-OP-1 A의 API 원장 검증은 실제 모델 증거이지만 웹 표면 검증은 아니다. 실행 보드에서 표면 상태를 `미검증`으로 유지한다.
