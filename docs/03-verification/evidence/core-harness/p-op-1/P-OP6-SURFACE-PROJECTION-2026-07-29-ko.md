# P-OP-6 · 사용자 표면 투영 계약 (2026-07-29)

원칙(오너 감사 지정): **내부 실행에는 원시 식별자를, 사용자 표면과 기억 후보에는 검증된
사람말 라벨을 쓴다. 하나의 표면에는 하나의 확정된 대상 사실만 투영한다.**
항목별 문구 패치가 아니라 표시 경로마다 **단일 변환 경계**를 확정한다.

## ② 이번에 닫은 것

1. **Codex `e2ac91d` 흡수**(cherry-pick `c21dfad`, 의미 단위 검토 후 전량 필요 판정):
   원시 chat id → `projectDefaultTarget` 라벨 투영(제안 카드·/patterns) ·
   승인 카드 scope/where 상충 제거(`확정된전송미리보기` — 계획·걸음 경로 공통) ·
   sentVia 라벨 승계 · 빈 답 말풍선 생략. 검사 포함(카드에 scope 부재 · 라벨만 노출).
2. **무효 선언 표시** — 재검사 탈락 선언이 `/connectors/truth` 의 `invalidDeclared` 로
   `지금은 붙일 수 없어요 — <이유>` 와 함께 나타난다. 유효 목록에는 섞지 않는다(반대시험).
3. **retry 문구 시점 정직화** — `다시 한 번 해볼게요`(같은 턴 재시도는 지문이 막음) →
   `잠시 뒤에 다시 시도해 볼 수 있어요`(실제 가능한 시점).

## ③ 웹·채널 교차 (⑥)

같은 사건이 두 표면에서 같은 사실을 보는 계약은 기존 봉인 검사들이 든다:
채널 답장의 전달 원장 기록 · 승인 알림의 도구 id 비노출·같은 말투 · allowlist 게이트의
HTTP 관통 · 채널 승인 재개. 라이브 근거는 F(웹 승인→텔레그램 실도착 4자 일치)와
과거 채널 왕복 전달 20건.

## ④ 감사 후속 (2026-07-29, 같은 날 닫음) — 사용자 화면 도달 + 설치 전 코드 항목

독립 감사 판정(핵심 투영 통과 · 화면 미도달 차단 · P-OP-7 선행 조건 미충족)을 그대로 반영했다.

1. **연결 패널이 `invalidDeclared` 를 실제로 소비한다** — 도구함(연결) 패널 맨 아래
   "지금은 붙일 수 없는 서비스" 절: 서비스 이름 + 이유(사람 말) + **정리** 버튼
   (`POST /connectors/declared/remove` — 사용자가 만든 것은 사용자가 거둔다).
   화면 확인: 무효 선언 주입 → 패널에 이유와 함께 표시 → 정리 클릭 → 저장소·표면 모두
   제거 확인. 반대시험: 정리 후 진실 표면 invalidDeclared 0 · 저장소 0.
2. **기억 지문 HMAC** — 원장 digest 를 로컬 비밀키(0600, `memory-ledger.key`) HMAC 으로.
   같은 문장이라도 자리(키)가 다르면 지문이 다르다(사전 대입 불가) · 같은 자리의 수명주기
   연결은 유지 · 평문 sha256 절단과 불일치 검사.
3. **단일 writer 강제** — `acquireWriterLock`: 라이브 부팅이 데이터 디렉터리 잠금을 잡고,
   살아 있는 다른 서버가 있으면 사람 말로 정직하게 멈춘다. 죽은 잠금은 pid 생존 확인으로
   스스로 걷는다. SIGINT/SIGTERM 에서 해제.
