- **T5 ↔ Hermes(같은 모델 · 주축): `other_better`** — 둘 다 실물을 냈지만 **Hermes 의 숫자가
  맞고 T5 의 숫자가 틀렸다.** T5 는 네 파일을 다 읽고도(read 4회) 실물에는 매출정산만 실었다.
  판 ⑫ 의 알려진 얼굴(범위 선택)이 **비교에서 패배로 드러난 첫 자리**다.
- T5 ↔ OpenClaw(모델 다름 · 보조): `t5_better` — T5 는 실물을 냈고 OpenClaw 는 0개.

**위 표의 "OpenClaw 실물 0개 · 과업 미완"은 사실이 아니었다.** 실물은 방이 아니라
**오너 실제 바탕화면**에 생겼다:

- 원인(기계 확인): HOME·OPENCLAW_STATE_DIR·CONFIG_PATH·workspace·cwd 전부 방으로 줘도
  임베디드(codex 하네스)가 실제 홈에 행동한다. 제품 문서도 같은 말을 한다 —
  *"workspace 는 기본 cwd 일 뿐 하드 샌드박스가 아니다. 샌드박스를 켜지 않으면 절대경로로
  호스트 어디든 닿는다."* 재현 프로브: `openclaw-config/probe-2026-08-08T16-51-43-617Z.json`
  (확인.txt 가 오너 실제 Desktop 에 생김 — 실물은 `openclaw-config/probe-실물-확인.txt` 로 격리).
- 따라서 R1 OpenClaw 는 "거짓 성공"이 아니라 **측정 하네스의 격리 불성립**이다. 위
  "T5 ↔ OpenClaw: t5_better" 초안은 **철회하고 `not_comparable`(격리 불성립) 로 정정**한다.
- 방밖 실물 파일은 오너 바탕화면에 그대로 있다(이동 시도는 권한 차단) — **처분은 오너 몫.**
