# 동의 시트 프로브 — 스윕 2번 판정 근거 (같은 창 · 사람 개입 0)

목적: 우리 코드의 **시트 클릭 갈래를 걷어도 되는가**를 벤더 실측으로 가른다.
조건: 오너가 시트를 누르지 않기로 약속된 창 · 우리 클릭 0 · 크롬 pid 1466 · 카드 창 96.

```
프로브 1(세션 없이 — 우리 코드와 같은 조건)
  → "session 'gpao-t5' has ended; tool call 'browser_prepare' was rejected."
프로브 2(start_session 선언 뒤)
  → { "status": "refused",
      "refusal": { "code": "browser_consent_required",
        "message": "existing-profile attachment in standard mode requires
                    --grant existing-profile or an embedding authorization host;
                    bounded mode requires a matching manifest",
        "detail": { "authorization_required": true, "legacy_approval_enabled": false,
                    "permission_mode": "standard", "authorization_host": null } } }
```

## 가른 것 — 세 줄

1. **드라이버는 동의 시트를 띄우지 않는다.** standard 모드에서는 **요청 자체를 거절**한다
   (`refused` · 시트 없음). 우리 코드가 기다리던 *"원격 디버깅을 허용하시겠습니까?"* 시트는
   **이 경로에서 아예 뜨지 않는다** — 그러니 그 클릭 갈래는 **닿을 일이 없는 코드**다.
2. 정본은 `--grant existing-profile`(serve 인자)이나 embedding authorization host 다 —
   `legacy_approval_enabled: false` 가 옛 approval_token 통로가 닫혔음을 함께 말한다.
3. 우리가 시트를 눌러 붙이던 그림은 **드라이버 구버전/다른 모드의 것**이고, 지금 장착
   (앱 데몬 · standard)에서는 성립하지 않는다.

## 스윕 2번 판정 요청 (PM)

- **시트 클릭 갈래 제거는 안전하다** — 이 실측 기준으로 그 갈래는 도달 불가다. 제거해도
  "한국어 시트에서 붙기가 막힌다"는 우려는 성립하지 않는다(붙기는 시트가 아니라 grant 로 막힌다).
- 다만 **제거해도 기본 켬이 곧바로 서지는 않는다**: existing-profile 붙기 자체가 standard
  모드에서 거절이라, 기본 켬은 "붙기"가 아니라 **화면 관찰 범위**에서만 뜻이 있다(2026-08-09
  크롬 확인에서 로그인 화면이 화면 손으로 읽힌 그 자리). 즉 스윕 2번은 둘로 갈린다:
    (a) 시트 클릭 갈래 제거 — 지금 가능(도달 불가 코드 제거 · 봉인 근거 소멸)
    (b) CDP 붙기(탭 목록·JS 렌더 뒤 본문) — `--grant existing-profile` 로 데몬을 띄우는
        장착 결정이 필요. **오너 기계의 자동 시작 설정을 건드리는 일**이라 오너 판단 자리.
