# T5 FAQ — 이미 AI 에이전트가 많은데, 왜 T5인가요?

상태: 사용자 안내문

현재 범위 기준일: 2026-08-23

이 문서는 T5와 다른 에이전트 중 무엇을 써야 할지 판단하려는 사람을 위한 쉬운 안내문입니다.
제품 정의는 [T5-PRODUCT](../T5-PRODUCT.md), 현재 개발·검증 상태는
[T5-REFOUNDATION](../T5-REFOUNDATION.md)이 정본입니다.

## 먼저, 30초 답변

T5는 **기능을 골라 쓰는 AI 도구**보다 **나의 목적을 듣고 필요한 수단을 골라 실제로 끝내는 개인 AI
운영체제**를 지향합니다.

OpenClaw와 Hermes는 넓은 도구 생태계와 확장성이 강하고, Codex와 Claude Code는 개발자의 코드 작업에
매우 강합니다. T5는 이들이 부족해서 만든 제품이 아닙니다. 이들의 강한 모델·터미널·웹·브라우저·연결
기술을 일반 사용자가 내부 구조를 배우지 않고도 한 사람에게 일을 맡기듯 쓰게 만드는 것이 T5의 출발점입니다.

가장 짧게 구분하면 다음과 같습니다.

| 제품 | 중심에 놓인 경험 | 특히 잘 맞는 사람과 일 |
| --- | --- | --- |
| T5 | 평소 말로 목적을 맡기고, 필요한 손의 선택·전환·확인까지 위임 | 여러 앱·웹·파일을 오가며 실제 일을 끝내고 싶은 일반 사용자 |
| OpenClaw | 폭넓은 개인 비서 기능, 채널, 플러그인과 자동화의 구성 | 다양한 연결을 직접 구성해 강력한 개인 에이전트를 운영하려는 사용자 |
| Hermes Agent | 폭넓은 도구·모델·터미널 환경을 조합하는 확장형 에이전트 | 기술 설정을 감수하고 많은 도구와 실행 환경을 조합하려는 사용자 |
| Codex | 코드베이스를 이해하고 수정·검사하는 소프트웨어 작업 | 개발, 코드 리뷰, 저장소 조사와 반복적인 엔지니어링 작업 |
| Claude Code | 터미널 중심의 코딩 루프와 개발 확장 체계 | 코드 작성·수정·명령 실행을 중심으로 일하는 개발자 |

이 표는 우열표가 아닙니다. 같은 기반 능력이 많아도 **누가 도구를 이해하고 조립해야 하는가**, **무엇을
완료로 인정하는가**, **사용할수록 누구에게 맞춰지는가**에서 제품의 중심이 달라집니다.

## 1. T5는 정확히 무엇인가요?

T5는 사용자가 에이전트, 모델, 도구, 스킬, MCP, 프롬프트, 토큰, cron, sandbox 같은 말을 몰라도 쓰는
개인 AI 운영체제를 목표로 합니다.

사용자는 “검색해 줘”나 “브라우저 도구를 켜 줘”보다 원하는 결과를 말합니다. T5는 현재 현실을 확인하고,
터미널·파일·웹·브라우저·외부 서비스·기억·스킬 가운데 필요한 수단을 골라 실행하고, 결과를 다시 확인한 뒤
답합니다.

> 사용자는 T5를 배우지 않는다. T5가 사용자를 배우고, 사용자가 평소 말로 목적을 말하면 T5는 컴퓨터와
> 외부 자원을 활용해 실제로 끝낸다.

## 2. 이미 좋은 에이전트가 많은데 왜 새로 만들었나요?

기존 에이전트는 이미 대단히 많은 일을 할 수 있습니다. 그러나 강한 능력을 실제 생활에 쓰려면 사용자가
도구 이름, 연결 방식, 권한, 실행 환경과 실패 복구를 어느 정도 이해해야 하는 경우가 많습니다. 개발자는
로그·터미널·Git·테스트를 보고 결과를 확인할 수 있지만, 일반 사용자는 AI의 “완료했습니다”를 다시 검사할
방법이 부족합니다.

T5는 여기서 다른 질문을 합니다.

> 사용자가 AI를 잘 다루는 법을 배워야 하는 것이 아니라, 시스템이 사용자의 목적과 현실을 이해하고
> 필요한 수단의 선택·복구·검증까지 맡을 수는 없을까?

따라서 T5가 새로 만드는 핵심은 도구 목록 하나가 아닙니다. **목적을 놓치지 않는 실행 구조**, **실제로
일어난 것만 말하는 구조**, **필요한 순간에만 묻는 권한 구조**, **대화와 작업이 이어지는 구조**입니다.

## 3. 일반 챗봇과는 무엇이 다른가요?

챗봇은 보통 좋은 답을 만드는 데 중심이 있습니다. T5는 답변 요청도 처리하지만, 사용자의 말을 현실에서
끝내야 할 일로 볼 수 있습니다.

```text
사용자 목적
→ 현재 파일·웹·앱·대화 상태 확인
→ 적절한 수단 선택과 실행
→ 결과와 외부 효과 확인
→ 부족하면 다른 수단으로 전환
→ 실제 달성·부분 달성·현재 불가능을 구분해 답변
```

예를 들어 파일을 만들었다는 모델의 문장, 명령이 실행됐다는 사실, 파일이 실제로 생긴 사실, 그 파일이
사용자의 목적에 맞는다는 판단은 서로 다른 단계입니다. T5는 이들을 하나의 막연한 `성공`으로 합치지
않도록 설계합니다.

## 4. OpenClaw와 무엇이 다른가요?

OpenClaw는 웹·브라우저·메모리·스킬·예약 작업·여러 채널을 폭넓게 제공하는 강력한 개인 에이전트
플랫폼입니다. 많은 기능을 연결하고 세밀하게 구성하려는 사람에게 큰 장점이 있습니다.

T5의 차이는 기능 수 경쟁보다 사용자 역할에 있습니다. T5에서는 사용자가 플러그인과 도구 조합을 먼저
설계하는 대신 목적을 말하고, 시스템이 현재 가능한 손을 찾고 필요한 경우 준비한 뒤 원래 일을 이어가는
경험을 목표로 합니다. 또한 요청·허용·실행·실제 효과·목적 달성을 별도로 남기는 것을 코어 계약으로 둡니다.

**OpenClaw가 더 잘 맞을 수 있는 경우:** 지금 당장 폭넓은 채널과 플러그인을 직접 구성해 운영하고 싶을 때.

**T5가 더 잘 맞을 수 있는 경우:** 내부 구성을 배우기보다 평소 말로 여러 종류의 일을 맡기고 싶을 때.

## 5. Hermes Agent와 무엇이 다른가요?

Hermes Agent는 웹 검색, 브라우저 자동화, 터미널, 파일 편집, 메모리, 하위 에이전트, 예약 작업, MCP 등
폭넓은 도구를 제공하고 도구 묶음과 터미널 백엔드도 구성할 수 있는 확장형 에이전트입니다.

T5는 넓은 도구 레지스트리 자체보다 “현재 이 사용자 목적에 무엇이 필요한가”를 중심에 둡니다. 필요한
능력만 노출·준비하고, 준비 과정 때문에 원래 부탁이 끊기지 않으며, 효과가 확인된 방법만 재사용하는
방향입니다. 사용자가 도구 묶음을 고르고 관리하는 부담을 줄이는 것이 중요한 제품 차이입니다.

**Hermes가 더 잘 맞을 수 있는 경우:** 여러 모델·도구·실행 환경을 직접 조합하고 확장하는 자유가 중요할 때.

**T5가 더 잘 맞을 수 있는 경우:** 조합의 자유보다 한 대화에서 목적이 자연스럽게 끝나는 경험이 중요할 때.

## 6. Codex와 무엇이 다른가요?

Codex는 코드베이스를 읽고, 파일을 수정하고, 명령과 테스트를 실행하며, 여러 개발 작업을 병렬로 진행하는
소프트웨어 엔지니어링 에이전트입니다. 스킬·플러그인·MCP·예약 작업·터미널·샌드박스도 갖추고 있지만
제품의 가장 강한 중심은 코드 작업입니다.

T5는 개발자가 아닌 사람의 일상과 업무 전체를 중심에 둡니다. 고객 자료 정리, 여러 출처 조사, 로그인한
웹 업무, 첨부 파일 분석, 결과 문서 생성처럼 코드가 아닌 목적에서도 사용자가 내부 도구를 선택하지 않게
하는 것이 목표입니다.

**Codex가 더 잘 맞을 수 있는 경우:** 저장소 구현, 버그 수정, 리팩터링, 테스트, 코드 리뷰가 주된 일일 때.

**T5가 더 잘 맞을 수 있는 경우:** 코딩 여부와 관계없이 파일·웹·앱을 넘나드는 개인 업무를 한 조력자에게
계속 맡기고 싶을 때.

개발자는 둘을 함께 써도 됩니다. Codex를 개발 작업의 전문 도구로 쓰고, T5를 개인 업무 전반의 운영자로
쓰는 구분도 자연스럽습니다.

## 7. Claude Code와 무엇이 다른가요?

Claude Code는 터미널에서 작동하는 에이전트형 코딩 도구입니다. 코드와 파일을 읽고 수정하며 명령을
실행하고, 체크포인트·권한·세션 재개와 스킬·MCP·훅·하위 에이전트 확장을 제공합니다. 명령줄에서 할 수
있는 조사와 문서 작업에도 폭넓게 쓸 수 있지만 기본 출발점은 개발자의 작업 환경입니다.

T5는 터미널을 중요한 손으로 사용하되 터미널 자체를 사용자 경험으로 요구하지 않습니다. 일반 사용자가
개발 설정 파일이나 확장 구조를 관리하지 않고, 대화 안에서 로그인·연결·실행·확인·재개를 경험하게 하는
것이 차이입니다.

**Claude Code가 더 잘 맞을 수 있는 경우:** 터미널과 코드가 일의 중심이고 개발 워크플로를 세밀하게
확장하고 싶을 때.

**T5가 더 잘 맞을 수 있는 경우:** 터미널을 몰라도 컴퓨터의 힘을 이용해 자신의 일을 끝내고 싶을 때.

## 8. 그러면 T5가 다른 제품보다 더 좋은가요?

모든 면에서 그렇다고 주장하지 않습니다.

- 순수 코딩 작업은 Codex나 Claude Code가 더 직접적이고 성숙한 선택일 수 있습니다.
- 당장 가장 넓은 플러그인·채널·도구 구성이 필요하면 OpenClaw나 Hermes가 더 적합할 수 있습니다.
- T5가 아직 실제 기기나 실제 계정에서 검증하지 않은 환경이라면 검증된 다른 도구를 쓰는 편이 낫습니다.

T5가 이기려는 기준은 기능 개수가 아니라 다음 네 가지의 곱입니다.

1. 실제로 해내는 힘
2. 사용자가 내부 구조를 배우지 않고 그 힘을 꺼내는 자연스러움
3. 사용할수록 사용자의 사실·선호·진행 중인 일을 정확히 이어가는 지속성
4. 필요한 능력만 준비하고, 효과가 없으면 멈추거나 바꾸는 적응성

이 기준도 선언으로 달성됐다고 보지 않습니다. 실제 사용자 과업에서 계속 비교하고 검증해야 합니다.

## 9. T5는 지금 무엇을 할 수 있나요?

현재 측정된 macOS 콘솔 환경에서는 다음 순환이 실제로 연결돼 있습니다.

- 평소 말로 부탁하고 대화를 이어가기
- 로컬 파일과 폴더 확인, 터미널 명령 실행, 과정이 긴 작업 제어
- 웹 검색·링크 읽기·여러 출처 조사
- 정적 읽기가 어려운 동적·로그인 웹을 T5 전용 브라우저로 확인
- 사용자가 보이는 창에서 직접 로그인한 뒤, 비밀번호를 모델에 주지 않고 같은 로그인 상태 사용
- 파일 직접 첨부, 문서·이미지·표 데이터의 지원 범위 안 분석
- 결과 파일 생성, 다시 열어 검증, 콘솔에서 다운로드
- 대화·재시작을 넘어 명시된 기억과 진행 상태 이어가기
- 검증된 스킬·CLI·일부 외부 연결을 필요할 때 찾고, 원래 목적 재개
- 예약 작업 생성·실행·중지·재개·취소와 재시작 복원

“할 수 있다”는 말은 모든 사이트·형식·계정에서 무조건 성공한다는 뜻이 아닙니다. 사이트 차단, 로그인,
외부 서비스 정책, 파일 형식과 현재 연결 상태에 따라 일부 완료나 현재 불가능으로 끝날 수 있습니다.

## 10. 사용자가 터미널·MCP·스킬을 알아야 하나요?

원칙적으로는 아닙니다. 사용자는 수단보다 목적을 말하면 됩니다.

- “`web_read`로 이 URL을 읽어 줘”보다 “이 업체가 실제로 오늘 영업하는지 공식 정보와 최근 정보를
  비교해 줘”
- “스프레드시트 스킬을 써 줘”보다 “이 매출 파일 둘을 합쳐 고객별 합계가 있는 엑셀로 만들어 줘”
- “MCP를 붙여 줘”보다 “내 노션의 지난 회의 결정을 찾아 이번 계획에 반영해 줘”

필요한 연결이나 로그인이 있으면 T5가 그 대화에서 준비 단계를 열고, 사용자가 해야 하는 한 가지 행동만
알린 뒤 원래 부탁을 이어가는 것이 목표입니다.

## 11. 권한은 매번 물어보나요?

T5는 모든 행동마다 승인을 받는 방식을 목표로 하지 않습니다. 사용자의 명시적 목적과 범위 안에서 되돌릴
수 있는 확인·분석·준비·실행은 자동성을 우선합니다. 기본적으로 멈춰 묻는 경계는 네 가지입니다.

1. 비밀값 입력
2. 백업 없는 파괴
3. 새로운 상대에게 보내는 첫 외부 전송
4. 돈이 나가는 일

이 밖에도 현재 효과를 확실히 알 수 없는 외부 쓰기처럼 안전하게 재시도할 수 없는 상황에서는 실행을
꾸며내거나 반복하지 않고 멈출 수 있습니다.

## 12. 비밀번호와 로그인 정보도 T5가 보나요?

T5의 관리 브라우저에서 로그인이 필요하면 사용자가 눈앞의 창에 비밀번호와 OTP를 직접 입력합니다. 모델은
그 값을 전달받지 않고, 로그인 뒤 실제 화면만 계속 사용합니다.

현재 허용된 경계도 있습니다. 앱을 완전히 종료한 뒤 서비스가 세션 전용 로그인을 끝내면 다시 로그인해야
할 수 있습니다. CAPTCHA 우회, 자동 2단계 인증, 계정 복구를 T5의 능력으로 주장하지 않습니다.

## 13. 기억과 자가학습은 어떻게 다른가요?

T5는 사용자를 하나의 고정된 성격이나 직업으로 단정하지 않습니다.

- **기억**은 사용자가 말한 사실·선호·결정입니다.
- **과거 경험**은 실제로 무엇을 했고 어떤 결과가 났는지입니다.
- **스킬**은 기존 수단을 더 잘 쓰는 재사용 가능한 방법입니다.
- **학습**은 새 방법을 즉시 정답으로 덮어쓰는 것이 아니라 제안·시험·비교·승격·교체·폐기하는 과정입니다.

사용자가 직접 말한 사실과 T5의 잠정적 추론을 같은 기억으로 합치지 않고, 현재 사용자의 교정이 과거의
기억과 방법보다 우선해야 합니다. 사용자는 대화로 기억을 확인·수정·삭제할 수 있어야 합니다.

현재 T5에는 명시적 기억과 검증된 스킬 재사용이 있지만, 무엇이든 스스로 배우고 코어를 마음대로 고치는
무제한 자가학습이나 스킬 마켓을 완성 기능으로 열어 두지는 않았습니다.

## 14. 누가 T5를 쓰면 좋은가요?

특히 다음과 같은 사람을 위해 만들고 있습니다.

- 파일·웹사이트·메신저·업무 서비스를 오가지만 개발 도구를 배우고 싶지는 않은 사람
- 조사 결과만이 아니라 정리된 파일, 확인된 상태, 실제 실행까지 맡기고 싶은 사람
- 같은 설명을 매번 반복하지 않고 이전 결정과 자신의 방식을 이어가고 싶은 사람
- AI가 무엇을 했는지, 무엇은 못 했는지 정직하게 구분하는 것을 중요하게 보는 사람
- 자영업자, 프리랜서, 운영자, 기획자, 연구자처럼 종류가 다른 작은 일을 한 곳에서 이어가는 사람

직업으로 사용자를 고정하지는 않습니다. 개발자도 코딩 밖의 개인 업무를 맡기는 용도로 사용할 수 있습니다.

## 15. 언제는 T5를 고르지 않는 편이 좋은가요?

다음 조건이 가장 중요하다면 현재는 다른 선택이 더 좋을 수 있습니다.

- 거의 모든 일이 코드 저장소 안에서 일어난다: Codex 또는 Claude Code
- 매우 많은 플러그인·채널·홈 자동화 연결을 지금 직접 구성해야 한다: OpenClaw 또는 Hermes
- Windows나 Linux 실제 기기에서 검증된 전체 사용자 경험이 반드시 필요하다
- 앱이 꺼져 있어도 장애 복구되는 상시 백그라운드 에이전트가 필요하다
- T5가 아직 지원하지 않는 특정 서비스·파일 형식·미디어 분석이 업무의 핵심이다
- 다중 에이전트 조직이나 원격 스킬 마켓을 즉시 운영해야 한다

## 16. 지금 T5의 솔직한 한계는 무엇인가요?

- 현재 전체 사용자 순환은 macOS/POSIX 콘솔 환경에서 가장 많이 검증됐습니다. Windows 실제 기기의
  터미널·프로세스 종료·파일 선택·다운로드 경험은 아직 완료로 판정하지 않습니다.
- 앱의 비정상 종료 뒤에도 장기 작업이 자동 복구되는 상시 실행 구조는 아직 제품 약속이 아닙니다.
- OpenClaw나 Hermes처럼 넓은 연결·채널 생태계를 이미 갖춘 상태는 아닙니다.
- DOCX·PPTX 내용 추출, 음성·영상 장면 이해, OCR·손글씨·복잡한 PDF 표와 일부 압축 형식은 아직 제한됩니다.
- YouTube 자막 분석은 가능한 경우가 있지만 고속 영상 분석으로 홍보할 수준은 아닙니다.
- 생산 계정의 모든 외부 쓰기와 모든 사이트를 자동 시험한 것은 아닙니다. 효과가 불명확한 외부 쓰기는
  재시도하지 않고 `결과 불명확`으로 남길 수 있습니다.
- 일반 사용자를 위한 경험과 내부 구조는 계속 실제 사용 실패를 근거로 다듬는 중입니다. T5는 완성된 모든
  기능의 백화점이 아니라, 검증된 범위를 넓혀 가는 제품입니다.

## 17. 어떻게 부탁하면 가장 잘 쓸 수 있나요?

도구 이름 대신 네 가지만 평소 말로 알려주면 좋습니다.

1. **원하는 결과:** 마지막에 무엇이 생기거나 달라져야 하는지
2. **쓸 자료:** 파일·링크·대화·서비스 가운데 무엇을 참고할지
3. **중요한 조건:** 날짜, 예산, 형식, 판단 기준
4. **넘지 말아야 할 선:** 보내지 말 것, 지우지 말 것, 결제하지 말 것

예시는 다음처럼 간단해도 됩니다.

> 지난 견적서 두 개와 오늘 받은 주문 파일을 합쳐서, 고객별 합계와 미확인 항목이 보이는 엑셀을 만들어 줘.
> 원본은 바꾸지 마.

> 이 병원에 부모님을 모시고 갈지 판단하려고 해. 공식 정보와 최근의 신뢰할 만한 출처를 함께 확인하고,
> 확인되지 않은 부분은 따로 표시해 줘.

> 내 노션의 지난 회의 결정을 찾아 이번 주 실행 목록으로 정리해 줘. 누구에게도 보내지는 말고 초안만 보여 줘.

## 18. 결국 T5를 한 문장으로 고르면요?

**코드 작업의 전문 에이전트나 직접 조립하는 에이전트 플랫폼이 아니라, 내 말을 이해하고 컴퓨터와 외부
자원을 골라 쓰며 결과까지 확인하는 한 명의 개인 조력자를 원할 때 T5를 선택합니다.**

다만 현재 지원 범위보다 필요한 일이 더 크다면, 그 일을 이미 검증한 다른 도구를 선택하는 것이 맞습니다.
T5의 목표는 다른 에이전트의 존재를 부정하는 것이 아니라, 그 강한 능력을 일반 사용자가 배우지 않고도
믿고 맡길 수 있는 경험으로 만드는 것입니다.
