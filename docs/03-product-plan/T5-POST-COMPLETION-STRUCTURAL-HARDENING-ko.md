# T5 완성 후 구조 건전화 작업

- 상태: `RESERVED_POST_COMPLETION`
- 성격: 현재 기능 개발과 분리된 행동 보존형 구조 정리
- 착수 시점: T-cell, H 검증·보완, 지정 후속 기능, 전체 제품 마감과 완성 기준선 봉인 이후
- 현재 개발 차단 여부: 없음

## 1. 목적

T5의 첫 완성본을 기준선으로 고정한 뒤, 사용자 행동과 저장된 진실을 훼손하지 않으면서 코드 구조를
더 단순하고 명확하게 만든다. 이 작업은 기능 재개발이나 정책 변경이 아니다. 이후 수정·보강·진화를
더 빠르고 안전하게 하기 위한 별도 구조 건전화 작업이다.

## 2. 착수 조건

아래 조건이 모두 충족되기 전에는 이 작업을 열지 않는다.

1. T-cell 구현과 H단계 검증·보완이 끝났다.
2. 스킬·크론·에이전트·자동화와 한국 사장님용 도구 등 지정 후속 작업이 끝났다.
3. 최소 안전·최대 자동화 관점의 전체 제품 마감이 끝났다.
4. 실제 모델·화면·파일·원장·복구를 포함한 T5 완성 기준선이 봉인됐다.
5. 정리 전후를 비교할 인간 시나리오와 측정값이 남아 있다.

완성 기준선 이전에 구조 정리가 꼭 필요한 경우에는 현재 결함을 닫는 최소 범위만 허용한다. 이 문서를
근거로 현재 기능 개발을 멈추거나 광범위한 리팩터링을 시작하지 않는다.

## 3. 작업 범위

1. 큰 파일과 복잡한 흐름의 책임을 제품 경계에 맞게 분리한다.
2. 기억·입장·승인·상태·표면의 중복 판정을 제거하고 공통 진실을 한 곳에서 판정한다.
3. 서버 조립, 제품 판단, 저장, 실행, 사용자 표면의 책임을 구분한다.
4. 활성 소스를 변조하거나 다른 검증과 충돌할 수 있는 검사 도구를 격리한다.
5. 저장 형식·세션·원장·복구의 이전 데이터 호환성과 이행 경로를 정비한다.
6. 죽은 코드, 중복 검사, 낡은 주석, 더 이상 쓰이지 않는 임시 호환 경로를 증거와 함께 제거한다.
7. 새 개발자와 에이전트가 전체 구조와 단일 진실의 위치를 빠르게 이해할 수 있는 구조 지도를 만든다.

## 4. 절대 보존 조건

다음은 구조 정리의 대상이 아니다.

- 말귀와 모델의 자연스러운 판단 능력
- 최소 안전·최대 자동화 원칙
- 카드·질문·클릭·대기 시간의 현재 기준선
- 파일·웹·앱·터미널·커넥터·에이전트 실행 능력
- 기억·맥락·학습·성장의 실제 사용자 효과
- 승인·권한·원장·복구의 안전 경계
- 기존 사용자 데이터와 세션의 읽기·복원 가능성

## 5. 금지

- 기능 추가와 구조 정리를 한 변경에 섞지 않는다.
- 승인 정책, 모델 지시, 사용자 문구를 구조 정리라는 이름으로 바꾸지 않는다.
- 여러 책임을 한 번에 전면 재작성하지 않는다.
- 저장 형식을 바꾸면서 이전 데이터 이행과 복구 증거를 생략하지 않는다.
- 자동화 테스트 통과만으로 사용자 행동 보존을 주장하지 않는다.
- 코드 줄 수 감소나 파일 수 감소를 성공 지표로 삼지 않는다.

## 6. 실행 원칙

1. 완성 기준선의 사용자 행동과 내부 불변식을 먼저 동결한다.
2. 한 번에 한 책임 또는 한 중복 판정 계열만 정리한다.
3. 각 변경은 독립적으로 되돌릴 수 있는 크기로 유지한다.
4. 정리 전후에 같은 입력, 모델 공급 사실, 실행 계획, 승인, 저장 상태, 원장, 복구 결과를 비교한다.
5. 기존 데이터 fixture와 실제 사용자 경로를 함께 검증한다.
6. 구조 변경마다 단위·통합·전체 회귀·돌연변이·라이브 인간 시나리오를 위험에 비례해 실행한다.
7. 더 단순해졌다는 주장은 책임 수, 중복 판정 수, 의존 방향, 변경 영향 범위로 증명한다.

## 7. 필수 산출물

- 정리 전 T5 완성 기준선과 재현 절차
- 7개 코어 기준 책임·의존 구조 지도
- 중복 판정과 다중 진실 위치 목록
- 저장 형식 호환·이행·복구 계획
- 단위별 구조 변경 기록과 되돌림 경로
- 정리 전후 행동 동등성 보고서
- 실제 모델·화면·파일·원장·복구 재검증 증거

## 8. 완료 조건

1. 동일한 사용자 시나리오에서 목표 달성률과 말귀가 유지되거나 개선된다.
2. 질문·카드·클릭·대기 시간이 증가하지 않는다.
3. 기존 기억·세션·원장·복구 데이터가 손실 없이 이어진다.
4. 공통 상태를 서로 다르게 판정하는 활성 경로가 남지 않는다.
5. 전경과 후경, 판단과 실행, 제품 상태와 표면의 책임 경계가 코드에서 식별된다.
6. 전체 회귀와 구조 검사가 통과하고, 실제 인간 시나리오에서도 행동 보존이 확인된다.
7. 구조 정리 때문에 새 승인·제약·사용자 관리 부담이 생기지 않는다.

이 조건이 닫힌 뒤부터 T5의 수정·보강·진화는 정리된 구조를 새 기준선으로 사용한다.

## 별첨 A. JavaScript 중심 코어와 언어 확장 원칙

### A.1 기본 판정

T5가 JavaScript 중심으로 이루어졌다는 사실은 그 자체로 결함이나 기술적 열세가 아니다. T5 코어의 주요
책임은 모델 응답, 파일·웹·앱·터미널·커넥터 호출, 세션·기억·원장 저장, 비동기 작업 조정처럼 I/O 중심이다.
Node.js와 JavaScript는 이 영역에 적합하며, 단일 실행 계층과 적은 런타임 의존성은 설치·복구·배포·감사
범위를 단순하게 만든다.

구조 건전화는 언어 수를 늘리는 작업이 아니다. JavaScript 코어를 기본값으로 유지하고, 실제로 확인된
필요가 있을 때만 해당 책임을 다른 언어의 격리된 모듈로 추가한다.

### A.2 JavaScript 코어가 계속 소유할 책임

- 대화와 턴 조정
- Selfhood와 현재 실행 현실 조립
- Intent·Context·T-cell의 운영 흐름
- ActionPlan과 Authority 경계
- Truth Ledger, 기억 상태, 복구 계약
- 사용자 표면과 커넥터 조정
- 다른 프로세스·도구·에이전트의 호출과 결과 수용

### A.3 다른 언어를 검토할 수 있는 조건

아래 중 하나가 실행 증거로 확인될 때만 언어 확장을 검토한다.

1. 대규모 문서·이미지·영상·임베딩·벡터 계산처럼 CPU 병목이 반복 측정된다.
2. JavaScript에서 안정적으로 사용할 수 없는 운영체제 전용 API가 제품 성공에 필수다.
3. 보안·안정성 때문에 코어와 강하게 격리된 실행기가 필요하다.
4. 검증된 전문 라이브러리를 재구현하는 비용과 위험이 별도 모듈 유지 비용보다 크다.
5. Worker·별도 프로세스 등 JavaScript 안의 단순한 해법으로는 요구 성능이나 장애 격리를 충족하지 못한다.

“다른 제품이 쓴다”, “더 전문적으로 보인다”, “파일이나 언어가 많아야 강해 보인다”는 도입 근거가 아니다.

### A.4 권장 확장 형태

필요가 확인되면 T5 전체를 다시 쓰지 않고 역할이 한정된 손발로 붙인다.

| 필요 | 검토 가능한 형태 |
|---|---|
| 무거운 AI·데이터·문서 처리 | Python 보조 프로세스 |
| 높은 성능·격리·장기 실행기 | Rust 또는 Go 서비스·실행기 |
| macOS의 깊은 시스템·앱 제어 | Swift 어댑터 |
| 외부 도구·에이전트 연결 | MCP, JSON-RPC, 표준 입출력 계약 |

언어 간 경계는 구조화된 요청·응답, 명시적 타임아웃, 실패 상태, 재시도·중단 규칙, 권한 범위, 영수증을
가져야 한다. 보조 프로세스가 실패하거나 설치되지 않아도 T5 코어의 대화·상태·복구가 오염되지 않아야 한다.

### A.5 언어 확장 전 필수 질문

1. 실제 사용자 문제와 측정된 병목은 무엇인가?
2. JavaScript 내부의 더 단순한 해법으로 닫을 수 없는가?
3. 새 언어가 추가하는 설치·보안·업데이트·복구 비용은 얼마인가?
4. 실패했을 때 코어가 정상적으로 축소 동작할 수 있는가?
5. 기존 데이터·권한·원장·사용자 흐름을 그대로 보존하는가?
6. 해당 모듈을 독립적으로 교체·비활성화·되돌릴 수 있는가?

### A.6 금지

- 측정된 병목 없이 유행이나 인상을 이유로 언어를 추가하지 않는다.
- 구조 건전화와 전체 언어 전환을 묶지 않는다.
- T5 코어 전체를 다른 언어로 일괄 재작성하지 않는다.
- 언어별로 기억·권한·원장·상태의 별도 진실을 만들지 않는다.
- 외부 프로세스에 원시 비밀이나 코어 전체 권한을 기본 제공하지 않는다.
- 보조 모듈의 성공을 코어가 검증 없이 사실로 받아들이지 않는다.

### A.7 완료 판정

언어 확장은 파일 수나 벤치마크 한 건으로 판정하지 않는다. 실제 사용자 흐름에서 필요한 능력·성능·격리가
개선되고, 설치·실패·업데이트·복구 경로가 닫히며, JavaScript 코어의 단순성과 단일 진실이 보존돼야 한다.
이 기준을 충족하지 못하면 언어 확장을 채택하지 않는다.
