# T5 공장 도달표 — 전원을 켜면 어디까지 도는가 (PM 전수 감사 · 2026-08-11)

오너 지시: *"공장이라면 전원 버튼을 눌렀을 때 정상 가동되도록 설비·배선·동력·도구가 다
연결돼 있는지 파악하라. 결핍 목록을 만들고, 실패·회피·포기가 불가능한 조건을 먼저 세운 뒤
전부 해결하라."*

**이 문서는 새 계획서가 아니다.** 계획서(`design/T5-PLAN.md`)의 노드를 대체하지 않고,
**한 장짜리 도달 대조표**로 그 노드들과 장부 항목을 하나의 그림에 놓는다. 채점 전 동결 대상.

---

## 0. 재는 자 — 「도달」의 정의 네 칸

만든 것과 닿은 것을 구분하는 것이 이 저장소의 가장 비싼 교훈이다(F-59). 그래서 칸마다 넷을 묻는다.

```
① 있나        코드·설비가 존재하는가
② 닿나        그 턴에 모델이 그것을 볼 수 있는가(노출)
③ 완결되나    사용자가 대화만으로 끝까지 갈 수 있는가 ← 오너 요구의 본문
④ 물리나      실경로 관통 봉인이 있는가
```

**③이 이번 감사의 핵심이다.** 오너 요구 원문: *"자연스러운 요구와 대화만으로."*

---

## 1. 공장 도면 — 일곱 영역 × 네 칸

| 영역 | ① 있나 | ② 닿나 | ③ 대화로 완결 | ④ 봉인 | 판정 |
|---|---|---|---|---|---|
| 1 자기파악(Selfhood) | O | O | △ 능력 서술은 되나 "지금 뭐 할 수 있어"는 미측정 | O | **부분** |
| 2 모델 운용 | O | O | △ 이력 12턴·4,000자 **고정값** — 창 크기를 아는 자리 없음(노드 W) | 부분 | **부분** |
| 3 Intent·기억·성장 | O | O(제안) | ✗ **기억 승격이 표면 클릭 전용** · 성장(l5-growth 20) 실사용 관측 0 | 부분 | **단절** |
| 4 Authority(경계) | O | O | O 카드 0회(과잉 차단 없음) · 단 넷 밖 정지 1건 | O | **양호** |
| 5 Execution(손) | O | O | △ 파일·터미널·웹 완결 · 화면 실물 3회 · 쓰기 경로·중첩 진입 결손 | O | **부분** |
| 6 Work Surface | O | — | ✗ **대화↔표면 왕복 단절**(제안은 뜨는데 대화로 확정 불가) · 채널 왕복 측정 0 | 부분 | **단절** |
| 7 원장·복구·성장 | O | O | O 원장·영수증 강함(F-64 조각 진행) · 성장은 미가동 | O | **부분** |

### ★ 오늘 확정된 계열 결함 — 「제안-실현 단절」

7과목 전수 실측:

```
모델이 낸 제안    자동화 2 · 기억 1 · 스킬 0 · 에이전트 0
실제로 선 것      job 0 · run 0 · 승격 기억 0
```

`automation.propose` · `memory.propose` · `skill.propose` · `agent.propose` — **네 채널 모두
후보만 만들고, 확정은 표면 라우트(사용자 클릭) 전용**이다. 즉 T5 의 성장·자동화·기억 계열
전체가 **대화만으로는 구조적으로 완결 불가**다. L6 은 그 계열의 첫 얼굴일 뿐이다.

이것이 오너가 말한 *"부분만 완성되고 전체 완성도가 안 오르는"* 구조의 정체다 — 조각을 고쳐도
**계열이 그대로**라 종합시험에서 계속 떨어진다.

## 2. 결핍 — **기관 완결성**으로 다시 센다 (오너 지시 2026-08-11)

> **"손이 있으면 손으로 할 수 있는 모든 일이 가능해야 한다. 눈이 있으면 눈으로 할 수 있는
> 모든 일이, 입이 있으면 입으로 할 수 있는 모든 일이 가능해야 한다."** *— 오너*

앞선 12개 목록은 **시험을 통과하는 조각**이었다. 그 자를 버리고 기관별 동사 완결성으로 다시 센다.
동사 인벤토리는 실측(`demo-context.js` DESCRIPTORS enum 전수).

| 기관 | 지금 가진 동사 | 그 기관이 할 수 있어야 하는데 없는 것 | 판정 |
|---|---|---|---|
| 눈 — 화면 | status · observe (2) | (없음) | **완결** |
| 손 — 화면 | focus scroll move resize launch quit click type double_click right_click drag press_key hotkey menu copy paste wait (17) | (없음 — 가장 완결된 기관) | **완결** |
| 눈 — 브라우저 | open · snapshot (2) | 텍스트 추출·요소 목록은 snapshot 안 · 탭 목록 | **부분** |
| **손 — 브라우저** | **scroll · click (2)** — 계약 원문이 *"보고 있는 화면을 더 본다"* | **타이핑 · 주소 이동 · 뒤로 · 탭 전환 · 폼 입력/제출 · 다운로드 · 로그인 후 조회** | **★부재(눈만 있고 손이 없다)** |
| 손 — 파일 | list read write move bulk_move delete undo versions (8) | (없음) | **완결** |
| 손 — 터미널/프로세스 | 자유 명령 · start status logs stop (4) | (없음) | **완결** |
| 입 — 채널 | telegram.send · slack.post · mail.send (발신) | **수신·조회**(모델이 부를 수 있는 「내 메시지 읽기」 없음) | **반쪽** |
| 손 — 확정 | (없음) | **자동화 등록 · 기억 승격 · 스킬 확정 · 에이전트 생성** — 넷 다 제안만 | **★부재** |
| 머리 — 창 | 이력 12턴·4,000자 **고정값** | 창 크기 인지 · 예산 배분(노드 W) | **부분** |
| 기억·성장 | 저장·인용·정정·철회 | 승격(위 「손-확정」) · 성장 가동 | **반쪽** |

### 결손 셋으로 요약된다 — 그리고 전부 **같은 병**이다

```
★1 브라우저 손 부재      눈은 열었는데 그 안에서 아무것도 못 한다
★2 확정하는 손 부재      제안은 하는데 확정을 못 한다 (자동화·기억·스킬·에이전트)
★3 귀(수신 조회) 부재    말은 보내는데 온 것을 못 읽는다
```

**병의 이름: 기관이 반쪽으로 배선됐다.** 관찰은 열어 두고 행위는 사람에게 남겼다 —
안전해 보이는 설계였지만, 결과는 *"눈만 있는 손"* 이고 이것이 종합시험에서 계속 떨어지는 뿌리다.
앞서 적은 D2~D12 는 이 셋 아래의 정밀 항목으로 내려간다(삭제하지 않는다 — C1 동결 유지).

## 3. 실패·회피·포기가 불가능한 조건 (착수 전 동결)

오너 지시의 핵심. 아래 일곱은 **작업 시작 전에 못박고, 진행 중 바꾸지 않는다.**

```
C1 칸 목록 동결        위 결핍 D1~D12 가 이번 프로그램의 전부다.
                       새 결핍이 나오면 장부로 가고 **다음 프로그램**이 받는다(범위 확장 금지).
                       칸을 빼는 것도 금지 — 못 하면 "기록된 한계"로 닫되 사유·재검 조건을 남긴다.

C2 부분 완성 금지      칸 하나가 초록이어도 **프로그램 완료라 말하지 않는다.**
                       완료 선언은 §4 결승선 하나로만 한다.

C3 닫는 문장 선행      칸마다 착수 전에 **사용자 문장**을 적는다("손이 생겼다"가 아니라
                       "그 문장이 다르게 끝난다"). 못 쓰면 그 칸은 아직 착수 대상이 아니다.

C4 실경로 관통 봉인    칸마다 선빨강 → 수리 → 절단으로 빨강 확인. **부품 초록은 증거가 아니다**(F-59).

C5 회귀 보존           칸을 닫을 때 기존 검사 전량이 초록이어야 한다. 검사를 고쳐서 초록을
                       만들면 그 칸은 무효(채점 기준 변경 금지).

C6 막힘 처리 규칙      같은 자리 3회 막히면 멈추고 PM 판정. PM 은 셋 중 하나만 한다 —
                       ⓐ 재설계 지시 ⓑ 기록된 한계로 닫기(재검 조건 명기) ⓒ 오너 안건 상신.
                       **조용히 넘어가기는 선택지에 없다.**

C7 독립 감사           프로그램 종료 판정은 구현한 손이 하지 않는다. 겸임이면 Dual-Role 표기 +
                       독립 재감사 전까지 "닫힘" 아님.
```

## 4. 결승선 — 이 프로그램이 끝나는 단 하나의 문장

> **동결 7과목 재시험에서 완주 7 · 거짓 0 이고, 같은 시험을 같은 모델의 헤르메스와 나란히
> 놓아 지는 과목이 0 이며, 열두 칸 전부가 ③(대화로 완결) 초록이다.**

- 이 문장 하나로만 닫는다. 부분 성적표로는 안 닫힌다(C2).
- **모델은 gpt-5.1 고정.** 모델 교체(gpt-5.5 OAuth)는 이 결승선을 통과한 **뒤에** 별도 실험으로
  돌린다 — 반쪽 상태에서 모델을 바꾸면 원인이 섞인다(오너 판단 채택).
- 미달이면 그 자체로 방향 재검토 안건이 오너에게 올라간다(접는 조건의 기계 판정면).

## 5. 순서 — 매듭부터, 조각은 그 아래로

```
1단계  D1 제안-실현 단절 (매듭)      네 채널을 한 자리에서 연다.
       설계: 확정(가역)은 모델 손으로 자동 · 실행 시점 경계는 그대로(D1 봉인 유지) ·
             안전은 카드가 아니라 표면 즉시 가시성 + 원장 + 되돌리기 한 번
       닫는 문장: "매주 월요일 아침에 지난주 정산 알려줘" 가 대화만으로 켜지고,
                  "이번 주는 쉬어" 로 멈추고, 화면에 그대로 보인다

2단계  D2·D3·D4·D5 (완료·경로 매듭)   작업셋 root 를 읽기뿐 아니라 **쓰기·중첩·완료 결속**까지
       한 원천으로 통일. 조각으로 따로 고치지 않는다
       닫는 문장: "같은 폴더에 정리해서 저장해줘" 가 자료 옆에 실물로 끝난다

3단계  D6 창 예산 · D10 화면 효과      모델 앞의 현실 정밀화(노드 W · F-60 은 오너 봉인 확인 후)

4단계  D7 채널 왕복 · D8 자기 인식     "밖에서 시켜도 그 자리로 돌아온다" · "너 뭐 할 수 있어"

5단계  D11 한계 삼단 · D12 한국어      사용자가 매일 보는 표면의 마감

6단계  D9 성장                        앞 단계가 만든 실사용 실패 이력이 입력이 된다. 마지막이 맞다
```

각 단계 종료 조건은 동일하다: **닫는 문장 + 실경로 봉인 + 회귀 보존 + 7과목 부분 재측정.**
전체 7과목 정식 재시험은 **6단계 뒤 한 번**(측정 낭비 금지 · 결승선 판정용).
