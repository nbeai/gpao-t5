## 0. 첫 다섯 문장 — 이것만은 먼저

1. **T5 는 한국 비개발자를 위한 AI 운영체제다.** 사용자가 방법이 아니라 **목적**을 말하면
   T5 가 끝까지 해낸다. 대화는 입구이지 성취가 아니다.
2. **주객이 뒤바뀌면 안 된다.** 런타임은 방·경계·진실을 소유하고, **대화와 작업 루프는 모델이
   소유한다.** 런타임이 모델 대신 판단하기 시작하면 그게 결함이다.
3. **T5 가 묻는 것은 넷뿐이다** — 비밀 입력 · 되돌릴 수 없는 파괴 · 새 상대 첫 전송 · 돈.
   나머지는 전부 자동이다. **마찰을 늘려 안전을 사면 제품이 죽는다.**
4. **절대 게이트 일곱은 언제나 0이다** — 거짓 성공 · 오대상 실행 · 승인 전 효과 · 거절 뒤 실행 ·
   중복 실행 · 현재 요청 침해 · 원장↔영수증↔실물 불일치.
5. **검사가 초록인 것과 제품이 되는 것은 다르다.** 2026-08-04 에 검사 2,336건이 전부 초록인
   상태에서 실제로 써 보니 두 시간에 결함 4개가 나왔다. **라이브로 밟지 않은 것은 모른다.**

## 4. 이 저장소에서 반복해서 틀린 것들 — **먼저 알고 시작해라**

같은 실수를 세 번째 하지 않으려고 적는다. 전부 실측으로 걸린 것이다.

**① 목록으로 짐작하면 반드시 뚫린다.**
금지 문구 목록, 허용 장식 목록, 도구 이름 목록 — 전부 한 번씩 뚫렸다. 마지막 사례는
`[ \t>*-]` 로 줄 앞 장식을 열거한 가드였는데 모델이 백틱을 쓰자 통과했다.
**구조로 판정해라**(예: "글자가 아닌 것 전부").

**② 재는 자리를 검증하지 않으면 초록인데 안 고쳐진다.**
같은 날 두 번 당했다. 한 번은 엉뚱한 배열을 재서 통과했고, 한 번은 도청 검출기가 고장난 채로
"모델 잘못"이라고 확정했다. **계측기부터 검증해라** — 반드시 잡혀야 하는 대조를 같은 실행에 넣어라.

**③ 확정 못 한 원인을 고치면 두 번 틀린다.**
가설을 세우고 고쳤는데 그대로 재현된 일이 두 번 있다. **밟아서 확정한 뒤에 고쳐라.**

**④ 검사가 결함을 축복하게 두지 마라.**
"지금 이렇다"를 통과 조건으로 적으면 다음 사람이 그것을 계약으로 읽는다.
못 고쳤으면 검사로 박지 말고 **장부에 적어라.**

**⑤ 닫을 수 있을 때 닫아라.**
결함을 쫓는 것은 값있지만, 종료 조건이 정의돼 있지 않으면 영원히 안 닫힌다.
현재 단계의 종료 조건은 인수인계 문서 「감사 인계」 절에 여섯 개로 적혀 있다.

---

**⑤ 만든 것과 닿은 것은 다르다 — 2026-08-07 하루에 여덟 번 났다.**
값을 만들고, 규칙을 쓰고, 손을 붙였는데 **소비자까지 안 이어진** 것이다. 검사는 초록인데 제품은 그대로다.

```
GPAO_T5_CUA_BIN 미점화        화면 손이 제품에 없었다
connectedTools 미전달          화면 사용법이 모델에 한 번도 안 갔다
automationProposal 미노출      예약을 만들어 놓고 모델이 몰랐다
GPAO_T5_BROWSER_PROFILE 미점화  로그인 크롬이 제품에 없었다
도구쓰는순서 **읽는 자리 0곳**   "먼저 손으로 찾아본다"가 한 글자도 안 갔다 ← 원래 끊겨 있었다
turn.js:1106 이 local.file 전용  후보를 올려도 붙는 자리가 없었다
```

**막는 법은 하나다 — 끝에서 끝까지 태우는 검사.** 단위 검사는 이걸 절대 못 잡는다.
`buildTaskContext → buildModelMessages → turn.js` 를 한 벌로 태워라.

**⑥ 선언과 강제가 다르면 사람이 선언을 믿는다.**
`F-46`: 파일 범위 선언은 넷인데 강제는 홈 전체였다. **세 사람이 차례로 속았다**
(PM 두 번, 개발 라인 한 번). 그리고 **모델도 속아서** 할 수 있는 일을 못 한다고 포기했다.
주석도 마찬가지다 — 같은 파일 안에서 두 주석이 반대로 말하고 있었다.
**밟은 것만 사실이다. 주석은 근거가 아니다.**

**⑦ 사용자에게 할 말이 모델에게 가면 모델이 그대로 되묻는다.**
2026-08-07 하루에 **세 번** 나왔다.

```
"창제목으로 짚어 주세요"            userSafeSummary
"그 폴더를 열어 주시면 바로 볼게요"   nextSafeAction
"여럿이면 짧게 보여주고 고르게 한다"  **손 설명서(schema.description) 안에**
```

**소비자별로 칸을 나눠라.** `nextSafeAction` 은 사람, `다음수단` 은 모델이다.
그리고 **손 설명서도 모델이 읽는 자리다** — 거기 "사용자에게 물어라"를 쓰지 마라.

## 5. 역할 경계

- **개발**은 구현자가 한다. 벽을 만나면 뚫고, 인접 문제를 발견하면 장부에 적는다.
- **종료 판정은 감사가 한다.** 구현자가 "닫혔다"고 선언하지 않는다.
- **오너에게 넘기는 것은 넷뿐이다** — 계정 로그인·동의·비밀 입력·비용/외부 권한,
  그리고 대체할 수 없는 최종 제품 판단. 명령 실행·브라우저 조작·재현·측정은 구현자가 한다.

## 6. 오너가 반복해서 요구한 것 — **실제 판정 기준**

문서보다 이 목록이 먼저다. 전부 오너가 직접 말한 것이고, 대부분 **질책으로 왔다.**

### 무엇을 위해 만드나

1. **모든 것의 위에 §0 이 있다** — AI 와 AI 운영체제의 존재 이유는 **인간 사용자의 목적 달성**이다.
   그 위에 아무것도 없다. 기술도, 안전도, 우아함도.
2. **방법이 목적을 덮으면 안 된다.** 시작은 언제나 사용자 목적이다. 도구가 늘어도
   사용자 문장이 그대로 끝나면 **0점**이다.
3. **첫 번째 목표는 동작하는 제품이다.** 보고서는 목적이 아니라 과정의 일부다.
4. **사용자 비용은 에너지 > 시간 > 돈 순이다.** 방법을 고를 때 사용자가 **아무것도 안 해도 되는 길**
   (0번)이 있으면 그 길이다. 다시 로그인시키는 것이 2번이다.

### 무엇을 만들지 않나

5. **자동성이 의무다.** 승인으로 안전을 사지 마라. **T5 가 묻는 것은 넷뿐이다** —
   비밀 입력 · **되돌릴 수 없는** 파괴 · 새 상대 첫 전송 · 돈. 다섯째를 만들지 마라.
6. **과잉개발 금지.** 구성요소는 대체로 **이미 있다.** 안 되는 것은 손이 없어서가 아니라
   제자리에 안 놓여서인 경우가 훨씬 많다 — 그걸 먼저 확인해라(정렬 판 §4 「귀속 넷」).
7. **만들지 말고 읽고 판정해라.** 오너에게 올리는 것은 셋뿐이다 —
   P0 · 방향 오류 · 되돌릴 수 없는 것.

### 무엇을 사실이라고 부르나

8. **판정칸은 밟은 기계 사실에서만 적는다.** 빈 측정을 긍정 증거로 세우지 마라.
   `미측정` 은 `통과` 가 아니다.
9. **관측을 결함으로 승격하지 마라.** 재현 없으면 관측이다. 표본이 적으면 가설로 적어라.
10. **대리지표를 결과로 세우지 마라.** 프로세스 수·호출 수는 참이지만 **사용자가 보는 것이 아니다.**
11. **영향 0 인 작업을 제품 효과로 보고하지 마라.** 계약 관통 ≠ 제품 변화.
12. **시간은 학습의 근거가 아니다.** 반복과 실패 이력이 근거다. 시계는 lease·TTL 에만.
13. **비교군은 채점 전에 확정한다.** 결과를 본 뒤 기준이나 비교군을 고르지 마라.
14. **내 주장에도 같은 계약을 적용한다.** 이름·호출·존재로 효과를 단정하지 마라 —
    그건 남을 심사할 때 쓰는 잣대다. 자기 진단에도 똑같이 써라.
15. **희망고문 금지.** 부족하면 부족하다고, 모르면 모른다고 적어라.

### 어떻게 고치나

16. **문제마다 패치를 붙이지 마라** — 나비효과(작은 한 곳이 전체를 바꾼다) ·
    프랙탈(같은 모양이 모든 층에 있다) · 매듭(여러 증상이 한 자리에서 묶인다).
17. **감사 지적은 패턴으로 흡수한다.** 지적을 고치는 것 + 그렇게 만든 원인을 밝히는 것 +
    재발을 막는 구조, 이 셋이 한 세트다.
18. **역할 경계** — 개발은 구현자가 한다. 벽을 만나면 뚫어라. 그러나 **닫혔다고 선언하지 마라.**
    종료 판정은 감사가 한다.
19. **라이브까지 직접 돌리고 보고해라.** 서버를 띄우고 그 문장을 실제로 넣어 최종 답을 본 뒤에
    보고한다. 검사가 초록인 것과 제품이 되는 것은 다르다.
