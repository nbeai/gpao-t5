### 1-A. 게이트 성능 선이 흔들린다 (2026-08-06 · 밟아서 확정)

**코드 회귀가 아니다.** 08-05 커밋(`f36700b`)과 지금 HEAD 를 같은 명령으로 직접 재니
CPU 가 사실상 같다:

```
f36700b (08-05)   real 25.0   user 38.17  sys 12.13   → CPU 50.3s
HEAD    (08-06)   real 28.1   user 37.85  sys 11.74   → CPU 49.6s
```

**한 번 적었던 "부하 탓이 아니다" 는 틀렸다**(정정). 게이트가 CPU 101.7s 를 두 번 냈지만,
같은 검사를 직접 돌리면 50s 다. **CPU 는 부하에 흔들린다** — §17 주석이 *"CPU 는 부하를
걸어도 ±3%"* 라고 적은 것은 1,598건 시절의 관측이고, 3,100건에서는 두 배까지 벌어진다.

**남는 진짜 문제는 벽시계 쪽이다.**

```
CPU 상한     pass × 0.025s          → 검사가 늘면 같이 는다
벽시계 상한   30s 고정               → 검사가 늘어도 안 는다
```

`--test-concurrency=3` 이라 검사 파일이 늘면 벽시계는 선형으로 는다
(287 → 320 파일, 2026-08-05 → 08-06). 실측 27.2s ~ 33.7s — **선 위에 걸쳐 있다.**
잠든 검사가 없어도 통과·차단이 뒤집힌다. 그게 §17 이 막으려던 바로 그 상태다.

**어느 검사가 느려서가 아니다** — 오늘 추가된 32개 중 제일 무거운 것이 1.1s 다.
**고칠 자리는 선의 모양이지 검사가 아니다.** 선을 옮기는 것은 오너 결정이다(§17).

## 5. 가장 중요한 열린 구멍

> **되돌릴 수 있는 대량 이동은 승인 카드 없이 실행된다.**

자동성 헌장이 그렇게 정했다 — 되돌릴 수 있으면 묻지 않는다. 그 자체는 옳다.
문제는 **짧은 발화 하나가 수백 개를 옮기는 실행으로 이어질 수 있고, 사용자가 막을 자리가 없다**는 것이다.

실제로 일어났다: 2026-08-05 00:03, 격리를 안 건 채 실모델을 돌렸더니 **"아이기스" 한 단어에
파일 443개가 옮겨졌다.** 되돌렸고 손실은 0이지만, **카드는 한 번도 뜨지 않았다.**

오늘 세운 그물 어느 것도 못 막는다 — 이월 보호는 도구 지문만 보고, 발화밖 파괴는 `delete` 만 본다.
`bulk_move` 는 되돌릴 수 있어 전부 통과한다.

**여전히 열려 있다.** 전환(§8)이 우선순위를 가져갔고, 이건 기능을 더하는 일이라
전환에 안 들어간다. 막는 방법은 마찰을 늘리는 쪽이라 **오너 판단이 먼저다.**
